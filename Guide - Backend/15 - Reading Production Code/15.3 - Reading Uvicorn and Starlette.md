## ASGI, in One Screen

```python
async def app(scope, receive, send):
    assert scope["type"] == "http"
    body = b""
    while True:
        message = await receive()
        body += message.get("body", b"")
        if not message.get("more_body", False):
            break

    await send({"type": "http.response.start", "status": 200,
                "headers": [(b"content-type", b"text/plain")]})
    await send({"type": "http.response.body", "body": b"Hello"})
```

💡 **That is the entire interface between a server and a framework.** Three arguments: a dict describing the connection, a callable to receive messages, and a callable to send them.

⚠️ **Everything Starlette and FastAPI do is built on this.** Routing, middleware, dependency injection, request objects — **all of it is a layer over `scope`, `receive` and `send`.**

**Read the ASGI specification once.** It is short, and it makes the rest of this session straightforward.

## The Path

### 1. Startup — `uvicorn/server.py`

```python
class Server:
    async def serve(self, sockets=None):
        config = self.config
        if not config.loaded:
            config.load()
        self.lifespan = config.lifespan_class(config)
        await self.startup(sockets=sockets)
        await self.main_loop()
        await self.shutdown(sockets=sockets)
```

**Read `startup`.** It creates the socket, installs signal handlers, and starts the lifespan protocol.

💡 **`config.load()` is where your `--workers`, `--loop` and `--http` choices become actual objects.** `uvloop` versus `asyncio`, `httptools` versus `h11` — **and the difference is measurable** ([[01.9 - ASGI and How Uvicorn Serves a Request]]).

⚠️ **`install_signal_handlers` is the graceful shutdown entry point.** Note that it sets `self.should_exit` rather than acting immediately ([[11.7 - Graceful Shutdown and Draining]]).

### 2. A connection arrives — `uvicorn/protocols/http/httptools_impl.py`

```python
class HttpToolsProtocol(asyncio.Protocol):
    def connection_made(self, transport):
        self.connections.add(self)
        self.transport = transport
        ...

    def data_received(self, data):
        try:
            self.parser.feed_data(data)
        except httptools.HttpParserError:
            self.send_400_response("Invalid HTTP request received.")
```

💡 **This is `asyncio.Protocol`, the callback-based low-level API** — not `async def`. The event loop calls `data_received` when bytes arrive ([[01.4 - Building an Event Loop From Scratch]]).

⚠️ **`data_received` can be called with a partial request.** The parser is fed incrementally, exactly as in [[15.2 - Reading Redis Networking]] — **the same problem, the same solution.**

### 3. Building the scope — `on_headers_complete`

```python
def on_headers_complete(self):
    self.scope["method"] = self.parser.get_method().decode("ascii")
    self.scope["path"] = ...
    self.scope["headers"] = self.headers
    ...
    self.cycle = RequestResponseCycle(scope=self.scope, transport=self.transport, ...)
    self.tasks.add(self.loop.create_task(self.cycle.run_asgi(app)))
```

💡 **`create_task` is where your handler becomes a task on the event loop.** Everything before this is callback-driven; everything after is a coroutine ([[01.5 - Coroutines Tasks and Futures]]).

**Note that the task is tracked in `self.tasks`** — that is what makes graceful shutdown able to wait for in-flight requests.

### 4. The request/response cycle — `RequestResponseCycle`

```python
async def run_asgi(self, app):
    try:
        result = await app(self.scope, self.receive, self.send)
    except BaseException as exc:
        msg = "Exception in ASGI application\n"
        self.logger.error(msg, exc_info=exc)
        if not self.response_started:
            await self.send_500_response()
        else:
            self.transport.close()          # ⚠️ already streaming — cannot send 500
```

⚠️ **That `else` branch is important.** Once the response has started, the status is already on the wire — **an exception mid-stream can only close the connection** ([[03.6 - Compression and Streaming Responses]]).

💡 **This is why a streaming endpoint must handle its own errors** and emit them in-band, as an SSE error event or a trailing JSON object ([[05.3 - Error Design]]).

```python
async def receive(self):
    if self.waiting_for_100_continue and not self.transport.is_closing():
        self.transport.write(b"HTTP/1.1 100 Continue\r\n\r\n")
    ...
    await self.message_event.wait()
```

**`receive` is how the body reaches your handler**, in chunks, with flow control.

### 5. Backpressure — `send`

```python
async def send(self, message):
    ...
    self.transport.write(body)
    await self.flow.drain()          # ← waits if the client is slow
```

💡 **`flow.drain()` is application-level backpressure.** If the client is not reading, the transport buffer fills and `drain` suspends your coroutine — **so a slow client slows one handler rather than exhausting memory** ([[04.7 - Presence Fanout and Backpressure]]).

⚠️ **`FlowControl` in `uvicorn/protocols/utils.py` implements `pause_writing`/`resume_writing`.** This is asyncio's transport flow control, and it is the mechanism most people writing streaming endpoints have never heard of.

### 6. Starlette — routing and middleware

```python
class Starlette:
    async def __call__(self, scope, receive, send):
        scope["app"] = self
        await self.middleware_stack(scope, receive, send)
```

```python
def build_middleware_stack(self):
    app = self.router
    for cls, args, kwargs in reversed(middleware):
        app = cls(app, *args, **kwargs)
    return app
```

⚠️ **`reversed`.** Middleware added first is *outermost*, so it sees the request first and the response last.

💡 **This one line explains every middleware ordering surprise you have had.** Read it, then predict the execution order of three middleware and verify.

```python
class Router:
    async def app(self, scope, receive, send):
        for route in self.routes:
            match, child_scope = route.matches(scope)
            if match == Match.FULL:
                scope.update(child_scope)
                await route.handle(scope, receive, send)
                return
```

⚠️ **Routes are matched in registration order, first match wins.** `/documents/{id}` registered before `/documents/search` means `search` is treated as an ID.

### 7. Request and Response

```python
class Request(HTTPConnection):
    async def body(self) -> bytes:
        if not hasattr(self, "_body"):
            chunks = [chunk async for chunk in self.stream()]
            self._body = b"".join(chunks)
        return self._body

    async def is_disconnected(self) -> bool:
        ...
```

💡 **`Request` is a thin wrapper over `scope` and `receive`.** `request.headers` reads `scope["headers"]`; `request.body()` drains `receive`.

⚠️ **`await request.body()` buffers the entire body in memory.** For large uploads, use `request.stream()` — **and note that calling `body()` after `stream()` fails, because the stream is consumed.**

### 8. Cancellation on disconnect

```python
# BaseHTTPMiddleware, and Starlette's response handling
```

⚠️ **When a client disconnects, uvicorn cancels the task running your handler** ([[01.7 - Cancellation and Structured Concurrency]]).

💡 **This is why a multi-step operation inline in a request can be left half-done** — the `CancelledError` is raised at the next `await`, which could be between two database writes.

**That is the concrete reason for the durable-record-then-queue pattern from [[08.1 - Why Background Work Exists]].**

## What to Take Away

### Middleware ordering

```python
app = Starlette(middleware=[
    Middleware(CORSMiddleware, ...),        # outermost
    Middleware(AuthenticationMiddleware),
    Middleware(GZipMiddleware),             # innermost
])
```

```
Request:  CORS → Auth → GZip → handler
Response: handler → GZip → Auth → CORS
```

💡 **Logging middleware should be outermost** so it sees the final status, including one set by an error handler. **Auth should be outside anything that reads the body.**

### `BaseHTTPMiddleware` has a cost

⚠️ **`BaseHTTPMiddleware` runs your handler in a separate task with an anyio memory stream**, which breaks `contextvars` propagation in some versions and adds overhead per request.

💡 **Pure ASGI middleware is faster and avoids the task boundary:**

```python
class TimingMiddleware:
    def __init__(self, app):
        self.app = app

    async def __call__(self, scope, receive, send):
        if scope["type"] != "http":
            return await self.app(scope, receive, send)
        start = time.perf_counter()
        await self.app(scope, receive, send)
        duration.observe(time.perf_counter() - start)
```

**Write middleware this way unless you need the `Request`/`Response` convenience.**

### The worker model

```
uvicorn --workers 4
```

⚠️ **Uvicorn's `--workers` forks processes, each with its own event loop and its own connection pool.** Four workers with a pool of 20 is 80 database connections from one container ([[06.9 - Connection Pooling and PgBouncer]]).

💡 **And it derives the worker count from the host's CPUs unless you tell it otherwise** — which on a limited container is wrong ([[13.1 - Containers From First Principles]]).

## In Production

### What this changes about your code

| You learned | You should |
|---|---|
| Middleware is reversed | Order deliberately, and test the order |
| Routes match first-wins | Register specific before parametric |
| `body()` buffers everything | Stream large uploads |
| Errors after `response.start` cannot set a status | Handle stream errors in-band |
| The handler task is cancelled on disconnect | Write a durable record, then queue |
| `flow.drain()` provides backpressure | Do not fight it with your own buffering |
| `BaseHTTPMiddleware` costs a task | Use pure ASGI middleware |

### Graceful shutdown, in the source

```python
async def shutdown(self, sockets=None):
    for server in self.servers:
        server.close()
    for connection in list(self.server_state.connections):
        connection.shutdown()
    while self.server_state.tasks and not self.force_exit:
        await asyncio.sleep(0.1)
```

💡 **Reading this makes [[11.7 - Graceful Shutdown and Draining]] concrete:** stop accepting, tell connections to close after their current request, then wait for in-flight tasks.

⚠️ **Note there is no delay before closing the listening socket.** That is why you need a `preStop` sleep — uvicorn cannot know that the load balancer has not yet removed you.

### Debugging with what you now know

```python
@app.middleware("http")
async def debug_scope(request, call_next):
    print(request.scope.keys())
    return await call_next(request)
```

💡 **`scope` contains everything** — the client address, the TLS info, the path parameters after routing, and whatever middleware added. **Printing it once is a fast way to understand what your framework has available.**

**Part 2 — A raw ASGI application.** No Starlette, no FastAPI. Three routes, one middleware, request body reading, and a streaming response.

**About 100 lines**, and it removes the framework entirely from your mental model.

**Part 3 — Predict, then verify.** Before running anything, write predictions:

| Question | |
|---|---|
| Three middleware — what order on request and response? | |

**Then verify each. Record which predictions were wrong** — those are the surprises worth keeping.

**Part 4 — Disconnect and cancellation.** A handler doing three sequential database writes with a delay between them.

**Disconnect the client after the first.** Inspect the database.

**Confirm the state is inconsistent.** Then implement the durable-record-then-queue pattern and confirm consistency.

Then measure: **how often does this happen at realistic client timeout settings** under load?

**Part 5 — Backpressure, observed.** A streaming endpoint sending 100MB.

**Connect a client that reads slowly (or not at all).** Measure server memory.

**Then instrument `flow.drain()`** — add a log line or a breakpoint — and confirm your handler is suspended rather than buffering.

Then disable flow control (buffer yourself) and **watch memory grow.**

**Part 6 — Errors mid-stream.** A streaming endpoint that raises after sending 1KB.

**Confirm the client receives a truncated 200, not a 500.**

Then implement in-band error signalling and a client that detects it. **Then write a naive client that only checks the status and show it silently accepting the truncation.**

**Part 7 — Middleware cost.** The same timing middleware written with `BaseHTTPMiddleware` and as pure ASGI.

**Benchmark both: requests per second, p99 latency, and memory per request.**

Then test `contextvars` propagation through each. **Report the difference.**

**Part 8 — mini-uvicorn.** An `asyncio.Protocol` HTTP server that:

```
- parses requests with h11 or by hand
- builds an ASGI scope
- runs an ASGI app as a task
- implements receive and send
- handles flow control
- cancels the task on disconnect
- shuts down gracefully, waiting for in-flight tasks
```

**Then run your Starlette application on it unmodified.** If it works, you have understood ASGI.

**Done when:**
- Your trace covers all eight stages, verified with breakpoints
- A raw ASGI application works without any framework
- You recorded which of five predictions were wrong
- A mid-handler disconnect leaves inconsistent state, and the fix prevents it
- You observed `flow.drain()` suspending your handler under a slow client
