# Rapid Fire - HTML CSS and Accessibility

## HTML

**Why not use a `div` with an onClick instead of a button?**
A `<button>` gives focusability, Enter and Space activation, screen reader announcement as a button, `:disabled` state, form submission and a default focus ring. Recreating that takes roughly twenty lines and is usually done wrong. → [[09.1 - Semantic HTML and Document Structure]]

**`article` vs `section` vs `div`?**
`article` is independently distributable — a post, a comment, a product card. `section` is a thematic grouping and **should have a heading**; without one it is a `div`. `div` has no semantics and is correct for layout wrappers. → [[09.1 - Semantic HTML and Document Structure]]

**Does the HTML5 outline algorithm scope heading levels?**
No. It was never implemented by any browser or screen reader and has been removed from the spec. An `<h1>` inside a nested `<section>` is still an `h1` — use explicit levels and do not skip them. → [[09.1 - Semantic HTML and Document Structure]]

**Why does `type="number"` cause problems for phone numbers and OTPs?**
It strips leading zeros, allows `e` and `-`, and scroll-wheel changes the value accidentally. Use `type="text"` with `inputmode="numeric"`. → [[09.2 - Forms and Native Input Behavior]]

**Why is placeholder text not a label?**
It disappears on focus, usually fails contrast requirements, and is not reliably announced. A real `<label>` also expands the click target, which matters for checkboxes on mobile. → [[09.2 - Forms and Native Input Behavior]]

**What does `autocomplete` actually do?**
Lets browsers and password managers fill a form in one tap. `autocomplete="one-time-code"` enables SMS OTP autofill on iOS and Android. It is a few attributes and measurably improves completion rates. → [[09.2 - Forms and Native Input Behavior]]

**Why must images have `width` and `height`?**
The browser reserves space from the ratio before the image loads. Without them, every image arrival shifts the layout — the largest single contributor to CLS. → [[09.3 - Images Media and Loading Attributes]]

**`srcset` vs `<picture>`?**
`srcset` with `sizes` for resolution switching — same image, different sizes. `<picture>` for art direction (different crops) and format negotiation (AVIF/WebP with a fallback). → [[09.3 - Images Media and Loading Attributes]]

**Why is a hero image as a CSS background a performance problem?**
The preload scanner cannot see it, so it is discovered only after CSS is parsed — delaying LCP. Make the LCP element a real `<img>` in the initial HTML. → [[09.3 - Images Media and Loading Attributes]]

**Why do social share previews break in SPAs?**
Social crawlers generally do not execute JavaScript, so Open Graph tags set in an effect are never seen. They must be in the server-rendered HTML. → [[09.4 - Head Metadata and SEO Basics]]

## CSS

**How does specificity work?**
Counted as `(IDs, classes/attributes/pseudo-classes, elements)`, compared component-wise. It does **not** carry — eleven classes still lose to one ID. `:where()` is always zero; `:is()` and `:not()` take their highest argument's specificity. → [[10.1 - The Cascade Specificity and Inheritance]]

**What sits above specificity in the cascade?**
Origin and importance first, then `@layer` ordering, then specificity, then source order. Cascade layers are the clean way to end specificity wars — a later layer always beats an earlier one regardless of selector weight. → [[10.1 - The Cascade Specificity and Inheritance]]

**Which properties inherit?**
Typography — `color`, `font-*`, `line-height`, `text-align`, `visibility`, `cursor`. Box properties do not. Form controls do not inherit fonts by default, hence `font: inherit` in every reset. → [[10.1 - The Cascade Specificity and Inheritance]]

**`content-box` vs `border-box`?**
With `content-box` (the default), `width` is the content width and padding and border are added on top. With `border-box`, `width` is the total. `border-box` is what almost everyone wants. → [[10.2 - The Box Model and Sizing]]

**What is margin collapsing?**
Adjacent vertical margins merge into the larger of the two — between siblings, and between a parent and its first or last child when nothing separates them. Blocked by padding, border, `overflow` other than visible, `display: flow-root`, and flex/grid containers. → [[10.2 - The Box Model and Sizing]]

**Why does my flex item overflow its container?**
Flex items have `min-width: auto`, so they refuse to shrink below their content's intrinsic size. Add `min-width: 0`. In Grid, the equivalent is `minmax(0, 1fr)`. → [[10.2 - The Box Model and Sizing]]

**Why does `height: 100%` do nothing?**
Percentage heights need a definite parent height. Use `100dvh`, or a grid/flex parent. `100vh` is too tall on mobile because it uses the largest viewport height. → [[10.2 - The Box Model and Sizing]]

**Flexbox vs Grid?**
Flexbox is one-dimensional and content-driven; Grid is two-dimensional and layout-driven. They compose — a page is a grid, the components inside it are flex. → [[11.1 - Flexbox]]

**`flex: 1` vs `flex: auto`?**
`flex: 1` is `1 1 0%`, so items end up equal width regardless of content. `flex: auto` is `1 1 auto`, so they size proportionally to their content. → [[11.1 - Flexbox]]

**`auto-fit` vs `auto-fill`?**
`auto-fill` creates as many tracks as fit, leaving empty ones. `auto-fit` collapses empty tracks so existing items stretch. `repeat(auto-fit, minmax(250px, 1fr))` is a responsive card grid with no media queries. → [[11.2 - CSS Grid]]

**What creates a stacking context?**
The root, `position` other than static with a `z-index`, `position: fixed` or `sticky`, `opacity < 1`, `transform`, `filter`, `backdrop-filter`, `clip-path`, `mix-blend-mode`, `isolation: isolate`, `will-change` on any of those, and `contain: paint`. A child cannot escape its parent's context regardless of z-index. → [[10.5 - Positioning and Stacking Contexts]]

**Why did my `position: fixed` element stop being fixed?**
An ancestor has a `transform`, `filter` or `perspective`, which makes it the containing block for fixed descendants. Portal out of the transformed subtree, or use the top layer via `<dialog>`. → [[10.5 - Positioning and Stacking Contexts]]

**Why is my sticky element not sticking?**
Three usual causes: no `top`/`bottom` offset set, an ancestor with `overflow: hidden` or `auto`, or a parent no taller than the sticky element. → [[10.5 - Positioning and Stacking Contexts]]

**Which properties animate cheaply?**
`transform` and `opacity` only — handled by the compositor, skipping layout and paint. Everything else triggers layout or paint every frame. → [[11.4 - Transitions and Animations]]

**How do you animate to `height: auto`?**
Transition `grid-template-rows` from `0fr` to `1fr` with `overflow: hidden` on the child. `interpolate-size` and `calc-size()` are arriving to make it direct. → [[11.4 - Transitions and Animations]]

**Container queries vs media queries?**
Media queries ask about the viewport; container queries ask about the component's available space. Only the latter makes a component genuinely reusable in a sidebar and a full-width grid. → [[11.3 - Responsive Design]]

**`rem` vs `em`?**
`rem` is relative to the root font size and respects the user's browser setting. `em` is relative to the element's own font size and compounds when nested — useful for padding that should scale with text. → [[10.4 - Units Custom Properties and Theming]]

**Why use `oklch` over `hsl`?**
It is perceptually uniform, so equal lightness values look equally light across hues. Generating a palette by varying lightness in HSL produces a yellow that looks far brighter than a blue at the same value. → [[10.4 - Units Custom Properties and Theming]]

**How do you avoid a flash of the wrong theme?**
A small blocking inline script in `<head>`, before any stylesheet, that reads the stored preference and sets a data attribute. Reading it in an effect means the page paints light first. → [[10.4 - Units Custom Properties and Theming]]

## Accessibility

**What are the four WCAG principles?**
Perceivable, Operable, Understandable, Robust. Level AA is the practical target and the legal standard in most jurisdictions. → [[09.5 - Accessibility Fundamentals]]

**What are the rules of ARIA?**
Use a native element if one exists; do not change native semantics; all interactive ARIA must be keyboard operable; never put `aria-hidden` or `role="presentation"` on a focusable element; every interactive element needs an accessible name. No ARIA is better than bad ARIA. → [[09.5 - Accessibility Fundamentals]]

**Why `:focus-visible` instead of `:focus`?**
It shows the focus ring for keyboard users without showing it on mouse click — which removes the reason people wrote `outline: none` in the first place. → [[09.5 - Accessibility Fundamentals]]

**What are the `tabindex` rules?**
`0` inserts into the natural tab order, `-1` makes an element programmatically focusable but not tabbable. Never use a positive value — it overrides document order and becomes unmaintainable. → [[09.5 - Accessibility Fundamentals]]

**What breaks in SPA navigation?**
Focus is not reset and nothing is announced, so a screen reader user stays where they were while the content changes entirely. Move focus to `<main>` or the page heading and update `document.title` on every navigation. → [[23.1 - Client Side Routing Fundamentals]]

**Why does my live region not announce?**
The container must exist in the DOM **before** the content changes. Rendering the whole region conditionally means the screen reader never observes a change within an existing region. → [[12.5 - Custom Events and Observer APIs]]

**`aria-live="polite"` vs `role="alert"`?**
`polite` waits for a pause — status updates, result counts. `role="alert"` (implicitly assertive) interrupts — errors and time-critical information only. → [[09.5 - Accessibility Fundamentals]]

**What are the contrast requirements?**
4.5:1 for normal text, 3:1 for large text and UI component boundaries. Never convey information by colour alone. → [[09.5 - Accessibility Fundamentals]]

**How much do automated accessibility tools catch?**
Roughly 30–40% — missing alt text, contrast, missing labels, invalid ARIA. Keyboard-only testing and a screen reader catch most of the rest. → [[09.5 - Accessibility Fundamentals]]

**Why is `<dialog>` better than a custom modal?**
`showModal()` renders in the browser's top layer above all stacking contexts, and provides focus trapping, Escape to close, background inertness and `::backdrop` — all things custom modals routinely get wrong. → [[22.2 - Portals]]
