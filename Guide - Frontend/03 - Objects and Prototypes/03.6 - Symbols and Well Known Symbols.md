# Symbols and Well Known Symbols

`Symbol` is the seventh primitive type. Every symbol is **unique** — two symbols with the same description are still different values — which makes them collision-proof property keys.

```js
const a = Symbol("id");
const b = Symbol("id");
a === b;        // false
a.description;  // "id"
typeof a;       // "symbol"
```

Symbols cannot be created with `new`, cannot be implicitly converted to strings (`"" + sym` throws a `TypeError`), and are the only non-string type usable as a property key.

## Symbols as keys

```js
const CACHE = Symbol("cache");

function decorate(obj) {
  obj[CACHE] = new Map();
  return obj;
}
```

The `CACHE` property is invisible to `Object.keys`, `for...in`, `JSON.stringify` and `Object.assign`'s enumeration of string keys — though spread *does* copy symbol keys. It is retrievable only via `Object.getOwnPropertySymbols` or `Reflect.ownKeys`.

This is the mechanism for attaching metadata to objects you do not own without any chance of clashing with the owner's properties or with another library doing the same thing. It is not a *security* boundary — symbols are discoverable — it is a *collision* boundary.

## The global symbol registry

```js
Symbol.for("app.id") === Symbol.for("app.id");  // true
Symbol.keyFor(Symbol.for("app.id"));            // "app.id"
Symbol.keyFor(Symbol("app.id"));                // undefined
```

`Symbol.for` looks up a cross-realm registry, so the same key returns the same symbol even across iframes and workers. Use it when two independently loaded copies of a library must agree on a symbol; use plain `Symbol()` otherwise.

## Well-known symbols

These are the interesting part: hooks the language itself calls on your objects. Implementing one changes how a built-in operation behaves.

**`Symbol.iterator`** — makes an object usable with `for...of`, spread and destructuring ([[06.6 - Iterators and Generators]]).

```js
class Range {
  constructor(start, end) { this.start = start; this.end = end; }

  *[Symbol.iterator]() {
    for (let i = this.start; i <= this.end; i++) yield i;
  }
}

[...new Range(1, 4)]; // [1, 2, 3, 4]
```

**`Symbol.asyncIterator`** — same, for `for await...of`. This is how you consume a paginated API or a stream as a sequence.

**`Symbol.toPrimitive`** — controls coercion to a primitive, overriding `valueOf` and `toString`.

```js
class Money {
  constructor(amount) { this.amount = amount; }

  [Symbol.toPrimitive](hint) {
    if (hint === "number") return this.amount;
    if (hint === "string") return `₹${this.amount}`;
    return `Money(${this.amount})`;
  }
}

const m = new Money(500);
+m;          // 500
`${m}`;      // "₹500"
m + "";      // "Money(500)"  — default hint
```

The three hints — `"number"`, `"string"`, `"default"` — are how the engine tells you what it is trying to do. Understanding this demystifies most of the coercion table in [[05.3 - Types Coercion and Equality]].

**`Symbol.toStringTag`** — customizes `Object.prototype.toString.call(x)`.

```js
class Collection {
  get [Symbol.toStringTag]() { return "Collection"; }
}
Object.prototype.toString.call(new Collection()); // "[object Collection]"
```

This is what makes `Object.prototype.toString.call(new Map())` return `"[object Map]"`, which is why that idiom works as a type check ([[02.8 - call apply and bind]]).

**`Symbol.hasInstance`** — customizes `instanceof`.

```js
class Even {
  static [Symbol.hasInstance](n) { return Number.isInteger(n) && n % 2 === 0; }
}
4 instanceof Even; // true
```

Rarely useful, occasionally elegant for validator objects.

**Others worth knowing exist:** `Symbol.species` (what constructor derived methods like `map` use), `Symbol.match`/`replace`/`split`/`search` (making an object usable as a regex argument), `Symbol.unscopables` (a `with`-statement escape hatch that exists purely for web compatibility).

## Where you meet symbols in practice

**React** marks valid elements with `Symbol.for("react.element")`. Using a registered symbol rather than a plain string is a deliberate security measure: a JSON payload from a server can contain the string `"react.element"` but cannot contain a symbol, so a maliciously crafted API response cannot be mistaken for a React element and rendered. That is a genuinely instructive use of the type.

**Redux** uses `Symbol.observable` for interop with observable libraries.

**Iteration everywhere** — every array, string, `Map`, `Set`, `NodeList` and generator implements `Symbol.iterator`. That is why spread works uniformly across all of them.

## How senior engineers actually use this

**They implement `Symbol.iterator` on custom collections.** A domain object that wraps a list becomes spreadable and `for...of`-able for free, which makes it feel native to consumers.

**They use symbols for library-internal metadata.** A cache, a "already normalized" marker, a link back to a parent — anything that must ride along on a user's object without appearing in their serialization.

**They use `Symbol.toStringTag` in libraries** so debugging output and type checks report something meaningful instead of `[object Object]`.

**They do not use symbols for privacy.** `#` private fields ([[03.4 - Classes vs Prototypes]]) or closures are the tools for that. Symbols are enumerable via `getOwnPropertySymbols`.

## Common pitfalls

- Expecting symbol-keyed properties to survive `JSON.stringify`. They are dropped entirely.
- Expecting `Object.keys` or `for...in` to include them. They do not; spread and `Object.assign` do.
- Implicitly stringifying a symbol — `"id: " + sym` throws. Use `String(sym)` or `sym.description`.
- Using `Symbol()` where `Symbol.for()` was needed, so two module instances disagree.
- Adding `Symbol.iterator` but forgetting `Symbol.asyncIterator`, then finding `for await` fails.

## Interview angle

Symbols come up as "what is a Symbol and why does it exist" and occasionally "make this object iterable". Answer that they are unique primitives usable as keys, so they cannot collide, and that the language reserves a set of well-known ones as extension points. Implementing `Symbol.iterator` with a generator on the spot is a compact way to show you understand both symbols and iteration protocols at once.
