# Repository Pattern

## At a Glance

|||
|---|---|
|**Type**|Backend / Enterprise|
|**Intent**|Encapsulate data access logic behind a collection-like interface, decoupling domain from persistence|
|**Origin**|Domain-Driven Design (Eric Evans)|
|**Frequency in Backend**|★★★★★ — every serious backend uses this|

---

## The Problem It Solves

Without Repository, business logic is entangled with database queries. Changing from SQL to a different DB, or writing unit tests, requires touching business logic.

```python
# ❌ Business logic mixed with SQL
class OrderService:
    def get_pending_orders_above(self, amount: Decimal):
        # Business logic directly executes SQL
        rows = db.execute("""
            SELECT * FROM orders 
            WHERE status = 'PENDING' 
            AND total > %s
            ORDER BY created_at DESC
        """, (amount,))
        return [Order.from_row(r) for r in rows]
    # Testing this requires a real DB (or complex mock of db object)
    # Switching to MongoDB = rewrite OrderService
```

---

## Structure

```
┌──────────────────┐          ┌─────────────────────────────┐
│  OrderService    │─uses────▶│ <<interface>>               │
│  (domain layer)  │          │ OrderRepository             │
└──────────────────┘          ├─────────────────────────────┤
                              │ + save(order)               │
                              │ + find_by_id(id) → Order    │
                              │ + find_pending() → [Order]  │
                              │ + delete(order)             │
                              └─────────────────────────────┘
                                             △
                               ┌────────────┴─────────────┐
                    ┌──────────┴───────┐     ┌────────────┴────────┐
                    │ SqlOrderRepository│     │ InMemoryOrderRepo   │
                    │ (prod)            │     │ (tests)             │
                    └───────────────────┘     └─────────────────────┘
```

## Full Backend Example: Order Repository

```python
# domain/order.py
from dataclasses import dataclass, field
from uuid import UUID
from decimal import Decimal
from enum import Enum
from datetime import datetime
from typing import List

class OrderStatus(Enum):
    PENDING = "PENDING"
    CONFIRMED = "CONFIRMED"
    PAID = "PAID"
    CANCELLED = "CANCELLED"

@dataclass
class Order:
    id: UUID
    user_id: UUID
    status: OrderStatus
    total: Decimal
    created_at: datetime
    items: List["OrderItem"] = field(default_factory=list)


# repositories/order_repository.py  (interface — in domain layer)
from abc import ABC, abstractmethod
from typing import List, Optional
from uuid import UUID
from decimal import Decimal

class OrderRepository(ABC):
    
    @abstractmethod
    def save(self, order: Order) -> Order:
        """Persist new or updated order. Returns the saved order."""
        pass
    
    @abstractmethod
    def find_by_id(self, order_id: UUID) -> Optional[Order]:
        pass
    
    @abstractmethod
    def find_by_user(self, user_id: UUID, limit: int = 20) -> List[Order]:
        pass
    
    @abstractmethod
    def find_pending(self) -> List[Order]:
        pass
    
    @abstractmethod
    def find_by_status(self, status: OrderStatus) -> List[Order]:
        pass
    
    @abstractmethod
    def find_above_total(self, amount: Decimal) -> List[Order]:
        pass
    
    @abstractmethod
    def delete(self, order_id: UUID) -> bool:
        pass
    
    @abstractmethod
    def exists(self, order_id: UUID) -> bool:
        pass


# infrastructure/sql_order_repository.py  (implementation — in infra layer)
from sqlalchemy.orm import Session
from sqlalchemy import select, and_

class SqlOrderRepository(OrderRepository):
    
    def __init__(self, session: Session):
        self._session = session
    
    def save(self, order: Order) -> Order:
        existing = self._session.get(OrderModel, order.id)
        if existing:
            # Update existing
            self._map_to_model(order, existing)
        else:
            # Insert new
            model = self._to_model(order)
            self._session.add(model)
        self._session.flush()  # get DB-generated values without committing
        return order
    
    def find_by_id(self, order_id: UUID) -> Optional[Order]:
        model = self._session.get(OrderModel, order_id)
        return self._to_domain(model) if model else None
    
    def find_by_user(self, user_id: UUID, limit: int = 20) -> List[Order]:
        stmt = (
            select(OrderModel)
            .where(OrderModel.user_id == user_id)
            .order_by(OrderModel.created_at.desc())
            .limit(limit)
        )
        models = self._session.execute(stmt).scalars().all()
        return [self._to_domain(m) for m in models]
    
    def find_pending(self) -> List[Order]:
        stmt = select(OrderModel).where(
            OrderModel.status == OrderStatus.PENDING.value
        )
        return [self._to_domain(m) for m in self._session.execute(stmt).scalars()]
    
    def find_by_status(self, status: OrderStatus) -> List[Order]:
        stmt = select(OrderModel).where(OrderModel.status == status.value)
        return [self._to_domain(m) for m in self._session.execute(stmt).scalars()]
    
    def find_above_total(self, amount: Decimal) -> List[Order]:
        stmt = select(OrderModel).where(OrderModel.total > amount)
        return [self._to_domain(m) for m in self._session.execute(stmt).scalars()]
    
    def delete(self, order_id: UUID) -> bool:
        model = self._session.get(OrderModel, order_id)
        if not model:
            return False
        self._session.delete(model)
        return True
    
    def exists(self, order_id: UUID) -> bool:
        return self._session.get(OrderModel, order_id) is not None
    
    # ── Private mapping methods ──────────────────────────────
    
    def _to_domain(self, model: "OrderModel") -> Order:
        return Order(
            id=model.id,
            user_id=model.user_id,
            status=OrderStatus(model.status),
            total=Decimal(str(model.total)),
            created_at=model.created_at,
            items=[self._item_to_domain(i) for i in model.items]
        )
    
    def _to_model(self, order: Order) -> "OrderModel":
        model = OrderModel(
            id=order.id,
            user_id=order.user_id,
            status=order.status.value,
            total=float(order.total),
            created_at=order.created_at
        )
        model.items = [self._item_to_model(item, model) for item in order.items]
        return model
    
    def _item_to_domain(self, model): ...
    def _item_to_model(self, item, parent): ...


# infrastructure/in_memory_order_repository.py  (for testing)
class InMemoryOrderRepository(OrderRepository):
    """Fast, no-DB implementation for unit tests."""
    
    def __init__(self):
        self._store: dict[UUID, Order] = {}
    
    def save(self, order: Order) -> Order:
        import copy
        self._store[order.id] = copy.deepcopy(order)  # simulate DB isolation
        return order
    
    def find_by_id(self, order_id: UUID) -> Optional[Order]:
        return self._store.get(order_id)
    
    def find_by_user(self, user_id: UUID, limit: int = 20) -> List[Order]:
        orders = [o for o in self._store.values() if o.user_id == user_id]
        return sorted(orders, key=lambda o: o.created_at, reverse=True)[:limit]
    
    def find_pending(self) -> List[Order]:
        return [o for o in self._store.values() if o.status == OrderStatus.PENDING]
    
    def find_by_status(self, status: OrderStatus) -> List[Order]:
        return [o for o in self._store.values() if o.status == status]
    
    def find_above_total(self, amount: Decimal) -> List[Order]:
        return [o for o in self._store.values() if o.total > amount]
    
    def delete(self, order_id: UUID) -> bool:
        return bool(self._store.pop(order_id, None))
    
    def exists(self, order_id: UUID) -> bool:
        return order_id in self._store
    
    # Test helpers
    def clear(self): self._store.clear()
    def count(self) -> int: return len(self._store)


# service layer — completely unaware of DB
class OrderService:
    def __init__(self, repo: OrderRepository):
        self._repo = repo
    
    def get_order(self, order_id: UUID) -> Order:
        order = self._repo.find_by_id(order_id)
        if not order:
            raise OrderNotFoundError(order_id)
        return order
    
    def get_high_value_pending_orders(self, threshold: Decimal) -> List[Order]:
        pending = self._repo.find_pending()
        return [o for o in pending if o.total >= threshold]


# Test — no DB needed
def test_get_high_value_pending():
    repo = InMemoryOrderRepository()
    service = OrderService(repo)
    
    repo.save(Order(id=uuid4(), ..., status=OrderStatus.PENDING, total=Decimal("500")))
    repo.save(Order(id=uuid4(), ..., status=OrderStatus.PENDING, total=Decimal("50")))
    repo.save(Order(id=uuid4(), ..., status=OrderStatus.PAID, total=Decimal("1000")))
    
    result = service.get_high_value_pending_orders(Decimal("100"))
    assert len(result) == 1
    assert result[0].total == Decimal("500")
```

## Repository vs DAO (Data Access Object)

||Repository|DAO|
|---|---|---|
|Abstraction level|Domain objects|Database rows|
|Returning|Domain entities|DTOs / raw data|
|Methods|Business-meaningful (`find_pending_orders`)|CRUD (`find_by_status("PENDING")`)|
|Origin|DDD|Enterprise Java (J2EE)|
|Query location|Inside repository|Anywhere|

---

## When NOT to Use Repository

- **Simple CRUD apps** — a thin ORM wrapper (Django ORM, SQLAlchemy) may be sufficient
- **Read-heavy reporting** — complex queries with joins are better expressed in raw SQL in a Query Object, not a Repository method
- **Script-level code** — scripts don't need the abstraction cost

---

## Tradeoffs

|Pro|Con|
|---|---|
|Domain layer has no DB knowledge|More files and mapping code|
|Swap DB or ORM without touching services|Mapping domain ↔ model is tedious|
|Fast unit tests with InMemory impl|InMemory behavior may diverge from real DB|
|Enforces query discipline|Easy to add too many `find_by_*` methods (query object better)|

---

## Common Mistakes

1. **Fat repositories** — 30+ `find_by_*` methods → extract to Specification pattern or Query Object
2. **Leaking ORM objects** — repository returns `OrderModel` (SQLAlchemy model) instead of `Order` domain object
3. **Transaction management in repository** — transactions belong in Unit of Work or application service, not repository
4. **InMemory repo diverging from SQL** — e.g., InMemory allows duplicate emails, SQL doesn't → test passes but prod fails

---

## Interview Perspective

> "How do you structure your data access layer?"

Repository pattern. Show: interface in domain layer, SQL implementation in infra layer, InMemory for tests. Emphasize the clean separation — domain layer doesn't import SQLAlchemy.
