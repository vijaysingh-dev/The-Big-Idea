# Indexing: Incremental Updates, Freshness, and Deduplication

## The Indexing Lifecycle Problem

A RAG index isn't static. Documents are created, edited, and deleted. Users expect answers based on current information. The indexing system must handle:

1. **New documents**: Add to index
2. **Updated documents**: Replace old index entries
3. **Deleted documents**: Remove from index
4. **Permission changes**: Update metadata without re-embedding
5. **Stale content**: Detect and surface content age

Getting this wrong means users receive outdated or inconsistent answers.

---

## Indexing Modes

### Full Re-index

Re-process all documents from scratch periodically:

```python
def full_reindex(connector, pipeline):
    # Step 1: Build new index in shadow space
    new_index = create_shadow_index()
    
    for document in connector.list_all_documents():
        chunks = pipeline.process(document)
        new_index.upsert(chunks)
    
    # Step 2: Atomic swap (zero-downtime)
    swap_index(new_index, production_index)
    delete_old_index()
```

**Pros**: Simple, always consistent.  
**Cons**: Slow (hours for large corpora), expensive (re-embeds everything), high latency for new content.  
**Use when**: Corpus is small (<100K docs), or doing a full schema migration.

---

### Incremental Indexing

Only process documents that changed since last sync:

```python
def incremental_sync(connector, pipeline, last_sync_time):
    # Fetch only modified docs
    for doc in connector.list_documents(modified_since=last_sync_time):
        if doc.action == "created" or doc.action == "modified":
            chunks = pipeline.process(doc)
            vector_store.upsert_chunks(doc.id, chunks)   # replace old chunks
            keyword_store.upsert_doc(doc.id, chunks)
        
        elif doc.action == "deleted":
            vector_store.delete_by_document_id(doc.id)
            keyword_store.delete_by_document_id(doc.id)
    
    # Update sync checkpoint
    last_sync_time = now()
```

**Key challenge**: Source systems must reliably report what changed.

|Source System|Change Detection Mechanism|
|---|---|
|Google Drive|`modifiedTime` filter on Files API|
|Confluence|Space activity feed + `lastModified`|
|Slack|Event webhooks (`message_changed`, `message_deleted`)|
|GitHub|Webhooks on push events|
|Generic file system|`inotify` or polling with hash comparison|

**When webhook is unavailable**: Fall back to polling + checksum comparison:

```python
def has_changed(doc_id, new_content, checksum_store):
    new_hash = hashlib.sha256(new_content.encode()).hexdigest()
    old_hash = checksum_store.get(doc_id)
    if new_hash != old_hash:
        checksum_store.set(doc_id, new_hash)
        return True
    return False
```

## Upsert Semantics

When a document is updated, you must replace all of its old chunks atomically:

```python
def upsert_document(document, chunks, vector_store):
    # Delete all existing chunks for this document
    vector_store.delete_by_filter({"document_id": document.id})
    
    # Insert new chunks
    for chunk in chunks:
        vector_store.insert(chunk)
```

**Problem**: There's a window between delete and insert where the document is not retrievable. Solutions:

- Use a vector DB that supports atomic document-level upsert (Vespa does this)
- Tag new chunks as "pending" and swap atomically
- Run full re-index if consistency is critical

## Handling Deletions

Document deletion is the hardest case. The source document is gone — but your index still has its chunks.

**Explicit deletion**: Source system sends a webhook or API event. Process immediately.

**Implicit deletion**: Document disappears without a notification. Detected by periodically diffing the source system's current document list against your index:

```python
def detect_deleted_documents(connector, index):
    # Get set of document IDs currently in source
    current_ids = set(connector.list_all_document_ids())
    
    # Get set of document IDs in our index
    indexed_ids = set(index.list_all_document_ids(source=connector.name))
    
    # Documents in index but not in source → deleted
    deleted = indexed_ids - current_ids
    for doc_id in deleted:
        index.delete_by_document_id(doc_id)
    
    return len(deleted)
```

Schedule this reconciliation job to run daily or weekly.

## Freshness

### Why Freshness Matters

A user asking "What's our current parental leave policy?" shouldn't get the 2019 version if the 2024 version exists.

### Freshness Strategies

**1. Timestamp filtering at query time**

```python
# Exclude documents older than 2 years for most queries
results = vector_store.search(
    query=query,
    filter={"modified_at": {"$gte": two_years_ago}}
)
```

**Problem**: May exclude the only relevant document if it's old.

**2. Recency boost in ranking**

Score documents higher if they're more recent, without hard cutoffs:

```python
def recency_boost(base_score, doc_modified_at, half_life_days=365):
    age_days = (now() - doc_modified_at).days
    decay = 0.5 ** (age_days / half_life_days)   # exponential decay
    return base_score * (1 + decay)
```

Vespa supports this natively via rank expressions.

**3. Explicit freshness metadata in context**

Include document date in the context so the LLM can reason about freshness:

```
[Source: Parental Leave Policy — last updated March 2024]
...content...

[Source: Parental Leave Policy — last updated January 2019]  ← LLM will prefer newer
...old content...
```

## Deduplication

### The Problem

The same content appears in multiple places:

- A Confluence page mirrored to Google Drive
- A Slack message quoting a document
- A document with multiple versions in different folders
- Re-indexed content after a failed sync job

Duplicate chunks waste storage, slow retrieval, and cause the same content to appear multiple times in the LLM context.

### Near-Duplicate Detection

```python
from datasketch import MinHash, MinHashLSH

def build_dedup_index(chunks):
    lsh = MinHashLSH(threshold=0.85, num_perm=128)
    unique_chunks = []
    
    for chunk in chunks:
        # Shingle the text
        shingles = {chunk.text[i:i+5] for i in range(len(chunk.text) - 4)}
        
        minhash = MinHash(num_perm=128)
        for shingle in shingles:
            minhash.update(shingle.encode())
        
        # Check if near-duplicate exists
        if not lsh.query(minhash):
            lsh.insert(chunk.id, minhash)
            unique_chunks.append(chunk)
        else:
            # Keep chunk with higher-quality source (e.g., prefer Confluence over Slack)
            pass
    
    return unique_chunks
```

### Canonical Source Priority

When duplicates exist, define source priority:

```python
SOURCE_PRIORITY = {
    "confluence": 1,    # authoritative
    "google_drive": 2,  # official
    "notion": 3,
    "slack": 4,         # ephemeral
    "email": 5,
}

def keep_canonical(duplicate_group):
    return min(duplicate_group, key=lambda d: SOURCE_PRIORITY.get(d.source, 99))
```

## Index Health Monitoring

Track these metrics to detect index issues:

```python
INDEX_HEALTH_METRICS = {
    "total_documents": gauge("rag.index.document_count"),
    "total_chunks": gauge("rag.index.chunk_count"),
    "index_lag_seconds": gauge("rag.index.lag"),          # how far behind source
    "failed_ingestions": counter("rag.ingestion.failures"),
    "deleted_documents": counter("rag.index.deletions"),
    "duplicate_chunks": gauge("rag.index.duplicates"),
    "avg_chunk_age_days": gauge("rag.index.avg_age"),
}
```

Alert on:

- Index lag > 1 hour (documents not being picked up quickly)
- Ingestion failure rate > 1% (connector or pipeline issues)
- Sudden drop in document count (accidental mass deletion)
