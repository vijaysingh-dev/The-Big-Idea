# Flexbox

Flexbox lays out items along **one axis** and distributes space between them. Use it when the content should determine the sizes; use Grid when the layout should ([[11.2 - CSS Grid]]).

## Axes

```css
.container {
  display: flex;
  flex-direction: row;   /* main axis: horizontal (default) */
}
```

Everything in flexbox is described relative to the **main axis** (set by `flex-direction`) and the **cross axis** (perpendicular to it). Changing `flex-direction` to `column` swaps which physical direction each property affects — `justify-content` now controls vertical distribution and `align-items` horizontal.

This is the single most important thing to internalize, and the source of most confusion.

## Container properties

```css
.container {
  display: flex;
  flex-direction: row | row-reverse | column | column-reverse;
  flex-wrap: nowrap | wrap | wrap-reverse;
  gap: 1rem;                    /* or row-gap / column-gap */

  justify-content: flex-start | center | space-between | space-around | space-evenly;
  align-items: stretch | flex-start | center | baseline | flex-end;
  align-content: /* same values — only applies when wrapped onto multiple lines */
}
```

- **`justify-content`** — distribution along the main axis
- **`align-items`** — alignment along the cross axis, per line
- **`align-content`** — distribution of the lines themselves, and it does nothing without `flex-wrap: wrap`

`align-items: stretch` is the default and is why flex children become equal height automatically — often desirable, occasionally the cause of a stretched image or button.

`gap` replaced margin-based spacing entirely. No last-child exceptions, no negative margins on the container, and it works identically in Grid.

## Item properties

```css
.item {
  flex-grow: 0;      /* share of leftover space to absorb */
  flex-shrink: 1;    /* share of overflow to give up */
  flex-basis: auto;  /* starting size along the main axis */

  flex: 0 1 auto;    /* the shorthand, in that order — the default */

  align-self: center;  /* override align-items for this item */
  order: 2;            /* visual reorder — does NOT change DOM/tab order */
}
```

The `flex` shorthand values worth memorizing:

```css
flex: 1;        /* 1 1 0%  — equal share of the container, ignoring content size */
flex: auto;     /* 1 1 auto — grow from content size, proportional to content */
flex: none;     /* 0 0 auto — fixed at content size, never grows or shrinks */
flex: 0 0 200px;/* fixed 200px */
```

The difference between `flex: 1` and `flex: auto` catches people out. With `flex: 1`, the basis is `0%`, so all items end up the same width regardless of content. With `flex: auto`, the basis is the content size, so items with more content end up wider.

`order` changes only paint order. Keyboard navigation still follows the DOM, so a visual order that differs from the DOM order is an accessibility problem ([[09.5 - Accessibility Fundamentals]]).

## The min-width: auto trap

The most common flexbox bug, and worth its own section.

Flex items have `min-width: auto` (or `min-height` in a column), meaning they refuse to shrink below their content's intrinsic minimum size. A long unbroken string, a wide table, or a `<pre>` block will blow the layout out rather than shrink.

```css
.flex-item {
  min-width: 0;        /* row direction */
  min-height: 0;       /* column direction */
}
```

Or, for text specifically:

```css
.flex-item { overflow: hidden; }        /* also removes the auto minimum */
.flex-item { overflow-wrap: break-word; }
```

Any time a flex layout overflows its container horizontally, check this first.

## Common patterns

**Centering:**

```css
.center {
  display: flex;
  align-items: center;
  justify-content: center;
}
```

**Header with pushed-right actions:**

```css
.header { display: flex; align-items: center; gap: 1rem; }
.header .spacer { margin-left: auto; }
```

`margin: auto` in flexbox absorbs all free space on that side, which is often cleaner than `justify-content: space-between` when only one item should be pushed.

**Sticky footer:**

```css
body {
  min-height: 100dvh;
  display: flex;
  flex-direction: column;
}
main { flex: 1; }
```

**Sidebar plus fluid content:**

```css
.layout { display: flex; gap: 2rem; }
.sidebar { flex: 0 0 250px; }
.content { flex: 1; min-width: 0; }
```

**Wrapping card row where cards grow to fill the last line:**

```css
.cards { display: flex; flex-wrap: wrap; gap: 1rem; }
.card { flex: 1 1 300px; }
```

Each card is at least 300px, wraps when it cannot fit, and grows to share the remaining space. This is often mistaken for a Grid requirement; flexbox does it in two lines. The difference is that the last row's items stretch to fill, whereas Grid keeps them column-aligned — pick based on which you want.

**Media object:**

```css
.media { display: flex; gap: 1rem; align-items: flex-start; }
.media__body { flex: 1; min-width: 0; }
```

## Flexbox vs Grid

| Use flexbox when | Use grid when |
| --- | --- |
| One dimension at a time | Two dimensions simultaneously |
| Content determines sizes | Layout determines sizes |
| Items should wrap freely | Rows and columns must align |
| Distributing space in a toolbar or row | Page or card layout with defined regions |

They compose: a grid page layout containing flex toolbars is the normal arrangement. Do not treat it as a choice of one.

## Logical properties

`flex-direction: row` follows the writing mode, so it reverses in RTL languages automatically. Prefer logical properties elsewhere for the same reason:

```css
margin-inline-start: 1rem;    /* left in LTR, right in RTL */
padding-block: 1rem;          /* top and bottom */
inset-inline-end: 0;
```

For a product serving Arabic, Hebrew or Urdu, using logical properties from the start avoids a full RTL retrofit later.

## Debugging

Chrome and Firefox DevTools both have a flexbox overlay — click the `flex` badge next to the element in the Elements panel. It draws the main and cross axes, shows free space, and highlights which items are growing or shrinking. It answers "why is this item not the size I expect" faster than reading the CSS.

## How senior engineers actually use this

**They use `gap` universally** and never reach for `margin-right` on all-but-last-child.

**They add `min-width: 0` to any flex item containing text or a scroll container**, preemptively.

**They use `flex: 1` for equal columns and `flex: auto` for content-proportional ones**, deliberately rather than by trial.

**They avoid `order` for anything that changes meaningful sequence**, because DOM order remains the accessibility order.

## Common pitfalls

- Items overflowing due to `min-width: auto`.
- `align-content` having no effect without `flex-wrap: wrap`.
- Expecting `flex: 1` to size items proportionally to content — it does not.
- Percentage `flex-basis` failing because the container has no definite size in that axis.
- `order` creating a mismatch between visual and keyboard order.
- Using flexbox for a two-dimensional layout and fighting it, where Grid is a few lines.
- `align-items: stretch` distorting images or buttons that should keep their natural size.

## Interview angle

"Difference between flexbox and grid" is asked constantly — one-dimensional versus two-dimensional, content-driven versus layout-driven, and note that they compose rather than compete. The `flex: 1` versus `flex: auto` distinction and the `min-width: auto` trap are both good details. A practical task like "build a header with a logo left and nav right" is common; `margin-left: auto` is the elegant answer.
