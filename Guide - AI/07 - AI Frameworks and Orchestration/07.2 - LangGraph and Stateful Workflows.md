# LangGraph and Stateful Workflows

## What LangGraph Is

LangGraph is a framework for building **stateful, cyclical agent workflows** as directed graphs. Built by the LangChain team but architecturally distinct — it addresses the problems that LangChain chains have with complex, multi-step, stateful workflows.

Core abstraction: your agent is a **graph** where:

- **Nodes** are Python functions (can call LLMs, tools, databases)
- **Edges** are transitions between nodes (conditional or unconditional)
- **State** is a typed dictionary that flows through the graph and persists across steps

---

## Why Graphs for Agents

Agents have two properties that chains don't handle well:

**1. Cycles**: Agents loop — they take an action, observe the result, decide whether to continue or finish. A linear chain can't express "if the answer is wrong, try again."

**2. State**: Across multiple steps, agents need to remember what happened. LangGraph's state dict is explicitly managed, inspectable, and persistent.

```
Simple chain (LangChain):        Agent workflow (LangGraph):
A → B → C → D → end              A → B → C
                                        ↓
                                        [conditional]
                                       / \
                                      D   E → B (loop back)
                                      ↓
                                      end
```

## LangGraph Core Concepts

### State

A typed dict (using TypedDict) that's passed between all nodes:

```python
from typing import TypedDict, Annotated
import operator

class AgentState(TypedDict):
    messages: Annotated[list, operator.add]  # append-only list
    query: str
    retrieved_docs: list
    answer: str
    retry_count: int
```

The `Annotated[list, operator.add]` annotation tells LangGraph to append new messages rather than replace the full list — crucial for conversation history.

### Nodes

Regular Python functions that take state and return state updates:

```python
def retrieve_node(state: AgentState) -> dict:
    query = state["query"]
    docs = vector_store.search(query, top_k=10)
    return {"retrieved_docs": docs}   # partial update; other state fields unchanged

def generate_node(state: AgentState) -> dict:
    context = format_docs(state["retrieved_docs"])
    messages = state["messages"] + [{"role": "user", "content": f"Context: {context}\n{state['query']}"}]
    response = llm.invoke(messages)
    return {"messages": [response], "answer": response.content}
```

### Graph Construction

```python
from langgraph.graph import StateGraph, END

workflow = StateGraph(AgentState)

# Add nodes
workflow.add_node("retrieve", retrieve_node)
workflow.add_node("generate", generate_node)
workflow.add_node("validate", validate_node)

# Add edges
workflow.set_entry_point("retrieve")
workflow.add_edge("retrieve", "generate")
workflow.add_conditional_edges(
    "generate",
    should_retry,               # router function
    {
        "retry": "retrieve",    # if should_retry returns "retry" → loop back
        "done": END,            # if "done" → finish
    }
)

# Compile
app = workflow.compile()
```

### Conditional Routing

```python
def should_retry(state: AgentState) -> str:
    answer = state["answer"]
    retry_count = state["retry_count"]
    
    if retry_count >= 3:
        return "done"   # give up after 3 retries
    
    if is_answer_grounded(answer, state["retrieved_docs"]):
        return "done"   # answer checks out
    else:
        return "retry"  # retrieved wrong context, try again
```

## Persistence and Checkpointing

LangGraph supports **checkpoints** — saving the full graph state to a database after each node execution:

```python
from langgraph.checkpoint.sqlite import SqliteSaver

checkpointer = SqliteSaver.from_conn_string("checkpoints.db")
app = workflow.compile(checkpointer=checkpointer)

# Run with a thread ID (for multi-turn persistence)
config = {"configurable": {"thread_id": "user_123_session_456"}}
result = app.invoke(initial_state, config=config)

# Resume later — state is persisted
result = app.invoke({"messages": [new_message]}, config=config)
```

This enables:

- **Human-in-the-loop**: Pause, wait for human approval, resume
- **Long-running agents**: Run for minutes/hours without holding a connection open
- **Fault tolerance**: Resume after crash from last checkpoint

## Human-in-the-Loop Pattern

```python
# Define an interrupt before a dangerous action
workflow.add_node("dangerous_action", dangerous_action_node)
workflow.compile(interrupt_before=["dangerous_action"])

# Run until interrupt
result = app.invoke(state, config)
# result.next == "dangerous_action" — paused here

# Human reviews and approves
print(f"About to: {result.values['pending_action']}")
approved = input("Approve? (y/n): ")

if approved == "y":
    result = app.invoke(None, config)  # resume from checkpoint
```

## ReAct Agent in LangGraph

The classic ReAct pattern implemented as a graph:

```
[call_model] → tool_calls? → YES → [execute_tools] → [call_model] (loop)
                             NO  → END
```

```python
def call_model(state):
    response = llm_with_tools.invoke(state["messages"])
    return {"messages": [response]}

def execute_tools(state):
    tool_calls = state["messages"][-1].tool_calls
    results = []
    for call in tool_calls:
        result = tools[call.name].invoke(call.args)
        results.append(ToolMessage(content=result, tool_call_id=call.id))
    return {"messages": results}

def should_continue(state):
    last = state["messages"][-1]
    return "continue" if last.tool_calls else "end"

workflow.add_node("agent", call_model)
workflow.add_node("tools", execute_tools)
workflow.add_conditional_edges("agent", should_continue, {"continue": "tools", "end": END})
workflow.add_edge("tools", "agent")
```

## Multi-Agent Graphs

Multiple specialized agents as subgraphs, orchestrated by a supervisor:

```
[Supervisor]
   / | \
  /  |  \
[Research  [Code      [Writer
 Agent]    Agent]     Agent]
```

```python
def supervisor_node(state):
    # LLM decides which agent to call next
    decision = supervisor_llm.invoke(f"Given: {state['task']}\nWhich agent next?")
    return {"next_agent": decision}

def route_to_agent(state):
    return state["next_agent"]  # "research", "code", "writer", or "FINISH"

workflow.add_conditional_edges("supervisor", route_to_agent, {
    "research": "research_agent",
    "code": "code_agent", 
    "writer": "writer_agent",
    "FINISH": END,
})
```

## When to Use LangGraph

**✅ Use LangGraph when**:

- Agent needs to loop (retry, reflection, multi-step tool use)
- You need human-in-the-loop interrupts
- Long-running workflows that need fault tolerance
- Multi-agent orchestration with shared state
- You need to inspect/debug agent state at each step

**❌ Skip LangGraph when**:

- Linear workflow (A → B → C, no loops)
- Simple RAG (just retrieval + generation)
- One-off scripts
- Team is unfamiliar with graph concepts (add cognitive overhead)
