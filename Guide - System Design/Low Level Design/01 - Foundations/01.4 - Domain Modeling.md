# Domain Modeling

Domain modeling is the process of capturing the essential concepts of a problem space in code. Good domain models make code _speak_ the business language — when a business requirement changes, you know exactly where in the code to look.

---

## Core Concepts at a Glance

|Concept|What It Is|Example|
|---|---|---|
|**Entity**|Has identity, mutable over time|`Order`, `User`, `Product`|
|**Value Object**|Defined by attributes, immutable|`Money`, `Address`, `DateRange`|
|**Aggregate**|Cluster of entities/VOs with one root|`Order` (root) + `OrderItems`|
|**Aggregate Root**|Single entry point to an aggregate|`Order` manages its `OrderItems`|
|**Domain Service**|Logic that doesn't belong to any entity|`PricingService`, `TransferService`|
|**Repository**|Collection-like persistence abstraction|`OrderRepository`|
|**Domain Event**|Something meaningful that happened|`OrderPlaced`, `PaymentFailed`|
|**Bounded Context**|Boundary where a model is consistent|Order context vs Inventory context|

## Entities

An entity's identity persists even when its attributes change. A `User` is still the same user after changing their email.

```python
from uuid import UUID, uuid4
from dataclasses import dataclass, field
from datetime import datetime

@dataclass
class User:
    id: UUID
    email: str
    name: str
    created_at: datetime
    
    def change_email(self, new_email: str):
        """Domain logic lives in the entity, not a service."""
        if not self._is_valid_email(new_email):
            raise DomainError(f"Invalid email: {new_email}")
        self.email = new_email
    
    def __eq__(self, other):
        if not isinstance(other, User):
            return False
        return self.id == other.id   # identity-based equality
    
    def __hash__(self):
        return hash(self.id)
    
    def _is_valid_email(self, email: str) -> bool:
        return "@" in email and "." in email.split("@")[1]
```

## Value Objects

Immutable. Equality by value. Should be treated like primitive types in your domain.

```python
from decimal import Decimal
from dataclasses import dataclass

@dataclass(frozen=True)   # frozen makes it immutable
class Money:
    amount: Decimal
    currency: str
    
    def __post_init__(self):
        if self.amount < 0:
            raise DomainError("Money amount cannot be negative")
        if len(self.currency) != 3:
            raise DomainError("Currency must be ISO 4217 code")
    
    def __add__(self, other: "Money") -> "Money":
        self._assert_same_currency(other)
        return Money(self.amount + other.amount, self.currency)
    
    def __sub__(self, other: "Money") -> "Money":
        self._assert_same_currency(other)
        result = self.amount - other.amount
        if result < 0:
            raise DomainError("Cannot subtract to negative money")
        return Money(result, self.currency)
    
    def multiply(self, factor: Decimal) -> "Money":
        return Money(self.amount * factor, self.currency)
    
    def _assert_same_currency(self, other):
        if self.currency != other.currency:
            raise CurrencyMismatchError(f"{self.currency} vs {other.currency}")
    
    def __str__(self):
        return f"{self.currency} {self.amount:.2f}"


@dataclass(frozen=True)
class Address:
    street: str
    city: str
    state: str
    country: str
    postal_code: str
    
    def is_domestic(self, home_country: str) -> bool:
        return self.country == home_country
    
    def formatted(self) -> str:
        return f"{self.street}, {self.city}, {self.state} {self.postal_code}, {self.country}"


@dataclass(frozen=True)
class DateRange:
    start: datetime
    end: datetime
    
    def __post_init__(self):
        if self.start >= self.end:
            raise DomainError("DateRange start must be before end")
    
    def overlaps(self, other: "DateRange") -> bool:
        return self.start < other.end and self.end > other.start
    
    def duration_days(self) -> int:
        return (self.end - self.start).days
    
    def contains(self, dt: datetime) -> bool:
        return self.start <= dt < self.end
```

## Aggregates

An aggregate is a cluster of entities and value objects treated as a **single unit of consistency**. The aggregate root is the only public entry point.

### Why Aggregates Exist

Without aggregates, it's impossible to enforce business invariants that span multiple objects. "An order's total must match the sum of its items" — who enforces that?

```python
from typing import List, Optional
from uuid import UUID, uuid4
from decimal import Decimal
from enum import Enum

class OrderStatus(Enum):
    DRAFT = "DRAFT"
    CONFIRMED = "CONFIRMED"
    PAID = "PAID"
    SHIPPED = "SHIPPED"
    DELIVERED = "DELIVERED"
    CANCELLED = "CANCELLED"


@dataclass
class OrderItem:
    """Part of the Order aggregate — NOT directly accessible from outside."""
    id: UUID
    product_id: UUID
    product_name: str
    unit_price: Money
    quantity: int
    
    @property
    def subtotal(self) -> Money:
        return self.unit_price.multiply(Decimal(self.quantity))
    
    def increase_quantity(self, qty: int):
        if qty <= 0:
            raise DomainError("Quantity increase must be positive")
        self.quantity += qty


class Order:
    """
    Aggregate Root — all modifications to OrderItems go through Order.
    Enforces all order-level invariants.
    """
    
    MAX_ITEMS = 50
    
    def __init__(self, order_id: UUID, user_id: UUID):
        self._id = order_id
        self._user_id = user_id
        self._items: List[OrderItem] = []
        self._status = OrderStatus.DRAFT
        self._coupon: Optional[Coupon] = None
        self._events: List[DomainEvent] = []
    
    # ── Accessors (read-only views) ──────────────────────────
    
    @property
    def id(self) -> UUID:
        return self._id
    
    @property
    def status(self) -> OrderStatus:
        return self._status
    
    @property
    def total(self) -> Money:
        subtotal = sum(
            (item.subtotal for item in self._items),
            Money(Decimal("0"), "USD")
        )
        return self._coupon.apply(subtotal) if self._coupon else subtotal
    
    @property
    def item_count(self) -> int:
        return sum(item.quantity for item in self._items)
    
    def get_events(self) -> List["DomainEvent"]:
        return list(self._events)
    
    def clear_events(self):
        self._events.clear()
    
    # ── Mutations (all go through root) ─────────────────────
    
    def add_item(self, product_id: UUID, name: str, price: Money, qty: int):
        """Business rule: if same product, merge. Otherwise add."""
        self._assert_status(OrderStatus.DRAFT, "add items to")
        
        if len(self._items) >= self.MAX_ITEMS:
            raise DomainError(f"Order cannot exceed {self.MAX_ITEMS} distinct items")
        
        existing = self._find_item_by_product(product_id)
        if existing:
            existing.increase_quantity(qty)
        else:
            self._items.append(
                OrderItem(id=uuid4(), product_id=product_id,
                         product_name=name, unit_price=price, quantity=qty)
            )
    
    def remove_item(self, product_id: UUID):
        self._assert_status(OrderStatus.DRAFT, "remove items from")
        self._items = [i for i in self._items if i.product_id != product_id]
    
    def apply_coupon(self, coupon: "Coupon"):
        self._assert_status(OrderStatus.DRAFT, "apply coupon to")
        if self._coupon:
            raise DomainError("Coupon already applied — remove existing coupon first")
        coupon.validate_for_order(self)
        self._coupon = coupon
    
    def confirm(self):
        self._assert_status(OrderStatus.DRAFT, "confirm")
        if not self._items:
            raise DomainError("Cannot confirm an empty order")
        self._status = OrderStatus.CONFIRMED
        self._events.append(OrderConfirmed(order_id=self._id, total=self.total))
    
    def mark_paid(self, payment_id: UUID):
        self._assert_status(OrderStatus.CONFIRMED, "mark as paid")
        self._status = OrderStatus.PAID
        self._events.append(OrderPaid(order_id=self._id, payment_id=payment_id))
    
    def cancel(self, reason: str):
        if self._status in (OrderStatus.SHIPPED, OrderStatus.DELIVERED):
            raise DomainError(f"Cannot cancel order in {self._status.value} status")
        self._status = OrderStatus.CANCELLED
        self._events.append(OrderCancelled(order_id=self._id, reason=reason))
    
    # ── Private helpers ──────────────────────────────────────
    
    def _find_item_by_product(self, product_id: UUID) -> Optional[OrderItem]:
        return next((i for i in self._items if i.product_id == product_id), None)
    
    def _assert_status(self, expected: OrderStatus, action: str):
        if self._status != expected:
            raise InvalidStateTransition(
                f"Cannot {action} order in {self._status.value} state"
            )
```

### Aggregate Design Rules

1. **One transaction = one aggregate** — if you're saving two aggregates in one transaction, reconsider your boundaries
2. **Reference other aggregates by ID** — `Order` stores `user_id: UUID`, not `user: User`
3. **Small aggregates preferred** — large aggregates = contention, slow loads
4. **Invariants stay inside the aggregate** — don't enforce `Order` invariants in `OrderService`

## Domain Services

When logic doesn't naturally belong to any single entity, extract it into a Domain Service.

```python
class MoneyTransferService:
    """
    Transfer logic spans two Account aggregates.
    Neither Account "owns" the transfer concept.
    """
    
    def transfer(self, from_account: Account, to_account: Account,
                 amount: Money, reference: str) -> Transfer:
        
        # Cross-aggregate invariant enforcement
        if from_account.currency != to_account.currency:
            raise DomainError("Cross-currency transfers require explicit FX")
        
        from_account.debit(amount, reference)
        to_account.credit(amount, reference)
        
        return Transfer(
            id=uuid4(),
            from_id=from_account.id,
            to_id=to_account.id,
            amount=amount,
            reference=reference
        )
```

**When to use Domain Service vs putting logic in Entity:**

- Involves multiple aggregates → Domain Service
- Requires infrastructure (DB, email) → Application Service (not domain service)
- Natural responsibility of one entity → put it in the entity

## Domain Events

Something significant that happened in the domain. Named in past tense.

```python
@dataclass(frozen=True)
class DomainEvent:
    event_id: UUID = field(default_factory=uuid4)
    occurred_at: datetime = field(default_factory=datetime.now)

@dataclass(frozen=True)
class OrderConfirmed(DomainEvent):
    order_id: UUID = None
    total: Money = None

@dataclass(frozen=True)
class OrderPaid(DomainEvent):
    order_id: UUID = None
    payment_id: UUID = None

@dataclass(frozen=True)
class OrderCancelled(DomainEvent):
    order_id: UUID = None
    reason: str = None
```

Events are collected on the aggregate and dispatched _after_ persistence in the application layer. This keeps domain logic infrastructure-free.

## Bounded Contexts

The same word can mean different things in different contexts. `Product` in the catalog context (name, description, images) is different from `Product` in the inventory context (quantity, location, SKU).

```
┌─────────────────────┐    ┌──────────────────────┐    ┌─────────────────────┐
│   Catalog Context   │    │   Ordering Context   │    │ Inventory Context   │
│                     │    │                      │    │                     │
│  Product            │    │  OrderItem           │    │  StockItem          │
│  - id               │    │  - product_id (ref)  │    │  - product_id (ref) │
│  - name             │    │  - name (snapshot)   │    │  - quantity         │
│  - description      │    │  - price (snapshot)  │    │  - warehouse_loc    │
│  - images           │    │  - quantity          │    │  - reorder_point    │
│  - category         │    │                      │    │                     │
└─────────────────────┘    └──────────────────────┘    └─────────────────────┘
         │                           │                          │
         └───────────────────────────┴──────────────────────────┘
                              Context Map
                    (how contexts communicate — events, APIs)
```

### Key Principle

In the **Ordering context**, `OrderItem` stores a **snapshot** of the product name and price at time of order. It does NOT reference the live Catalog. This is correct — you don't want an old order's line items to change when the product is renamed.

## Putting It Together: Domain Model Sketch

```python
# Ubiquitous Language: the vocabulary shared by business and engineering

# Entities
class Customer:    ...  # identity by customer_id
class Order:       ...  # identity by order_id, aggregate root
class Product:     ...  # identity by product_id (in catalog context)

# Value Objects
class Money:       ...  # amount + currency, immutable
class Address:     ...  # street/city/country, immutable
class OrderStatus: ...  # enum — not a VO but close

# Domain Events
class OrderPlaced:     ...
class PaymentReceived: ...
class OrderShipped:    ...

# Domain Services
class ShippingCostCalculator: ...   # needs two contexts: order + logistics
class OrderCancellationPolicy: ...  # complex cross-entity rules

# Repositories (interfaces — implementation in infra layer)
class OrderRepository(ABC):
    def save(self, order: Order): ...
    def find_by_id(self, id: UUID) -> Optional[Order]: ...
    def find_by_customer(self, customer_id: UUID) -> List[Order]: ...
```

## Interview Quick Hits

|Question|Key Answer|
|---|---|
|"What's the difference between Entity and Value Object?"|Entity: identity-based equality, mutable. VO: value-based equality, immutable|
|"What is an Aggregate Root?"|The single entry point enforcing consistency of the aggregate cluster|
|"When would you use a Domain Service?"|When logic spans multiple aggregates or doesn't naturally fit one entity|
|"What is a Domain Event?"|A record that something meaningful happened — enables decoupled reactions|
|"What is a Bounded Context?"|A boundary where the domain model is consistent and has its own ubiquitous language|
