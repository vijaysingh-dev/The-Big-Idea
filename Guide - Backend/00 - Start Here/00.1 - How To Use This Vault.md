# How To Use This Vault

#backend #meta

> **In one line:** Read the note, read the real code, then build it yourself. Skipping step three is why most engineers plateau.

---

## What This Vault Is

This is the backend half of your notes. It covers the layer under the code you write every day — the Python runtime, the network, the database, the queue, the log — and the way all of it fails in production.

It does not repeat what you already have. When a topic is covered elsewhere, this vault links out and then covers only the gap.

---

## The Shape of Every Note

Every note in this vault has the same five parts.

| Part | What it does |
|---|---|
| **The idea** | The mental model, in plain words, before any jargon |
| **How it really works** | The mechanism, with diagrams and code |
| **In production** | What senior engineers do with it, what goes wrong, tradeoffs |
| **Codebase** | Which real open-source files to open, and the question to answer |
| **Exercise** | What to build, in multiple files, from scratch |
| **Resources** | Two to five links worth your time. No filler |

The Codebase and Exercise boxes are not optional extras. They are the note.

## The Three Passes

### Pass 1 — Read the note

Goal: get the model and the vocabulary. One hour. Do not take notes yet. Just read.

You are done when you can explain the topic to someone in two minutes without looking.

### Pass 2 — Read real code

Goal: see the model survive contact with reality. Two hours.

Open the exact files in the Codebase box. Do not browse. Trace one path — one request, one message, one query — from entry to exit. Write down three things that surprised you.

Full method in [[00.2 - The Codebase First Method]].

### Pass 3 — Build it

Goal: turn recognition into recall. Three to eight hours.

Do the exercise. Type every line. No copy-paste, no frameworks, tests included.

You will discover you did not understand things you thought you understood. That discovery is the entire point of this pass.

---

## Why Reading Alone Fails

Reading gives you **recognition** — you see a concept and think "yes, I know that."

Interviews and production incidents need **recall** — you have to produce the concept from nothing, under pressure, with no article in front of you.

The gap between the two is enormous, and only building closes it. This is the single reason people with five years of experience can still fail senior interviews.

## The Weekly Rhythm

One topic per week is a realistic pace alongside a job.

| Day | Work | Hours |
|---|---|---|
| Mon–Tue | Read the notes for the topic | 2 |
| Wed | Codebase reading session | 2 |
| Thu–Fri | The drill | 4–6 |
| Weekend | Conduit phase work | 4 |

Roughly 12–14 hours a week. Twelve months covers the whole vault with the capstone finished.

If you have less time, cut Conduit before you cut the drills. Never cut the drills.

## Revision Strategy

You will forget things. That is normal and planned for.

| When | What to do |
|---|---|
| **Same week** | Reread only your own README from the drill, not the note |
| **One month later** | Answer the note's Codebase question from memory. If you cannot, reread that one section |
| **Before an interview** | [[Assets.6 - Rapid Fire Question Bank]] plus one Conduit phase walkthrough out loud |
| **Quick refresh** | The index tables in [[00 - Index (Backend)]] — the one-line topic column is a memory trigger |

Do not reread whole notes. Rereading feels productive and does almost nothing. Answering questions from memory is what works.

## What "Top 1%" Actually Means Here

It is not knowing more facts. It is these six things:

1. **You know the layer below.** When something is slow, you can go down a level instead of guessing.
2. **You have numbers.** Not "Redis is fast" but "sub-millisecond, and here is the throughput I measured."
3. **You design for failure first.** Your first question about any component is what happens when it dies.
4. **You have read real code.** You can say "this is how Celery actually acks" instead of "I think it acks after."
5. **You can defend a tradeoff.** Including the option you rejected and why.
6. **You have built the primitives.** You wrote an event loop, a task queue, a log. Nothing is magic to you anymore.

Every part of this vault is aimed at one of those six.

## Codebase

**Not a code session — a setup session.**

Clone the five core repos now, before you start section 01. You will come back to them constantly and you do not want the friction later.

```bash
mkdir -p ~/study && cd ~/study
git clone --depth 50 https://github.com/redis/redis
git clone --depth 50 https://github.com/encode/uvicorn
git clone --depth 50 https://github.com/encode/starlette
git clone --depth 50 https://github.com/celery/celery
git clone --depth 50 https://github.com/celery/kombu
git clone --depth 50 https://github.com/saleor/saleor
git clone --depth 50 https://github.com/GoogleCloudPlatform/microservices-demo
git clone --depth 50 https://github.com/python/cpython
```

**Question to answer:** For each repo, find the entry point — the file that runs first — in under five minutes each. Write the eight paths down. This is a skill and it is trainable.
