# Attention Mechanism

## The Problem Attention Solves

Before attention (RNN era), language models processed text sequentially — word by word. This created two critical problems:

1. **Long-range dependency failure**: "The cat, which had been sleeping on the warm mat in the corner near the fireplace, opened its ___ (eyes)." By the time you get to the blank, the information about "cat" has been diluted through many RNN steps.
    
2. **No parallelism**: You can't compute step 5 until step 4 is done. Training on long sequences was slow.
    

**Attention solves both**: It allows every position to directly "look at" every other position, regardless of distance. And it can be computed in parallel.

---

## The Core Intuition

Attention is a **soft lookup mechanism**. Given a query, find which keys are most relevant, and return a weighted combination of their values.

The analogy: a database query.

- In a hard database lookup: exact match on a key → returns one value
- In attention (soft lookup): similarity match on all keys → returns _weighted average_ of all values

```
Hard lookup:  "cat" → retrieves entry for "cat" (one entry)
Soft lookup:  "cat" → 70% from "feline", 20% from "animal", 10% from "pet" (weighted blend)
```

---

## Self-Attention: Mechanism

In self-attention, every token attends to every other token in the sequence. Each token plays three roles simultaneously:

- **Query (Q)**: "What am I looking for?"
- **Key (K)**: "What do I offer to others?"
- **Value (V)**: "What information do I carry?"

### Step-by-Step

Given a sequence of token embeddings X:

**Step 1 — Project into Q, K, V**

```
Q = X @ W_Q    (shape: seq_len × d_k)
K = X @ W_K    (shape: seq_len × d_k)
V = X @ W_V    (shape: seq_len × d_v)
```

`W_Q, W_K, W_V` are learned weight matrices.

**Step 2 — Compute attention scores**

```
scores = Q @ K.T / sqrt(d_k)    (shape: seq_len × seq_len)
```

Each position i gets a score against every position j. Division by `sqrt(d_k)` stabilizes gradients (without it, large dot products push softmax into saturation).

**Step 3 — Softmax to get attention weights**

```
weights = softmax(scores, dim=-1)    (each row sums to 1)
```

Now each position has a probability distribution over all other positions — "how much attention to pay to each position."

**Step 4 — Weighted sum of values**

```
output = weights @ V    (shape: seq_len × d_v)
```

Each position's output is a blend of all values, weighted by attention.

### In matrix form:

```
Attention(Q, K, V) = softmax(Q @ K.T / sqrt(d_k)) @ V
```

This is the entire attention equation. The rest of the Transformer is wrapping around this.

---

## Why Causal (Masked) Attention for Decoders

In language generation (decoder models like GPT), a token must not attend to future tokens — that would be cheating (the model would see the answer it's supposed to predict).

Solution: **causal masking** — set future positions to -∞ before softmax, so they get 0 weight after softmax:

```
scores[i][j] = -inf if j > i else scores[i][j]
```

This enforces left-to-right generation: each token can only see itself and previous tokens.

---

## Multi-Head Attention

Running a single attention operation only captures one type of relationship. **Multi-head attention** runs H attention operations in parallel, each with different `W_Q, W_K, W_V` projections:

```python
# H parallel attention heads
heads = [attention(Q @ W_Qi, K @ W_Ki, V @ W_Vi) for i in range(H)]
output = concat(heads) @ W_O    # project back to model dimension
```

Different heads learn to track different relationship types:

- One head might track syntactic dependencies (subject-verb)
- Another might track coreference (pronoun → noun)
- Another might track semantic similarity

This is why more heads generally means better language understanding — up to a point.

---

## Attention Complexity

Self-attention is O(n²) in sequence length — every token attends to every other token. This is why:

- Context windows were historically limited (4K, 8K tokens)
- Long-context models (128K+) require engineering tricks (sparse attention, flash attention, grouped-query attention)

**Flash Attention**: An algorithm that computes the same result but tiles the computation to use GPU memory more efficiently, enabling longer sequences without changing mathematical output.

---

## What Attention Learns

After training on massive text corpora, attention heads develop specializations:

- **Position-tracking heads**: track where certain tokens appear
- **Rare token heads**: attend heavily to infrequent words (high information content)
- **Copying heads**: copy patterns from earlier in context (relevant for in-context learning)
- **Retrieval heads**: fetch factual associations learned during pretraining

This is why in-context learning works — [[../03 - LLM Foundations/03.7 - Prompting and In-Context Learning|attention heads can implement learned algorithms at inference time]].
