# Latency and Cost Optimization

## The Optimization Mindset

In production AI systems, latency and cost are often in tension:

- Larger models → better quality, higher cost, higher latency
- More retrieved chunks → better context, higher tokens, higher cost
- More tool calls → better accuracy, higher latency

The senior AI engineer's job is to maximize quality within latency and cost budgets, not to minimize all three simultaneously.

**First principle: Measure before optimizing.** Profile your pipeline before guessing where time and money go.

---

## Profiling Your Pipeline

Instrument every stage:

```python
import time
from contextlib import contextmanager

@contextmanager
def timer(name):
    start = time.perf_counter()
    yield
    elapsed = (time.perf_counter() - start) * 1000
    metrics.histogram(f"pipeline.{name}_ms", elapsed)
    print(f"{name}: {elapsed:.0f}ms")

async def rag_query(question, user_id):
    with timer("query_embedding"):
        query_emb = await embed(question)
    
    with timer("retrieval"):
        chunks = await vector_store.search(query_emb, top_k=10)
    
    with timer("reranking"):
        chunks = await reranker.rerank(question, chunks)
    
    with timer("permission_filter"):
        chunks = [c for c in chunks if has_permission(c, user_id)]
    
    with timer("context_assembly"):
        prompt = build_prompt(question, chunks)
    
    with timer("llm_generation"):
        response = await llm.stream(prompt)
    
    return response
```

**Typical latency distribution in a RAG pipeline**:

|Stage|Typical latency|% of total|
|---|---|---|
|Query embedding|30–80ms|5%|
|Vector search|20–100ms|8%|
|BM25 search|5–30ms|2%|
|Reranker|50–300ms|15%|
|Permission filter|5–50ms|3%|
|LLM generation (TTFT)|300–1500ms|50%|
|Streaming tokens|1–10s|variable|

The LLM call dominates. Optimizing embedding or retrieval saves 10% at best; optimizing LLM usage is 10×.

## Latency Optimization Techniques

### 1. Parallelize Everything That Can Be Parallelized

```python
# BAD: Sequential
query_emb = await embed(question)              # 50ms
bm25_results = await bm25_search(question)     # 20ms  → total: 70ms

# GOOD: Parallel
query_emb_task = asyncio.create_task(embed(question))
bm25_task = asyncio.create_task(bm25_search(question))
query_emb, bm25_results = await asyncio.gather(query_emb_task, bm25_task)
# Total: max(50, 20) = 50ms  → saves 20ms
```

Parallelize:

- Query embedding + BM25 search (both can start immediately)
- Multiple tool calls in agents
- Document embedding at ingestion time

### 2. Stream Responses

Don't wait for the full LLM response before sending to user. Stream tokens as they generate:

```python
async def stream_rag_response(question, user_id, websocket):
    # Everything before LLM call is fast — do it synchronously
    chunks = await retrieve(question, user_id)
    prompt = build_prompt(question, chunks)
    
    # Stream tokens immediately as generated
    async for token in llm.stream(prompt):
        await websocket.send_text(token)
```

**Impact**: User sees first token in 300–500ms even if total generation takes 10s. Dramatically improves perceived performance.

### 3. Reduce LLM Input Tokens

The LLM processes every input token at O(n²) attention cost. Shorter prompts = faster generation + lower cost.

**Techniques**:

- **Context compression**: Only send the sentences from each chunk that are relevant to the query (see [[../05 - RAG Systems/05.5 - Hybrid Retrieval and Reranking|05.5]])
- **Prompt compression**: Use LLMLingua or similar to compress system prompts by 3–5× with minimal quality loss
- **Fewer retrieved chunks**: If 5 chunks are sufficient, don't send 10
- **Truncate long docs**: Set maximum chunk character length; very long chunks rarely add proportional value

```python
def compress_context(question, chunks, max_tokens=4000):
    total = 0
    compressed = []
    for chunk in chunks:
        # Estimate tokens (rough: chars/4)
        chunk_tokens = len(chunk.text) / 4
        if total + chunk_tokens > max_tokens:
            break
        compressed.append(chunk)
        total += chunk_tokens
    return compressed
```

### 4. Use Smaller Models for Appropriate Tasks

|Task|Needs GPT-4?|Use Instead|
|---|---|---|
|Query rewriting|No|gpt-4o-mini, claude-haiku|
|Simple classification|No|gpt-4o-mini|
|Final synthesis (complex)|Yes|gpt-4o, claude-sonnet|
|Embedding|N/A|dedicated embedding model|
|Reranking|No|cross-encoder model (not LLM)|

Routing simple steps to cheaper models can cut costs by 60–80% with minimal quality impact.

### 5. Reduce Reranker Candidate Count

```python
# Retrieve 50 instead of 100; rerank 20 instead of 50
# Quality impact minimal; latency cut by 40%
chunks = await vector_store.search(query_emb, top_k=50)
fused = rrf_fusion(chunks, bm25_results)[:20]
reranked = reranker.rerank(question, fused)[:10]
```

## Cost Optimization

### Token Counting and Budget Tracking

```python
def estimate_cost(model, input_tokens, output_tokens):
    RATES = {
        "gpt-4o":       (0.0025, 0.010),  # per 1K tokens
        "gpt-4o-mini":  (0.00015, 0.0006),
        "claude-sonnet-4-5": (0.003, 0.015),
    }
    r = RATES[model]
    return (input_tokens / 1000) * r[0] + (output_tokens / 1000) * r[1]
```

Track cost per query, per user, per feature. Alert on anomalies.

### Prompt Token Reduction

System prompts are sent on every call. Audit their token count:

```python
import tiktoken
enc = tiktoken.get_encoding("cl100k_base")

system_prompt_tokens = len(enc.encode(SYSTEM_PROMPT))
print(f"System prompt: {system_prompt_tokens} tokens × $0.0025/1K = ${system_prompt_tokens * 0.0025 / 1000:.4f} per call")
# At 10K calls/day: system_prompt_tokens * $0.0025 / 1000 * 10000 per day
```

A 2000-token system prompt at 10K calls/day = $50/day in input tokens alone. Trim aggressively.

### Batching at Ingestion

At index time, batch embedding calls:

```python
# BAD: One embedding call per chunk
for chunk in chunks:
    emb = openai.embeddings.create(model="text-embedding-3-small", input=chunk.text)

# GOOD: Batch up to 2048 items per call
BATCH_SIZE = 100
for batch in chunked(chunks, BATCH_SIZE):
    embeddings = openai.embeddings.create(
        model="text-embedding-3-small",
        input=[c.text for c in batch]
    )
```

Batching reduces API overhead and can be 5–10× cheaper per token for bulk operations.

### Cost vs Quality Measurement

Before optimizing, measure whether quality degrades:

```python
# A/B test: expensive config vs cheap config
expensive = {"model": "gpt-4o", "top_k": 10, "reranker": "cohere"}
cheap     = {"model": "gpt-4o-mini", "top_k": 5, "reranker": None}

# Run both on 100 eval questions
expensive_scores = run_eval(expensive, eval_set)
cheap_scores = run_eval(cheap, eval_set)

# Is quality drop acceptable?
quality_delta = expensive_scores.mean() - cheap_scores.mean()
cost_delta = expensive_cost - cheap_cost
print(f"Quality: -{quality_delta:.2%} | Cost savings: -{cost_delta:.2%}")
```

Often the cheap config is 80% of the quality at 20% of the cost — that's worth the tradeoff.

## Latency Budget Framework

Define your SLA upfront, then allocate budget to each stage:

```
Total budget: 2000ms (end-to-end, including streaming to first token)

Allocation:
├── Query embedding:      50ms
├── Parallel retrieval:  100ms
├── Permission filter:    10ms
├── Context assembly:     20ms
├── LLM TTFT:           500ms  ← largest budget
├── Network/infra:        50ms
└── Buffer:             1270ms (for first token streaming, rest of generation)
```

If you're over budget on a stage, that's where to focus optimization. Don't over-optimize fast stages.
