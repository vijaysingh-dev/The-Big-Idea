# Build Your Own: Pub/Sub System

> **Revision tags:** #build-your-own #messaging #pubsub  
> **Related:** [[03.9 - PubSub and Event Bus]]

---

## Goal

Build a topic-based pub/sub system where:
- Publishers send messages to named topics
- Multiple subscribers receive every message (fan-out)
- Each subscriber has its own independent delivery queue
- Subscribers can filter messages by type

This is the SNS / Google Pub/Sub model — not Kafka.

---

## Core Design

```
[Publisher] → publish("order-events", event)
                        │
               [EventBus]
                 Topic: "order-events"
                   ├── Subscription "email-worker"  → [Queue A] → email consumer
                   ├── Subscription "analytics"     → [Queue B] → analytics consumer
                   └── Subscription "inventory"     → [Queue C] → inventory consumer
```

Each subscriber gets its own independent queue. One subscriber being slow doesn't affect others.

## Implementation

```python
import threading
import uuid
import time
from dataclasses import dataclass, field
from typing import Dict, List, Callable, Optional, Any
from collections import deque
from queue import Queue, Empty

# ── Event ────────────────────────────────────────────────────────────────────

@dataclass
class Event:
    topic: str
    event_type: str
    payload: dict
    id: str = field(default_factory=lambda: str(uuid.uuid4()))
    published_at: float = field(default_factory=time.time)

    def matches_filter(self, event_type_filter: Optional[str]) -> bool:
        """Check if this event matches the subscriber's filter."""
        if event_type_filter is None:
            return True  # no filter = receive all
        return self.event_type == event_type_filter


# ── Subscription ─────────────────────────────────────────────────────────────

@dataclass
class Subscription:
    """
    Represents one subscriber's connection to a topic.
    Each subscription has its own bounded delivery queue.
    """
    id: str
    topic: str
    name: str
    event_type_filter: Optional[str] = None   # None = receive all event types
    max_queue_size: int = 1000

    _queue: Queue = field(init=False)

    def __post_init__(self):
        self._queue = Queue(maxsize=self.max_queue_size)

    def deliver(self, event: Event) -> bool:
        """
        Attempt to deliver an event to this subscriber's queue.
        Returns False if queue is full (backpressure).
        """
        if not event.matches_filter(self.event_type_filter):
            return True  # filtered out — not an error

        try:
            self._queue.put_nowait(event)
            return True
        except Exception:
            # Queue full — apply backpressure (drop or block depending on policy)
            print(f"[Subscription {self.name}] Queue full, dropping event {event.id}")
            return False

    def poll(self, timeout: float = 1.0) -> Optional[Event]:
        """Blocking poll — returns next event or None on timeout."""
        try:
            return self._queue.get(timeout=timeout)
        except Empty:
            return None

    def poll_nowait(self) -> Optional[Event]:
        """Non-blocking poll."""
        try:
            return self._queue.get_nowait()
        except Empty:
            return None

    @property
    def queue_depth(self) -> int:
        return self._queue.qsize()


# ── Event Bus ─────────────────────────────────────────────────────────────────

class EventBus:
    """
    Central pub/sub broker.
    Thread-safe: publishers and subscribers can operate concurrently.
    """

    def __init__(self):
        # topic → list of subscriptions
        self._subscriptions: Dict[str, List[Subscription]] = {}
        self._lock = threading.RLock()

    def subscribe(self,
                  topic: str,
                  name: str,
                  event_type_filter: Optional[str] = None,
                  max_queue_size: int = 1000) -> Subscription:
        """
        Create a new subscription on a topic.
        Returns the Subscription object — consumer uses this to poll.
        """
        sub = Subscription(
            id=str(uuid.uuid4()),
            topic=topic,
            name=name,
            event_type_filter=event_type_filter,
            max_queue_size=max_queue_size
        )
        with self._lock:
            if topic not in self._subscriptions:
                self._subscriptions[topic] = []
            self._subscriptions[topic].append(sub)
            print(f"[EventBus] '{name}' subscribed to '{topic}'"
                  + (f" (filter: {event_type_filter})" if event_type_filter else ""))
        return sub

    def unsubscribe(self, subscription: Subscription):
        """Remove a subscription."""
        with self._lock:
            topic_subs = self._subscriptions.get(subscription.topic, [])
            self._subscriptions[subscription.topic] = [
                s for s in topic_subs if s.id != subscription.id
            ]

    def publish(self, topic: str, event_type: str, payload: dict) -> Event:
        """
        Publish an event to a topic.
        Delivers to all matching subscriptions (fan-out).
        """
        event = Event(topic=topic, event_type=event_type, payload=payload)

        with self._lock:
            subscribers = list(self._subscriptions.get(topic, []))

        # Deliver to all subscribers (outside lock to avoid blocking publishers)
        delivered = 0
        for sub in subscribers:
            if sub.deliver(event):
                delivered += 1

        print(f"[EventBus] Published '{event_type}' to '{topic}' "
              f"→ {delivered}/{len(subscribers)} subscribers")
        return event

    def stats(self) -> dict:
        with self._lock:
            return {
                topic: [
                    {"name": s.name, "queue_depth": s.queue_depth}
                    for s in subs
                ]
                for topic, subs in self._subscriptions.items()
            }


# ── Push-style subscriber (callback) ─────────────────────────────────────────

class PushSubscriber:
    """
    Wraps a Subscription and calls a callback for each event.
    Runs in its own background thread — simulates a push-based consumer.
    """

    def __init__(self, subscription: Subscription,
                 callback: Callable[[Event], None]):
        self.subscription = subscription
        self.callback = callback
        self._running = False
        self._thread = threading.Thread(target=self._run, daemon=True)

    def start(self):
        self._running = True
        self._thread.start()

    def stop(self):
        self._running = False

    def _run(self):
        while self._running:
            event = self.subscription.poll(timeout=1.0)
            if event:
                try:
                    self.callback(event)
                except Exception as e:
                    print(f"[PushSubscriber {self.subscription.name}] "
                          f"Error processing event: {e}")
```

## Usage Example

```python
# Create the event bus
bus = EventBus()

# Three subscribers to the same topic
email_sub     = bus.subscribe("order-events", "email-worker")
analytics_sub = bus.subscribe("order-events", "analytics")
# Inventory only cares about OrderPlaced, not OrderCancelled
inventory_sub = bus.subscribe("order-events", "inventory",
                              event_type_filter="OrderPlaced")

# Start push consumers
def handle_email(event):
    print(f"  [Email] Sending confirmation for order {event.payload['order_id']}")

def handle_analytics(event):
    print(f"  [Analytics] Recording {event.event_type} event")

def handle_inventory(event):
    print(f"  [Inventory] Reserving stock for order {event.payload['order_id']}")

email_worker     = PushSubscriber(email_sub, handle_email)
analytics_worker = PushSubscriber(analytics_sub, handle_analytics)
inventory_worker = PushSubscriber(inventory_sub, handle_inventory)

email_worker.start()
analytics_worker.start()
inventory_worker.start()

# Publish events
bus.publish("order-events", "OrderPlaced",    {"order_id": 42, "total": 150})
bus.publish("order-events", "OrderCancelled", {"order_id": 39, "reason": "user"})
bus.publish("order-events", "OrderPlaced",    {"order_id": 43, "total": 220})

time.sleep(0.5)
print(bus.stats())
```

### Output

```
[EventBus] 'email-worker' subscribed to 'order-events'
[EventBus] 'analytics' subscribed to 'order-events'
[EventBus] 'inventory' subscribed to 'order-events' (filter: OrderPlaced)
[EventBus] Published 'OrderPlaced' to 'order-events' → 3/3 subscribers
  [Email]     Sending confirmation for order 42
  [Analytics] Recording OrderPlaced event
  [Inventory] Reserving stock for order 42
[EventBus] Published 'OrderCancelled' to 'order-events' → 2/3 subscribers
  [Email]     Sending confirmation for order 39       (cancellation email)
  [Analytics] Recording OrderCancelled event
  (Inventory filtered out — doesn't receive cancellations)
```

## What Production Systems Add

| Feature | What's Missing Here |
|---|---|
| Network transport | Our bus is in-process; real brokers communicate over TCP |
| Durability | Events in subscriber queues are lost if process restarts |
| At-least-once delivery | No ACK mechanism — consumer must handle duplicates externally |
| Message retention | Can't replay past events from our in-memory deque |
| Dead letter queue per subscription | Failed deliveries silently dropped |
| Backpressure to publishers | We drop silently; production may block or error the publisher |
| Schema registry | No validation of event structure |
| Multiple processes | Subscriptions don't span processes; need a real broker |
| Ordered delivery | No partition-based ordering |
| Fan-out performance | For 10M subscribers, need tiered fan-out (Kafka → per-region queues) |

---

## Key Takeaways

- Each subscriber has **its own queue** — isolation is fundamental to pub/sub
- Fan-out happens at publish time — the broker does the work, not the publisher
- Event type filtering belongs in the subscription, not in the publisher
- Backpressure surfaces as a full subscriber queue — decide: drop, block, or error
