# Sets and Hashing Your Own Classes

#python #sets #hashing

> **In one line:** A set is a dict with only keys: O(1) membership plus fast union, intersection and difference. To use your own objects in sets or as dict keys, `__hash__` and `__eq__` must agree, and the hash must never change while the object is in a container.

---

## Sets

```python
seen = set()
tags = {"python", "backend"}           # literal ({} alone is an empty DICT)
frozen = frozenset({"a", "b"})         # immutable and hashable: can be a dict key or a set member

"python" in tags                       # O(1)
tags.add("db"); tags.discard("x")      # discard does not raise if missing; remove does
```

### Set algebra

```python
a = {1, 2, 3, 4}
b = {3, 4, 5}
a | b      # union            {1, 2, 3, 4, 5}
a & b      # intersection     {3, 4}
a - b      # difference       {1, 2}
a ^ b      # symmetric diff   {1, 2, 5}
a <= b     # subset?
a.isdisjoint(b)
```

Real uses:

```python
# Permissions: does the user have every required scope?
required <= user.scopes

# Diff two states: what to add, what to remove
to_add = desired - current
to_remove = current - desired

# Deduplicate while keeping order (sets do not keep order; dicts do)
unique = list(dict.fromkeys(items))
```

### The O(n²) fix you will make in code review

```python
# ❌ O(n·m): list membership inside a loop
active = [u for u in users if u.id in active_ids_list]

# ✅ O(n + m)
active_ids = set(active_ids_list)
active = [u for u in users if u.id in active_ids]
```

## The Hash/Eq Contract

For objects to work as dict keys or set members:

1. **If `a == b`, then `hash(a) == hash(b)`.** (The reverse need not hold; collisions are allowed.)
2. **The hash must not change** while the object is in a set or dict.

Default behaviour for your classes: `__eq__` compares identity, `__hash__` is based on `id()`. So two "equal-looking" objects are different keys:

```python
class Point:
    def __init__(self, x, y): self.x, self.y = x, y

{Point(1, 2), Point(1, 2)}       # two members — equality is identity
```

### Defining `__eq__` removes `__hash__`

```python
class Point:
    def __init__(self, x, y): self.x, self.y = x, y
    def __eq__(self, other):
        return isinstance(other, Point) and (self.x, self.y) == (other.x, other.y)

hash(Point(1, 2))     # TypeError: unhashable type: 'Point'
```

Python sets `__hash__ = None` when you define `__eq__` without `__hash__`, precisely to stop you from breaking rule 1. Add one that hashes the **same fields** that `__eq__` compares:

```python
    def __hash__(self):
        return hash((self.x, self.y))
```

### The mutable-key bug

```python
p = Point(1, 2)
s = {p}
p.x = 99           # hash changed while inside the set
p in s             # False — the set looks in the wrong slot
len(s)             # 1 — and now it cannot be found or removed
```

**Rule: only hash immutable fields, and make hashable objects immutable.** The easy way:

```python
from dataclasses import dataclass

@dataclass(frozen=True, slots=True)
class Point:
    x: int
    y: int
# __eq__ and __hash__ generated from the fields; assignment raises FrozenInstanceError
```

Dataclass rules for `eq`, `frozen` and `unsafe_hash` are in [[07.2 - Dataclasses]]. Pydantic models are hashable only with `frozen=True` ([[07.3 - Pydantic Fundamentals]]).

## Choosing What to Hash: Identity vs Value

| Object kind | Equality should be | Example |
|---|---|---|
| **Value object** | By value; immutable | `Money`, `Point`, `EmailAddress`, a cache key |
| **Entity** | By identity (database ID), or left as default | `User`, `Order` — two objects with the same ID are the same entity even if fields differ |

For entities, hashing on a mutable field such as `name` is wrong; hash on the stable ID, or do not define equality at all. See the value-object vs entity distinction in [[01.4 - Domain Modeling]].

## Making Cache Keys

`functools.lru_cache` and any dict-based cache need hashable arguments:

```python
@lru_cache
def price(sku: str, opts: frozenset[str]) -> Decimal: ...

price("A1", frozenset({"gift", "express"}))      # works
price("A1", {"gift"})                            # TypeError: unhashable type: 'set'
```

Normalise unhashable arguments: lists to tuples, sets to frozensets, dicts to `tuple(sorted(d.items()))`. For distributed caches (Redis), you need a **stable string** key, not `hash()`, because `hash` changes per process. See [[08.2 - Cache Strategies and Invalidation]].
