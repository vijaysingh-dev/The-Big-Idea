# CTI and Voice

## What CTI means

**CTI** — Computer Telephony Integration — connects the phone system to the CRM. The practical outcomes:

- An incoming call opens the caller's record before the agent says hello
- Click a phone number to dial it
- Call duration, outcome, and recording are logged automatically
- Calls are routed using the same rules as other work

Without CTI, an agent answers the phone, asks for a name, searches, and finds the record. That is thirty seconds per call, times hundreds of calls a day, plus a worse customer experience.

## Two approaches

**Open CTI.** A JavaScript API that lets any telephony vendor build a softphone inside Salesforce. The vendor runs the telephony; Salesforce provides the frame and the API. Most contact centre platforms have an Open CTI adapter on AppExchange.

**Service Cloud Voice.** Salesforce's own telephony offering, either using Amazon Connect underneath, a partner provider, or a bring-your-own-telephony model. Deeper integration: real-time transcription, Einstein assistance during the call, and voice as a native Omni-Channel channel rather than a bolted-on one.

The decision usually comes down to whether the organization already has a contact centre platform it intends to keep. If yes, Open CTI with that vendor's adapter. If the telephony is being replaced anyway, Voice is worth evaluating for the transcription and AI features.

## Open CTI in practice

The softphone lives in the utility bar of a console app. The adapter is a Visualforce page or Lightning component using the Open CTI JavaScript API.

```javascript
import { LightningElement } from 'lwc';
import { enableClickToDial, onClickToDial, screenPop,
         getSoftphoneLayout, saveLog } from 'lightning/platformOpenCTI';

export default class TelephonyAdapter extends LightningElement {

    connectedCallback() {
        enableClickToDial({ callback: this.handleEnableResult });
        onClickToDial({ listener: this.handleDialRequest.bind(this) });
    }

    // called when the telephony platform reports an inbound call
    handleInboundCall(callerNumber) {
        screenPop({
            type: 'SearchResult',
            params: { searchParams: callerNumber },
            callback: this.handlePopResult
        });
    }

    logCall(callDetails) {
        saveLog({
            value: {
                entityApiName: 'Task',
                Subject: 'Inbound call',
                CallDurationInSeconds: callDetails.duration,
                CallType: 'Inbound',
                WhoId: callDetails.contactId,
                WhatId: callDetails.caseId,
                Description: callDetails.notes
            },
            callback: this.handleLogResult
        });
    }
}
```

**Screen pop** is the feature agents notice most. The API supports popping a specific record, a search result list, or a new record page prefilled with the caller's number.

The design decision: what to pop when the number matches several contacts, or none. Popping a search result list is the safe default; popping straight to a record is better when the match is unambiguous. Popping a new Contact page when there is no match speeds up first-time callers.

Matching a caller number requires care, because stored phone numbers are inconsistent:

```java
public with sharing class CallerLookupService {

    @AuraEnabled(cacheable=true)
    public static List<Contact> findByPhone(String rawNumber) {
        // strip formatting and match on the last 10 digits, since stored numbers vary in prefix
        String digits = rawNumber.replaceAll('[^0-9]', '');
        String suffix = digits.length() > 10 ? digits.right(10) : digits;
        String pattern = '%' + suffix;

        return [
            SELECT Id, Name, Phone, MobilePhone, Account.Name, Account.Id
            FROM Contact
            WHERE Phone LIKE :pattern OR MobilePhone LIKE :pattern
            WITH USER_MODE
            LIMIT 5
        ];
    }
}
```

A leading-wildcard `LIKE` cannot use an index, so on a large Contact table this query is non-selective and slow. The production answer is a formula or trigger-maintained field holding the normalized digits, marked as an external ID so it is indexed, and an exact match against that. Building the naive version first and discovering it at two million contacts is a familiar path. See [[08.9 - Indexes and Selective Queries]].

## Service Cloud Voice

Voice makes telephony a first-class Omni-Channel channel, which is the structural difference from Open CTI.

What that gives you:

**Unified routing.** Calls, cases, chats, and messages all route through Omni-Channel with one capacity model. An agent on a call does not receive a chat.

**Real-time transcription.** The conversation is transcribed as it happens, stored in `VoiceCall` and `ConversationEntry` records.

**Einstein assistance during the call.** Knowledge articles surfaced based on what is being said, next-best-action recommendations, and automatic call summaries afterwards.

**Native call recording and playback** attached to the record.

```sql
SELECT Id, CallDurationInSeconds, CallType, CallDisposition,
       RelatedRecordId, OwnerId, EndTime, Recording__c
FROM VoiceCall
WHERE CreatedDate = LAST_N_DAYS:7
ORDER BY CreatedDate DESC
```

The transcription is what enables everything else. Post-call summaries, sentiment detection, and compliance keyword monitoring all read from it, and none of them are possible with a plain Open CTI integration.

## Call recording and consent

A legal question before a technical one, and one that varies substantially by jurisdiction.

India, the EU under GDPR, the UK, and individual US states differ on whether one-party or all-party consent is required, on notification obligations, and on retention limits. A global support operation may need different recording behaviour per region.

Practically this means:

- An announcement at call start, which the telephony platform usually handles
- Configurable recording per region, per queue, or per call type
- A retention policy with automatic deletion
- Pausing recording during payment card capture, which is a PCI requirement rather than a preference

Getting this wrong is a compliance incident, and it is entirely foreseeable. Raise it during design.

## Call logging

Calls are logged as **Task** records with `CallType`, `CallDurationInSeconds`, and `CallDisposition`, or as `VoiceCall` records under Service Cloud Voice.

Consistency matters for reporting. An org where some calls are logged as Tasks by an Open CTI adapter, some as VoiceCall records, and some not at all cannot answer basic questions about contact volume.

`CallDisposition` — the outcome — is the field that carries analytical value and the one agents skip. Making it required on call wrap-up, and keeping the list short, is the usual approach.

## Wrap-up time

After-call work: logging the call, updating the case, setting a disposition. During wrap-up the agent should not receive another call.

Omni-Channel supports an after-conversation work period, configurable in duration. Setting it to zero means agents get a call the instant they hang up and never complete their notes, which produces a support desk with excellent handle time metrics and no usable data.

## Reporting

The metrics telephony adds:

```sql
SELECT Owner.Name agent,
       COUNT(Id) calls,
       AVG(CallDurationInSeconds) avgDuration,
       SUM(CASE WHEN CallDisposition = 'Resolved' THEN 1 ELSE 0 END) resolved
FROM Task
WHERE CallType != null AND CreatedDate = LAST_N_DAYS:30
GROUP BY Owner.Name
ORDER BY COUNT(Id) DESC
```

The contact centre metrics that matter — abandonment rate, average speed of answer, service level percentage — usually live in the telephony platform rather than Salesforce, unless Service Cloud Voice is in use. Knowing which system holds which number saves a lot of reconciliation.

## Practical guidance

**Normalize phone numbers into an indexed field.** The leading-wildcard lookup does not survive scale.

**Decide screen pop behaviour for ambiguous and unmatched numbers.** Both cases are common.

**Handle recording consent per region.** It is a legal obligation with real consequences.

**Make call disposition required.** It is the only analytical output of a phone call.

**Configure a non-zero wrap-up period.** Agents need time to finish, and denying it destroys the data.

**Log calls consistently.** One mechanism, not three.

**Evaluate Service Cloud Voice when transcription matters.** Post-call summaries and in-call assistance are only possible with it, and they are the main reason to choose it over a vendor adapter.
