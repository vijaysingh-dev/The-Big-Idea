# Multimodal Basics

## What It Is

Multimodal AI systems work with multiple data modalities — text, images, audio, video — either by processing them independently with separate models or by using a unified model that handles multiple modalities in a shared representation space. For AI engineers building RAG and search systems, multimodal capabilities enable: searching documents by image content, answering questions about charts and figures, processing invoices and scanned documents, and building cross-modal retrieval (text query → image results).

---

## Why It Matters

- Nanonets and Fractal (your targets) do document intelligence — PDFs with tables, charts, and images are core. Text-only extraction misses visual content.
- Enterprise documents are heavily visual: earnings presentations, product manuals, architecture diagrams, floor plans. A search system that can't interpret these has blind spots.
- CLIP-style embeddings enable cross-modal retrieval: embed both images and text into the same space, then find images matching a text query or vice versa.
- Multimodal LLMs (GPT-4o, Claude 3.5, Gemini 1.5) can now reason about images natively — understanding this capability and its limits is necessary for system design.

---

## CLIP — Contrastive Language-Image Pretraining

### What It Is

CLIP (OpenAI, 2021) trains a text encoder and an image encoder jointly to embed matching (text, image) pairs close together in a shared vector space.

```
Training:
  Text: "a dog playing in the snow"  → text_encoder → text_vec
  Image: [photo of dog in snow]      → image_encoder → img_vec

  Loss: maximize cosine_sim(text_vec, img_vec) for matching pairs
        minimize cosine_sim(text_vec, img_vec) for non-matching pairs
```

After training, you can:
- Find images matching a text query (text → image retrieval)
- Find text descriptions matching an image (image → text retrieval)
- Classify images with zero-shot prompting ("Is this a photo of a cat or a dog?")

### Architecture

```
Text Encoder:    Transformer (ViT-B or larger)
Image Encoder:   Vision Transformer (ViT) — patches the image into 14×14 or 16×16 pixel tiles

Both encoders output a fixed-size vector (e.g., 512 or 768 dims)
Both vectors are L2-normalized
Similarity = dot product (which equals cosine for normalized vectors)
```

### CLIP for Image Search

```python
import torch
import clip
from PIL import Image

# Load model and preprocessing
device = "cuda" if torch.cuda.is_available() else "cpu"
model, preprocess = clip.load("ViT-B/32", device=device)

# Encode images for indexing
def encode_images(image_paths: list[str]) -> torch.Tensor:
    images = torch.stack([
        preprocess(Image.open(p)) for p in image_paths
    ]).to(device)
    with torch.no_grad():
        image_features = model.encode_image(images)
        image_features /= image_features.norm(dim=-1, keepdim=True)  # normalize
    return image_features.cpu()

# Encode text query
def encode_text(text: str) -> torch.Tensor:
    tokens = clip.tokenize([text]).to(device)
    with torch.no_grad():
        text_features = model.encode_text(tokens)
        text_features /= text_features.norm(dim=-1, keepdim=True)
    return text_features.cpu()

# Cross-modal search: text → images
def search_images(query: str, image_database: list, image_embeddings: torch.Tensor, top_k: int = 5):
    query_emb = encode_text(query)
    similarities = (image_embeddings @ query_emb.T).squeeze()
    top_indices = similarities.argsort(descending=True)[:top_k]
    return [(image_database[i], similarities[i].item()) for i in top_indices]

# Usage
image_paths = ["diagram1.png", "chart2.png", "photo3.jpg"]
image_embeddings = encode_images(image_paths)
results = search_images("bar chart showing revenue growth", image_paths, image_embeddings)
```

### CLIP Variants and Modern Alternatives

| Model | Embedding dim | Strengths | Use case |
|-------|--------------|-----------|---------|
| CLIP ViT-B/32 | 512 | Fast, small | Quick prototyping |
| CLIP ViT-L/14 | 768 | Better quality | Production image search |
| OpenCLIP ViT-H | 1024 | State-of-art open | Self-hosted high quality |
| SigLIP (Google) | 1152 | Better zero-shot | Image classification |
| E5-V | 4096 | Best text-image alignment | Cross-modal RAG |

## Multimodal RAG

### Document with Images Pipeline

Most enterprise documents mix text and images. A complete pipeline handles both:

```python
from unstructured.partition.pdf import partition_pdf
import base64

def process_document_with_images(pdf_path: str) -> list[dict]:
    """Extract both text chunks and image chunks from a PDF."""

    # Extract with image extraction enabled
    elements = partition_pdf(
        filename=pdf_path,
        strategy="hi_res",
        extract_images_in_pdf=True,
        extract_image_block_types=["Image", "Table"],
        extract_image_block_to_payload=True,  # embed images as base64
    )

    chunks = []
    for element in elements:
        if element.category in ("NarrativeText", "Title"):
            # Text chunk → embed with text embedding model
            chunks.append({
                "type": "text",
                "content": str(element),
                "page": element.metadata.page_number,
            })
        elif element.category in ("Image", "Table"):
            # Image chunk → embed with CLIP or describe with vision LLM
            image_b64 = element.metadata.image_base64
            chunks.append({
                "type": "image",
                "content": image_b64,
                "page": element.metadata.page_number,
                "description": describe_image_with_llm(image_b64),  # optional
            })

    return chunks

def describe_image_with_llm(image_b64: str) -> str:
    """Use vision LLM to generate text description of image for text-based retrieval."""
    response = openai.chat.completions.create(
        model="gpt-4o",
        messages=[{
            "role": "user",
            "content": [
                {
                    "type": "image_url",
                    "image_url": {"url": f"data:image/jpeg;base64,{image_b64}"}
                },
                {
                    "type": "text",
                    "text": "Describe this image concisely for search indexing. "
                            "Include all text, numbers, labels, and key visual elements."
                }
            ]
        }]
    )
    return response.choices[0].message.content
```

### Two Strategies for Indexing Images

**Strategy A: Convert to text via LLM description**
- Generate a text description for each image using a vision LLM
- Embed the description with your standard text embedding model
- Retrieve text description, include original image in context for LLM

Pros: Works with any text embedding model, descriptions are searchable with natural language
Cons: LLM description call per image (expensive at scale), loses visual details

**Strategy B: CLIP image embeddings**
- Embed each image directly with CLIP
- Store image embeddings in a separate index (or dual-vector field in Qdrant)
- At query time: embed query with CLIP text encoder, search image index

Pros: No per-image LLM call, preserves visual content
Cons: Requires CLIP-compatible vector store, cross-modal quality lower than text-to-text

**Strategy C: Hybrid (for production)**
- Generate text description (for text search, BM25)
- Store CLIP embedding (for visual similarity)
- At query time: search both, fuse results

### Multimodal Context Injection

When the retrieved context includes images, pass them to the vision LLM:

```python
def build_multimodal_prompt(question: str, chunks: list[dict]) -> list[dict]:
    """Build a message with both text and image content blocks."""
    content = []

    # Add instruction
    content.append({
        "type": "text",
        "text": "Answer the question using the provided documents (text and images).\n\n"
    })

    # Add retrieved chunks (mix of text and image)
    for i, chunk in enumerate(chunks):
        if chunk["type"] == "text":
            content.append({
                "type": "text",
                "text": f"[Document {i+1}, Page {chunk['page']}]\n{chunk['content']}\n\n"
            })
        elif chunk["type"] == "image":
            content.append({
                "type": "text",
                "text": f"[Figure {i+1}, Page {chunk['page']}]\n"
            })
            content.append({
                "type": "image_url",
                "image_url": {
                    "url": f"data:image/jpeg;base64,{chunk['content']}",
                    "detail": "high"  # "low" for thumbnails, "high" for detailed analysis
                }
            })

    # Add question
    content.append({"type": "text", "text": f"\nQuestion: {question}"})

    return [{"role": "user", "content": content}]
```

## Multimodal LLMs — GPT-4o, Claude 3.5, Gemini

Modern vision LLMs can directly interpret images, charts, diagrams, and documents:

```python
# GPT-4o vision — analyze a chart
response = openai.chat.completions.create(
    model="gpt-4o",
    messages=[{
        "role": "user",
        "content": [
            {
                "type": "image_url",
                "image_url": {
                    "url": "https://example.com/earnings_chart.png",
                    # OR: "url": f"data:image/png;base64,{base64_data}"
                    "detail": "high"  # high = full resolution analysis
                }
            },
            {
                "type": "text",
                "text": "What does this chart show? Extract all numerical values and trends."
            }
        ]
    }],
    max_tokens=500,
)
print(response.choices[0].message.content)
```

### Vision LLM Capabilities and Limits

| Capability | Quality | Notes |
|-----------|---------|-------|
| OCR / text extraction | Excellent | Often better than dedicated OCR |
| Chart interpretation | Good | Bar, line, pie charts well understood |
| Table extraction | Good | Complex tables sometimes fail |
| Diagram understanding | Moderate | Flow diagrams, architecture OK; complex schematics harder |
| Handwriting recognition | Moderate | Clear handwriting OK; cursive difficult |
| Low-resolution images | Poor | Requires at least 500px to be useful |
| Very long documents | Limited | Context window constrains number of images |

### Token Cost for Images

Images consume tokens. GPT-4o pricing:
- `detail: "low"`: fixed 85 tokens per image
- `detail: "high"`: 85 + 170 × (number of 512×512 tiles to cover the image)
  - 1024×1024 image → 4 tiles → 85 + 680 = 765 tokens
  - 2048×2048 image → 16 tiles → 85 + 2720 = 2805 tokens

For RAG with many documents, use `detail: "low"` for initial retrieval scoring and `detail: "high"` only for the final context window.

## ColPali — Document Image Embeddings

A newer approach: instead of extracting text from PDFs then embedding, embed document page images directly as retrieval units.

```python
# ColPali: visual document retrieval
# The model is a vision-language model fine-tuned for document retrieval
# Queries are embedded as text; document pages as images
# No text extraction needed — handles complex layouts natively

from colpali_engine.models import ColPali
from PIL import Image
import torch

model = ColPali.from_pretrained("vidore/colpali-v1.3", torch_dtype=torch.bfloat16)
processor = ColPaliProcessor.from_pretrained("vidore/colpali-v1.3")

# Index: embed each page as an image
page_images = [Image.open(f"page_{i}.png") for i in range(num_pages)]
with torch.no_grad():
    page_embeddings = model(**processor.process_images(page_images))

# Query: embed text query
query = "What was the revenue growth in Q3?"
with torch.no_grad():
    query_embedding = model(**processor.process_queries([query]))

# Score: multi-vector MaxSim scoring (ColBERT-style)
scores = model.score_multi_vector(query_embedding, page_embeddings)
```

ColPali achieves state-of-the-art on document retrieval benchmarks (DocVQA, InfoVQA) because it preserves visual layout information that text extraction loses.

## Revision Anchors

- **CLIP**: Text encoder + image encoder trained together on (text, image) pairs. Shared embedding space enables cross-modal search. Both outputs normalized → dot product = cosine similarity.
- **Image indexing strategies**: (A) LLM description → text embed (natural language search, expensive). (B) CLIP embed (visual similarity, cheap). (C) Hybrid — both for production.
- **Vision LLM for RAG context**: Pass base64 images in content blocks alongside text chunks. Use `detail: "high"` for charts/tables, `detail: "low"` for thumbnails. Images cost tokens — budget carefully.
- **ColPali**: Embed document pages as images directly — no text extraction. Handles complex layouts (multi-column, tables, charts) better than text-based approaches.
- **Multimodal prompt structure**: Build a content list with alternating text and image_url blocks. Label each chunk with page/figure number for citation.
