# Bulkified Trigger Patterns

## The patterns that recur

[[10.6 - Bulkification Patterns]] covers the principle. This note is the catalogue of shapes that appear in real trigger code, each written bulk-safe.

## Stamping a value from a parent

The most common requirement, and the one where before-insert behaviour catches people.

```java
public with sharing class ClaimService {

    public static void stampAssetDetails(List<Warranty_Claim__c> claims) {
        Set<Id> assetIds = new Set<Id>();
        for (Warranty_Claim__c claim : claims) {
            if (claim.Asset__c != null) {
                assetIds.add(claim.Asset__c);
            }
        }
        if (assetIds.isEmpty()) {
            return;
        }

        // querying explicitly, since __r traversal is unavailable in before insert
        Map<Id, Asset> assets = new Map<Id, Asset>([
            SELECT Id, SerialNumber, AccountId, Account.BillingCountry, Warranty_End_Date__c
            FROM Asset WHERE Id IN :assetIds
        ]);

        for (Warranty_Claim__c claim : claims) {
            Asset asset = assets.get(claim.Asset__c);
            if (asset == null) {
                continue;
            }
            claim.Asset_Serial__c = asset.SerialNumber;
            claim.Account__c = asset.AccountId;
            claim.Region__c = asset.Account?.BillingCountry;
            claim.Under_Warranty__c = asset.Warranty_End_Date__c >= claim.Claim_Date__c;
        }
    }
}
```

One query for any number of claims. Called from a before trigger, so no DML is needed.

## Roll-up to a parent

Aggregating children onto a parent where a native roll-up is unavailable.

```java
public with sharing class ClaimRollupService {

    public static void recalculate(Set<Id> assetIds) {
        if (assetIds.isEmpty()) {
            return;
        }

        Map<Id, Asset> assets = new Map<Id, Asset>([
            SELECT Id, Open_Claim_Count__c, Total_Claim_Value__c, Last_Claim_Date__c
            FROM Asset WHERE Id IN :assetIds
        ]);

        Map<Id, Asset> original = assets.deepClone(true);

        // resetting first means assets whose last claim closed go to zero rather than
        // keeping a stale value
        for (Asset asset : assets.values()) {
            asset.Open_Claim_Count__c = 0;
            asset.Total_Claim_Value__c = 0;
            asset.Last_Claim_Date__c = null;
        }

        for (AggregateResult ar : [
            SELECT Asset__c assetId, COUNT(Id) claimCount,
                   SUM(Claim_Amount__c) claimTotal, MAX(Claim_Date__c) lastClaim
            FROM Warranty_Claim__c
            WHERE Asset__c IN :assetIds AND Status__c != 'Closed'
            GROUP BY Asset__c
        ]) {
            Asset asset = assets.get((Id) ar.get('assetId'));
            asset.Open_Claim_Count__c = (Integer) ar.get('claimCount');
            asset.Total_Claim_Value__c = (Decimal) ar.get('claimTotal');
            asset.Last_Claim_Date__c = (Date) ar.get('lastClaim');
        }

        // updating only changed parents avoids firing the Asset trigger for nothing
        List<Asset> changed = new List<Asset>();
        for (Asset asset : assets.values()) {
            Asset before = original.get(asset.Id);
            if (asset.Open_Claim_Count__c != before.Open_Claim_Count__c
                || asset.Total_Claim_Value__c != before.Total_Claim_Value__c
                || asset.Last_Claim_Date__c != before.Last_Claim_Date__c) {
                changed.add(asset);
            }
        }

        if (!changed.isEmpty()) {
            update changed;
        }
    }
}
```

Three details make this correct: the aggregate query does the counting in the database, the reset handles deletions, and the change comparison prevents an unnecessary cascade into the Asset trigger. See [[08.4 - Aggregate Queries, GROUP BY and HAVING]] and [[11.6 - Recursion Control and Static Guards]].

## Collecting both old and new parent Ids

When a child is reparented, both parents need recalculating.

```java
public static Set<Id> affectedAssetIds(
    List<Warranty_Claim__c> newClaims,
    Map<Id, Warranty_Claim__c> oldClaims
) {
    Set<Id> assetIds = new Set<Id>();

    if (newClaims != null) {
        for (Warranty_Claim__c claim : newClaims) {
            if (claim.Asset__c != null) {
                assetIds.add(claim.Asset__c);
            }
            Warranty_Claim__c prior = oldClaims == null ? null : oldClaims.get(claim.Id);
            if (prior?.Asset__c != null && prior.Asset__c != claim.Asset__c) {
                assetIds.add(prior.Asset__c);
            }
        }
    }

    if (oldClaims != null && newClaims == null) {
        // delete context: only the old records exist
        for (Warranty_Claim__c claim : oldClaims.values()) {
            if (claim.Asset__c != null) {
                assetIds.add(claim.Asset__c);
            }
        }
    }

    return assetIds;
}
```

Handling both the reparent case and the delete case in one method means the handler can call it from every event.

## Creating child records

```java
public with sharing class ClaimService {

    public static void createInitialParts(List<Warranty_Claim__c> claims) {
        Set<Id> assetIds = new Set<Id>();
        for (Warranty_Claim__c claim : claims) {
            if (claim.Asset__c != null) {
                assetIds.add(claim.Asset__c);
            }
        }
        if (assetIds.isEmpty()) {
            return;
        }

        Map<Id, List<Standard_Part__c>> partsByAsset = new Map<Id, List<Standard_Part__c>>();
        for (Standard_Part__c part : [
            SELECT Id, Asset_Model__c, Product__c, Default_Quantity__c
            FROM Standard_Part__c WHERE Asset_Model__c IN :assetIds
        ]) {
            if (!partsByAsset.containsKey(part.Asset_Model__c)) {
                partsByAsset.put(part.Asset_Model__c, new List<Standard_Part__c>());
            }
            partsByAsset.get(part.Asset_Model__c).add(part);
        }

        List<Claim_Part__c> toInsert = new List<Claim_Part__c>();
        for (Warranty_Claim__c claim : claims) {
            List<Standard_Part__c> standardParts = partsByAsset.get(claim.Asset__c);
            if (standardParts == null) {
                continue;
            }
            for (Standard_Part__c standard : standardParts) {
                toInsert.add(new Claim_Part__c(
                    Warranty_Claim__c = claim.Id,
                    Product__c = standard.Product__c,
                    Quantity__c = standard.Default_Quantity__c
                ));
            }
        }

        if (!toInsert.isEmpty()) {
            insert toInsert;
        }
    }
}
```

The nested loop here is acceptable — the inner collection is that claim's own standard parts, so total iterations equal the number of parts created, not claims times parts.

## Cross-object validation

Validation needing data from another object, which a validation rule cannot express.

```java
public with sharing class ClaimValidationService {

    public static void validateCoverage(List<Warranty_Claim__c> claims) {
        Set<Id> assetIds = new Set<Id>();
        for (Warranty_Claim__c claim : claims) {
            if (claim.Asset__c != null) {
                assetIds.add(claim.Asset__c);
            }
        }
        if (assetIds.isEmpty()) {
            return;
        }

        Map<Id, Machine_Coverage__c> coverageByAsset = new Map<Id, Machine_Coverage__c>();
        for (Machine_Coverage__c coverage : [
            SELECT Asset__c, Coverage_Start_Date__c, Coverage_End_Date__c, Coverage_Limit__c
            FROM Machine_Coverage__c
            WHERE Asset__c IN :assetIds AND Service_Contract__r.Status__c = 'Active'
            ORDER BY Coverage_End_Date__c DESC
        ]) {
            if (!coverageByAsset.containsKey(coverage.Asset__c)) {
                coverageByAsset.put(coverage.Asset__c, coverage);
            }
        }

        for (Warranty_Claim__c claim : claims) {
            Machine_Coverage__c coverage = coverageByAsset.get(claim.Asset__c);

            if (coverage == null) {
                claim.addError('Asset__c',
                    'This machine has no active service contract coverage.');
            } else if (claim.Claim_Date__c > coverage.Coverage_End_Date__c) {
                claim.addError('Claim_Date__c',
                    'Coverage for this machine ended on '
                    + coverage.Coverage_End_Date__c.format() + '.');
            } else if (claim.Claim_Amount__c > coverage.Coverage_Limit__c) {
                claim.addError('Claim_Amount__c',
                    'This claim exceeds the coverage limit of '
                    + coverage.Coverage_Limit__c.format() + '.');
            }
        }
    }
}
```

`addError` on the specific field, with a message naming the actual constraint, is what makes this usable rather than merely correct.

## Preventing duplicates

Enforcing uniqueness across a combination the platform cannot index.

```java
public with sharing class CoverageValidationService {

    public static void preventDuplicateCoverage(
        List<Machine_Coverage__c> coverages,
        Map<Id, Machine_Coverage__c> oldCoverages
    ) {
        Map<String, Machine_Coverage__c> incoming = new Map<String, Machine_Coverage__c>();
        Set<Id> assetIds = new Set<Id>();

        for (Machine_Coverage__c coverage : coverages) {
            String key = coverage.Asset__c + '|' + coverage.Service_Contract__c;

            // duplicates within the incoming batch itself, which a query cannot catch
            if (incoming.containsKey(key)) {
                coverage.addError('This machine appears twice for the same contract.');
                continue;
            }
            incoming.put(key, coverage);
            assetIds.add(coverage.Asset__c);
        }

        Set<String> existing = new Set<String>();
        for (Machine_Coverage__c coverage : [
            SELECT Id, Asset__c, Service_Contract__c
            FROM Machine_Coverage__c WHERE Asset__c IN :assetIds
        ]) {
            if (oldCoverages != null && oldCoverages.containsKey(coverage.Id)) {
                continue;   // this is one of the records being updated
            }
            existing.add(coverage.Asset__c + '|' + coverage.Service_Contract__c);
        }

        for (String key : incoming.keySet()) {
            if (existing.contains(key)) {
                incoming.get(key).addError('This machine is already covered by that contract.');
            }
        }
    }
}
```

Checking within the batch **and** against existing records is what makes this correct. Checking only the database misses duplicates that arrive together in the same insert, which is exactly what happens with a data load.

For a hard guarantee, a unique text field populated with the composite key is better, because the database enforces it regardless of how the record arrives. See [[02.8 - Many-to-Many and Junction Objects]].

## Deferring expensive work

When the work is too heavy for the save transaction.

```java
public with sharing class ClaimService {

    public static void queueErpNotification(
        List<Warranty_Claim__c> newClaims,
        Map<Id, Warranty_Claim__c> oldClaims
    ) {
        Set<Id> toNotify = new Set<Id>();

        for (Warranty_Claim__c claim : newClaims) {
            Warranty_Claim__c prior = oldClaims == null ? null : oldClaims.get(claim.Id);
            if (claim.Status__c == 'Approved'
                && (prior == null || prior.Status__c != 'Approved')) {
                toNotify.add(claim.Id);
            }
        }

        if (toNotify.isEmpty()) {
            return;
        }

        // enqueued rather than called: a callout cannot run after DML
        System.enqueueJob(new ErpNotificationQueueable(toNotify));
    }
}
```

Passing Ids rather than records to the Queueable means it queries fresh data in its own transaction, which is correct — the records may have changed by the time it runs. See [[12.3 - Queueable Apex]].

## Limiting the async chain

A trigger can enqueue at most **50 Queueable jobs** per transaction, and one job from within a Queueable. Enqueuing per record exhausts this immediately.

```java
// Wrong: one job per record
for (Warranty_Claim__c claim : claims) {
    System.enqueueJob(new ErpNotificationQueueable(new Set<Id>{ claim.Id }));
}

// Correct: one job for all of them
System.enqueueJob(new ErpNotificationQueueable(claimIds));
```

The same applies to future method calls and to `EventBus.publish`.

## The anti-patterns

**Query in a loop.** The universal failure.

**DML in a loop.**

**Nested loops over record collections.** Build a map.

**Assuming one record.** `Trigger.new[0]` is the tell.

**No empty-collection guard** before DML.

**Ignoring the reparent case** in roll-ups.

**Checking only the database for duplicates**, missing in-batch ones.

**Enqueuing async work per record.**

## Testing bulk behaviour

Every service needs a test that pushes at least 200 records through it, with the parent distribution that exposes aggregation bugs.

```java
@IsTest
static void rollupIsCorrectWhenSeveralClaimsShareAnAsset() {
    List<Asset> assets = TestDataFactory.createAssets(50);

    List<Warranty_Claim__c> claims = new List<Warranty_Claim__c>();
    for (Integer i = 0; i < 200; i++) {
        claims.add(new Warranty_Claim__c(
            Asset__c = assets[Math.mod(i, 50)].Id,
            Claim_Amount__c = 10000,
            Claim_Date__c = Date.today(),
            Status__c = 'Submitted'
        ));
    }

    Test.startTest();
    insert claims;
    Test.stopTest();

    Map<Id, Asset> refreshed = new Map<Id, Asset>([
        SELECT Id, Open_Claim_Count__c, Total_Claim_Value__c FROM Asset WHERE Id IN :assets
    ]);

    for (Asset asset : assets) {
        Assert.areEqual(4, refreshed.get(asset.Id).Open_Claim_Count__c,
            'Each asset should have four claims');
        Assert.areEqual(40000, refreshed.get(asset.Id).Total_Claim_Value__c,
            'Each asset should total 40000');
    }
}
```

Two hundred claims across fifty assets is deliberate. A one-to-one distribution passes even with a broken aggregation; four-to-one does not.
