# Model Routing and Multi-Model Architecture

## Why Multi-Model Architecture

No single model is optimal for all tasks. A production AI system uses multiple models intelligently:

|Concern|Motivation|
|---|---|
|**Cost**|Cheap models for simple tasks; expensive only where needed|
|**Latency**|Fast models for real-time; slow models for background|
|**Quality**|Specialized models outperform general models on narrow tasks|
|**Reliability**|Fallback to secondary model if primary is down|
|**Compliance**|Different models for different data classifications|

---

## Routing Strategies

### Rule-Based Routing

Deterministic routing based on query properties:

```python
def route_to_model(query: str, task_type: str, context_length: int) -> str:
    # Long context → model with large context window
    if context_length > 100_000:
        return "claude-opus-4-5"  # 200K context
    
    # Classification → cheap fast model
    if task_type == "classification":
        return "gpt-4o-mini"
    
    # Code generation → code-specialized model
    if task_type == "code" or "write a function" in query.lower():
        return "gpt-4o"
    
    # Complex reasoning detected
    if task_type == "reasoning" or "step by step" in query.lower():
        return "o1-mini"
    
    # Default
    return "gpt-4o-mini"
```

### LLM-Based Routing

Use a classifier (another small LLM) to determine the right model:

```python
ROUTER_PROMPT = """Classify this query into one category:
- simple: factual lookups, short answers, basic formatting
- complex: multi-step reasoning, analysis, synthesis
- code: programming questions, debugging, code generation
- creative: writing, brainstorming, ideation

Query: {query}
Output only the category name."""

def llm_route(query):
    category = fast_classifier.call(ROUTER_PROMPT.format(query=query))
    return MODEL_MAP[category.strip()]

MODEL_MAP = {
    "simple": "gpt-4o-mini",
    "complex": "gpt-4o",
    "code": "gpt-4o",
    "creative": "claude-sonnet-4-5",
}
```

### Cascade Routing

Try the cheap model first; escalate to expensive if confidence is low:

```python
async def cascade_query(question, context):
    # Try cheap model
    response = await gpt4o_mini.call(question, context)
    confidence = assess_response_confidence(response, context)
    
    if confidence > 0.85:
        return response, "gpt-4o-mini"
    
    # Escalate to better model
    response = await gpt4o.call(question, context)
    return response, "gpt-4o"

def assess_response_confidence(response, context):
    # Heuristics: hedging language, unsupported claims, completeness
    hedging_phrases = ["I'm not sure", "I think", "possibly", "might be"]
    confidence = 1.0
    for phrase in hedging_phrases:
        if phrase.lower() in response.lower():
            confidence -= 0.15
    return max(0.0, confidence)
```

## Fallback Architecture

Handle model API failures gracefully:

```python
class ModelWithFallback:
    def __init__(self, primary: str, fallbacks: list[str]):
        self.primary = primary
        self.fallbacks = fallbacks
    
    async def call(self, messages, **kwargs):
        models_to_try = [self.primary] + self.fallbacks
        last_error = None
        
        for model in models_to_try:
            try:
                return await llm_call(model, messages, **kwargs)
            except (RateLimitError, ServiceUnavailableError) as e:
                last_error = e
                metrics.increment(f"model.fallback", tags={"from": model})
                await asyncio.sleep(1)
                continue
        
        raise last_error  # All models failed

# Usage
model = ModelWithFallback(
    primary="gpt-4o",
    fallbacks=["gpt-4o-2024-08-06", "claude-sonnet-4-5"]
)
```
