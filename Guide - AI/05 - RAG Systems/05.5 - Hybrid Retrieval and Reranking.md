# Hybrid Retrieval and Reranking

## The Full Retrieval Pipeline

Production retrieval is a multi-stage funnel — each stage refines the candidate set:

```
Query (transformed)
      │
      ├──────────────────────────────┐
      ▼                              ▼
[Dense Retrieval]            [Sparse Retrieval]
 top-100 by vector           top-100 by BM25
      │                              │
      └──────────┬───────────────────┘
                 ▼
         [Score Fusion (RRF)]
          merged top-100
                 │
                 ▼
         [Permission Filter]
          remove unauthorized
                 │
                 ▼
         [Reranker (Cross-Encoder)]
          re-score top-100
                 │
                 ▼
         [Context Assembly]
          select top-10 for LLM context
```

This file covers dense retrieval, fusion, and reranking in the context of a full RAG pipeline. BM25 internals are in [[../03 - LLM Foundations/03.5 - BM25 and Hybrid Search]]. Reranker architecture is in [[../03 - LLM Foundations/03.6 - Rerankers - Cross vs Bi Encoders]].

## Dense Retrieval in Production

### Batching Queries

At scale, batching embedding requests reduces cost and latency:

```python
async def batch_embed_queries(queries: list[str], batch_size=32):
    embeddings = []
    for i in range(0, len(queries), batch_size):
        batch = queries[i:i + batch_size]
        batch_embeddings = await embedding_client.embed(batch)
        embeddings.extend(batch_embeddings)
    return embeddings
```

### Embedding Model Consistency

The same model must embed both queries and documents. Track the model version:

## Fusion Strategies

### Reciprocal Rank Fusion (RRF)

Combines ranked lists without needing score normalization:

```python
def rrf_fusion(result_lists: list[list[SearchResult]], k=60) -> list[SearchResult]:
    scores = defaultdict(float)
    doc_map = {}
    
    for result_list in result_lists:
        for rank, result in enumerate(result_list):
            scores[result.id] += 1.0 / (k + rank + 1)
            doc_map[result.id] = result  # store doc data
    
    sorted_ids = sorted(scores, key=lambda x: scores[x], reverse=True)
    return [doc_map[id] for id in sorted_ids]
```

**When to use**: Default fusion method. Robust, no tuning required.

### Weighted Hybrid Score

When you want explicit control of dense vs sparse balance:

```python
def weighted_fusion(dense_results, sparse_results, alpha=0.5):
    # Normalize scores to [0,1] range
    dense_norm = normalize_scores(dense_results)
    sparse_norm = normalize_scores(sparse_results)
    
    combined = {}
    for id, score in dense_norm.items():
        combined[id] = combined.get(id, 0) + alpha * score
    for id, score in sparse_norm.items():
        combined[id] = combined.get(id, 0) + (1 - alpha) * score
    
    return sorted(combined.items(), key=lambda x: x[1], reverse=True)
```

**Alpha tuning**: For keyword-heavy domains (legal, medical with specific terminology): `alpha=0.3` (lean sparse). For semantic/conceptual domains: `alpha=0.7` (lean dense). Always validate with your eval set.

## Reranking Integration

```python
async def full_retrieval_pipeline(
    query: str,
    vector_store,
    keyword_store, 
    reranker,
    user_permissions: set[str],
    top_k_retrieve=100,
    top_k_rerank=20,
    top_k_final=10,
) -> list[Chunk]:
    
    # Stage 1: Dual retrieval (run in parallel)
    dense_future = asyncio.create_task(
        vector_store.search(query, top_k=top_k_retrieve)
    )
    sparse_future = asyncio.create_task(
        keyword_store.search(query, top_k=top_k_retrieve)
    )
    dense_results, sparse_results = await asyncio.gather(dense_future, sparse_future)
    
    # Stage 2: Fuse
    fused = rrf_fusion([dense_results, sparse_results])[:top_k_retrieve]
    
    # Stage 3: Permission filter (before reranking — no point reranking forbidden docs)
    authorized = [r for r in fused if has_permission(r, user_permissions)]
    
    # Stage 4: Rerank (only top-N for latency)
    candidates = authorized[:top_k_rerank]
    pairs = [(query, chunk.text) for chunk in candidates]
    rerank_scores = reranker.predict(pairs)
    
    reranked = sorted(zip(candidates, rerank_scores), key=lambda x: x[1], reverse=True)
    
    return [chunk for chunk, _ in reranked[:top_k_final]]
```

## Context Compression

Before sending retrieved chunks to the LLM, optionally compress them to reduce token usage:

### LLM-Based Extraction

```python
COMPRESS_PROMPT = """
Given this document chunk and a question, extract only the sentences 
from the chunk that are relevant to answering the question.

Question: {question}
Chunk: {chunk}

Output only the relevant sentences, preserving exact wording.
"""

def compress_chunk(question, chunk, llm):
    return llm.call(COMPRESS_PROMPT.format(question=question, chunk=chunk))
```

**Tradeoff**: Reduces tokens (saves cost, allows more chunks in context) but adds latency and another LLM call. Worth it only when chunks are verbose and context window is tight.

### Sentence-Level Filtering

Lighter alternative: embed each sentence in a chunk, keep only those above a similarity threshold to the query:

```python
def sentence_filter(query, chunk_text, threshold=0.6):
    sentences = split_sentences(chunk_text)
    query_emb = embedding_model.encode(query)
    sent_embs = embedding_model.encode(sentences)
    
    similarities = [cosine_sim(query_emb, e) for e in sent_embs]
    return " ".join(s for s, sim in zip(sentences, similarities) if sim > threshold)
```

## Context Ordering (Lost in the Middle)

After retrieval and reranking, the order you place chunks in the context window matters. Research shows LLMs use information better when it's at the beginning or end of context, not the middle.

```python
def order_chunks_for_llm(chunks: list[Chunk]) -> list[Chunk]:
    # Best-known ordering: place most relevant at beginning and end
    # Put least relevant in the middle
    n = len(chunks)
    ordered = []
    
    # Front-load top half
    for i in range(0, n // 2):
        ordered.append(chunks[i * 2])       # even indices: top chunks
    
    # Back-load remaining
    for i in range(n // 2, n):
        ordered.append(chunks[i])           # fill end
    
    return ordered
```

In practice: put the highest-relevance chunk first. This is enough for most cases.
