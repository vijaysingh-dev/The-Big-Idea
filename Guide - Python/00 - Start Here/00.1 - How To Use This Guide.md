# How To Use This Guide

#python #meta

> **In one line:** Watch the course section, read the matching note, read the CPython or library source it names, then build the drill. A topic is done when you can predict what Python will do before you run it.

---

## Who This Is For

You already write Python every day: FastAPI services, scripts, tests. You can make things work. This guide is for the next step: **knowing why they work**, so that when something behaves strangely (a default argument that remembers, a closure capturing the wrong value, a dict that is slow, a Pydantic model that coerces when you did not expect it) you recognise it immediately.

The test of mastery is **prediction**. Before running any snippet in these notes, say what it prints. When you are wrong, that is the lesson.

---

## The Three Passes

Same method as the Backend guide ([[00.2 - The Codebase First Method]]):

1. **Watch and read.** The Udemy section, then the note. The course is thorough; the note is the compressed version with production context.
2. **Read the source.** Each note's Codebase box points at real files: CPython's `Lib/` (pure Python, very readable), parts of `Objects/` (C, read selectively), or libraries such as Pydantic and pytest.
3. **Build the drill.** Each Exercise box describes a small multi-file project in `py-drills/`. Type it yourself. No copy-paste.

## The Drill Repo

```
py-drills/
├── pyproject.toml          # one project, managed with uv (see 03.2)
├── src/pydrills/
│   ├── memory/             # section 01
│   ├── functions/          # section 02
│   ├── ...
└── tests/                  # pytest, mirroring src/
```

Set it up once, using what you learn in [[03.2 - Packaging and Project Tooling]]:

```bash
uv init --package py-drills
cd py-drills
uv add --dev pytest pytest-asyncio hypothesis mypy ruff
uv run pytest
```

Every drill ships with tests. The tests are where you write down your predictions.

## How to Use the REPL

Most of the "aha" moments in Python come from poking objects in a REPL:

```python
>>> x = [1, 2, 3]
>>> id(x), type(x), x.__class__.__mro__
>>> import dis; dis.dis(lambda: x[0] + 1)      # what bytecode runs
>>> import sys; sys.getrefcount(x)              # how many references
>>> vars(SomeClass), dir(obj)                   # what lives where
>>> import inspect; print(inspect.getsource(functools.wraps))
```

Use `python -X importtime`, `dis`, `inspect` and `sys.getsizeof` freely. They are how you check your predictions.

## Versions

The notes assume **Python 3.12+**, mention 3.13/3.14 changes where they matter (free threading, the new REPL, deferred annotations), and use **Pydantic v2**. When behaviour differs across versions, the note says so.
