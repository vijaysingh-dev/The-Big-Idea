# Classes and Instances

#python #oop #classes

> **In one line:** A class is an object (an instance of `type`) holding shared attributes and functions. An instance holds its own attributes in a dict, and looking up `obj.x` checks the instance, then the class and its bases. A method is just a function that gets bound to the instance when you look it up.

---

## A Class Is an Object

```python
class Account:
    """A bank account."""
    currency = "USD"                 # class attribute: shared

    def __init__(self, owner, balance=0):
        self.owner = owner           # instance attributes: per object
        self.balance = balance

    def deposit(self, amount):
        self.balance += amount

type(Account)          # <class 'type'>
Account.__dict__       # mappingproxy({'currency': 'USD', '__init__': <function>, 'deposit': <function>, ...})
a = Account("ana")
a.__dict__             # {'owner': 'ana', 'balance': 0}
```

The `class` statement runs its body like a function, collects the resulting namespace, and calls `type(name, bases, namespace)` to build the class object. That is why you can put any code in a class body, and why metaclasses can intercept class creation ([[06.8 - Metaprogramming]]).

---

## Attribute Lookup

For `obj.attr`, roughly:

1. A **data descriptor** on the class (such as a `property`) wins.
2. Otherwise, the **instance `__dict__`**.
3. Otherwise, the **class and its bases** in MRO order (non-data descriptors such as methods, and plain class attributes).
4. Otherwise, `__getattr__` if defined.
5. Otherwise, `AttributeError`.

The full machinery is in [[06.5 - Descriptors]]. The practical consequences:

```python
a = Account("ana"); b = Account("bo")
a.currency = "EUR"        # creates an INSTANCE attribute that shadows the class one
b.currency                # "USD" — unaffected
Account.currency = "GBP"  # changes it for every instance without its own value
b.currency                # "GBP"
```

⚠️ **Mutable class attributes are shared.** `class Cart: items = []` gives every cart the same list. Create mutable state in `__init__`. ([[01.2 - Mutability Equality and Copying]])

## Methods and Binding

A function defined in a class is a plain function stored on the class. Looking it up **through an instance** creates a *bound method* that remembers the instance:

```python
Account.deposit                 # <function Account.deposit> — plain function
a.deposit                       # <bound method Account.deposit of <Account>>
a.deposit(10)                   # same as Account.deposit(a, 10)
m = a.deposit
m.__self__ is a, m.__func__ is Account.deposit    # True, True
```

`self` is not a keyword. It is just the first parameter, filled in by binding. This binding happens because functions are descriptors with a `__get__` method.

## classmethod, staticmethod, property

```python
from datetime import date

class User:
    def __init__(self, name, born: date):
        self.name, self.born = name, born

    @classmethod
    def from_row(cls, row):                     # alternative constructor; gets the class
        return cls(row["name"], date.fromisoformat(row["born"]))

    @staticmethod
    def is_valid_name(name):                    # no self, no cls: a function in the class namespace
        return bool(name.strip())

    @property
    def age(self):                              # computed attribute, read like a field
        today = date.today()
        return today.year - self.born.year - ((today.month, today.day) < (self.born.month, self.born.day))
```

| Decorator | First argument | Use for |
|---|---|---|
| (none) | The instance | Behaviour that uses instance state |
| `@classmethod` | The class (`cls`) | **Alternative constructors** (`from_row`, `from_json`, `dict.fromkeys`). They respect subclasses because `cls` is whatever class it was called on. |
| `@staticmethod` | Nothing | A helper that belongs with the class conceptually. Often a module-level function is just as good. |
| `@property` | The instance | Computed values, or validation on assignment, without changing the public API |

### Property with a setter

```python
class Temperature:
    def __init__(self, celsius):
        self.celsius = celsius            # goes through the setter, so it is validated too

    @property
    def celsius(self):
        return self._celsius

    @celsius.setter
    def celsius(self, value):
        if value < -273.15:
            raise ValueError("below absolute zero")
        self._celsius = value
```

💡 **Start with plain attributes.** Python lets you change an attribute into a property later without changing any caller, so getters and setters "just in case" (Java style) are unnecessary.

## Construction: `__new__` and `__init__`

```python
obj = Cls(*args)
# 1. obj = Cls.__new__(Cls, *args)    creates the object (rarely overridden)
# 2. if isinstance(obj, Cls): obj.__init__(*args)   initialises it
```

Override `__new__` only to customise creation of **immutable** types (subclassing `str`, `int`, `tuple`) or to return cached instances. Everything else belongs in `__init__`.

## Privacy by Convention

| Name | Meaning |
|---|---|
| `name` | Public |
| `_name` | Internal. "Do not touch unless you know why." Not enforced. |
| `__name` | **Name-mangled** to `_ClassName__name`, to avoid clashes in subclasses. Not real privacy. |
| `__name__` | Special ("dunder") methods for the language. Do not invent your own. |

Python has no private members. It has conventions, and linters enforce them.

## Dynamic Attributes

```python
getattr(obj, "balance", 0)
setattr(obj, "balance", 10)
hasattr(obj, "close")
vars(obj)                    # obj.__dict__

class Settings:
    def __getattr__(self, name):         # called ONLY when normal lookup fails
        return os.environ[name.upper()]
```

`__getattr__` powers lazy proxies, API clients (`client.users.list()`), and mocks. `__getattribute__` intercepts **every** lookup. It is rarely what you want, and easy to make recursive.
