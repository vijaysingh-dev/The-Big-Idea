# Facade Pattern

## At a Glance

|||
|---|---|
|**Type**|Structural|
|**Intent**|Provide a simplified, unified interface to a complex subsystem|
|**Frequency in Backend**|★★★★☆ — service layer over domain, SDK simplification|

---

## The Problem It Solves

A subsystem has many moving parts (validation, pricing, inventory, notifications, persistence). Callers shouldn't need to orchestrate all of them. Facade provides one clean entry point.

---

## Full Backend Example: Order Placement Facade

```python
# Without Facade — caller orchestrates everything (messy)
class OrderController:
    def place_order(self, request):
        # Caller must know and coordinate all subsystems
        validator.validate(request)
        customer = customer_repo.find(request.customer_id)
        
        for item in request.items:
            inventory.check_availability(item.product_id, item.quantity)
        
        pricing = pricing_engine.calculate(request.items, customer.tier)
        
        payment = payment_gateway.charge(customer.payment_method, pricing.total)
        if not payment.success:
            raise PaymentError(payment.error)
        
        for item in request.items:
            inventory.reserve(item.product_id, item.quantity)
        
        order = order_factory.create(request, pricing, payment)
        order_repo.save(order)
        
        email_service.send_confirmation(customer, order)
        analytics.track("order_placed", order)
        loyalty.award_points(customer, pricing.total)
        # ... 50 lines in controller


# order_facade.py — Facade hides all of this
from dataclasses import dataclass
from typing import List
from decimal import Decimal
from uuid import UUID

@dataclass
class PlaceOrderRequest:
    customer_id: UUID
    items: List["OrderItemRequest"]
    payment_method_id: str
    shipping_address_id: str
    idempotency_key: str

@dataclass  
class PlaceOrderResult:
    order_id: UUID
    total: Decimal
    estimated_delivery: str
    tracking_url: str


class OrderFacade:
    """
    Facade: single entry point for the entire order placement workflow.
    Hides coordination of 8+ subsystems behind one clean method.
    """
    
    def __init__(self, validator, customer_repo, inventory, 
                 pricing_engine, payment_gateway, order_repo,
                 notifier, analytics, loyalty):
        self._validator = validator
        self._customers = customer_repo
        self._inventory = inventory
        self._pricing = pricing_engine
        self._payments = payment_gateway
        self._orders = order_repo
        self._notifier = notifier
        self._analytics = analytics
        self._loyalty = loyalty
    
    def place_order(self, request: PlaceOrderRequest) -> PlaceOrderResult:
        """
        Complete order placement workflow.
        Caller knows nothing about the subsystems.
        """
        # Idempotency check
        existing = self._orders.find_by_idempotency_key(request.idempotency_key)
        if existing:
            return self._to_result(existing)
        
        # Validation
        self._validator.validate(request)
        customer = self._customers.get_or_raise(request.customer_id)
        
        # Inventory check (before charging!)
        for item in request.items:
            self._inventory.assert_available(item.product_id, item.quantity)
        
        # Pricing
        pricing = self._pricing.calculate(request.items, customer.tier)
        
        # Payment
        payment = self._payments.charge(
            method_id=request.payment_method_id,
            amount=pricing.total,
            idempotency_key=request.idempotency_key
        )
        
        # Create + persist order
        order = self._orders.create_and_save(
            request=request,
            pricing=pricing,
            payment=payment
        )
        
        # Reserve inventory (after successful payment)
        for item in request.items:
            self._inventory.reserve(item.product_id, item.quantity, order.id)
        
        # Post-placement side effects (non-critical — don't fail the order)
        self._post_placement(customer, order, pricing)
        
        return self._to_result(order)
    
    def cancel_order(self, order_id: UUID, reason: str) -> bool:
        """Another facade method — hides cancel workflow complexity."""
        order = self._orders.get_or_raise(order_id)
        order.cancel(reason)
        self._orders.save(order)
        
        # Refund if paid
        if order.payment_id:
            self._payments.refund(order.payment_id, order.total)
        
        # Release inventory
        for item in order.items:
            self._inventory.release(item.product_id, item.quantity, order_id)
        
        self._notifier.send_cancellation(order)
        return True
    
    def _post_placement(self, customer, order, pricing):
        """Side effects that don't affect the core outcome."""
        try:
            self._notifier.send_confirmation(customer, order)
        except Exception as e:
            logger.error(f"Confirmation email failed: {e}")  # don't raise
        
        try:
            self._analytics.track("order_placed", {"order_id": str(order.id)})
            self._loyalty.award_points(customer.id, pricing.total)
        except Exception as e:
            logger.error(f"Post-placement task failed: {e}")
    
    def _to_result(self, order) -> PlaceOrderResult:
        return PlaceOrderResult(
            order_id=order.id,
            total=order.total,
            estimated_delivery="3-5 business days",
            tracking_url=f"https://track.company.com/{order.id}"
        )


# Controller is now clean — one call does everything
class OrderController:
    def __init__(self, facade: OrderFacade):
        self._facade = facade
    
    def place_order(self, request_dto):
        result = self._facade.place_order(
            PlaceOrderRequest(**request_dto)
        )
        return {"order_id": str(result.order_id), "total": str(result.total)}
```

## Facade Layers in a Typical Backend

```
API Controller
     │ calls
     ▼
Application Facade    ← thin — just orchestrates
     │ uses
     ├──▶ Domain Services   ← business rules
     │         │ uses
     │         ├──▶ Repositories
     │         ├──▶ Domain Entities
     │         └──▶ Value Objects
     │
     └──▶ Infrastructure Facades
               ├──▶ EmailFacade (wraps SendGrid + templates)
               ├──▶ PaymentFacade (wraps Stripe)
               └──▶ SearchFacade (wraps Elasticsearch)
```

---

## When NOT to Use Facade

- **Subsystem is already simple** — adding a Facade is just noise
- **Callers need full power of subsystem** — Facade hides things they need
- **Using Facade to hide bad design** — fix the design, don't paper over it

---

## Tradeoffs

|Pro|Con|
|---|---|
|Simple interface for callers|Can become a "God object" if too many methods|
|Subsystem can change without callers knowing|Hides subsystem — callers can't access edge functionality|
|Easy to test facade in isolation|Facade itself needs testing of workflow|
|Reduces coupling to complex subsystems|Over-simplified — may not expose enough|
