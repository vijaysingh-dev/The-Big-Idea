# Head Metadata and SEO Basics

The `<head>` controls how the page is parsed, rendered, indexed and shared. It is also the most render-blocking part of the document, so its contents and their order have direct performance consequences.

## The essentials

```html
<!DOCTYPE html>
<html lang="en">
<head>
  <meta charset="utf-8">
  <meta name="viewport" content="width=device-width, initial-scale=1">
  <title>Page title — Site name</title>
  <meta name="description" content="A concise summary, roughly 150 characters.">
  <link rel="canonical" href="https://example.com/page">
</head>
```

**`<!DOCTYPE html>`** — without it, browsers use quirks mode, where the box model and several layout behaviors revert to pre-standard rules.

**`charset`** must be within the first 1024 bytes. The browser guesses an encoding until it finds this and re-parses if wrong, so put it first.

**`lang`** on `<html>` determines screen reader pronunciation, browser translation offers, and locale-specific font and hyphenation behavior. A missing `lang` is one of the most common accessibility audit failures.

**`viewport`** — without it, mobile browsers render at a 980px virtual width and scale down, making a responsive layout pointless. Avoid `maximum-scale=1` or `user-scalable=no`; blocking zoom fails accessibility requirements.

## Title and description

The title is the single strongest on-page ranking signal and the clickable text in search results.

```html
<title>Pricing — Acme</title>
```

Roughly 50–60 characters before truncation. Put the distinguishing part first: `Pricing — Acme`, not `Acme — Pricing`, because a truncated title should still be identifiable.

The description does not affect ranking directly but does affect click-through, since it usually becomes the snippet. Around 150–160 characters, describing the page rather than the company.

## Canonical URLs

```html
<link rel="canonical" href="https://example.com/products/shoes">
```

Tells search engines which URL is authoritative when the same content is reachable at several. This matters more than people expect: `?utm_source=`, `?page=1`, trailing slashes, `http` versus `https`, and `www` versus apex all create duplicate URLs. Without a canonical, ranking signals split across them.

Use absolute URLs, and make each page's canonical point to itself unless it genuinely is a duplicate.

## Open Graph and Twitter cards

What appears when a link is shared on WhatsApp, LinkedIn, Slack or X:

```html
<meta property="og:title" content="Pricing — Acme">
<meta property="og:description" content="Plans starting at ₹499/month.">
<meta property="og:image" content="https://example.com/og/pricing.png">
<meta property="og:url" content="https://example.com/pricing">
<meta property="og:type" content="website">

<meta name="twitter:card" content="summary_large_image">
```

The image should be roughly 1200×630 and served over absolute HTTPS. Relative URLs do not work — crawlers fetch these without page context.

Note that social crawlers generally do **not** execute JavaScript. A client-rendered SPA that sets OG tags with `useEffect` will show nothing in a share preview. These tags must be in the initial HTML, which is a concrete argument for SSR or prerendering ([[28.11 - Rendering Strategies]]).

## Robots directives

```html
<meta name="robots" content="index, follow">
<meta name="robots" content="noindex, nofollow">
```

Common on staging environments, search result pages, and thin content. Note `noindex` requires the page to be crawlable — blocking it in `robots.txt` prevents the crawler from ever seeing the `noindex`, which is a classic mistake that keeps pages indexed indefinitely.

## Resource hints

```html
<link rel="preconnect" href="https://api.example.com" crossorigin>
<link rel="dns-prefetch" href="https://cdn.example.com">
<link rel="preload" as="font" href="/fonts/inter.woff2" type="font/woff2" crossorigin>
<link rel="prefetch" href="/next-page.js">
<link rel="modulepreload" href="/chunks/main.js">
```

- **`preconnect`** opens the DNS + TCP + TLS connection early. Costs a connection, so use it for two or three critical origins at most.
- **`preload`** fetches a resource the current page definitely needs, at high priority. Fonts are the classic case, and `crossorigin` is required even for same-origin fonts.
- **`prefetch`** fetches at low priority for a *future* navigation.
- **`modulepreload`** preloads and parses an ES module and its dependencies.

Over-preloading is counterproductive: everything preloaded competes with everything else for bandwidth, so preloading ten things effectively prioritizes nothing ([[29.2 - Prefetching and Preloading]]).

## Structured data

```html
<script type="application/ld+json">
{
  "@context": "https://schema.org",
  "@type": "Product",
  "name": "Running Shoes",
  "offers": {
    "@type": "Offer",
    "price": "2999",
    "priceCurrency": "INR",
    "availability": "https://schema.org/InStock"
  },
  "aggregateRating": {
    "@type": "AggregateRating",
    "ratingValue": "4.5",
    "reviewCount": "89"
  }
}
</script>
```

JSON-LD is the format Google recommends. It powers rich results — star ratings, prices, FAQ dropdowns, breadcrumbs — which materially affect click-through even without a ranking change.

The common types worth knowing: `Product`, `Article`, `BreadcrumbList`, `FAQPage`, `Organization`, `LocalBusiness`, `Event`. Validate with Google's Rich Results Test; malformed structured data is ignored silently.

## Favicons and app metadata

```html
<link rel="icon" href="/favicon.ico" sizes="32x32">
<link rel="icon" href="/icon.svg" type="image/svg+xml">
<link rel="apple-touch-icon" href="/apple-touch-icon.png">
<link rel="manifest" href="/manifest.webmanifest">
<meta name="theme-color" content="#0b0b0b">
```

An SVG icon plus a 180×180 apple-touch-icon plus a legacy `.ico` covers essentially everything.

## Head order matters

The browser parses the head sequentially, and synchronous scripts and stylesheets block rendering ([[13.1 - The Critical Rendering Path]]). A workable order:

1. `charset`, `viewport`
2. `preconnect` to critical origins
3. `title`, `description`
4. Critical CSS or the main stylesheet link
5. `preload` for critical fonts
6. Deferred scripts
7. Everything else — social tags, structured data, icons

Scripts in the head should be `defer` (executes in order after parsing) or `async` (executes whenever it arrives, order not guaranteed). A plain `<script>` in the head stops HTML parsing entirely.

## SPAs and SEO

Client-rendered pages present two problems. Googlebot does render JavaScript, but on a delayed second pass, so indexing lags. Other crawlers — including every social preview bot — generally do not render at all.

Practical approaches:

- **SSR or SSG** for anything that needs to rank or be shared.
- **Per-route metadata**, whether through a framework's metadata API or a head-management library.
- **Real `<a href>` links** — crawlers follow anchors, not `onClick` handlers that call a router.
- **A sitemap.xml** with real URLs.

## How senior engineers actually use this

**They treat metadata as route configuration.** Title, description, canonical and OG tags are defined alongside the route, not scattered through components.

**They verify with the actual tools.** Google's Rich Results Test, the Facebook sharing debugger and a `curl` of the raw HTML tell you what crawlers see — which is frequently not what the browser shows.

**They audit `lang` and `viewport` first** in any accessibility review, since both are one-line fixes with wide impact.

**They keep preload lists short.** Fonts and the LCP image, and little else.

## Common pitfalls

- Missing `lang`.
- `user-scalable=no`, blocking zoom.
- OG tags set client-side, so share previews are blank.
- Relative URLs in OG image tags.
- `noindex` on a page also blocked by `robots.txt`, so it never takes effect.
- Duplicate or missing canonicals across query-parameter variants.
- Preloading a dozen resources and diluting priority.
- Synchronous scripts in the head blocking the parser.

## Interview angle

Head metadata comes up in SEO and performance contexts rather than as a topic of its own. The points that matter: `charset` and `viewport` early, `lang` for accessibility, canonical for duplicate content, OG tags needing to be in the server-rendered HTML because social crawlers do not run JavaScript, and resource hints used sparingly. That last constraint — that preloading everything prioritizes nothing — is a good signal of practical experience.
