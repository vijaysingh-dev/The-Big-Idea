# Voice and Speech Stack

## What It Is

The voice/speech stack converts between audio and text at both ends of a conversational AI pipeline:

```
User speaks
    │
    ▼
[ASR — Automatic Speech Recognition]   audio → text
    │
    ▼
[NLU / LLM pipeline]                   text → text
    │
    ▼
[TTS — Text-to-Speech]                 text → audio
    │
    ▼
User hears
```

For companies like Haptik, Observe.AI, Gnani, Skit, and Yellow.ai, this stack **is** the product. Getting ASR accuracy, TTS naturalness, and streaming latency right determines whether the product is usable.

---

## Why It Matters for AI Engineers

- A 300ms LLM improvement is invisible if ASR takes 2s
- Word Error Rate (WER) in ASR compounds through the pipeline — a misheard "not" inverts meaning
- Streaming architecture is fundamentally different from request-response
- Indian-language support (Hindi, Tamil, Telugu, Kannada) has different ASR model requirements than English — directly relevant to your target companies
- Observe.AI and Skit process call center audio at scale — every 100ms of latency × millions of minutes = real cost

## ASR Internals

### What ASR Does

Takes a raw audio waveform → produces a text transcript, optionally with:
- Word-level timestamps
- Speaker diarization (who said what)
- Confidence scores per word
- Punctuation restoration

### Architecture Evolution

**Traditional (pre-deep learning)**: GMM-HMM pipeline. Acoustic model + pronunciation dictionary + language model. Interpretable but brittle.

**CTC-based (2015–2020)**: Connectionist Temporal Classification. A single neural network maps audio frames → character probabilities. Much better accuracy. Still requires a separate language model for good results.

**Attention/Transformer-based (2020+)**: End-to-end sequence-to-sequence. Audio encoder + text decoder. No separate language model needed — the decoder is itself a language model.

**Whisper (OpenAI, 2022)**: The current dominant architecture for English and multilingual ASR. Encoder-decoder Transformer trained on 680K hours of supervised audio. Key properties:
- Trained on 99 languages
- Robust to noise, accents, domain shift
- Produces punctuated, formatted output (not raw tokens)
- Open weights — can self-host

### How Whisper Works Internally

```
Audio input (16kHz PCM)
    │
    ▼
[Log-Mel Spectrogram]         ← convert waveform to frequency representation
80 mel filterbanks × time frames
    │
    ▼
[Convolutional Feature Extractor]  ← 2 Conv layers reduce time dimension
    │
    ▼
[Transformer Encoder]         ← 6–32 layers depending on model size
    │
    ▼
[Transformer Decoder]         ← autoregressive text generation
with special tokens:
  <|startoftranscript|>
  <|en|>                      ← language token
  <|transcribe|>              ← task token (vs <|translate|>)
  <|notimestamps|>            ← or timestamp tokens
    │
    ▼
Transcript text
```

The decoder is a standard language model decoder. This means Whisper can be prompted — the first few decoded tokens condition the rest, enabling:
- Language forcing: `<|hi|>` for Hindi
- Task switching: `<|translate|>` to translate while transcribing
- Initial prompt injection: supply context to bias transcription toward domain vocabulary

### Whisper Model Sizes

| Model | Parameters | English WER | Relative Speed | VRAM |
|-------|-----------|-------------|----------------|------|
| tiny | 39M | 5.7% | 32× | ~1GB |
| base | 74M | 4.2% | 16× | ~1GB |
| small | 244M | 3.4% | 6× | ~2GB |
| medium | 769M | 3.1% | 2× | ~5GB |
| large-v3 | 1550M | 2.7% | 1× | ~10GB |
| large-v3-turbo | 809M | 2.8% | 3× | ~6GB |

**Production rule**: `large-v3-turbo` is the sweet spot — near large-v3 quality at 3× the speed. Use `small` for edge devices or ultra-low latency.

### Word Error Rate (WER)

The primary ASR quality metric:

```
WER = (Substitutions + Deletions + Insertions) / Reference word count

Example:
Reference:  "the cat sat on the mat"        (6 words)
Hypothesis: "the cat sat on a mat"          (1 substitution: "a" for "the")
WER = 1/6 = 16.7%
```

**Industry benchmarks**:
- LibriSpeech clean test: ~2–3% WER for best models
- Real-world call center (noisy, accented, domain-specific): 10–25% WER is realistic
- Indian English: typically 5–15% higher WER than American English on English-trained models

## Streaming ASR

For real-time conversation, you cannot wait for the user to stop speaking before starting transcription. Streaming ASR produces partial transcripts incrementally.

### Two Streaming Modes

**Offline chunking**: Buffer audio into chunks (e.g., 5–10s), transcribe each chunk, concatenate. Simple but introduces latency proportional to chunk size.

**True streaming (VAD + rolling window)**: Use Voice Activity Detection to detect speech/silence. Transcribe rolling windows. Emit partial (unstable) and final (stable) results.

```
Audio stream: [speaking...........................][silence][speaking...]
VAD output:   [speech  ][speech][silence         ][silence][speech  ]
Chunker:      └──chunk 1──────┘                           └──chunk 2┘
ASR output:   "hello how are"  "you doing today"           "thanks for calling"
                ↑ partial results within chunk ↑ final
```

### faster-whisper for Production Streaming

`faster-whisper` is a CTranslate2-based reimplementation of Whisper — 4× faster than the original with lower memory.

```python
from faster_whisper import WhisperModel

model = WhisperModel("large-v3-turbo", device="cuda", compute_type="float16")

def transcribe_stream(audio_chunk: bytes) -> str:
    # Audio chunk: 16kHz, 16-bit PCM, mono
    segments, info = model.transcribe(
        audio_chunk,
        language="en",
        beam_size=5,
        vad_filter=True,          # built-in silero VAD
        vad_parameters={
            "min_silence_duration_ms": 500,  # wait 500ms silence before finalizing
        },
        initial_prompt="Customer service call transcript:",  # domain priming
    )
    
    return " ".join(segment.text for segment in segments)
```

### VAD (Voice Activity Detection)

VAD classifies each audio frame as speech or silence. Critical for:
- Deciding when to send audio to ASR
- Turn detection in conversation (when is the user done speaking?)
- Removing silence from audio to reduce ASR compute

**Silero VAD** is the production standard: fast (~1ms per frame), accurate, runs on CPU.

```python
import torch

# Load once at startup
vad_model, utils = torch.hub.load(
    repo_or_dir='snakers4/silero-vad',
    model='silero_vad',
    force_reload=False,
)
(get_speech_timestamps, _, read_audio, *_) = utils

def detect_speech_boundaries(audio_path: str) -> list[dict]:
    audio = read_audio(audio_path, sampling_rate=16000)
    timestamps = get_speech_timestamps(
        audio, vad_model,
        threshold=0.5,              # speech probability threshold
        min_speech_duration_ms=250,
        min_silence_duration_ms=500,
        return_seconds=True,
    )
    return timestamps  # [{"start": 0.5, "end": 3.2}, {"start": 5.1, "end": 8.7}]
```

## TTS Internals

### Architecture Families

**Concatenative (legacy)**: Stitch together recorded phonemes. Sounds robotic. Never use.

**Statistical parametric (HMM-based, legacy)**: Generate speech parameters from text. Better but still robotic.

**Neural TTS (current standard)**: End-to-end neural networks that generate natural-sounding audio.

Neural TTS systems have two components:
1. **Acoustic model**: Text → mel spectrogram (frequency representation)
2. **Vocoder**: Mel spectrogram → waveform

```
Text: "Hello, how can I help you?"
    │
    ▼
[Text Normalization]    "Hello, how can I help you?"
                        → phoneme sequence
    │
    ▼
[Acoustic Model]        phonemes → mel spectrogram
(FastSpeech2, VITS, etc.)
    │
    ▼
[Vocoder]               mel spectrogram → PCM waveform
(HiFi-GAN, WaveGlow)
    │
    ▼
Audio output
```

### Key TTS Models

**VITS (2021)**: End-to-end model that learns both acoustic model and vocoder jointly. Very natural output, fast inference. Open source.

**FastSpeech 2**: Non-autoregressive acoustic model — generates all mel frames in parallel rather than step-by-step. Much faster than autoregressive models. Used in production systems.

**Coqui TTS**: Open-source library wrapping multiple models (FastSpeech2, VITS, YourTTS). Best starting point for self-hosted TTS.

**ElevenLabs**: Best cloud TTS API for naturalness and voice cloning. High latency (~300ms TTFB). Expensive.

**OpenAI TTS**: Good quality, simple API, 6 voices. 300ms typical first audio chunk latency.

**Deepgram Aura**: Low latency (~100ms TTFB), good quality, streaming support. Better for real-time conversation.

**Sarvam AI**: Worth noting for your target companies — provides both ASR and TTS optimized for Indian languages.

### TTS Latency Metrics

| Metric | Definition | Acceptable |
|--------|-----------|-----------|
| TTFB (Time To First Byte) | Time to first audio chunk | < 200ms |
| RTF (Real-Time Factor) | Generation time / audio duration | < 0.5 |
| Total latency | TTFB + streaming delivery | < 500ms perceived |

TTFB matters more than RTF for perceived responsiveness. Stream audio as it generates — don't wait for the full response.

## Streaming TTS

For conversational AI, stream audio chunks as they generate:

```python
import httpx, asyncio

async def stream_tts(text: str, voice_id: str) -> AsyncIterator[bytes]:
    async with httpx.AsyncClient() as client:
        async with client.stream(
            "POST",
            "https://api.elevenlabs.io/v1/text-to-speech/{voice_id}/stream",
            headers={"xi-api-key": API_KEY},
            json={
                "text": text,
                "model_id": "eleven_turbo_v2",     # lower latency model
                "voice_settings": {"stability": 0.5, "similarity_boost": 0.75},
                "optimize_streaming_latency": 4,   # 0-4, higher = lower latency
            },
            timeout=30,
        ) as response:
            async for chunk in response.aiter_bytes(chunk_size=4096):
                yield chunk   # MP3 chunks, stream to client

# Usage: start playing audio before LLM has finished generating
async def respond_with_voice(llm_stream, websocket):
    tts_buffer = ""
    
    async for token in llm_stream:
        tts_buffer += token
        
        # Flush to TTS when we have a complete sentence
        if token.endswith(('.', '!', '?', '\n')) and len(tts_buffer) > 20:
            async for audio_chunk in stream_tts(tts_buffer, voice_id="rachel"):
                await websocket.send_bytes(audio_chunk)
            tts_buffer = ""
    
    # Flush remaining
    if tts_buffer.strip():
        async for audio_chunk in stream_tts(tts_buffer, voice_id="rachel"):
            await websocket.send_bytes(audio_chunk)
```

**Sentence-flush pattern**: Don't wait for the entire LLM response before starting TTS. Flush each complete sentence to TTS immediately. Reduces perceived latency by 1–3 seconds.

## Full Real-Time Conversation Pipeline

```
User audio (WebSocket/WebRTC)
        │
        ▼
[VAD]  — detect end of utterance
        │
        ▼
[ASR]  — Whisper large-v3-turbo (faster-whisper)
        │
        ▼
[LLM]  — streaming generation with sentence detection
        │
        ├── sentence 1 ready → [TTS] → audio chunk stream → user
        ├── sentence 2 ready → [TTS] → audio chunk stream → user
        └── ...
```

### Latency Budget for Real-Time Voice

```
Total perceived latency budget: 800ms (feels responsive)

Breakdown:
├── VAD (end of utterance detection):   0ms (concurrent with speaking)
├── ASR (transcription):                150–300ms
├── LLM (first token):                  200–400ms
├── TTS (first audio chunk):            100–200ms
├── Network (both directions):          50–100ms
│                                       ──────────
└── Total:                              500–1000ms

Optimization levers:
- ASR: faster-whisper on GPU reduces to 150ms
- LLM: smaller model or streaming from first token
- TTS: Deepgram Aura TTFB < 100ms
- Architecture: parallelize — start LLM while ASR is in last frames
```

## Speaker Diarization

Identifies who is speaking when. Critical for call center applications (Observe.AI, Skit).

```python
from pyannote.audio import Pipeline

# Load diarization pipeline
pipeline = Pipeline.from_pretrained(
    "pyannote/speaker-diarization-3.1",
    use_auth_token="HF_TOKEN"
)

def diarize(audio_path: str) -> list[dict]:
    diarization = pipeline(audio_path, num_speakers=2)  # agent + customer
    
    segments = []
    for turn, _, speaker in diarization.itertracks(yield_label=True):
        segments.append({
            "speaker": speaker,
            "start": turn.start,
            "end": turn.end,
        })
    return segments
```

**Combined ASR + diarization** (word-level speaker attribution):

```python
from pyannote.audio import Pipeline
from faster_whisper import WhisperModel

def transcribe_with_speakers(audio_path: str) -> list[dict]:
    # 1. Transcribe with word timestamps
    model = WhisperModel("large-v3-turbo", device="cuda")
    segments, _ = model.transcribe(audio_path, word_timestamps=True)
    words = [word for segment in segments for word in segment.words]
    
    # 2. Diarize
    diarization = diarize(audio_path)
    
    # 3. Align words to speakers
    result = []
    for word in words:
        speaker = find_speaker_at_time(word.start, diarization)
        result.append({
            "word": word.word,
            "start": word.start,
            "end": word.end,
            "speaker": speaker,
        })
    return result
```

## Indian Language ASR

For your target companies (Gnani, Skit, Sarvam, Yellow.ai), Indian language support is a key differentiator.

**Whisper performance on Indian languages**: Whisper large-v3 covers Hindi, Bengali, Tamil, Telugu, Kannada, Malayalam, Gujarati. Quality varies — Hindi is good, smaller languages are weaker.

**IndicWhisper**: Fine-tuned Whisper models for Indian languages from AI4Bharat. Better accuracy than vanilla Whisper on Indian languages.

**Sarvam Saarika**: Sarvam AI's ASR model specifically for Indian languages + Indian English accents. Strong candidate for your target companies.

**Conformer-based models** (NVIDIA NeMo): Conformer combines convolutional local features with global Transformer attention. State of the art for many languages. NVIDIA NeMo Parakeet-CTC-0.6B is a strong English model.

```python
# AI4Bharat IndicWhisper
from transformers import pipeline

asr = pipeline(
    "automatic-speech-recognition",
    model="ai4bharat/indicwav2vec-hindi",
    device=0,
)
result = asr("hindi_audio.wav")
print(result["text"])  # Hindi transcript
```

## Production Architecture for Voice AI

### Call Center Deployment (Observe.AI / Skit pattern)

```
Telephony Layer (Twilio / Vonage)
        │ (WebSocket audio stream)
        ▼
Media Server (processes RTP audio)
        │ (16kHz PCM chunks, 20ms frames)
        ▼
ASR Service (faster-whisper cluster)
        │ (text + timestamps)
        ▼
NLU / Intent Classification
        │
        ├── known_intent → rule-based response
        └── unknown/complex → LLM pipeline
                │
                ▼
        LLM Response (streaming)
                │
                ▼
        TTS Service
                │ (audio stream)
                ▼
Telephony Layer (back to caller)
```

### Key Infrastructure Decisions

**WebRTC vs WebSocket for audio**: WebRTC has built-in echo cancellation, jitter buffer, and packet loss recovery — use for browser-based voice. WebSocket is simpler for server-to-server or telephony integration.

**Audio format**: 16kHz, 16-bit PCM mono is the universal standard for ASR input. Always resample to this before passing to models. Storing as FLAC or Opus for cost; decode before inference.

**GPU allocation**: ASR and TTS can share a GPU if batched carefully. Prioritize low-latency inference over throughput for real-time conversation. Use dedicated GPUs for batch processing of call recordings (asynchronous quality analysis).

## Revision Anchors

- **ASR pipeline**: Audio → mel spectrogram → Transformer encoder → decoder → text. Whisper is the dominant model; `faster-whisper` for production.
- **WER**: `(Sub + Del + Ins) / Reference words`. Real-world call center: 10–25% is realistic.
- **Streaming pattern**: VAD detects end of utterance → chunk to ASR → LLM streaming → sentence-flush to TTS → audio chunks back. Total latency target: < 800ms.
- **Sentence-flush trick**: Don't wait for full LLM response. TTS each sentence as it completes. Reduces perceived latency 1–3s.
- **Indian language**: IndicWhisper (AI4Bharat) or Sarvam Saarika for better accuracy than vanilla Whisper.
- **TTFB matters more than RTF** for real-time voice: first audio chunk latency determines perceived responsiveness.
