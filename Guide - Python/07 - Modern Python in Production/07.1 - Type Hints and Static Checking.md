# Type Hints and Static Checking

#python #typing #mypy #pyright

> **In one line:** Type hints are annotations that Python ignores at runtime but tools read: mypy and pyright catch bugs before you run the code, editors autocomplete, and libraries like Pydantic and FastAPI turn the same hints into runtime validation and API schemas.

---

## The Idea

```python
def find_user(user_id: int, *, active_only: bool = True) -> User | None:
    ...
```

At runtime, Python stores these in `find_user.__annotations__` and does **nothing else**. Passing a string still works, until it breaks somewhere else. A **static type checker** reads the whole program and reports the mismatch before it runs:

```
error: Argument 1 to "find_user" has incompatible type "str"; expected "int"
error: Item "None" of "User | None" has no attribute "email"
```

That second error is the important one. "Forgot to handle `None`" is probably the most common runtime error in Python services, and the checker catches it every time.

## The Vocabulary

```python
from collections.abc import Callable, Iterable, Iterator, Mapping, Sequence, Awaitable
from typing import Any, Literal, TypedDict, Protocol, TypeAlias, Final, ClassVar, Self

x: int = 1
names: list[str] = []                       # built-in generics (3.9+)
scores: dict[str, float] = {}
pair: tuple[int, str] = (1, "a")
many: tuple[int, ...] = (1, 2, 3)           # variable-length tuple
maybe: str | None = None                    # Optional[str], 3.10+ syntax
mode: Literal["r", "w"] = "r"               # only these values
handler: Callable[[Request], Awaitable[Response]]
MAX_RETRIES: Final = 3                      # cannot be reassigned
UserId: TypeAlias = int                     # or: type UserId = int  (3.12 syntax)
```

### Accept general types, return specific ones

```python
def total(prices: Iterable[Decimal]) -> Decimal: ...     # accepts list, tuple, generator, set
def tags_of(post: Post) -> list[str]: ...                # promises a concrete list
def render(ctx: Mapping[str, Any]) -> str: ...           # read-only view: callers know you won't mutate
```

`Iterable` means "I loop once", `Sequence` means "I index or loop again", `Mapping` means "I read", `MutableMapping` means "I may write". Choosing correctly documents behaviour and catches the double-iteration bug from [[04.3 - Iterables and Iterators]].

## Narrowing

The checker follows your control flow:

```python
def email_domain(user: User | None) -> str:
    if user is None:
        raise NotFound()
    return user.email.split("@")[1]        # here, user is User

def handle(x: int | str) -> None:
    if isinstance(x, int):
        ...                                 # x: int
    else:
        ...                                 # x: str
```

For your own checks, `TypeGuard` / `TypeIs` (3.13) teach the checker what a predicate proves. For "this can never happen", `assert_never` gives exhaustiveness checks ([[06.6 - Enums]]).

## Generics

```python
from typing import TypeVar, Generic

T = TypeVar("T")

def first(items: Sequence[T]) -> T | None:
    return items[0] if items else None

first([1, 2])        # int | None
first(["a"])         # str | None

# 3.12+ syntax: no TypeVar boilerplate
def first[T](items: Sequence[T]) -> T | None: ...

class Page[T]:
    def __init__(self, items: list[T], next_cursor: str | None):
        self.items, self.next_cursor = items, next_cursor

class Repository[T, ID]:
    async def get(self, id: ID) -> T | None: ...
    async def add(self, entity: T) -> None: ...
```

`ParamSpec` preserves a wrapped function's signature through decorators ([[02.1 - Parameters and Arguments]]). `Self` types methods that return their own class (builders, `from_dict` classmethods).

## Structural Types: Protocol and TypedDict

```python
class SupportsClose(Protocol):
    def close(self) -> None: ...

class UserPayload(TypedDict):
    id: int
    email: str
    nickname: NotRequired[str]

def parse(raw: UserPayload) -> User: ...
```

- `Protocol`: any object with the right methods matches, no inheritance needed ([[06.3 - Inheritance Composition and Protocols]]).
- `TypedDict`: a typed shape for plain dicts. Good for JSON that you do not want to wrap in classes, and for `**kwargs` (`Unpack[Options]`). **No runtime validation.** For data from outside, use Pydantic.

## Any: The Escape Hatch

`Any` turns checking off for that value, and it spreads: anything derived from an `Any` is also unchecked. Untyped third-party libraries return `Any`. Use `object` when you mean "anything, but make me check before using it", and use `cast()` sparingly, as a visible "trust me" marker.

## Choosing and Running a Checker

| | mypy | pyright (basedpyright) |
|---|---|---|
| Written in | Python | TypeScript (fast) |
| Editor integration | Via plugins | Powers Pylance in VS Code |
| Plugins | Yes: Django, SQLAlchemy and Pydantic plugins exist | No plugins; relies on standards like `dataclass_transform` |
| Default strictness | Lenient | Moderate |

Either is fine. Pick one, run it in CI, and ratchet up strictness:

```toml
[tool.mypy]
python_version = "3.12"
strict = true                        # start here for new projects
plugins = ["pydantic.mypy"]

[[tool.mypy.overrides]]
module = ["legacy.*"]
ignore_errors = true                 # adopt gradually in older codebases
```

New tools are appearing (Astral's `ty`, Meta's `pyrefly`), written in Rust and much faster. The type system they check is the same.

## Annotations at Runtime

Libraries read hints at runtime with `typing.get_type_hints()` and `inspect`:

| Library | Uses hints to |
|---|---|
| Pydantic | Build validators and JSON Schema ([[07.3 - Pydantic Fundamentals]]) |
| FastAPI | Decide what is a path param, query param or body, and generate OpenAPI |
| dataclasses | Discover fields ([[07.2 - Dataclasses]]) |
| SQLAlchemy 2.0 | `Mapped[int]` defines columns |
| Typer | Build CLI arguments |

`Annotated[T, metadata]` attaches extra information without changing the type: `Annotated[int, Field(gt=0)]`, `Annotated[Session, Depends(get_db)]`.

⚠️ `from __future__ import annotations` turns every annotation into a string, which runtime readers must then resolve. That breaks some patterns (types defined inside functions). Python 3.14 makes annotations lazily evaluated by default (PEP 649/749), which fixes most of the forward-reference pain without strings.

## Codebase

**Repos:** `python/typeshed`, `python/cpython`

**Question to answer:** Where does mypy get the types for `json.loads` and `dict.get`, and what does `typing.get_type_hints` do that `__annotations__` does not?

**Read, in order:**

1. typeshed `stdlib/json/__init__.pyi` and `stdlib/builtins.pyi` (search `class dict` and its `get` overloads). Stubs are how the stdlib is typed.
2. CPython `Lib/typing.py` — `get_type_hints()` (resolving string annotations, `Annotated` handling) and `TypedDict`'s `_TypedDictMeta`
3. Your favourite library's `py.typed` marker and one of its `.pyi` stubs (or inline hints), e.g. `httpx/_client.py` signatures

**Size:** 1 session.
