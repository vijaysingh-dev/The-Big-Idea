# Composite Pattern

## At a Glance

|||
|---|---|
|**Type**|Structural|
|**Intent**|Compose objects into tree structures. Let clients treat individual objects and compositions uniformly|
|**Frequency in Backend**|★★★☆☆ — permission trees, category hierarchies, rule engines|

---

## The Problem It Solves

Tree-shaped data where leaves and branches need the same operations. Without Composite, every operation needs `if isinstance(node, Leaf)` checks.

---

## Full Backend Example: Permission System

```python
# permissions.py
from abc import ABC, abstractmethod
from typing import List

class Permission(ABC):
    """Component — uniform interface for leaves and composites."""
    
    @abstractmethod
    def allows(self, action: str, resource: str, context: dict) -> bool: pass
    
    @abstractmethod
    def name(self) -> str: pass


class SimplePermission(Permission):
    """Leaf — single permission check."""
    
    def __init__(self, action: str, resource: str):
        self._action = action
        self._resource = resource
    
    def allows(self, action: str, resource: str, context: dict) -> bool:
        action_match = self._action == "*" or self._action == action
        resource_match = self._resource == "*" or self._resource == resource
        return action_match and resource_match
    
    def name(self): return f"{self._action}:{self._resource}"


class ConditionalPermission(Permission):
    """Leaf with context-based condition."""
    
    def __init__(self, action: str, resource: str, condition):
        self._action = action
        self._resource = resource
        self._condition = condition  # callable(context) -> bool
    
    def allows(self, action, resource, context):
        basic = self._action == action and self._resource == resource
        return basic and self._condition(context)
    
    def name(self): return f"{self._action}:{self._resource}[conditional]"


class PermissionGroup(Permission):
    """Composite — contains other permissions (including groups)."""
    
    def __init__(self, group_name: str, require_all: bool = False):
        self._name = group_name
        self._permissions: List[Permission] = []
        self._require_all = require_all  # AND vs OR
    
    def add(self, permission: Permission) -> "PermissionGroup":
        self._permissions.append(permission)
        return self
    
    def remove(self, permission: Permission):
        self._permissions.remove(permission)
    
    def allows(self, action: str, resource: str, context: dict) -> bool:
        if not self._permissions:
            return False
        
        if self._require_all:
            return all(p.allows(action, resource, context) for p in self._permissions)
        else:
            return any(p.allows(action, resource, context) for p in self._permissions)
    
    def name(self): return self._group_name


# Build permission trees
admin_permissions = (PermissionGroup("admin")
    .add(SimplePermission("*", "*"))   # admins can do anything
)

editor_permissions = (PermissionGroup("editor")
    .add(SimplePermission("read", "*"))
    .add(SimplePermission("write", "articles"))
    .add(SimplePermission("write", "media"))
    .add(ConditionalPermission(
        "publish", "articles",
        condition=lambda ctx: ctx.get("article_reviewed") is True
    ))
)

viewer_permissions = (PermissionGroup("viewer")
    .add(SimplePermission("read", "articles"))
    .add(SimplePermission("read", "media"))
)

# Composite group — user has editor + some extra
user_perms = (PermissionGroup("user_123")
    .add(editor_permissions)                    # nested group
    .add(SimplePermission("manage", "profile")) # single permission
)

# Same interface works for leaf or composite
def check_access(permission: Permission, action: str, resource: str, context: dict):
    if not permission.allows(action, resource, context):
        raise PermissionDenied(f"Action '{action}' on '{resource}' not allowed")

check_access(user_perms, "write", "articles", {})      # allowed via editor group
check_access(user_perms, "publish", "articles", {"article_reviewed": True})  # conditional
```

## Other Backend Uses

|Use Case|Tree Structure|
|---|---|
|Product categories|Category → Subcategory → Product|
|Org chart|Department → Team → Employee|
|File system|Directory → Subdirectory → File|
|Rule engine|Rule group (AND/OR) → Individual rules|
|Menu system|Menu → Submenu → MenuItem|
|Price calculation|Total = sum(line items, each possibly composite)|

---

## Tradeoffs

|Pro|Con|
|---|---|
|Uniform treatment of leaves/composites|Can make design overly general|
|Easy to add new leaf/composite types|Hard to restrict what can be composed|
|Recursive operations are clean|Deep trees can cause stack overflow|
