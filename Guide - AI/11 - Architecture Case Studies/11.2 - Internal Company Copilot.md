# Architecture Case Study: Internal Company Copilot

## What's Different From Search

An enterprise search assistant answers factual questions from documents. A **company copilot** does more:

- Drafts documents, emails, reports
- Performs multi-step reasoning over company data
- Takes actions (create Jira ticket, draft Slack message)
- Remembers user context across sessions
- Integrates tightly with workflows

---

## Key Architectural Additions

### 1. Persistent User Context

```python
@dataclass
class UserContext:
    user_id: str
    name: str
    role: str              # "backend engineer", "product manager"
    team: str              # "platform", "payments"
    recent_projects: list  # last 5 projects worked on
    preferences: dict      # {"response_length": "concise", "code_examples": True}
    
# Injected at start of every conversation
def build_system_prompt(user: UserContext) -> str:
    return f"""You are a helpful assistant for {user.company}.
    
User context:
- Name: {user.name}
- Role: {user.role}, Team: {user.team}
- Recent projects: {', '.join(user.recent_projects)}

Adapt your responses to be relevant to their role and context."""
```

### 2. Action Tools

Beyond retrieval, the copilot can take actions:

```python
COPILOT_TOOLS = [
    {
        "name": "create_jira_ticket",
        "description": "Create a Jira issue. Use when user asks to create a ticket, task, or bug report.",
        "parameters": {"title": "string", "description": "string", "type": "Bug|Task|Story", "priority": "Low|Medium|High"}
    },
    {
        "name": "draft_slack_message",
        "description": "Draft a Slack message for a channel. Does NOT send — user reviews first.",
        "parameters": {"channel": "string", "message": "string"}
    },
    {
        "name": "search_internal_docs",
        "description": "Search company knowledge base",
        "parameters": {"query": "string", "source_filter": "confluence|github|drive|all"}
    },
    {
        "name": "get_my_open_tickets",
        "description": "Get list of Jira tickets assigned to the current user",
        "parameters": {}
    }
]
```

### 3. Conversation Memory

```python
class CopilotSession:
    def query(self, message: str, user_id: str, session_id: str) -> str:
        # Load persistent session history
        history = self.session_store.get(session_id)
        if not history:
            history = [{"role": "system", "content": build_system_prompt(get_user(user_id))}]
        
        history.append({"role": "user", "content": message})
        
        # Retrieve relevant context
        chunks = self.retrieve(message, user_id)
        history_with_context = inject_context(history, chunks)
        
        # Generate with tools
        response = self.llm.call(history_with_context, tools=COPILOT_TOOLS)
        
        # Handle tool calls
        if response.tool_calls:
            response = self.handle_tool_calls(response, history_with_context, user_id)
        
        # Persist updated history
        history.append({"role": "assistant", "content": response.content})
        self.session_store.set(session_id, history, ttl=86400)  # 24h
        
        return response.content
```

## Human-in-the-Loop for Destructive Actions

Never auto-execute write actions. Always show and confirm:

```python
def handle_tool_call(tool_name, args, user_id):
    if tool_name in WRITE_ACTIONS:  # create_ticket, send_email, etc.
        # Return preview, not execution
        return {
            "type": "action_preview",
            "tool": tool_name,
            "args": args,
            "preview": render_preview(tool_name, args),
            "confirmation_required": True
        }
    else:
        # Read actions execute immediately
        return execute_tool(tool_name, args, user_id)
```
