# Special Methods and the Data Model

#python #oop #dunder #data-model

> **In one line:** Python's syntax is a set of hooks. `len(x)` calls `x.__len__()`, `a + b` calls `a.__add__(b)`, `with` calls `__enter__`, and `if x:` calls `__bool__`. Implement the right dunder methods and your objects work with every built-in function and operator.

---

## The Idea

Python does not ask "is this a list?". It asks "does this object implement `__len__` and `__getitem__`?" That is the **data model**, and implementing it is how you make objects feel native.

| You write | Python calls |
|---|---|
| `repr(x)`, REPL display | `x.__repr__()` |
| `str(x)`, `print(x)`, f-string | `x.__str__()` (falls back to `__repr__`) |
| `f"{x:.2f}"` | `x.__format__(".2f")` |
| `len(x)` | `x.__len__()` |
| `x[k]`, `x[k] = v`, `del x[k]` | `__getitem__`, `__setitem__`, `__delitem__` |
| `k in x` | `__contains__` (falls back to iterating) |
| `for i in x` | `__iter__` ([[04.3 - Iterables and Iterators]]) |
| `if x:` | `__bool__`, else `__len__ != 0`, else `True` |
| `x()` | `__call__` |
| `with x:` | `__enter__`, `__exit__` ([[04.6 - Context Managers]]) |
| `a == b`, `a < b` | `__eq__`, `__lt__`, ... |
| `a + b`, `a * b`, `-a`, `abs(a)` | `__add__`, `__mul__`, `__neg__`, `__abs__` |
| `hash(x)` | `__hash__` ([[05.2 - Sets and Hashing Your Own Classes]]) |
| `await x` | `__await__` |

Special methods are looked up **on the type**, not the instance. Assigning `obj.__len__ = ...` on an instance does nothing for `len(obj)`.

## `__repr__` and `__str__`

```python
class Money:
    def __init__(self, amount, currency):
        self.amount, self.currency = amount, currency
    def __repr__(self):
        return f"Money({self.amount!r}, {self.currency!r})"    # unambiguous; ideally eval-able
    def __str__(self):
        return f"{self.amount} {self.currency}"                # for humans
```

**Always write `__repr__`.** It appears in logs, tracebacks, debuggers, test failure messages and the REPL. `<app.models.Money object at 0x7f...>` in a 3 a.m. log line helps nobody. Dataclasses and Pydantic generate a good one for you.

## Comparisons

```python
from functools import total_ordering

@total_ordering
class Version:
    def __init__(self, s):
        self.parts = tuple(int(p) for p in s.split("."))
    def __eq__(self, other):
        if not isinstance(other, Version):
            return NotImplemented
        return self.parts == other.parts
    def __lt__(self, other):
        if not isinstance(other, Version):
            return NotImplemented
        return self.parts < other.parts
    def __hash__(self):
        return hash(self.parts)

sorted([Version("1.10.0"), Version("1.9.3")])   # 1.9.3 first — not string order
```

- `@total_ordering` derives `<=`, `>`, `>=` from `__eq__` and `__lt__`.
- **Return `NotImplemented` (not `False`, not raise) for unknown types.** Python then tries the reflected operation on the other operand, and if that also returns `NotImplemented`, `==` falls back to identity and `<` raises `TypeError`. Returning `False` breaks that protocol.

## Arithmetic Operators

```python
class Vector:
    def __init__(self, x, y): self.x, self.y = x, y
    def __add__(self, other):
        if not isinstance(other, Vector):
            return NotImplemented
        return Vector(self.x + other.x, self.y + other.y)
    def __mul__(self, k):                     # v * 3
        if not isinstance(k, (int, float)):
            return NotImplemented
        return Vector(self.x * k, self.y * k)
    __rmul__ = __mul__                        # 3 * v → int.__mul__ fails → Vector.__rmul__
    def __abs__(self):
        return (self.x ** 2 + self.y ** 2) ** 0.5
    def __bool__(self):
        return bool(self.x or self.y)
```

| Method | Called for | When |
|---|---|---|
| `__add__` | `a + b` | First try |
| `__radd__` | `a + b` | If `a.__add__` returned `NotImplemented`: tried on `b` |
| `__iadd__` | `a += b` | If missing, falls back to `a = a + b` |

`sum(vectors, Vector(0, 0))` works once `__add__` exists. `sum()` starts from `0`, so either pass a start value or handle `0` in `__radd__`.

Use operator overloading only when the meaning is obvious: `Money + Money`, `Path / "file"`, `datetime - timedelta`, SQLAlchemy's `User.age > 30` (which builds a SQL expression). Do not make `+` send an email.

## Containers

```python
class Inventory:
    def __init__(self): self._items = {}
    def __len__(self): return len(self._items)
    def __getitem__(self, sku): return self._items[sku]
    def __setitem__(self, sku, qty):
        if qty < 0: raise ValueError("negative quantity")
        self._items[sku] = qty
    def __delitem__(self, sku): del self._items[sku]
    def __contains__(self, sku): return sku in self._items
    def __iter__(self): return iter(self._items)
```

Or inherit from `collections.abc.MutableMapping`: implement the five abstract methods and get `get`, `pop`, `update`, `items`, `keys`, `setdefault`, `__eq__` and more for free.

## `__bool__` Pitfalls

```python
if not results:        # True for [], {}, "", 0, None, and any object whose __len__ is 0
```

⚠️ An ORM object or a custom collection that defines `__len__` is **falsy when empty**. `if user_list:` when you meant `if user_list is not None:` is a real bug, for example when a valid "zero items" response is treated as missing. Say `is None` when you mean `None`.

## `__call__`, `__getattr__` and Friends

- `__call__`: stateful callables, decorator classes, strategy objects ([[02.2 - First-Class Functions]]).
- `__getattr__`: fallback attribute lookup, for proxies and lazy loading ([[06.1 - Classes and Instances]]).
- `__init_subclass__` and `__set_name__`: hooks for class creation ([[06.8 - Metaprogramming]], [[06.5 - Descriptors]]).
- `__class_getitem__`: makes `MyType[int]` work for generics.
