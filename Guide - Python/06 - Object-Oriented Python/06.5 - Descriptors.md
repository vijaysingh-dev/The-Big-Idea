# Descriptors

#python #oop #descriptors #advanced

> **In one line:** A descriptor is an object on a class that controls what happens when an attribute is read, written or deleted through instances, via `__get__`, `__set__` and `__delete__`. Methods, `property`, `classmethod`, `__slots__`, ORM columns and many field systems are descriptors.

---

## The Idea

Normally `obj.x` finds a value. If the value found **on the class** has a `__get__` method, Python calls it instead and returns its result. That hook is the descriptor protocol.

```python
class Loud:
    def __get__(self, obj, objtype=None):
        return "computed!"

class C:
    x = Loud()

C().x       # 'computed!' — Loud.__get__(descriptor, instance, C)
C.x         # 'computed!' — __get__(descriptor, None, C)
```

| Method | Called on | Signature |
|---|---|---|
| `__get__` | `obj.attr`, `Cls.attr` | `(self, obj, objtype)` — `obj` is `None` for class access |
| `__set__` | `obj.attr = v` | `(self, obj, value)` |
| `__delete__` | `del obj.attr` | `(self, obj)` |
| `__set_name__` (3.6+) | When the owning class is created | `(self, owner, name)` — tells the descriptor its attribute name |

---

## Data vs Non-Data Descriptors

This distinction decides lookup order:

| Kind | Defines | Priority vs instance `__dict__` | Examples |
|---|---|---|---|
| **Data descriptor** | `__set__` or `__delete__` (and usually `__get__`) | **Wins** over the instance dict | `property`, slots, ORM columns, validated fields |
| **Non-data descriptor** | Only `__get__` | **Loses** to the instance dict | Functions (methods), `classmethod`, `staticmethod`, `cached_property` |

Full lookup for `obj.attr` (this is `object.__getattribute__`):

```
1. Look up attr on type(obj).__mro__ → found `d`?
2.   If `d` is a DATA descriptor → return d.__get__(obj, type(obj))
3. If attr in obj.__dict__ → return it
4. If `d` was found:
5.   if it is a non-data descriptor → return d.__get__(obj, type(obj))
6.   else → return d (a plain class attribute)
7. __getattr__ fallback, else AttributeError
```

That order explains several things at once:

- **Methods can be shadowed** by instance attributes (`obj.save = 5` hides the method), because functions are non-data descriptors.
- **`property` cannot be shadowed**, because it is a data descriptor. Assigning to a property without a setter raises `AttributeError`.
- **`cached_property` works** by storing the computed value in `obj.__dict__` under the same name. Next time, step 3 finds it and the descriptor is never called again.

## Methods Are Descriptors

```python
class A:
    def f(self): ...

A.__dict__["f"]                    # <function A.f> — a plain function
A.__dict__["f"].__get__(a, A)      # <bound method A.f of a> — what a.f gives you
```

`function.__get__` returns a bound method. `classmethod.__get__` binds the class instead. `staticmethod.__get__` returns the underlying function untouched. That is the entire mechanism behind [[06.1 - Classes and Instances#Methods and Binding]].

It also explains the bug noted in [[02.4 - Decorators]]: a decorator implemented as a class instance without `__get__` does not bind `self` when used on a method.

## Writing a Validated Field

```python
class Field:
    def __init__(self, *, type_, min_value=None):
        self.type_, self.min_value = type_, min_value

    def __set_name__(self, owner, name):
        self.public = name
        self.private = "_" + name

    def __get__(self, obj, objtype=None):
        if obj is None:
            return self                       # class access returns the descriptor itself
        return getattr(obj, self.private)

    def __set__(self, obj, value):
        if not isinstance(value, self.type_):
            raise TypeError(f"{self.public} must be {self.type_.__name__}")
        if self.min_value is not None and value < self.min_value:
            raise ValueError(f"{self.public} must be >= {self.min_value}")
        setattr(obj, self.private, value)

class Order:
    quantity = Field(type_=int, min_value=1)
    price = Field(type_=float, min_value=0)

    def __init__(self, quantity, price):
        self.quantity = quantity              # validated
        self.price = price

Order(0, 9.99)   # ValueError: quantity must be >= 1
```

Key details:

- **Store per-instance data on the instance**, not on the descriptor. The descriptor is shared by all instances; `self.value = value` inside `__set__` would make every `Order` share one quantity.
- `__set_name__` removes the need to repeat the name (`Field("quantity")`).
- Returning `self` when `obj is None` keeps class-level introspection (`Order.quantity.min_value`) working.

## Where You Meet Descriptors in Real Code

| Library | Descriptor |
|---|---|
| Python itself | Functions, `property`, `classmethod`, `staticmethod`, slots, `cached_property` |
| SQLAlchemy | `Mapped[...]` columns are `InstrumentedAttribute`s. `User.name == "x"` (class access) builds SQL; `user.name` (instance access) returns the value and tracks changes for the unit of work. |
| Django ORM | `ForeignKeyDeferredAttribute`, related-object descriptors that lazy-load on access (the N+1 source in [[06.6 - The N+1 Problem and DataLoader]]) |
| attrs, dataclasses | Field metadata collected at class creation; `__set_name__` hooks |
| Pydantic | Mostly metaclass work rather than per-field descriptors, but `@computed_field` and private attributes use descriptor-like machinery |

💡 The SQLAlchemy example is the best demonstration of `obj is None`: the **same** attribute returns a SQL expression on the class and a value on an instance.
