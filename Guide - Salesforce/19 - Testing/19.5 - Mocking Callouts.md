# Mocking Callouts

## The rule

**A callout in a test throws** unless a mock is registered.

```
System.CalloutException: Methods defined as TestMethod do not support Web service callouts
```

That is deliberate — tests must not depend on an external system's availability, and must not send real requests.

## HttpCalloutMock

```java
@IsTest
public class ErpSuccessMock implements HttpCalloutMock {

    private final Integer statusCode;
    private final String body;

    public ErpSuccessMock(Integer statusCode, String body) {
        this.statusCode = statusCode;
        this.body = body;
    }

    public HttpResponse respond(HttpRequest request) {
        HttpResponse response = new HttpResponse();
        response.setStatusCode(statusCode);
        response.setHeader('Content-Type', 'application/json');
        response.setBody(body);
        return response;
    }
}
```

```java
@IsTest
static void confirmationNumberIsStoredOnTheClaim() {
    Test.setMock(HttpCalloutMock.class,
        new ErpSuccessMock(200, '{"confirmationNumber":"ERP-4471"}'));

    Warranty_Claim__c claim = TestDataFactory.createClaim();

    Test.startTest();
    ClaimSubmissionService.submit(new Set<Id>{ claim.Id });
    Test.stopTest();

    Warranty_Claim__c refreshed = [
        SELECT ERP_Confirmation__c FROM Warranty_Claim__c WHERE Id = :claim.Id
    ];
    Assert.areEqual('ERP-4471', refreshed.ERP_Confirmation__c);
}
```

**`Test.setMock` must be called before the callout**, and it applies to every callout in the test.

## Verifying the request

A mock that only returns a response tests half the code. Capturing the request tests the other half.

```java
@IsTest
public class RequestCapturingMock implements HttpCalloutMock {

    public HttpRequest capturedRequest;
    private final HttpResponse response;

    public RequestCapturingMock(Integer statusCode, String body) {
        response = new HttpResponse();
        response.setStatusCode(statusCode);
        response.setBody(body);
    }

    public HttpResponse respond(HttpRequest request) {
        // keeping the request lets the test assert on what was actually sent
        capturedRequest = request;
        return response;
    }
}
```

```java
@IsTest
static void submissionSendsTheCorrectPayloadAndIdempotencyKey() {
    RequestCapturingMock mock = new RequestCapturingMock(201, '{"confirmationNumber":"ERP-1"}');
    Test.setMock(HttpCalloutMock.class, mock);

    Warranty_Claim__c claim = TestDataFactory.createClaim(150000);

    Test.startTest();
    ClaimSubmissionService.submit(new Set<Id>{ claim.Id });
    Test.stopTest();

    Assert.areEqual('POST', mock.capturedRequest.getMethod());
    Assert.isTrue(mock.capturedRequest.getEndpoint().contains('/api/v2/claims'),
        'Endpoint was ' + mock.capturedRequest.getEndpoint());
    Assert.isNotNull(mock.capturedRequest.getHeader('Idempotency-Key'),
        'A retry-safe request needs an idempotency key');

    Map<String, Object> body = (Map<String, Object>)
        JSON.deserializeUntyped(mock.capturedRequest.getBody());
    Assert.areEqual(150000, body.get('amount'));
}
```

**Asserting on the request is frequently more valuable than asserting on the response handling**, because a malformed request is the failure the external team will report and the one hardest to diagnose after the fact.

## Several endpoints in one test

```java
@IsTest
public class MultiEndpointMock implements HttpCalloutMock {

    private final Map<String, HttpResponse> responsesByFragment =
        new Map<String, HttpResponse>();

    public MultiEndpointMock add(String pathFragment, Integer status, String body) {
        HttpResponse response = new HttpResponse();
        response.setStatusCode(status);
        response.setBody(body);
        responsesByFragment.put(pathFragment, response);
        return this;
    }

    public HttpResponse respond(HttpRequest request) {
        for (String fragment : responsesByFragment.keySet()) {
            if (request.getEndpoint().contains(fragment)) {
                return responsesByFragment.get(fragment);
            }
        }
        // failing loudly beats returning a default the test did not intend
        throw new CalloutException('No mock configured for ' + request.getEndpoint());
    }
}
```

```java
Test.setMock(HttpCalloutMock.class, new MultiEndpointMock()
    .add('/api/coverage', 200, '{"limit":500000}')
    .add('/api/claims', 201, '{"confirmationNumber":"ERP-1"}')
    .add('/api/inventory', 404, '{"error":"not found"}'));
```

**Throwing on an unmatched endpoint is deliberate.** A test that silently hits an unmocked endpoint and receives a default response is testing something other than what it claims.

## Sequenced responses

For retry logic, where the same endpoint must fail then succeed:

```java
@IsTest
public class SequencedMock implements HttpCalloutMock {

    private final List<HttpResponse> responses;
    private Integer callIndex = 0;
    public Integer callCount { get { return callIndex; } }

    public SequencedMock(List<HttpResponse> responses) {
        this.responses = responses;
    }

    public HttpResponse respond(HttpRequest request) {
        // each call advances, so a retry sees the next scripted response
        HttpResponse response = responses[Math.min(callIndex, responses.size() - 1)];
        callIndex++;
        return response;
    }
}
```

```java
@IsTest
static void aTransientFailureIsRetriedAndSucceeds() {
    Test.setMock(HttpCalloutMock.class, new SequencedMock(new List<HttpResponse>{
        buildResponse(503, '{"error":"unavailable"}'),
        buildResponse(200, '{"confirmationNumber":"ERP-1"}')
    }));

    Test.startTest();
    ClaimSubmissionService.submitWithRetry(claimIds);
    Test.stopTest();

    Assert.areEqual('Synced', refresh(claim).ERP_Sync_Status__c);
}
```

**Retry across async boundaries cannot be tested this way**, since only one chain level runs. Testing the retry *decision* separately is the compensation. See [[12.6 - Transaction Finalizers]].

## Static resource mocks

For a large realistic payload, keeping it in a static resource beats embedding it in a string.

```java
StaticResourceCalloutMock mock = new StaticResourceCalloutMock();
mock.setStaticResource('ErpClaimResponse');
mock.setStatusCode(200);
mock.setHeader('Content-Type', 'application/json');

Test.setMock(HttpCalloutMock.class, mock);
```

Useful when the response is a few hundred lines of realistic JSON, and it makes the fixture reusable across tests.

`MultiStaticResourceCalloutMock` maps endpoints to different resources:

```java
MultiStaticResourceCalloutMock mock = new MultiStaticResourceCalloutMock();
mock.setStaticResource('https://erp.northwind.com/api/coverage', 'CoverageResponse');
mock.setStaticResource('https://erp.northwind.com/api/claims', 'ClaimResponse');
```

The endpoint match is exact, which makes it awkward when the URL carries query parameters — the hand-written fragment-matching mock is more flexible.

## The failure paths

The paths that actually run in production, and the ones most often untested.

```java
@IsTest
static void aServerErrorMarksTheClaimAsFailed() {
    Test.setMock(HttpCalloutMock.class, new ErpSuccessMock(500, '{"error":"internal"}'));

    Test.startTest();
    ClaimSubmissionService.submit(new Set<Id>{ claim.Id });
    Test.stopTest();

    Assert.areEqual('Failed', refresh(claim).ERP_Sync_Status__c);
    Assert.areEqual(1, [SELECT COUNT() FROM Integration_Log__c],
        'A failure should be logged');
}
```

**Simulating a timeout** needs a mock that throws:

```java
@IsTest
public class TimeoutMock implements HttpCalloutMock {
    public HttpResponse respond(HttpRequest request) {
        // a CalloutException is what a genuine timeout produces
        throw new CalloutException('Read timed out');
    }
}
```

**Malformed responses** are worth one test each:

```java
@IsTest
static void malformedJsonIsHandledGracefully() {
    Test.setMock(HttpCalloutMock.class, new ErpSuccessMock(200, 'not json at all'));

    Test.startTest();
    ClaimSubmissionService.submit(new Set<Id>{ claim.Id });
    Test.stopTest();

    Assert.areEqual('Failed', refresh(claim).ERP_Sync_Status__c,
        'A malformed response should be treated as a failure, not an exception');
}
```

The cases worth covering: 200 with an unexpected shape, 400, 401, 404, 500, 503, and a timeout. Each exercises a different branch of the error classification. See [[13.17 - Error Handling, Retries and Idempotency]].

## Async callouts

```java
@IsTest
static void theQueueableCallsOutAndUpdatesTheClaim() {
    Test.setMock(HttpCalloutMock.class, new ErpSuccessMock(200, '{"confirmationNumber":"ERP-1"}'));

    Warranty_Claim__c claim = TestDataFactory.createClaim();

    Test.startTest();
    System.enqueueJob(new ErpSyncQueueable(new Set<Id>{ claim.Id }));
    Test.stopTest();   // the job, and its callout, run here

    Assert.areEqual('ERP-1', refresh(claim).ERP_Confirmation__c);
}
```

**The mock must be set before `startTest`**, and the callout happens at `stopTest`.

Where the callout is enqueued from a trigger, the same shape applies — set the mock, perform the DML, and assert after `stopTest`.

## The better alternative: mock the client

For testing a **service's logic**, mocking the HTTP layer tests more than intended. Mocking the client interface is cleaner.

```java
public interface IErpClient {
    ErpResponse submitClaim(Warranty_Claim__c claim);
}
```

```java
public with sharing class ClaimSubmissionService {

    @TestVisible
    private static IErpClient erpClient = new ErpClient();

    public static void submit(List<Warranty_Claim__c> claims) {
        for (Warranty_Claim__c claim : claims) {
            ErpResponse response = erpClient.submitClaim(claim);
            claim.ERP_Confirmation__c = response.confirmationNumber;
        }
    }
}
```

```java
@IsTest
static void confirmationIsStoredOnEachClaim() {
    // no HTTP at all — this tests the service's logic and nothing else
    ClaimSubmissionService.erpClient = new MockErpClient('ERP-4471');

    List<Warranty_Claim__c> claims = new List<Warranty_Claim__c>{
        new Warranty_Claim__c(Claim_Number__c = 'WC-001')
    };

    Test.startTest();
    ClaimSubmissionService.submit(claims);
    Test.stopTest();

    Assert.areEqual('ERP-4471', claims[0].ERP_Confirmation__c);
}
```

**Two layers, two kinds of test:**

**`HttpCalloutMock` tests on the client class** — request construction, header setting, response parsing, and error classification.

**Interface mocks on the service** — business logic, with no HTTP involved.

Separating them means the service tests are fast and focused, and the client tests are the only ones dealing with JSON. See [[18.8 - Dependency Injection and Testability]].

## Continuations

```java
@IsTest
static void theContinuationCallbackParsesTheInventoryResponse() {
    Test.setMock(HttpCalloutMock.class, new InventoryMock());

    Test.startTest();
    Continuation con = (Continuation) ErpInventoryController.getInventory('SN-88213');

    Map<String, HttpRequest> requests = con.getRequests();
    String label = new List<String>(requests.keySet())[0];

    HttpResponse response = new HttpResponse();
    response.setStatusCode(200);
    response.setBody('{"available":12,"warehouse":"Pune"}');
    // the specific helpers for continuation testing
    Test.setContinuationResponse(label, response);

    Object result = Test.invokeContinuationMethod(new ErpInventoryController(), con);
    Test.stopTest();

    Assert.isNotNull(result);
}
```

More ceremony than an ordinary callout, which is another small argument against using continuations where a normal callout would do. See [[12.7 - Apex Continuations]].

## Named Credentials

A mock intercepts the callout regardless of the endpoint form, so `callout:ERP_System/api/claims` works in a test without the credential existing.

That is convenient and it means **a broken Named Credential is invisible to tests.** The credential's correctness is verified by deployment and by a manual check, not by the suite — worth knowing when an integration passes every test and fails in production with a 401. See [[13.13 - Named Credentials and External Credentials]].

## Practical guidance

**Set the mock before the callout**, and before `startTest` for async.

**Capture and assert on the request**, not just the response.

**Throw on unmatched endpoints** in a multi-endpoint mock.

**Test the failure paths** — 400, 401, 500, timeout, malformed body.

**Mock the client interface for service tests**, and use `HttpCalloutMock` for client tests.

**Use static resources** for large realistic payloads.

**Remember mocks hide Named Credential problems.**
