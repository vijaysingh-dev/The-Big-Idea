# Sampling Strategies

## Overview

At each generation step, the LLM produces a probability distribution over its entire vocabulary (~50K–200K tokens). **Sampling strategies** determine how to select the next token from this distribution.

This is not a minor detail — the sampling configuration determines whether your output is creative or focused, verbose or concise, safe or risky.

---

## The Raw Distribution

Before sampling, the model produces **logits** (unnormalized scores). Softmax converts to probabilities:

```
Logits:        [cat: 4.2,  feline: 3.1,  dog: 1.2,  the: -0.3, ...]
Probabilities: [cat: 0.47, feline: 0.26, dog: 0.08, the: 0.02, ...]
```

All sampling parameters modify this distribution before the final token selection.

---

## Temperature

**Definition**: Scales the logits before softmax, controlling the "sharpness" of the distribution.

```python
adjusted_logits = logits / temperature
probabilities = softmax(adjusted_logits)
```

- **Temperature = 1.0**: Original distribution (no change)
- **Temperature < 1.0**: Sharpens distribution → top tokens more likely, rare tokens less likely → more **focused, deterministic**
- **Temperature > 1.0**: Flattens distribution → probabilities more equal → more **random, creative**

```
Temperature 0.2:  [cat: 0.92, feline: 0.07, dog: 0.01, ...]  ← "cat" almost certain
Temperature 1.0:  [cat: 0.47, feline: 0.26, dog: 0.08, ...]  ← balanced
Temperature 2.0:  [cat: 0.21, feline: 0.19, dog: 0.17, ...]  ← nearly uniform
```

**Temperature = 0**: Greedy decoding — always pick the highest probability token. Fully deterministic but can be repetitive.

**Production guidelines**:

- Factual QA, RAG answers: `0.0–0.3` (consistency matters)
- Coding / structured output: `0.0–0.2`
- General chat: `0.7–1.0`
- Creative writing, brainstorming: `1.0–1.5`

---

## Top-K Sampling

**Definition**: Keep only the K highest-probability tokens; redistribute probability mass among them.

```
Original: [cat: 0.47, feline: 0.26, dog: 0.08, bird: 0.06, mat: 0.04, ...]

With top-K=3: only consider [cat: 0.47, feline: 0.26, dog: 0.08]
Renormalize: [cat: 0.58, feline: 0.32, dog: 0.10]
Sample from this truncated distribution
```

**Why**: Prevents the model from accidentally sampling a very low-probability nonsensical token while maintaining diversity.

**Problem**: K is fixed regardless of distribution shape. When the model is very confident (`[cat: 0.95, everything_else: 0.05]`), K=50 still allows 49 unlikely tokens. When the model is uncertain, K=50 might cut off reasonable continuations.

---

## Top-P (Nucleus) Sampling

**Definition**: Keep the smallest set of top tokens whose cumulative probability exceeds P.

```
With top-P=0.9:
Sort tokens by probability: [cat: 0.47, feline: 0.26, dog: 0.08, bird: 0.06, mat: 0.04, ...]
Cumulative sum:              [0.47,       0.73,         0.81,      0.87,       0.91, ...]
Keep until cumsum > 0.9 → keep [cat, feline, dog, bird, mat]
Sample from this nucleus
```

**Advantage**: Adapts to the distribution. When the model is confident, nucleus is small (focuses sampling). When uncertain, nucleus is larger (allows diversity).

**Production default**: `top_p=0.9` or `top_p=0.95` combined with temperature. Often preferred over top-K.

---

## Frequency Penalty

**Definition**: Reduces the probability of tokens that have already appeared, in proportion to how many times they've appeared.

```
adjusted_logit(token) = logit(token) - frequency_penalty × count(token)
```

**Effect**: Discourages repetition within the response. Useful for long-form generation where the model might loop.

Range: 0.0 (disabled) to 2.0 (strong penalty). Typical: `0.1–0.5`.

---

## Presence Penalty

**Definition**: Reduces the probability of tokens that have appeared at least once, regardless of frequency (binary penalty).

```
adjusted_logit(token) = logit(token) - presence_penalty × (1 if token appeared else 0)
```

**Effect**: Encourages the model to introduce new topics and vocabulary. Useful for brainstorming and creative generation.

Range: 0.0–2.0. Typical: `0.0–0.3` for most tasks.

**Frequency vs Presence**: Frequency penalizes _how much_ something repeated; Presence penalizes _whether_ something appeared. Use frequency to reduce verbal tics; use presence to increase topical variety.

---

## Repetition Penalty (Alternative Framing)

Used by many open-source models (Llama, Mistral). A multiplier applied to token logits:

```python
if token in generated_tokens:
    logit /= repetition_penalty  # > 1.0 reduces logit
```

Typical value: `1.1–1.3`. Works similarly to frequency penalty but as a multiplier.

---

## Min-P Sampling

A newer strategy (increasingly popular with open-source models). Sets a minimum probability threshold as a fraction of the top token's probability:

```
Threshold = top_token_probability × min_p
Keep only tokens with probability > threshold
```

**Advantage**: Better adapts to confidence level than top-K, similar benefits to top-P but with different behavior at the tails. Used as default in many Llama-based applications.

---

## Recommended Configurations

|Use Case|Temperature|Top-P|Freq Penalty|Notes|
|---|---|---|---|---|
|RAG / factual QA|0.1|0.9|0.0|Consistency first|
|Code generation|0.2|0.95|0.0|Slight creativity for solutions|
|Summarization|0.3|0.9|0.1|Avoid verbatim repetition|
|Chat assistant|0.7|0.9|0.1|Natural feel|
|Creative writing|1.0|0.95|0.2|Diversity and flow|
|Brainstorming|1.2|0.95|0.5|Maximum variety|
|Classification|0.0|—|0.0|Greedy; deterministic|

---

## Interaction Between Parameters

**Don't set both top-K and top-P**: They both truncate the distribution; applying both can over-constrain generation. Choose one (prefer top-P).

**Temperature + top-P**: Combine freely. Temperature reshapes; top-P then truncates.

**Low temperature + high repetition penalty**: Often needed together for factual tasks — low temp for focus, repetition penalty to prevent looping.
