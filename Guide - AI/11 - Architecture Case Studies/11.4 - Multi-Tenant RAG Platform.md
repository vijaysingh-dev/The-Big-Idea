# Architecture Case Study: Multi-Tenant Enterprise RAG Platform

## Product Definition

A SaaS platform where enterprise customers bring their own data, connect their own sources, and get RAG-powered Q&A — all isolated from other customers. Think Onyx, Notion AI, or a white-label enterprise search product.

**Core complexity**: Everything done for a single-tenant RAG system must now be done for N tenants in parallel, with strict isolation between them.

---

## Multi-Tenancy Design Principles

### Isolation Requirements

|Resource|Isolation Level|Mechanism|
|---|---|---|
|Document data|Hard (no cross-tenant access possible)|Separate vector DB collections|
|User credentials|Hard|Encrypted per-tenant, separate KMS keys|
|Compute|Soft (shared pool, queued fairly)|Rate limiting per tenant|
|Configuration|Per-tenant|Database row per tenant|
|Logs/traces|Soft (shared infra, scoped by tenant_id)|Column filter|
|LLM API costs|Per-tenant tracking|Usage metering|

## Tenant Data Architecture

### Vector Database Isolation

```python
class TenantVectorStore:
    """Each tenant has a dedicated Qdrant collection."""
    
    def get_collection(self, tenant_id: str) -> str:
        return f"tenant_{tenant_id}"
    
    def ensure_collection_exists(self, tenant_id: str, embedding_dim: int = 1536):
        collection_name = self.get_collection(tenant_id)
        if not self.qdrant.collection_exists(collection_name):
            self.qdrant.create_collection(
                collection_name=collection_name,
                vectors_config=VectorParams(size=embedding_dim, distance=Distance.COSINE),
            )
            # Create payload indexes for filtering
            self.qdrant.create_payload_index(collection_name, "document_id", PayloadSchemaType.KEYWORD)
            self.qdrant.create_payload_index(collection_name, "user_ids", PayloadSchemaType.KEYWORD)
    
    def search(self, tenant_id: str, query_vec, user_id: str, top_k=10):
        return self.qdrant.search(
            collection_name=self.get_collection(tenant_id),  # strict tenant boundary
            query_vector=query_vec,
            query_filter=Filter(
                should=[
                    FieldCondition(key="user_ids", match=MatchValue(value=user_id)),
                    FieldCondition(key="is_public_to_tenant", match=MatchValue(value=True)),
                ]
            ),
            limit=top_k,
        )
```

### Relational Data Isolation

```sql
-- Row-level security on all shared tables
CREATE POLICY tenant_isolation ON documents
    FOR ALL
    USING (tenant_id = current_setting('app.current_tenant_id')::uuid);

-- Never query without tenant context
SET app.current_tenant_id = '${tenant_id}';
```

## Tenant Onboarding Flow

```
1. Tenant signs up → create tenant record + provision resources
2. Admin connects data sources → per-tenant connector credentials stored encrypted
3. Background: initial index build (can take hours for large corpora)
4. Tenant users authenticate via SSO → scoped JWT token includes tenant_id
5. Query → all requests scoped to tenant
```

```python
async def provision_new_tenant(tenant: TenantSignup) -> Tenant:
    tenant_id = uuid4()
    
    # Create tenant record
    db.insert("tenants", {
        "id": tenant_id,
        "name": tenant.company_name,
        "tier": tenant.plan,
        "created_at": now(),
    })
    
    # Provision isolated resources
    vector_store.ensure_collection_exists(tenant_id)
    
    # Create tenant-specific encryption key
    kms.create_key(f"tenant/{tenant_id}", description=f"Tenant {tenant_id} data key")
    
    # Set up default admin user
    create_user(tenant_id, tenant.admin_email, role="admin")
    
    # Queue initial connector setup
    setup_default_connectors.delay(tenant_id)
    
    return Tenant(id=tenant_id, status="provisioning")
```

## Usage Metering and Billing

Track LLM costs per tenant for billing:

```python
def record_llm_usage(tenant_id: str, user_id: str, model: str, 
                     input_tokens: int, output_tokens: int):
    cost = calculate_cost(model, input_tokens, output_tokens)
    
    db.insert("usage_events", {
        "tenant_id": tenant_id,
        "user_id": user_id,
        "model": model,
        "input_tokens": input_tokens,
        "output_tokens": output_tokens,
        "cost_usd": cost,
        "timestamp": now(),
    })
    
    # Increment real-time counters in Redis (for rate limiting)
    redis.incrbyfloat(f"tenant:{tenant_id}:monthly_cost", cost)
    
    # Check against plan limits
    monthly_cost = float(redis.get(f"tenant:{tenant_id}:monthly_cost") or 0)
    tenant_limit = get_tenant_plan_limit(tenant_id, "monthly_cost_usd")
    
    if monthly_cost > tenant_limit * 0.9:  # 90% threshold
        notify_tenant_approaching_limit(tenant_id, monthly_cost, tenant_limit)
    
    if monthly_cost > tenant_limit:
        raise TenantBudgetExceeded(f"Tenant {tenant_id} has exceeded monthly budget")
```

## Connector Credential Security

Per-tenant connectors authenticate with the tenant's OAuth credentials. These must be:

1. Encrypted at rest with tenant-specific keys
2. Never logged
3. Rotated when tenant offboards

```python
class TenantConnectorStore:
    def store_credentials(self, tenant_id: str, connector: str, creds: dict):
        # Encrypt with tenant-specific KMS key
        encrypted = kms.encrypt(
            plaintext=json.dumps(creds),
            key_id=f"tenant/{tenant_id}",
        )
        db.upsert("connector_credentials", {
            "tenant_id": tenant_id,
            "connector_type": connector,
            "encrypted_creds": encrypted,
            "updated_at": now(),
        })
    
    def get_credentials(self, tenant_id: str, connector: str) -> dict:
        row = db.get("connector_credentials", tenant_id=tenant_id, connector_type=connector)
        if not row:
            raise ConnectorNotConfigured(f"{connector} not configured for tenant {tenant_id}")
        
        decrypted = kms.decrypt(row["encrypted_creds"], key_id=f"tenant/{tenant_id}")
        return json.loads(decrypted)
```

## Fair Queuing Across Tenants

Prevent a single tenant's large index job from blocking others:

```python
# Celery with priority queues per tenant tier
CELERY_TASK_ROUTES = {
    "tasks.index_document": {
        "queue": "indexing",
    }
}

# Fair queue: enterprise tenants get higher priority
def get_task_priority(tenant_id: str) -> int:
    tier = get_tenant_tier(tenant_id)
    return {"enterprise": 9, "pro": 5, "free": 1}[tier]

index_document.apply_async(
    args=[doc_id, tenant_id],
    priority=get_task_priority(tenant_id),
    queue="indexing"
)
```

## Tenant Offboarding

Must completely purge all tenant data:

```python
async def offboard_tenant(tenant_id: str):
    # Delete vector data
    vector_store.delete_collection(f"tenant_{tenant_id}")
    
    # Delete relational data (cascade)
    db.execute("DELETE FROM tenants WHERE id = $1", tenant_id)
    # Cascades to: documents, chunks, users, connector_credentials, usage_events
    
    # Delete encryption key (makes encrypted backups unrecoverable)
    kms.schedule_key_deletion(f"tenant/{tenant_id}", pending_window_days=7)
    
    # Delete from object storage
    s3.delete_prefix(f"tenants/{tenant_id}/")
    
    # Audit log
    audit_log.record("tenant_offboarded", tenant_id=tenant_id, timestamp=now())
```

## Scaling the Platform

|Scale trigger|Solution|
|---|---|
|Many tenants, few docs each|Shared Qdrant + tenant-scoped collections (current)|
|Few tenants, huge corpora|Dedicated Qdrant instance per large tenant|
|High query volume|Horizontal API scaling + connection pooling|
|Indexing backlog growing|Scale up Celery worker count|
|LLM costs dominate|Aggressive caching + smaller models for simple queries|
