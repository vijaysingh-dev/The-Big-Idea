# Similarity Search

## Definition

Similarity search finds vectors in a database that are "closest" to a query vector. The choice of distance metric determines what "closest" means.

---

## The Three Core Distance Metrics

### Cosine Similarity

Measures the **angle** between two vectors, ignoring magnitude.

```
cosine_similarity(A, B) = (A · B) / (|A| × |B|)
```

Range: [-1, 1]. Value of 1 = identical direction. Value of 0 = orthogonal. Value of -1 = opposite.

```python
import numpy as np

A = np.array([0.1, 0.9, 0.3])
B = np.array([0.2, 0.8, 0.4])

cosine_sim = np.dot(A, B) / (np.linalg.norm(A) * np.linalg.norm(B))
# ~0.994 — very similar direction
```

**When to use**: Default choice for text embeddings. Text embeddings represent direction-as-meaning. The magnitude of the vector usually doesn't carry useful signal, so normalizing it out is correct.

---

### Dot Product (Inner Product)

```
dot_product(A, B) = A · B = Σ(Aᵢ × Bᵢ)
```

No normalization. Favors vectors that are both similar in direction **and** large in magnitude.

**When to use**: When you want magnitude to matter. Some embedding models are trained with dot product as the objective (e.g., DPR — Dense Passage Retrieval). Using cosine with such models gives suboptimal results. Check the model card.

**Relationship**: If all vectors are L2-normalized (unit vectors), dot product = cosine similarity. OpenAI's embedding models return normalized vectors, so either metric gives the same result.

---

### Euclidean Distance (L2)

```
L2(A, B) = sqrt(Σ(Aᵢ - Bᵢ)²)
```

Measures straight-line distance in the embedding space.

**When to use**: For embeddings where absolute position matters, not just direction. Less common for text, more common for image embeddings or numerical feature vectors.

**Problem with high dimensions**: In high-dimensional spaces (512+), Euclidean distances tend to converge — everything looks roughly equidistant ("curse of dimensionality"). Cosine similarity degrades less severely.

## Exact vs Approximate Search

### Exact Search (KNN)

Compare query vector to every vector in the database. Always returns the true top-K.

- Time: O(N × d) where N = number of vectors, d = dimensions
- **Problem**: At 1 million vectors × 1536 dimensions, this is ~6 billion multiplications per query. At 1 billion vectors, completely infeasible in real-time.

### Approximate Nearest Neighbor (ANN)

Sacrifice a small amount of accuracy for massive speed gains. Instead of checking all N vectors, ANN algorithms build an index structure that prunes the search space.

- Time: O(log N) to O(N^0.5) depending on algorithm
- **Recall**: Typically 95–99% — meaning ~1–5% of truly nearest neighbors may be missed
- This recall tradeoff is almost always acceptable in production (a near-perfect match is effectively as useful as the perfect match)

The major ANN algorithms (HNSW, IVF, PQ) are covered in depth in [[../06 - Vector Databases/06.1 - Vector DB Internals - ANN HNSW IVF PQ]].

## Similarity vs Relevance

An important distinction that matters for RAG:

**Similarity** = vector distance. Finds semantically similar text.

**Relevance** = does this document actually answer the query?

These are correlated but not identical:

- A document can be very similar in embedding space but not actually answer the question
- A document with very specific keywords might have a mediocre cosine similarity score but be highly relevant

This is why **reranking** exists: dense retrieval gets candidate documents, then a cross-encoder reranker scores them by actual relevance. See [[03.6 - Rerankers - Cross vs Bi Encoders]].

## The BEIR Benchmark

BEIR (Benchmarking IR) is the standard benchmark for evaluating retrieval system quality. It tests across 18 diverse retrieval tasks (finance, scientific, medical, code, etc.).

Key metric: **nDCG@10** — normalized discounted cumulative gain at 10 retrieved documents. Measures how well the truly relevant documents are ranked near the top.

Use BEIR scores to compare embedding models and retrieval strategies on domains similar to your use case. Don't just pick the model with the highest average — check performance on the specific domain.

## Practical Implementation

```python
# Cosine similarity search (manual, for understanding)
import numpy as np

def cosine_search(query_vec, doc_vecs, top_k=5):
    # Normalize all vectors
    query_norm = query_vec / np.linalg.norm(query_vec)
    doc_norms = doc_vecs / np.linalg.norm(doc_vecs, axis=1, keepdims=True)
    
    # Dot product of normalized vectors = cosine similarity
    scores = doc_norms @ query_norm
    
    # Return top-K indices
    top_indices = np.argsort(scores)[::-1][:top_k]
    return top_indices, scores[top_indices]
```

In production, this is handled by vector DBs (Qdrant, Vespa, Weaviate) with HNSW indexes — never implement brute-force search at scale.
