# First-Class Functions

#python #functions #functional

> **In one line:** Functions are ordinary objects. You can pass them, return them, store them in dicts and attach attributes to them, and that one fact is what callbacks, strategies, dispatch tables, `partial`, `key=` arguments and decorators are built on.

---

## The Idea

"First-class" means a function can do anything any other object can:

```python
def shout(s): return s.upper()

f = shout                     # bind another name
handlers = {"shout": shout}   # store in a container
def apply(fn, x): return fn(x)
apply(shout, "hi")            # pass as an argument
def make(): return shout      # return from a function
shout.__name__, shout.__doc__, shout.__defaults__, shout.__code__   # it has attributes
```

A **higher-order function** takes or returns functions. `sorted(key=...)`, `map`, `filter`, `functools.reduce`, every decorator, and every callback API are higher-order.

## Callables

Anything with `__call__` is callable, not just functions:

| Callable | Example |
|---|---|
| Functions and lambdas | `def f(): ...`, `lambda x: x` |
| Built-ins | `len`, `print` |
| Methods (bound) | `obj.method` — the function plus `self`, bundled |
| Classes | `int("5")` — calling a class creates an instance |
| Instances with `__call__` | Stateful callables, e.g. a rate limiter you call per request |
| `functools.partial` objects | A function with some arguments fixed |

```python
class Counter:
    def __init__(self): self.n = 0
    def __call__(self, *_):
        self.n += 1
        return self.n

hit = Counter()
hit(); hit()          # 2
callable(hit)         # True
```

## lambda

```python
sorted(users, key=lambda u: (u.last_name, u.first_name))
```

A `lambda` is an anonymous function limited to **one expression**. Use it for short `key=` and callback arguments. If it needs a name, a docstring or more than one line, write a `def`. Assigning a lambda to a name (`f = lambda x: ...`) is flagged by linters for this reason.

⚠️ Lambdas in a loop capture variables late. See [[02.3 - Scopes and Closures#The Late-Binding Trap]].

## map, filter, reduce vs Comprehensions

```python
list(map(str.upper, names))              # fine with an existing function
[n.upper() for n in names]               # usually clearer
list(filter(None, values))               # drops falsy values — a neat idiom
[v for v in values if v]                 # equivalent

from functools import reduce
from operator import mul
reduce(mul, [1, 2, 3, 4])                # 24 — but math.prod exists
```

The modern Python rule: **prefer comprehensions** unless you already have a named function to pass. `reduce` is rarely the clearest choice; `sum`, `math.prod`, `any`, `all`, `max`, `min` and an explicit loop usually win.

## operator: Functions for Operators

```python
from operator import itemgetter, attrgetter, methodcaller, add

sorted(rows, key=itemgetter("created_at"))        # faster and clearer than a lambda
sorted(users, key=attrgetter("dept", "name"))     # multi-key
list(map(methodcaller("strip"), lines))
get_xy = itemgetter(0, 1); get_xy([5, 6, 7])      # (5, 6)
```

`itemgetter` and `attrgetter` are implemented in C. They are faster than equivalent lambdas, and they pickle, which matters for multiprocessing.

## functools.partial

Fix some arguments now, supply the rest later:

```python
from functools import partial

def send(channel, msg, *, urgent=False): ...

alert = partial(send, "ops", urgent=True)
alert("disk full")          # send("ops", "disk full", urgent=True)

loop.run_in_executor(None, partial(resize, path, width=800))   # executors take no kwargs
```

`partial` objects keep `.func`, `.args` and `.keywords`, so they are inspectable, and they pickle when the wrapped function does. Lambdas do not pickle.

## Dispatch Tables Instead of if/elif Chains

```python
HANDLERS = {
    "created": on_created,
    "updated": on_updated,
    "deleted": on_deleted,
}

def handle(event):
    try:
        handler = HANDLERS[event.type]
    except KeyError:
        raise UnknownEvent(event.type) from None
    return handler(event)
```

This is the Strategy pattern without classes. It is easy to extend and easy to test each handler alone. For dispatch on **type** rather than value, see `functools.singledispatch` in [[02.4 - Decorators]]. For the class-based version, see [[02.12 - Strategy]] in the LLD guide. (Python 3.10's `match` statement is the other option when the shape of the data matters.)

## Introspection

```python
import inspect
def area(w: float, h: float = 1.0) -> float:
    "Rectangle area."
    return w * h

area.__name__          # 'area'
area.__qualname__      # 'area' — includes class or enclosing function names when nested
area.__module__
area.__doc__
area.__annotations__   # {'w': float, 'h': float, 'return': float}
area.__defaults__      # (1.0,)
area.__code__.co_varnames, area.__code__.co_argcount
inspect.getsource(area)
inspect.isfunction(area), inspect.ismethod(obj.m), inspect.iscoroutinefunction(fn)
```

Frameworks live on this. Starlette checks `iscoroutinefunction` to decide whether to run your endpoint in a thread pool ([[01.3 - Threads Processes and Coroutines]]). Pydantic reads `__annotations__`. Celery uses `__qualname__` and `__module__` to name tasks.

## Codebase

**Repo:** `python/cpython`

**Question to answer:** How is `partial` implemented, and why does `partial(partial(f, 1), 2)` not create two wrapper layers?

**Read, in order:**

1. `Lib/functools.py` — `class partial` (the pure-Python fallback): `__new__` flattens nested partials. Then `reduce` and `cmp_to_key`.
2. `Lib/operator.py` — `itemgetter`, `attrgetter`, `methodcaller` in pure Python. The C versions in `Modules/_operator.c` do the same, faster.
3. `Lib/inspect.py` — `iscoroutinefunction` and `markcoroutinefunction` (3.12): how a framework decides whether to `await` you

**Size:** 1 session.
