# LangChain: When to Use and When Not To

## What LangChain Is

LangChain is a Python/TypeScript framework that provides:

- Abstractions for LLM calls, prompt templates, chains
- Pre-built integrations with 100+ LLMs, vector DBs, tools
- Composable "chains" for multi-step LLM workflows
- An ecosystem (LangSmith for tracing, LangServe for deployment)

It became the most popular LLM framework in 2023, largely because it was the first to solve the "how do I connect everything?" problem when building LLM applications.

---

## LangChain's Problems in Production

This is more important than the feature list. LangChain has significant production issues:

### 1. Abstraction Over-engineering

LangChain wraps simple operations in elaborate class hierarchies. What should be 5 lines becomes 50 lines of LangChain chain composition. When something breaks, the stack trace is incomprehensible.

```python
# LangChain (verbose)
from langchain.chains import RetrievalQA
from langchain.vectorstores import Chroma
from langchain.embeddings import OpenAIEmbeddings

qa_chain = RetrievalQA.from_chain_type(
    llm=ChatOpenAI(model="gpt-4"),
    chain_type="stuff",
    retriever=Chroma(embedding_function=OpenAIEmbeddings()).as_retriever(),
)

# Direct (clear)
def rag_query(question):
    query_emb = openai.embeddings.create(model="text-embedding-3-small", input=question)
    chunks = chroma.query(query_embeddings=[query_emb], n_results=5)
    context = "\n".join(chunks["documents"][0])
    return openai.chat.completions.create(
        model="gpt-4",
        messages=[{"role": "user", "content": f"Context:\n{context}\n\nQuestion: {question}"}]
    ).choices[0].message.content
```

### 2. Rapid API Changes

LangChain's API has changed dramatically across versions. Code written 6 months ago often breaks. Production systems need stability.

### 3. Hidden Behavior

LangChain's built-in chains construct prompts internally. You don't control the exact prompt — and you can't easily debug why the model is behaving a certain way.

```python
# What prompt is RetrievalQA actually sending? You have to dig through source code.
# This is the opposite of what you want for prompt debugging.
```

### 4. Performance Overhead

LangChain's abstraction layers add significant latency. For high-throughput production systems, the overhead is measurable.

### 5. Debugging Difficulty

When a LangChain chain produces a wrong answer, the layered abstractions make it hard to trace what happened at each step.

## When LangChain IS Worth Using

Despite the problems, LangChain has legitimate uses:

### 1. Rapid Prototyping

If you need a working demo in 2 hours and don't need to debug it or put it in production, LangChain's pre-built pieces are genuinely fast.

### 2. LangSmith (Tracing / Observability)

LangSmith is LangChain's observability platform. It's one of the best tools for tracing LLM calls — even if you don't use LangChain's orchestration, you can use LangSmith for tracing.

```python
from langsmith import traceable

@traceable
def my_rag_function(question):
    # Your custom code here, not LangChain abstractions
    # LangSmith traces the LLM calls inside
    ...
```

### 3. Accessing Pre-built Document Loaders

LangChain has 100+ document loaders. For one-off scripts or prototyping, using their loader instead of writing your own is pragmatic.

### 4. Specific Well-Tested Chains

Some LangChain abstractions are battle-tested and worth using: `TextSplitter`, `RecursiveCharacterTextSplitter`. These are utility functions, not complex chains.

---

## The Principle: Use LangChain Selectively

**Good pattern**:

```python
# Use LangChain only for the utilities that are genuinely useful
from langchain.text_splitter import RecursiveCharacterTextSplitter

splitter = RecursiveCharacterTextSplitter(chunk_size=512, chunk_overlap=64)
chunks = splitter.split_text(document_text)

# Everything else: direct API calls
embeddings = openai_client.embeddings.create(model="text-embedding-3-small", input=chunks)
```

**Bad pattern**:

```python
# Building an entire LangChain pipeline that you can't debug or optimize
chain = (
    RunnableParallel({"context": retriever, "question": RunnablePassthrough()})
    | prompt
    | llm
    | StrOutputParser()
)
```

## Alternatives to LangChain

### For simple RAG: Write it yourself

A basic RAG pipeline is 50–100 lines of Python. Direct OpenAI/Anthropic SDK calls are fast, debuggable, and stable.

### For complex agents: LangGraph (see next file)

LangChain's graph-based agent orchestration framework. More principled than LangChain chains.

### For production orchestration: Custom + LangSmith

Build your own orchestration layer (direct SDK calls) and use LangSmith purely for observability. Best of both worlds.

### LlamaIndex

A focused alternative that's specifically designed for RAG. Better than LangChain for document indexing and retrieval pipelines. Less comprehensive than LangChain for general orchestration.

---

## Senior Engineer Verdict

Use LangChain for:

- ✅ `RecursiveCharacterTextSplitter` and other text utilities
- ✅ LangSmith tracing (regardless of whether you use LangChain orchestration)
- ✅ Document loaders in prototypes
- ✅ Learning RAG concepts (its code is educational)

Don't use LangChain for:

- ❌ Production RAG pipelines (write directly)
- ❌ Agent orchestration (use LangGraph or custom)
- ❌ Anything where you need prompt control
- ❌ High-throughput systems (latency overhead)
