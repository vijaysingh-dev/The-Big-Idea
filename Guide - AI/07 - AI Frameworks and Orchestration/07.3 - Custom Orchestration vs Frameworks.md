# Custom Orchestration vs Frameworks

## The Decision

When building an AI system, you choose between:

1. **Framework** (LangChain, LangGraph, LlamaIndex, CrewAI)
2. **Custom orchestration** (direct SDK calls + your own state management)

There's no universally correct answer. This file gives you a decision framework.

---

## What "Custom Orchestration" Means

Custom orchestration means:

- Call LLM APIs directly (OpenAI SDK, Anthropic SDK)
- Write your own state management (Python dataclasses, Redis)
- Write your own routing logic (if/else, Python functions)
- Write your own prompt templates (formatted strings or Jinja2)
- Integrate observability yourself (LangSmith, Langfuse, custom logging)

```python
# Custom orchestration — a complete RAG pipeline, ~60 lines
import openai
from dataclasses import dataclass

@dataclass
class RAGPipeline:
    llm: openai.OpenAI
    vector_store: VectorStore
    
    def query(self, question: str, user_id: str) -> dict:
        # 1. Transform query
        query_emb = self.llm.embeddings.create(
            model="text-embedding-3-small", input=question
        ).data[0].embedding
        
        # 2. Retrieve
        chunks = self.vector_store.search(query_emb, top_k=10, user_id=user_id)
        
        # 3. Assemble context
        context = "\n\n".join(f"[{c.title}]\n{c.text}" for c in chunks)
        
        # 4. Generate
        response = self.llm.chat.completions.create(
            model="gpt-4o",
            messages=[
                {"role": "system", "content": SYSTEM_PROMPT},
                {"role": "user", "content": f"Context:\n{context}\n\nQuestion: {question}"}
            ],
            stream=True,
        )
        
        # 5. Return with citations
        return {"chunks": chunks, "response": response}
```

## Framework vs Custom: Decision Criteria

### Use a Framework When:

**You need features the framework uniquely provides**:

- LangGraph: stateful agents with cycles + checkpointing (hard to build well yourself)
- LlamaIndex: sophisticated document indexing pipelines (many pre-built node parsers)
- CrewAI: multi-agent role-based collaboration (niche but useful for specific patterns)

**Prototype speed matters more than production quality**:

- Demos, internal tools, MVPs where you iterate on features not performance

**Team consensus**: If the whole team already knows LangChain, the switching cost to custom may outweigh the benefits.

### Use Custom Orchestration When:

**You need full control over prompts**:

- Prompt debugging requires seeing the exact string sent to the API
- Framework-generated prompts are opaque

**Performance matters**:

- Framework overhead is measurable in high-throughput systems
- Custom code can be profiled and optimized at each step

**Long-term maintainability**:

- Your own code doesn't break when a framework releases v0.3
- New engineers can read and understand direct SDK calls without learning the framework

**Specific behavior required**:

- Your retrieval pipeline has complex business logic that doesn't map to framework abstractions

---

## The Hybrid Approach (Best in Practice)

Most production AI systems at mature companies use a hybrid:

```
Custom for:
├── RAG retrieval pipeline (direct vector DB calls)
├── Prompt templates (formatted strings, Jinja2)
├── Context assembly (your domain logic)
└── Response processing (parsing, validation)

Framework for:
├── LangSmith / Langfuse (observability)
├── LangGraph (complex agent state + cycles)
└── LlamaIndex node parsers (document parsing utilities)
```

The principle: **use frameworks for the things they genuinely solve better than custom code; write custom for everything else.**

### 2. Prompt Registry

```python
# prompts.py — all prompts in one place, version controlled

PROMPTS = {
    "rag_v2": """You are a helpful assistant. Answer using ONLY the provided context.
If context doesn't contain the answer, say "I don't have that information."

Context:
{context}

Question: {question}""",
    
    "summarize_v1": """Summarize the following document in 3-5 bullet points:
{document}""",
}

def get_prompt(name: str, **kwargs) -> str:
    return PROMPTS[name].format(**kwargs)
```

### 3. Observability Integration

```python
import langsmith
from functools import wraps

def trace(name: str):
    """Decorator to trace any function in LangSmith."""
    def decorator(func):
        @wraps(func)
        def wrapper(*args, **kwargs):
            with langsmith.trace(name=name, inputs={"args": args, "kwargs": kwargs}) as run:
                result = func(*args, **kwargs)
                run.end(outputs={"result": result})
                return result
        return wrapper
    return decorator

@trace("rag_pipeline")
```

### 4. Retry and Fallback

```python
from tenacity import retry, stop_after_attempt, wait_exponential

@retry(stop=stop_after_attempt(3), wait=wait_exponential(min=1, max=10))
def call_llm_with_retry(messages):
    try:
        return primary_model.complete(messages)
    except RateLimitError:
        return fallback_model.complete(messages)  # cheaper/faster fallback
    except APIError as e:
        if e.status_code >= 500:
            raise  # retry
        raise  # don't retry 4xx errors
```

## Framework Maturity Comparison

|Framework|Production readiness|API stability|Community|Best for|
|---|---|---|---|---|
|LangChain|Medium|Poor (v0.x)|Very large|Prototyping, utilities|
|LangGraph|Medium|Improving|Growing|Stateful agents|
|LlamaIndex|Good|Better|Large|RAG pipelines|
|CrewAI|Low|Poor|Medium|Multi-agent roles|
|Haystack|Good|Good|Medium|Enterprise NLP|
