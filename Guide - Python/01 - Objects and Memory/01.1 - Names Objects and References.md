# Names Objects and References

#python #memory #fundamentals

> **In one line:** A Python variable is a name tag tied to an object, not a box that holds a value. Assignment never copies, every object knows how many names point at it, and it is freed the moment that count hits zero, unless it is stuck in a cycle.

---

## The Idea

In C, `int x = 5;` reserves a box called `x` and puts 5 in it. In Python, `x = 5` does something different:

1. Find or create an object representing `5` (somewhere in memory, with a type and a value).
2. Bind the name `x`, in the current namespace, to that object.

```
namespace (a dict)           heap
┌──────────────┐
│ "x" ─────────┼──────►  ┌──────────────────┐
│ "y" ─────────┼──────►  │ int object       │
└──────────────┘         │ refcount: 2      │
                         │ type: int        │
                         │ value: 5         │
                         └──────────────────┘
```

```python
x = 5
y = x          # y is bound to the SAME object. Nothing is copied.
print(id(x) == id(y))   # True
```

Every object has three things:

| | What | How to see it |
|---|---|---|
| **Identity** | Its address in memory (in CPython). Never changes while it lives. | `id(obj)`, compared with `is` |
| **Type** | What it is and what it can do. Never changes (in practice). | `type(obj)` |
| **Value** | Its contents. May change if the type is mutable. | `==`, `repr(obj)` |

## Assignment Rebinds, It Never Modifies

```python
a = [1, 2]
b = a
a = a + [3]      # builds a NEW list, rebinds a. b still points to the old one.
print(b)         # [1, 2]

a = [1, 2]
b = a
a += [3]         # list.__iadd__ mutates in place. a and b see the change.
print(b)         # [1, 2, 3]
```

This difference between `a = a + x` and `a += x` for mutable types catches everybody once. Details in [[01.2 - Mutability Equality and Copying]].

Function arguments follow the same rule. Python is **"call by object reference"** (sometimes called call by sharing): the parameter name is bound to the same object the caller passed.

```python
def add_item(items):
    items.append(99)     # mutates the caller's list
    items = []           # rebinds the local name only; the caller is unaffected

nums = [1]
add_item(nums)
print(nums)              # [1, 99]
```

## Reference Counting

CPython keeps a counter in every object's header: how many references point at it. When it drops to zero, the object is freed **immediately**.

```python
import sys

x = []
print(sys.getrefcount(x))   # 2: `x`, plus the temporary argument to getrefcount
y = x
print(sys.getrefcount(x))   # 3
del y
print(sys.getrefcount(x))   # 2
```

What increments a refcount: binding a name, putting the object in a container, passing it as an argument, an attribute pointing at it. `del name` removes **a name**, not the object. The object dies only when the last reference goes.

💡 **Immediate freeing is why `with open(...)` used to be optional in CPython.** A file object with no references is closed the instant its refcount hits zero. PyPy and other implementations do not refcount, so they close it "eventually". Always use `with`. Do not rely on refcount timing.

## The Garbage Collector Is for Cycles

Reference counting cannot free a cycle:

```python
a = {}
b = {"a": a}
a["b"] = b
del a, b      # each dict still references the other: refcounts are 1, never 0
```

CPython's **cyclic garbage collector** (the `gc` module) periodically scans container objects, finds groups that are only reachable from each other, and frees them. It is generational: new objects are scanned often, survivors less often.

```python
import gc
gc.get_count()        # allocations since the last collection, per generation
gc.get_threshold()    # when each generation is collected
gc.collect()          # force a full collection; returns the number of objects found
gc.freeze()           # move everything to a permanent generation (helps copy-on-write after fork)
```

| Production fact | Why it matters |
|---|---|
| GC pauses are usually short but grow with the number of live container objects | Services holding millions of objects can see multi-millisecond pauses. Instagram disabled GC entirely and saved memory. |
| Cycles involving objects with `__del__` are collectable since 3.4 | Older "uncollectable" advice is out of date |
| `weakref` lets you reference without keeping alive | Caches and observer patterns that should not prevent cleanup |

Backend context: [[02.2 - Processes]] explains why refcounting defeats copy-on-write after `fork`, and [[02.6 - Memory in Practice]] explains why freed memory often does not return to the OS.

## Namespaces Are Dicts

Names live in namespaces, and namespaces are (mostly) dictionaries:

```python
x = 10
globals()["x"]        # 10 — module globals are a real dict
def f():
    y = 1
    return locals()   # a snapshot dict of the function's locals
class C:
    z = 3
C.__dict__["z"]       # 3 — class namespace (a read-only mappingproxy)
```

Function locals are actually stored in a fast array, not a dict. That is why writing to `locals()` inside a function does not change variables (and why 3.13 made `locals()` semantics explicit, PEP 667). Scopes are covered fully in [[02.3 - Scopes and Closures]].

## Everything Is an Object

Functions, classes, modules, `None`, and types themselves are all objects with an identity, a type and a refcount:

```python
type(len)        # <class 'builtin_function_or_method'>
type(int)        # <class 'type'>
type(type)       # <class 'type'> — type is its own type
def f(): pass
f.custom = 1     # functions can carry attributes
```

This uniformity is what makes decorators ([[02.4 - Decorators]]), descriptors ([[06.5 - Descriptors]]) and metaclasses ([[06.8 - Metaprogramming]]) possible.
