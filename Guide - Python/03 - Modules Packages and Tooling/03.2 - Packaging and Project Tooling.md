# Packaging and Project Tooling

#python #packaging #uv #tooling

> **In one line:** A modern Python project is one `pyproject.toml`, a `src/` layout, an isolated virtual environment, a lockfile for exact reproducibility, and a fast toolchain (uv for environments and dependencies, ruff for lint and format, mypy or pyright for types).

---

## The Pieces

| Piece | What it is | Tool |
|---|---|---|
| **Interpreter** | A specific Python version | `uv python install 3.12`, pyenv, system packages |
| **Virtual environment** | A directory with its own `site-packages`, isolated from the system | `uv venv`, `python -m venv` |
| **Project metadata** | Name, version, dependencies, entry points, tool config | `pyproject.toml` |
| **Lockfile** | Exact versions and hashes of every transitive dependency | `uv.lock` (or `poetry.lock`, `requirements.txt` from pip-tools) |
| **Build backend** | Turns the source into a wheel | hatchling, setuptools, uv_build, pdm-backend |
| **Distribution** | A **wheel** (`.whl`: a zip, ready to install) or an sdist (source) | PyPI, a private index |

### Virtual environments in one picture

```
.venv/
├── bin/python   → a symlink to the base interpreter
├── bin/pip, bin/uvicorn ...   (scripts of installed packages)
├── lib/python3.12/site-packages/   ← your dependencies live HERE, not globally
└── pyvenv.cfg   ← "home = /usr/bin", the base interpreter
```

Activating a venv only puts `.venv/bin` first on `PATH`. `sys.prefix` then points into the venv, and `site-packages` is resolved from there. Nothing magic.

## pyproject.toml

```toml
[project]
name = "conduit"
version = "0.1.0"
requires-python = ">=3.12"
dependencies = [
    "fastapi>=0.115",
    "pydantic>=2.8",
    "asyncpg>=0.29",
]

[project.optional-dependencies]
otel = ["opentelemetry-sdk>=1.27"]

[project.scripts]
conduit = "conduit.cli:main"          # installs a `conduit` command

[dependency-groups]                   # PEP 735: dev-only groups, never published
dev = ["pytest>=8", "pytest-asyncio", "mypy", "ruff", "hypothesis"]

[build-system]
requires = ["hatchling"]
build-backend = "hatchling.build"

[tool.ruff]
line-length = 100
[tool.ruff.lint]
select = ["E", "F", "I", "UP", "B", "ASYNC", "S"]

[tool.mypy]
strict = true

[tool.pytest.ini_options]
asyncio_mode = "auto"
testpaths = ["tests"]
```

One file replaces `setup.py`, `setup.cfg`, `requirements*.txt`, `.flake8`, `mypy.ini` and `pytest.ini`.

## Library vs Application Dependencies

| | Library (published to PyPI) | Application (a service you deploy) |
|---|---|---|
| `dependencies` in pyproject | **Ranges**: `httpx>=0.27,<1` | Ranges are fine |
| Lockfile | Not published; used only for your CI | **Essential.** Deploy exactly what you tested. |
| Why | Users must be able to resolve your library alongside theirs | Reproducibility: the build next month gets identical versions |

⚠️ Pinning exact versions (`==`) in a **library** makes it impossible to install next to anything else. Not locking an **application** means a new transitive release can break production on a rebuild with no code change.

## uv: The Modern Workflow

`uv` (from Astral, written in Rust) replaces pip, pip-tools, virtualenv, pyenv and pipx with one fast tool.

```bash
uv init --package conduit           # scaffold: pyproject, src layout
uv python pin 3.12                  # writes .python-version
uv add fastapi "pydantic>=2.8"      # add dependency, update uv.lock, sync .venv
uv add --dev pytest ruff mypy
uv lock --upgrade-package fastapi   # bump one package deliberately
uv sync --frozen                    # CI/Docker: install exactly the lockfile, fail if out of date
uv run pytest                       # run inside the project env, syncing first
uv run --with ipython ipython       # a temporary extra tool
uvx ruff check .                    # run a tool without installing it into the project
uv tree                             # dependency tree
```

In a Dockerfile:

```dockerfile
FROM python:3.12-slim
COPY --from=ghcr.io/astral-sh/uv:0.5 /uv /bin/uv
WORKDIR /app
COPY pyproject.toml uv.lock ./
RUN uv sync --frozen --no-dev --no-install-project      # dependencies layer, cached
COPY src ./src
RUN uv sync --frozen --no-dev
CMD ["/app/.venv/bin/uvicorn", "conduit.main:app", "--host", "0.0.0.0"]
```

Layer caching and the rest of image design are covered in [[14.2 - Production Dockerfiles]]. Note the exec-form `CMD` ([[02.9 - Signals and Process Lifecycle]]).

## Why the src Layout

```
flat layout                         src layout
conduit/                            src/conduit/
tests/                              tests/
pyproject.toml                      pyproject.toml
```

With the flat layout, running tests from the repo root imports `conduit` **from the working directory**, not from the installed package. Tests pass locally even when packaging is broken (a missing file, a wrong `package-data`). With `src/`, the only way to import `conduit` is to install it, so tests exercise what you ship.

## The Toolchain

| Job | Tool | Notes |
|---|---|---|
| Lint + import sorting + upgrades | **ruff** | Replaces flake8, isort, pyupgrade, many plugins. The `B` (bugbear), `ASYNC` and `S` (bandit) rule sets catch real bugs |
| Format | **ruff format** | Black-compatible, much faster |
| Types | **mypy** or **pyright** | [[07.1 - Type Hints and Static Checking]] |
| Tests | **pytest** | [[07.5 - Testing With pytest]] |
| Pre-commit | `pre-commit` | Runs ruff and friends on every commit |
| Vulnerabilities | `pip-audit`, or `uv` plus your CI's scanner | Checks the lockfile against advisories |
| Task runner | `nox`, `just`, or `make` | Encode the "how do I run X" commands |

## Wheels and Native Extensions

Packages with C or Rust code (numpy, pydantic-core, orjson, asyncpg, cryptography) ship **platform wheels** built for a specific OS, CPU architecture and libc:

```
pydantic_core-2.23.4-cp312-cp312-manylinux_2_17_x86_64.manylinux2014_x86_64.whl
              │       │     │     │                    │
              version  py    ABI   glibc-based Linux    CPU
```

⚠️ **Alpine Linux uses musl, not glibc**, so `manylinux` wheels do not apply. pip falls back to compiling from source (slow, needs compilers) or fails. That is why `python:3.12-slim` (Debian) is usually a better base image than `python:3.12-alpine` for Python services. `musllinux` wheels exist for many packages now, but not all.

## Codebase

**Repos:** `astral-sh/uv` (docs), `pypa/hatch` (hatchling), `pypa/packaging`

**Question to answer:** What is inside a wheel, and how does the installer know where each file goes and which commands to create?

**Read, in order:**

1. Download any wheel (`uv pip download` or `pip download httpx --no-deps`) and unzip it. Read `*.dist-info/METADATA`, `RECORD`, `WHEEL` and `entry_points.txt`.
2. `pypa/packaging` — `src/packaging/tags.py`: how platform tags like `manylinux_2_17_x86_64` are generated and matched
3. `pypa/packaging` — `src/packaging/specifiers.py`: how `>=2.8,<3` is evaluated
4. CPython `Lib/venv/__init__.py` — `EnvBuilder.create()`: how a venv is laid out. It is short.
5. uv docs — "Concepts → Projects" and "Concepts → Resolution". Read the resolution docs for how a lockfile covers multiple platforms.

**Size:** 1–2 sessions.

## Exercise

**Drill 3.2 — Ship a real package**

```
pyhttpcheck/
├── pyproject.toml          # hatchling, src layout, [project.scripts] httpcheck = ...
├── uv.lock
├── src/pyhttpcheck/
│   ├── __init__.py
│   ├── cli.py              # argparse: check URLs concurrently, print status + latency
│   └── py.typed
├── tests/test_cli.py
├── .pre-commit-config.yaml # ruff, ruff-format, mypy
├── noxfile.py              # sessions: tests on 3.12 and 3.13, lint, typecheck
├── Dockerfile              # uv, --frozen, non-root, exec-form CMD
└── .github/workflows/ci.yml
```

1. Build a wheel with `uv build`. Install it into a **fresh** venv and run the `httpcheck` command.
2. Unzip the wheel and explain each file in `dist-info`.
3. Prove the src layout matters: move to a flat layout, forget to include a data file, and show tests still pass while the installed wheel breaks.
4. Make CI run nox sessions on two Python versions.

**Done when:** `uvx --from ./dist/pyhttpcheck-0.1.0-py3-none-any.whl httpcheck https://example.com` works, and CI is green.
