# Hallucinations and Grounding

## Definition

**Hallucination**: The model generates text that is confident-sounding but factually incorrect, unsupported by provided context, or completely fabricated.

This is not a bug — it's an inherent property of how LLMs work. Understanding _why_ they hallucinate is prerequisite to designing systems that mitigate it.

---

## Why LLMs Hallucinate

### 1. They are Probabilistic Completers, Not Fact Retrievers

LLMs don't store and retrieve facts like a database. They learn to predict the next token based on statistical patterns in training data. When generating text, they're asking "what would a plausible continuation look like?" not "is this factually correct?"

A model trained on lots of text about Napoleon will generate fluent Napoleon-sounding text even when asked about specific details it doesn't actually know — because fluent text about Napoleon is what comes next in the probability distribution.

### 2. Training Data Has Errors and Contradictions

Web-scraped training data contains false statements, satire, fiction, and conflicting facts. The model learns all of these without clear ground-truth signals about what is true.

### 3. Compression Loses Detail

The model compresses world knowledge into billions of parameters. Specific facts, especially rare ones, can be garbled or lost. The model may know "Paris is in France" confidently but hallucinate the population of a small town.

### 4. No Uncertainty Calibration by Default

Base language models are trained to produce fluent text, not to express uncertainty. They don't naturally say "I'm not sure about this" — they produce confident-sounding output whether certain or not.

RLHF/RLAIF training helps but doesn't fully solve calibration.

### 5. Context Length Pressure

In long prompts, information from early in the context may be "forgotten" by the model (the "lost in the middle" phenomenon). The model may hallucinate a detail that was actually provided in the context but too far back.

---

## Types of Hallucination

|Type|Example|Cause|
|---|---|---|
|**Factual**|"Paris has a population of 15 million" (it's ~2.1M)|Memorized wrong fact|
|**Confabulation**|Invents a plausible-sounding citation|Fluency > accuracy pressure|
|**Intrinsic**|Summary contradicts source document|Doesn't track source faithfully|
|**Extrinsic**|Adds details not in source|Fills gaps from parametric knowledge|
|**Context drift**|Loses the question and answers differently|Long-context attention issues|

---

## Grounding

**Grounding** = anchoring model outputs to verifiable external sources.

RAG is the primary grounding mechanism: instead of relying on parametric memory (what the model remembers), you inject the actual source material into the context and instruct the model to only use that.

### Grounding Effectiveness

Strong grounding instruction:

```
Answer ONLY based on the provided documents.
If the documents do not contain the answer, respond: "I don't have enough information to answer this."
Do not use any prior knowledge beyond what's in the documents.
```

This doesn't fully eliminate hallucination but significantly reduces it — the model has explicit permission to say "I don't know" and is constrained to cite specific material.

### Citation as a Grounding Signal

Requiring the model to cite sources for each claim forces it to check its reasoning against the retrieved documents:

```
Answer the question and cite the relevant document for each claim.
Format: [Claim]. [Source: Document Title, Section]
```

If the model can't find a source, it's more likely to say so rather than fabricate.

## Hallucination Mitigation Strategies

### Strategy 1: RAG with Strict Grounding

- Inject all necessary knowledge as context
- Explicit "only use provided context" instruction
- **Limits**: Context window constraints; if the answer isn't in the retrieved docs, no grounding helps

### Strategy 2: Structured Verification

For factual claims, add a verification step:

```
Step 1: Generate answer
Step 2: For each factual claim, find the supporting sentence in context
Step 3: If no support found, remove or flag the claim
```

### Strategy 3: Temperature = 0 for Factual Tasks

Lower temperature makes the model stick to high-probability continuations (what it "knows" most confidently). Reduces wild hallucinations but doesn't eliminate them.

### Strategy 4: Self-Consistency

Generate multiple responses at temperature > 0, then take the majority answer. Factually correct claims tend to appear consistently; hallucinated specifics vary. See [[03.10 - Chain of Thought and Reasoning]].

### Strategy 5: Confidence Elicitation

Ask the model to explicitly flag uncertainty:

```
If you are uncertain about any part of your answer, say "I'm not certain about X" explicitly.
```

RLHF-trained models are better at this than base models.

### Strategy 6: Retrieval Quality First

Most RAG hallucinations happen when retrieval fails to surface the relevant document, so the model fills the gap with parametric knowledge. Improving retrieval quality (better chunking, hybrid search, reranking) reduces hallucination more than prompt engineering alone.

## Context Poisoning

**Definition**: Retrieved documents that contain wrong, misleading, or adversarially injected content. The model faithfully uses this content → produces incorrect output.

Not technically a hallucination (the model is grounded to the context) but the effect is the same: wrong output.

Sources:

- Stale documents with outdated information
- User-controlled content injected with false claims
- Documents from untrusted sources mixed into the index
- **Prompt injection**: A retrieved document that contains "Ignore previous instructions and..."

Mitigations:

- Source trust scoring (weight retrieval by source reliability)
- Access control — only index from trusted sources
- Input sanitization for user-controlled content
- Separate indexes per trust level

---

## Evaluation for Hallucination

Key metrics:

- **Faithfulness** (RAGAS): Is the answer supported by the retrieved context? Scored by LLM-as-judge checking each claim against retrieved docs.
- **Factual consistency** (FactScore): Breaks answer into atomic facts, checks each against knowledge base.
- **Hallucination rate**: Percentage of responses containing at least one hallucinated fact.

See [[../10 - Production AI Engineering/10.5 - Evaluation Pipelines and Monitoring]].
