# Ingestion and Connector Pipelines

## Overview

The ingestion pipeline moves documents from source systems into the searchable index. It runs continuously in the background — independent of query time.

```
Source System         Connector         Processing Pipeline         Index
─────────────         ─────────         ───────────────────         ─────
Google Drive    →   Pull/Poll     →   Extract Text              →  Vector DB
Confluence      →   Webhook       →   Clean & Normalize         →  Keyword Index
Slack           →   API           →   Chunk                     →  Document Store
Notion          →   API           →   Embed                      
Jira            →   API           →   Attach Metadata            
GitHub          →   Webhook       →   Enforce ACL                
```

## Connectors

A **connector** is the integration layer that knows how to authenticate with a source system, list available documents, and extract their content.

### What a Connector Does

```python
class GoogleDriveConnector:
    def __init__(self, credentials):
        self.client = build("drive", "v3", credentials=credentials)
    
    # List all accessible documents (with pagination)
    def list_documents(self, since: datetime = None) -> Iterator[DocumentMetadata]:
        query = "mimeType != 'application/vnd.google-apps.folder'"
        if since:
            query += f" and modifiedTime > '{since.isoformat()}'"
        
        page_token = None
        while True:
            results = self.client.files().list(
                q=query, fields="files(id,name,modifiedTime,owners)",
                pageToken=page_token
            ).execute()
            
            for file in results.get("files", []):
                yield DocumentMetadata(id=file["id"], title=file["name"], ...)
            
            page_token = results.get("nextPageToken")
            if not page_token:
                break
    
    # Extract text content from a single document
    def get_document(self, doc_id: str) -> Document:
        # Export Google Docs as plain text
        content = self.client.files().export(
            fileId=doc_id, mimeType="text/plain"
        ).execute()
        return Document(id=doc_id, content=content.decode("utf-8"))
```

### Common Connector Challenges

**Authentication & Token Refresh** OAuth tokens expire. The connector must handle refresh gracefully:

```python
def get_client(self):
    if self.creds.expired and self.creds.refresh_token:
        self.creds.refresh(Request())
    return build("drive", "v3", credentials=self.creds)
```

**Rate Limiting** APIs impose rate limits. Connectors must back off and retry:

```python
@retry(wait=wait_exponential(min=1, max=60), stop=stop_after_attempt(5),
       retry=retry_if_exception_type(RateLimitError))
def fetch_document(self, doc_id):
    ...
```

**Format Diversity** Each source system has different document formats:

|Source|Format|Extraction method|
|---|---|---|
|Google Docs|Google native|Export API as text/html|
|Confluence|HTML|BeautifulSoup, strip tags|
|Slack|JSON messages|Assemble thread as text|
|GitHub|Markdown/code|Direct text, preserve structure|
|PDFs|Binary|PyPDF2, pdfminer, unstructured|
|DOCX|Binary|python-docx|

**Permission Propagation** Each document carries access permissions. These must be stored alongside content for ACL enforcement at query time (see [[05.6 - Citation and Access Control]]).

```python
# Store permissions with the document
document = Document(
    id=doc_id,
    content=content,
    metadata={
        "source": "google_drive",
        "permitted_users": ["user@company.com", "team@company.com"],
        "permitted_groups": ["engineering", "product"],
    }
)
```

## The Ingestion Pipeline

After connectors pull documents, a pipeline processes them into index-ready chunks:

```python
class IngestionPipeline:
    def __init__(self, chunker, embedder, vector_store, keyword_store):
        self.chunker = chunker
        self.embedder = embedder
        self.vector_store = vector_store
        self.keyword_store = keyword_store
    
    def process_document(self, document: Document):
        # Step 1: Clean text
        cleaned = self.clean(document.content)
        
        # Step 2: Chunk
        chunks = self.chunker.chunk(cleaned, metadata=document.metadata)
        
        # Step 3: Embed (batch for efficiency)
        embeddings = self.embedder.embed_batch([c.text for c in chunks])
        
        # Step 4: Store in both indexes
        for chunk, embedding in zip(chunks, embeddings):
            self.vector_store.upsert(chunk.id, embedding, chunk.metadata)
            self.keyword_store.index(chunk.id, chunk.text, chunk.metadata)
```

## Async / Queue Architecture

Ingestion is decoupled from the API via a job queue. This prevents ingestion from blocking the query API and allows horizontal scaling:

```
Connector (polls source)
      │
      ▼
Job Queue (Redis / Celery / Kafka)
      │
      ▼
Worker Pool (N parallel workers)
      │
      ├── Worker 1: process doc_001
      ├── Worker 2: process doc_002
      └── Worker 3: process doc_003
      │
      ▼
Vector DB + Keyword Index
```

**Onyx architecture**: Uses Celery + Redis for the task queue. The `indexing_pipeline` directory contains the worker logic. Multiple connectors enqueue tasks; a pool of indexing workers picks them up.

Key file in Onyx: `backend/danswer/background/celery/tasks/indexing.py`

## Incremental vs Full Re-indexing

**Full re-index**: Process every document from scratch. Simple but slow and expensive at scale.

**Incremental indexing**: Only process new or modified documents since last run.

```python
def run_incremental_sync(connector, last_sync_time):
    # Fetch only modified documents
    for doc_metadata in connector.list_documents(since=last_sync_time):
        if doc_metadata.modified_time > last_sync_time:
            doc = connector.get_document(doc_metadata.id)
            pipeline.process_document(doc)
    
    # Handle deletions
    current_ids = set(connector.list_all_ids())
    indexed_ids = set(vector_store.list_all_ids(source=connector.name))
    deleted_ids = indexed_ids - current_ids
    for doc_id in deleted_ids:
        vector_store.delete(doc_id)
        keyword_store.delete(doc_id)
```

**Challenge**: Many source systems don't have reliable "modified since" APIs. You may need to maintain your own change tracking (checksum-based).

## Document Text Extraction

The raw text quality directly impacts chunk quality, which impacts retrieval quality.

### Extraction Challenges

**PDFs**: The hardest format. PDFs store layout, not semantic structure.

- Text PDFs: extract directly (fast, high quality)
- Scanned PDFs: require OCR (Tesseract, AWS Textract, Azure Document Intelligence)
- Tables in PDFs: layout-based extraction loses table structure; need dedicated table parsers

**HTML**: Must strip navigation, ads, sidebars — preserve only body content.

```python
from bs4 import BeautifulSoup

def extract_html_content(html):
    soup = BeautifulSoup(html, "html.parser")
    # Remove non-content elements
    for tag in soup(["script", "style", "nav", "header", "footer", "aside"]):
        tag.decompose()
    return soup.get_text(separator="\n", strip=True)
```

**The `unstructured` library** is the best general-purpose solution — handles PDFs, DOCX, HTML, PPTX, images (via OCR) with a unified API.

## Metadata to Preserve

Every chunk should carry metadata used for filtering, citation, and access control:

```python
{
    "chunk_id": "gdrive_doc123_chunk_4",
    "document_id": "gdrive_doc123",
    "source": "google_drive",
    "title": "Q3 2024 Strategy Doc",
    "url": "https://docs.google.com/...",
    "author": "user@company.com",
    "created_at": "2024-01-15T10:30:00Z",
    "modified_at": "2024-09-20T14:22:00Z",
    "section": "Revenue Analysis",       # heading hierarchy
    "chunk_index": 4,                    # position in document
    "permitted_users": [...],            # ACL
    "permitted_groups": [...],           # ACL
}
```
