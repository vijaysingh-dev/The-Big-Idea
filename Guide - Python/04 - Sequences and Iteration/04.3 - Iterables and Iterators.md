# Iterables and Iterators

#python #iteration #protocols

> **In one line:** An iterable can give you an iterator (`__iter__`), and an iterator gives you the next item (`__next__`) until it raises `StopIteration`. Lists are iterables you can loop over many times. Iterators, generators, files and network streams are consumed once, and forgetting that is a classic silent bug.

---

## The Two Protocols

| | Must implement | Returns | Reusable? |
|---|---|---|---|
| **Iterable** | `__iter__()` | A fresh iterator | Yes. Each `iter()` starts over. |
| **Iterator** | `__next__()` **and** `__iter__()` returning `self` | The next item, or raises `StopIteration` | **No.** Once exhausted, stays exhausted. |

What a `for` loop really does:

```python
for x in collection:
    body(x)

# is
it = iter(collection)            # calls collection.__iter__()
while True:
    try:
        x = next(it)             # calls it.__next__()
    except StopIteration:
        break
    body(x)
```

Every consumer of iterables (`for`, `list()`, `sum`, `zip`, unpacking, `in`, `"".join`, comprehensions) uses this protocol.

---

## Iterable vs Iterator, Concretely

```python
nums = [1, 2, 3]          # iterable, not an iterator
it = iter(nums)           # list_iterator
next(it), next(it)        # 1, 2
list(it)                  # [3]
list(it)                  # []  ← exhausted, no error

list(nums), list(nums)    # [1, 2, 3], [1, 2, 3] — a list can be iterated again
```

⚠️ **The silent exhaustion bug:**

```python
rows = (parse(line) for line in open("data.csv"))     # a generator: an iterator
count = sum(1 for _ in rows)
valid = [r for r in rows if r.ok]                     # [] — rows is already used up
```

```python
def process(items):
    if not any(i.urgent for i in items):              # consumes part of an iterator
        return
    for i in items:                                   # ...so this misses items
        handle(i)
```

If a function needs to iterate twice, either accept a `Sequence` (and say so in the type hint) or call `items = list(items)` at the top. Type hints help here: `Iterable[T]` means "I will loop once", `Sequence[T]` means "I may index or loop again" ([[07.1 - Type Hints and Static Checking]]).

## Writing an Iterator Class

```python
class Countdown:
    """Iterable: each loop gets a fresh iterator."""
    def __init__(self, start):
        self.start = start
    def __iter__(self):
        return CountdownIterator(self.start)

class CountdownIterator:
    def __init__(self, n):
        self.n = n
    def __iter__(self):
        return self
    def __next__(self):
        if self.n <= 0:
            raise StopIteration
        self.n -= 1
        return self.n + 1
```

Splitting the iterable from its iterator is what lets `Countdown(3)` be looped over twice. In practice you rarely write `__next__` by hand. A generator function does it in a few lines ([[04.4 - Generators]]):

```python
class Countdown:
    def __init__(self, start): self.start = start
    def __iter__(self):
        n = self.start
        while n > 0:
            yield n
            n -= 1
```

## Lazy Evaluation

Iterators produce values on demand. That makes infinite or huge streams possible:

```python
import itertools
ids = itertools.count(1)          # 1, 2, 3, ... forever
next(ids)

with open("huge.log") as f:       # a file object is an iterator over lines
    errors = (line for line in f if "ERROR" in line)
    first_ten = list(itertools.islice(errors, 10))   # reads only as much as needed
```

Many built-ins return lazy iterators rather than lists: `map`, `filter`, `zip`, `enumerate`, `reversed`, `dict.items()` views (live views, not iterators), `range` (a lazy sequence, re-iterable).

---

## iter() Has a Second Form

`iter(callable, sentinel)` calls the function repeatedly until it returns the sentinel:

```python
from functools import partial
with open("blob.bin", "rb") as f:
    for chunk in iter(partial(f.read, 65536), b""):
        hasher.update(chunk)
```

This is the idiomatic way to read a file or socket in fixed-size chunks.

---

## The Sequence Fallback

If a class has no `__iter__` but has `__getitem__` that accepts 0, 1, 2…, `iter()` will still work, calling `__getitem__` until `IndexError`. That is why old-style sequence classes are iterable. `collections.abc.Iterable` does not detect this, so `isinstance(x, Iterable)` can be `False` for something you can loop over. The only reliable check is to try `iter(x)`.

## Async Iteration

The async versions are `__aiter__` and `__anext__` (raising `StopAsyncIteration`), consumed with `async for`:

```python
async for message in websocket:
    ...

async def stream_rows(conn):
    async with conn.transaction():
        async for record in conn.cursor("SELECT * FROM events"):
            yield record          # an async generator
```

Streaming database rows, consuming Kafka, reading WebSocket messages and LLM token streams all use this protocol. See [[05.4 - Streaming LLM Responses]] in the Backend guide.
