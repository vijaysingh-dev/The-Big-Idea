# Encoder vs Decoder vs Encoder-Decoder

## Why This Matters

Every LLM you use in production comes from one of these three families. Knowing which architecture does what determines:

- Which model to use for which task
- Why embeddings come from encoders, not decoders
- Why GPT-style models can chat but BERT can't generate text
- How to fine-tune the right architecture for your use case

---

## The Three Families

### Encoder-Only Models

**Architecture**: Full bidirectional attention — every token attends to every other token in both directions.

**Training objective**: **Masked Language Modeling (MLM)** — randomly mask 15% of tokens, predict the masked tokens from context.

```
Input:  "The [MASK] sat on the mat"
Learns: Predict "cat" using all surrounding context
```

Because it sees the full context in both directions, encoders are excellent at **understanding** — but cannot generate text (there's no autoregressive left-to-right generation).

**Key models**: BERT, RoBERTa, DeBERTa, sentence-transformers

**Best for**:

- Sentence embeddings (semantic search, RAG)
- Text classification
- Named entity recognition
- Reranking (cross-encoder setup)

**In AI engineering**: Encoder models are what you use for **embeddings** in RAG systems. When you call `text-embedding-3-small` or use `sentence-transformers`, you're using an encoder.

---

### Decoder-Only Models

**Architecture**: Causal (masked) attention — each token can only attend to previous tokens. No "looking ahead."

**Training objective**: **Causal Language Modeling (CLM)** — predict the next token given all preceding tokens.

```
Input:  "The cat sat"
Learns: Predict "on" given ["The", "cat", "sat"]
        Predict "sat" given ["The", "cat"]
        ...
```

This autoregressive structure enables open-ended text generation.

**Key models**: GPT-2, GPT-3, GPT-4, Llama, Mistral, Gemini, Claude, Falcon

**Best for**:

- Text generation (the "G" in GPT)
- Conversational AI / chat
- Code generation
- Instruction following
- Reasoning (Chain of Thought)

**In AI engineering**: All major LLMs you call via API (OpenAI, Anthropic) are decoder-only. This is the workhorse of AI applications.

---

### Encoder-Decoder Models (Seq2Seq)

**Architecture**: An encoder processes the input (bidirectionally), then a decoder attends to the encoder output (via **cross-attention**) and generates the output autoregressively.

**Training objectives**: Varies — T5 uses "span corruption" (mask spans, predict them), BART uses denoising.

**Key models**: T5, BART, mT5, Flan-T5

**Best for**:

- Translation (clear input → clear output mapping)
- Summarization
- Document question answering with extractive components
- Structured data → text

**In AI engineering**: Less commonly used today — GPT-class models have largely subsumed these use cases due to their emergent instruction-following ability. Still valuable for specialized summarization or translation tasks with fine-tuning.

---

## Side-by-Side Comparison

|Property|Encoder-Only|Decoder-Only|Encoder-Decoder|
|---|---|---|---|
|Attention direction|Bidirectional|Causal (left→right)|Encoder: bi; Decoder: causal + cross|
|Training objective|MLM (predict masked)|CLM (predict next token)|Denoising / seq2seq|
|Generates text?|No|Yes|Yes|
|Produces embeddings?|Yes (best quality)|Yes (worse quality)|Can (via encoder)|
|Best use|Retrieval, classification|Generation, chat, reasoning|Translation, summarization|
|Examples|BERT, RoBERTa|GPT-4, Llama, Claude|T5, BART|

---

## A Common Misconception: Decoder Models for Embeddings

You _can_ extract embeddings from decoder models (e.g., take the last token's hidden state). But decoder embeddings are generally lower quality for retrieval than dedicated encoder models because:

1. Causal masking means each token only sees past context, not future — so the representation is "incomplete"
2. Encoders are trained specifically to produce contextually rich representations of full inputs

**Practical rule**: Use encoder models (sentence-transformers, `text-embedding-*`) for RAG embeddings. Use decoder models for generation.

Exception: OpenAI's `text-embedding-3` models use a decoder-based architecture internally but are fine-tuned specifically for embedding tasks — so they perform well.

---

## Cross-Attention (Encoder-Decoder Bridge)

In encoder-decoder models, the decoder has a second attention layer — **cross-attention** — that attends to the encoder's output:

```
Decoder cross-attention:
  Q = decoder hidden state  ← "What am I currently generating?"
  K = encoder output        ← "What's in the source text?"
  V = encoder output
```

This lets the decoder selectively pull information from the source text at each generation step. It's the mechanism behind attention-based translation: when generating the word "chat" in French, the decoder attends to the word "cat" in the English encoder output.
