# Testing With pytest

#python #testing #pytest

> **In one line:** pytest finds `test_*` functions, rewrites plain `assert`s to show useful diffs, injects fixtures by parameter name, and multiplies tests with `parametrize`. Good tests mock only at the edges of your system, use real dependencies where they are cheap, and add property-based tests for logic with many cases.

---

## The Basics

```python
# tests/test_money.py
from decimal import Decimal
import pytest
from pydrills.money import Money, CurrencyMismatch

def test_add_same_currency():
    assert Money("1.50", "USD") + Money("2.25", "USD") == Money("3.75", "USD")

def test_add_different_currency_raises():
    with pytest.raises(CurrencyMismatch, match="USD.*EUR"):
        Money("1", "USD") + Money("1", "EUR")
```

```bash
uv run pytest                     # all tests
uv run pytest -x -q               # stop at first failure, quiet
uv run pytest -k "money and not slow"
uv run pytest tests/test_money.py::test_add_same_currency -vv
uv run pytest --lf                # re-run last failures
uv run pytest -n auto             # parallel, with pytest-xdist
```

pytest rewrites `assert` statements at import time, so `assert a == b` failing shows both values and a diff of dicts or lists. No `assertEqual` needed.

## Fixtures

A fixture is a function providing something a test needs. Tests ask for it **by parameter name**, the same `inspect.signature` trick from [[02.1 - Parameters and Arguments]].

```python
# tests/conftest.py — fixtures here are available to every test below this directory
import pytest

@pytest.fixture
def user():
    return User(id=1, email="a@x.com")

@pytest.fixture
def repo():
    r = InMemoryUserRepo()
    yield r                      # setup above, teardown below — like a context manager
    r.clear()

def test_register(repo, user):   # injected by name
    repo.add(user)
    assert repo.get(1) == user
```

### Scope

| Scope | Created once per | Use for |
|---|---|---|
| `function` (default) | Test | Anything mutable |
| `module` / `package` | File / package | Moderately expensive read-only setup |
| `session` | Whole run | A Postgres container, a compiled app |

A common pattern: a **session**-scoped database, plus a **function**-scoped transaction that rolls back after each test. That keeps tests isolated without recreating the schema each time.

```python
@pytest.fixture(scope="session")
def pg_url():
    with PostgresContainer("postgres:16") as pg:        # testcontainers
        run_migrations(pg.get_connection_url())
        yield pg.get_connection_url()

@pytest.fixture
async def db(pg_url):
    conn = await asyncpg.connect(pg_url)
    tx = conn.transaction()
    await tx.start()
    yield conn
    await tx.rollback()          # every test starts from a clean database
    await conn.close()
```

Built-in fixtures worth knowing: `tmp_path`, `monkeypatch`, `capsys`, `caplog`, `request`.

## parametrize

```python
@pytest.mark.parametrize(
    ("raw", "expected"),
    [
        ("1.0.0", (1, 0, 0)),
        ("10.2.3", (10, 2, 3)),
        pytest.param("1.0", None, marks=pytest.mark.xfail(reason="two-part versions not supported yet")),
    ],
    ids=["simple", "multi-digit", "two-part"],
)
def test_parse_version(raw, expected):
    assert parse_version(raw) == expected
```

One function, many cases, each reported separately. Stacked `parametrize` decorators produce the cross product, which is handy for transition matrices ([[06.6 - Enums]]).

## Mocking: Only at the Edges

```python
def test_signup_sends_welcome(monkeypatch):
    sent = []
    monkeypatch.setattr("app.services.signup.send_email", lambda to, body: sent.append(to))
    signup("a@x.com")
    assert sent == ["a@x.com"]
```

```python
from unittest.mock import AsyncMock

async def test_charge_retries_on_timeout():
    gateway = AsyncMock()
    gateway.charge.side_effect = [TimeoutError(), {"id": "ch_1"}]
    result = await PaymentService(gateway).pay(100)
    assert result == "ch_1"
    assert gateway.charge.await_count == 2
```

⚠️ **Patch where the name is looked up, not where it is defined.** If `app/services/signup.py` does `from app.email import send_email`, patch `app.services.signup.send_email` ([[03.1 - How Imports Work]]).

| Mock | Do not mock |
|---|---|
| Third-party HTTP APIs (use `respx` for httpx, or a fake server) | Your own domain logic |
| Time (`freezegun`, `time-machine`), randomness, UUIDs | The database, if a real one in a container is practical: it catches real SQL bugs |
| Email, SMS, payment gateways | Pydantic models, dataclasses, pure functions |

💡 **Prefer fakes over mocks.** A `FakeSender` class implementing the same `Protocol` ([[06.3 - Inheritance Composition and Protocols]]) is reusable, readable and type-checked. A `MagicMock` happily accepts any call, including ones with typos, and passes anyway. If you do use mocks, use `create_autospec(Real)` or `spec=Real` so wrong method names fail.

## Async Tests

```toml
[tool.pytest.ini_options]
asyncio_mode = "auto"           # pytest-asyncio: async def tests just work
```

```python
async def test_get_order(client):
    resp = await client.get("/orders/1")
    assert resp.status_code == 200

@pytest.fixture
async def client(app):
    async with httpx.AsyncClient(transport=httpx.ASGITransport(app=app), base_url="http://test") as c:
        yield c
```

`ASGITransport` calls your FastAPI app in-process: no server and no ports, but the full middleware and validation stack runs. Override dependencies with `app.dependency_overrides[get_repo] = lambda: fake_repo`.

## Property-Based Testing With Hypothesis

Instead of choosing examples, describe the input space and a property that must always hold:

```python
from hypothesis import given, strategies as st

@given(st.lists(st.integers()))
def test_sort_is_idempotent_and_ordered(xs):
    once = my_sort(xs)
    assert my_sort(once) == once
    assert all(a <= b for a, b in zip(once, once[1:]))
    assert sorted(xs) == once

@given(amount=st.decimals(min_value=0, max_value=10**6, places=2),
       parts=st.integers(min_value=1, max_value=50))
def test_allocation_preserves_total(amount, parts):
    shares = Money(amount, "USD").allocate([1] * parts)
    assert sum(shares, Money.zero("USD")) == Money(amount, "USD")
```

Hypothesis generates hundreds of cases, finds a failing one, then **shrinks** it to the smallest input that still fails. It is excellent at finding edge cases you would never write: empty lists, huge numbers, unicode, duplicates. Use it for parsers, serialisers (round-trip: `decode(encode(x)) == x`), money, and anything with invariants. Many drills in this guide already use it.

## Structuring a Test Suite

```
tests/
├── conftest.py            # shared fixtures: app, client, db, factories
├── unit/                  # pure logic, no I/O: milliseconds each
├── integration/           # real DB/Redis in containers
└── e2e/                   # full stack, few of them
```

| Habit | Why |
|---|---|
| One behaviour per test, named after it (`test_expired_token_is_rejected`) | The failure name is the bug report |
| Arrange / Act / Assert, visibly separated | Readability |
| Factories (`factory_boy`, or plain functions with defaults) for test data | Tests show only the fields that matter |
| Coverage as a guide (`pytest-cov`), not a target | 100% coverage with weak assertions proves little |
| Fast unit suite under ~10 s | You will actually run it |

Testing across services (contract tests, ephemeral environments) is in [[11.9 - Testing Microservices]].

## Codebase

**Repo:** `pytest-dev/pytest`

**Question to answer:** How does pytest rewrite `assert a == b` so the failure shows both values, and how does it resolve a fixture requested by parameter name?

**Read, in order:**

1. `src/_pytest/assertion/rewrite.py` — `AssertionRewritingHook` (an import hook from [[03.1 - How Imports Work]]) and `AssertionRewriter.visit_Assert`: rewriting the AST
2. `src/_pytest/fixtures.py` — `getfixtureclosure` and `FixtureRequest.getfixturevalue`: name-based lookup, scopes, caching, and teardown via generator finalisers
3. `src/_pytest/python.py` — `pytest_generate_tests` / `Metafunc.parametrize`: one function becomes many test items

**Size:** 2 sessions. pytest is a great codebase for seeing plugins, hooks and AST rewriting in production.
