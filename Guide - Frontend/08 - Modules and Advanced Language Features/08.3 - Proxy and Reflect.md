# Proxy and Reflect

A `Proxy` wraps an object and intercepts fundamental operations on it — reading a property, writing one, deleting, checking existence, enumerating keys. `Reflect` provides the default implementations of those operations as plain functions.

Together they are the mechanism behind Vue 3's reactivity, Immer's drafts, MobX observables and most modern validation and ORM libraries.

## Basic shape

```js
const target = { name: "Vijay" };

const proxy = new Proxy(target, {
  get(obj, prop, receiver) {
    console.log(`read ${String(prop)}`);
    return Reflect.get(obj, prop, receiver);
  },
  set(obj, prop, value, receiver) {
    console.log(`write ${String(prop)}`);
    return Reflect.set(obj, prop, value, receiver);
  },
});

proxy.name;        // logs "read name"
proxy.name = "K";  // logs "write name"
target.name;       // "K" — writes pass through
```

The handler object holds **traps**. Any trap you omit falls back to the default behavior on the target.

## The traps worth knowing

| Trap | Intercepts |
| --- | --- |
| `get` | property read, method access |
| `set` | property write |
| `has` | `in` operator |
| `deleteProperty` | `delete` |
| `ownKeys` | `Object.keys`, `for...in`, spread |
| `getOwnPropertyDescriptor` | descriptor reads, and required by `ownKeys` enumeration |
| `apply` | calling a function |
| `construct` | `new` |
| `defineProperty` | `Object.defineProperty` |
| `getPrototypeOf` / `setPrototypeOf` | prototype access |

Thirteen in total, covering every internal method an object can have.

## Why Reflect exists

Two reasons, and the second is the important one.

**Reflect gives you the default behavior as a function.** `Reflect.get(obj, prop)` instead of `obj[prop]`, `Reflect.has` instead of `in`, `Reflect.deleteProperty` instead of `delete`. Every `Reflect` method corresponds one-to-one with a proxy trap, with the same arguments.

**Reflect forwards the `receiver`, which keeps getters correct:**

```js
const parent = {
  _value: 1,
  get value() { return this._value; },
};

const child = Object.create(parent);
child._value = 2;

const proxy = new Proxy(parent, {
  get(obj, prop, receiver) {
    return obj[prop];              // wrong — `this` is parent
    // return Reflect.get(obj, prop, receiver);  // right — `this` is receiver
  },
});
```

Without passing `receiver`, a getter invoked through the proxy sees the target as `this` rather than the object the access actually started from. On a prototype chain that produces wrong values. Always use `Reflect.*` inside traps and forward `receiver`.

`Reflect` methods also return booleans rather than throwing, which makes strict-mode-correct trap implementations straightforward — `set` must return `true` on success or the operation throws a `TypeError` in strict mode.

## Practical patterns

**Validation:**

```js
function validated(target, schema) {
  return new Proxy(target, {
    set(obj, prop, value, receiver) {
      const check = schema[prop];
      if (check && !check(value)) {
        throw new TypeError(`Invalid value for ${String(prop)}`);
      }
      return Reflect.set(obj, prop, value, receiver);
    },
  });
}

const user = validated({}, { age: v => Number.isInteger(v) && v >= 0 });
user.age = -1;   // TypeError
```

**Default values:**

```js
const withDefault = (obj, fallback) =>
  new Proxy(obj, {
    get: (o, p, r) => (p in o ? Reflect.get(o, p, r) : fallback),
  });
```

**Negative array indices:**

```js
const arr = new Proxy([1, 2, 3], {
  get(target, prop, receiver) {
    const index = Number(prop);
    if (Number.isInteger(index) && index < 0) {
      return Reflect.get(target, String(target.length + index), receiver);
    }
    return Reflect.get(target, prop, receiver);
  },
});

arr[-1];   // 3
```

`Array.prototype.at` covers this natively now, but it illustrates the mechanism.

**Reactivity, in miniature:**

```js
function reactive(target, onChange) {
  return new Proxy(target, {
    get(obj, prop, receiver) {
      const value = Reflect.get(obj, prop, receiver);
      return typeof value === "object" && value !== null
        ? reactive(value, onChange)   // deep — wrap nested objects lazily
        : value;
    },
    set(obj, prop, value, receiver) {
      const result = Reflect.set(obj, prop, value, receiver);
      onChange(prop, value);
      return result;
    },
    deleteProperty(obj, prop) {
      const result = Reflect.deleteProperty(obj, prop);
      onChange(prop, undefined);
      return result;
    },
  });
}
```

This is Vue 3's core idea in fifteen lines. Vue 2 used `Object.defineProperty` accessors instead, which could not detect property *addition* or array index assignment — hence `Vue.set`. Proxies removed that limitation entirely, which is the concrete reason Vue 3 rewrote its reactivity system.

Immer works on the same principle: the draft is a proxy that records writes, and `produce` uses that record to build a structurally-shared copy ([[20.6 - Immer and Immutable Updates]]).

## Revocable proxies

```js
const { proxy, revoke } = Proxy.revocable(target, handler);
revoke();
proxy.anything;   // TypeError
```

Useful for handing an object to untrusted code and cutting access later, and for enforcing lifecycle boundaries — Immer revokes drafts after `produce` returns so a leaked draft cannot be used.

## Invariants

Proxies cannot lie about certain things. If the target has a non-configurable, non-writable property, a `get` trap must return that exact value; `ownKeys` must include all non-configurable own keys; a trap on a non-extensible target cannot invent properties.

Violating an invariant throws a `TypeError` at the operation site, which produces confusing errors when proxying frozen objects.

## Costs and limits

**Performance.** Every intercepted operation goes through a function call and defeats V8's inline caches ([[01.1 - How JavaScript Runs]]). Proxied property access is roughly an order of magnitude slower than direct access. Fine for state objects touched hundreds of times per render; not fine for a hot loop over a million elements.

**Not transparent.** `proxy !== target`, so identity checks fail. `instanceof` works (it goes through `getPrototypeOf`), but `WeakMap` lookups keyed by the target will miss when given the proxy.

**Private fields do not work through proxies.** A `#field` access is keyed to the actual instance, so calling a method with `#` fields on a proxy throws:

```js
class C { #x = 1; get() { return this.#x; } }
new Proxy(new C(), {}).get();   // TypeError
```

This is why proxying class instances is generally a bad idea.

**Cannot be polyfilled.** Proxy behavior is not expressible in ES5, which is why libraries depending on it dropped IE11 support entirely.

## How senior engineers actually use this

**They read proxies far more often than they write them.** Understanding the mechanism explains why Vue reactivity works, why Immer drafts behave oddly outside `produce`, and why certain objects in a debugger show unexpected values.

**They use them for development-only instrumentation.** A proxy that warns on access to a deprecated field, or logs every state mutation, costs nothing in production if it is stripped by an environment check.

**They avoid proxying hot data.** Reactivity libraries proxy state objects, not the elements of a 100,000-row dataset.

**They prefer explicit APIs in application code.** A proxy that magically adds behavior is harder to trace than a function that does it visibly. The magic is worth it in a library, rarely in a feature.

## Common pitfalls

- Using `obj[prop]` instead of `Reflect.get(obj, prop, receiver)` inside a `get` trap and breaking prototype getters.
- Forgetting `set` must return `true`, causing strict-mode `TypeError`s.
- Proxying class instances with private fields.
- Assuming `proxy === target`.
- Proxying frozen or sealed objects and hitting invariant violations.
- Deep-proxying eagerly instead of lazily on access, which is both slower and allocates far more.

## Interview angle

Proxy questions are usually framed as "how does Vue 3 reactivity work" or "how would you observe changes to an object". The answer is a proxy with `get` and `set` traps, with `get` tracking dependencies and `set` triggering effects, and nested objects wrapped lazily on access. Explaining why `Object.defineProperty` was insufficient — no interception of property addition or deletion — demonstrates you understand the motivation and not just the API.
