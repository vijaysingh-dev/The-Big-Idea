# Secure Apex Coding and OWASP on Platform

## The premise

**Apex enforces nothing by default.**

```java
public class ClaimController {

    @AuraEnabled
    public static List<Warranty_Claim__c> getClaims(Id accountId) {
        return [
            SELECT Id, Claim_Number__c, Claim_Amount__c, Internal_Margin__c
            FROM Warranty_Claim__c WHERE Account__c = :accountId
        ];
    }
}
```

That method: runs without sharing when entered directly, ignores field-level security, returns a field the user cannot see, and accepts any account Id from any authenticated user.

Every one of those is a separate defect, and none of them produces an error.

## Broken access control

The OWASP category that accounts for most Salesforce security findings.

**Sharing enforcement:**

```java
public with sharing class ClaimController { }      // enforces sharing
public without sharing class ClaimController { }   // does not
public inherited sharing class ClaimController { } // inherits the caller's context
public class ClaimController { }                   // no keyword — without sharing when entered directly
```

**A class with no keyword runs without sharing when it is the entry point** — which for an `@AuraEnabled` method, a REST resource, or an invocable action means no record-level security at all.

**Declare a keyword on every class**, and `inherited sharing` where a utility should adopt the caller's context.

**Field-level security and CRUD:**

```java
// Enforces object permissions, field-level security, and sharing
List<Warranty_Claim__c> claims = [
    SELECT Id, Claim_Amount__c FROM Warranty_Claim__c
    WHERE Account__c = :accountId
    WITH USER_MODE
];

insert as user newClaims;
update as user existingClaims;
```

**`WITH USER_MODE` nulls fields the user cannot read** rather than throwing, which is usually the behaviour you want. `WITH SECURITY_ENFORCED` throws instead and is the older form.

**On the write path, `stripInaccessible`:**

```java
@AuraEnabled
public static void save(Warranty_Claim__c claim) {
    // a crafted request can set any field; stripping removes what the user cannot write
    SObjectAccessDecision decision = Security.stripInaccessible(
        AccessType.UPSERTABLE, new List<Warranty_Claim__c>{ claim }
    );

    upsert as user decision.getRecords();
}
```

**Without it, a component rendering three fields can write to any field on the object.** The client controls the sObject; the server must not trust it.

## Insecure direct object references

The finding most often missed, because the code looks correct.

```java
@AuraEnabled(cacheable=true)
public static Warranty_Claim__c getClaim(Id claimId) {
    // any authenticated user can pass any Id, regardless of what the UI renders
    return [
        SELECT Id, Claim_Number__c, Claim_Amount__c
        FROM Warranty_Claim__c WHERE Id = :claimId
        WITH USER_MODE
    ];
}
```

`WITH USER_MODE` enforces sharing, so this is safe **if the sharing model is correct**. Where it is not — a public read-only object, or a portal user with broad access — the caller can enumerate records.

**Verify entitlement explicitly** where the sharing model is not the control:

```java
@AuraEnabled(cacheable=true)
public static Warranty_Claim__c getClaim(Id claimId) {
    List<Warranty_Claim__c> claims = [
        SELECT Id, Claim_Number__c, Claim_Amount__c, Account__c
        FROM Warranty_Claim__c WHERE Id = :claimId WITH USER_MODE LIMIT 1
    ];

    if (claims.isEmpty() || !isEntitledTo(claims[0].Account__c)) {
        // 404-equivalent, so the response does not confirm the record exists
        throw new AuraHandledException(Label.Claim_Error_Not_Found);
    }

    return claims[0];
}
```

**Returning "not found" rather than "not permitted"** matters — the distinction confirms existence, which is itself information.

## Injection

**SOQL injection:**

```java
// Vulnerable
String query = 'SELECT Id FROM Warranty_Claim__c WHERE Claim_Number__c = \'' + userInput + '\'';
List<SObject> results = Database.query(query);
```

Input of `x' OR Name != '` returns everything.

```java
// Bind variables — the fix
String query = 'SELECT Id FROM Warranty_Claim__c WHERE Claim_Number__c = :claimNumber';
List<SObject> results = Database.queryWithBinds(
    query,
    new Map<String, Object>{ 'claimNumber' => userInput },
    AccessLevel.USER_MODE
);
```

**Bind variables handle values. They do not handle field names, object names, or clause structure**, which is where dynamic queries remain vulnerable:

```java
// Still vulnerable — the field name is concatenated
String query = 'SELECT Id FROM Warranty_Claim__c WHERE ' + fieldName + ' = :value';
```

**An allowlist is the only defence for identifiers:**

```java
private static final Set<String> FILTERABLE_FIELDS = new Set<String>{
    'Claim_Number__c', 'Status__c', 'Account__c'
};

public static List<Warranty_Claim__c> search(String fieldName, String value) {
    if (!FILTERABLE_FIELDS.contains(fieldName)) {
        throw new SecurityException('Field not permitted for filtering');
    }

    String query = 'SELECT Id, Claim_Number__c FROM Warranty_Claim__c WHERE '
        + fieldName + ' = :value';

    return Database.queryWithBinds(query,
        new Map<String, Object>{ 'value' => value }, AccessLevel.USER_MODE);
}
```

**`String.escapeSingleQuotes` is not sufficient** on its own — it protects a value in quotes and does nothing for a field name.

**SOSL injection** works identically, with `String.escapeSingleQuotes` and bind variables.

See [[08.7 - Dynamic SOQL]].

## Cross-site scripting

**In LWC**, the framework escapes by default:

```html
<!-- Escaped automatically -->
<p>{userSuppliedText}</p>
```

**`lwc:dom="manual"` and `innerHTML` bypass that:**

```javascript
// Vulnerable
this.template.querySelector('.output').innerHTML = userInput;
```

The ESLint rule `@lwc/lwc/no-inner-html` catches it. See [[21.9 - Static Analysis, PMD and Code Review]].

**In Visualforce**, escaping is on by default and frequently disabled:

```html
<!-- Escaped -->
<apex:outputText value="{!userInput}"/>

<!-- Not escaped — a deliberate vulnerability unless the content is trusted -->
<apex:outputText value="{!userInput}" escape="false"/>
```

**`escape="false"` requires justification.** Rendering user-supplied HTML means sanitizing it first, and Apex has no built-in sanitizer worth relying on.

**Rich text fields** store HTML. Rendering one with `lightning-formatted-rich-text` is safe; rendering it through `innerHTML` is not.

## Storing secrets

```java
// Wrong: readable by anyone who can query the setting
Integration_Settings__c settings = Integration_Settings__c.getInstance();
req.setHeader('Authorization', 'Bearer ' + settings.Api_Key__c);
```

**Custom Settings and Custom Metadata are queryable.** A credential in either is visible to every user with read access, and it travels in every package and every sandbox refresh.

```java
// Correct: the platform resolves the credential, no secret in code or data
req.setEndpoint('callout:ERP_System/api/claims');
```

**Named Credentials** hold the secret encrypted, handle token refresh, and deploy without their secrets. See [[13.13 - Named Credentials and External Credentials]].

**Any credential found in a custom setting should be rotated**, not just moved — it has been readable.

**Never send a session Id externally:**

```java
// A credential leak, and a specific security review finding
req.setHeader('Authorization', 'Bearer ' + UserInfo.getSessionId());
req.setEndpoint('https://external-system.com/api');
```

## CSRF

State-changing operations must not be triggerable by a crafted link.

**LWC and Aura have CSRF protection built in**, so an `@AuraEnabled` method is protected by the framework.

**Visualforce pages performing DML on page load are the vulnerability:**

```html
<!-- A GET request that changes data -->
<apex:page controller="ClaimController" action="{!approveClaim}"/>
```

A link to that page, clicked by an authenticated user, approves a claim.

**State changes belong behind a POST** — a `commandButton` in a form, not a page action.

## The guest user

The highest-risk surface, covered in [[17.9 - Experience Cloud Basics]] and worth restating.

**Every `@AuraEnabled` method a guest user can reach is a public endpoint on the internet.**

```java
@AuraEnabled(cacheable=true)
public static List<Knowledge__kav> getPublicArticles(String category) {
    // reachable by anyone; every constraint must be in the query
    return [
        SELECT Id, Title, Summary FROM Knowledge__kav
        WHERE PublishStatus = 'Online' AND IsVisibleInPkb = true
          AND Category__c = :category
        WITH USER_MODE
        LIMIT 50
    ];
}
```

**`without sharing` on a guest-reachable class is a breach waiting to happen.**

**A record Id from a guest request is untrusted**, always.

## Debug output and logging

```java
// A compliance problem created by debugging
System.debug('Processing contact: ' + JSON.serialize(contact));
```

**Debug logs are readable by anyone with the permission and are retained.** A log containing customer names, emails, or payment details is personal data in an unexpected place.

The same applies to a custom logging framework — log identifiers and context, not payloads. See [[20.5 - Custom Logging Frameworks]].

## The review checklist

```
Access control
  [ ] Sharing keyword on every class
  [ ] WITH USER_MODE on queries
  [ ] as user on DML
  [ ] stripInaccessible on inbound sObjects
  [ ] Entitlement verified for client-supplied record Ids
  [ ] Not-found returned rather than not-permitted

Injection
  [ ] Bind variables in every dynamic query
  [ ] Allowlist for field and object names
  [ ] escapeSingleQuotes where a value is concatenated

Output
  [ ] No innerHTML with user-supplied content
  [ ] No escape="false" without justification
  [ ] Rich text rendered through a safe component

Secrets
  [ ] Named Credentials, not custom settings
  [ ] No session Id sent externally
  [ ] No credentials in debug output

Entry points
  [ ] Every @AuraEnabled method treated as public
  [ ] Guest-reachable code reviewed specifically
  [ ] Parameters validated — size, range, format
  [ ] Batch sizes capped
```

## Automating the checks

```bash
sf scanner run --target force-app --severity-threshold 3
sf scanner run dfa --target force-app --projectdir force-app
```

**PMD catches the mechanical findings** — missing sharing keywords, unescaped output, concatenated queries.

**The Graph Engine traces data flow across method calls**, which is what identifies an injection path from an `@AuraEnabled` parameter through three methods into a dynamic query. That is the analysis PMD cannot do and the one that most often produces a security review finding. See [[21.9 - Static Analysis, PMD and Code Review]].

**Automate what can be automated**, and review the rest — entitlement checks and business-logic authorization are not detectable by a scanner.

## Testing security

```java
@IsTest
static void theControllerDoesNotLeakAnotherAccountsClaim() {
    User agent = TestUserFactory.create('Support Agent', 'Claim_Access');
    Warranty_Claim__c otherClaim = TestDataFactory.createClaimForAnotherAccount();

    Test.startTest();
    System.runAs(agent) {
        try {
            ClaimController.getClaim(otherClaim.Id);
            Assert.fail('The controller should not return an inaccessible claim');
        } catch (AuraHandledException e) {
            // expected
        }
    }
    Test.stopTest();
}
```

**Testing as an administrator proves nothing** — they see everything. Every security test runs inside `System.runAs`. See [[19.8 - Testing Security and Sharing]].

## Practical guidance

**Declare a sharing keyword on every class.**

**`WITH USER_MODE` on queries, `as user` on DML, `stripInaccessible` on inbound sObjects.**

**Verify entitlement for client-supplied record Ids**, and return not-found rather than not-permitted.

**Bind variables for values, an allowlist for identifiers.**

**Never `innerHTML` user content**, never `escape="false"` without justification.

**Named Credentials for secrets**, and rotate anything found in a custom setting.

**Treat every `@AuraEnabled` method as a public endpoint.**

**Never log personal data.**

**Run the Graph Engine**, not just PMD.

**Test as a real user**, never as an administrator.
