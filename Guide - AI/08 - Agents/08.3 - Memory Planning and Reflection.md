# Memory, Planning, and Reflection in Agents

## Overview

Three capabilities separate capable agents from simple tool callers:

- **Memory**: What the agent knows and remembers across steps and sessions
- **Planning**: How the agent breaks down complex tasks before acting
- **Reflection**: How the agent evaluates and corrects its own work

---

## Memory in Agents

Agent memory operates at multiple timescales:

```
Within a task (in-context):
  Working memory — current task state, recent observations, tool results

Across tasks (external):
  Episodic memory — "what happened when I did this task before"
  Semantic memory — "what do I know about this user/domain"
  Procedural memory — "how do I typically approach this type of task"
```

### Working Memory (In-Context)

The agent's context window IS its working memory. What's in the messages list is what the agent can reason about.

**Management challenges**:

- Long-running tasks can exceed the context window
- Each tool result adds tokens; after 10–15 tool calls, context is bloated
- Models perform worse with very long contexts (lost-in-the-middle)

**Pruning strategies**:

```python
def prune_agent_context(messages, max_tokens=50000):
    total = count_tokens(messages)
    if total <= max_tokens:
        return messages
    
    # Always keep: system prompt + first user message + last N messages
    system = [m for m in messages if m["role"] == "system"]
    first_user = next(m for m in messages if m["role"] == "user")
    recent = messages[-20:]  # last 20 messages always kept
    
    # Summarize the middle section
    middle = messages[1:-20]
    if middle:
        summary = summarize_tool_results(middle)
        middle_compressed = [{"role": "system", "content": f"Summary of earlier steps: {summary}"}]
    
    return system + [first_user] + middle_compressed + recent
```

### Episodic Memory (External Vector Store)

Store summaries of past agent runs, indexed by task type:

```python
class AgentEpisodicMemory:
    def __init__(self, vector_store):
        self.store = vector_store
    
    def save_episode(self, task: str, steps: list, outcome: str, user_id: str):
        summary = {
            "task": task,
            "approach": summarize_steps(steps),
            "outcome": outcome,
            "what_worked": extract_successful_patterns(steps),
            "what_failed": extract_failure_patterns(steps),
        }
        self.store.add(
            text=json.dumps(summary),
            metadata={"user_id": user_id, "task_type": classify_task(task)}
        )
    
    def retrieve_similar_episodes(self, task: str, user_id: str, top_k=3):
        return self.store.search(
            query=task,
            filter={"user_id": user_id},
            top_k=top_k
        )
```

At the start of a new task, inject relevant past episodes:

```python
episodes = memory.retrieve_similar_episodes(task, user_id)
if episodes:
    system_prompt += f"\n\nRelevant past experience:\n{format_episodes(episodes)}"
```

### Procedural Memory (Learned Patterns)

What the agent has learned about how to approach certain task types — encoded in the system prompt or retrieved via RAG:

```python
# A "playbook" for research tasks
RESEARCH_PLAYBOOK = """When researching a topic:
1. Start with a broad web search to understand the landscape
2. Identify 2-3 most authoritative sources
3. Search for contradicting viewpoints
4. Synthesize with explicit uncertainty marking
5. Always include recency context (when was this information published)
"""
```

## Planning

Planning = deciding the sequence of steps before executing them. Reduces wasted steps and improves task success rate.

### Plan-Then-Execute

```python
PLAN_PROMPT = """Given this task, create a step-by-step plan.
Each step should be specific and actionable. Identify which tool you'll use at each step.

Task: {task}

Plan (numbered list):"""

def plan_then_execute(task, tools, llm):
    # Step 1: Generate plan
    plan = llm.call(PLAN_PROMPT.format(task=task))
    steps = parse_plan(plan)
    
    # Step 2: Execute each step
    results = {}
    for step in steps:
        tool_name, args = step.tool, step.args
        results[step.id] = execute_tool(tool_name, args)
    
    # Step 3: Synthesize
    return synthesize(task, plan, results, llm)
```

**Advantage**: Model knows the full plan before executing. Each step is informed by awareness of what comes next.

**Disadvantage**: Plan may be invalidated by early results. A rigid plan fails when step 2's result changes what step 3 should be.

### Dynamic Replanning

After each tool result, reassess whether the plan is still valid:

```python
REPLAN_PROMPT = """Original plan: {plan}
Steps completed: {completed}
Latest result: {latest_result}

Is the original plan still appropriate? 
If not, output an updated plan for remaining steps.
If yes, output "CONTINUE"."""

def execute_with_replanning(task, tools, llm):
    plan = generate_initial_plan(task, llm)
    
    for step in plan:
        result = execute_step(step)
        
        # Check if replanning needed
        replan_decision = llm.call(REPLAN_PROMPT.format(
            plan=plan, completed=completed_steps, latest_result=result
        ))
        
        if replan_decision != "CONTINUE":
            plan = update_plan(plan, replan_decision)
```

## Reflection

Reflection = the agent evaluating its own output before returning it.

### Self-Critique Pattern

```python
CRITIQUE_PROMPT = """Review your answer to this task.

Task: {task}
Your answer: {answer}

Check for:
1. Does the answer actually address the task?
2. Are all claims supported by the tool results you gathered?
3. Is anything missing or incomplete?
4. Are there any logical errors?

If the answer is satisfactory, output "LOOKS GOOD".
If not, output specific issues that need to be fixed."""

def agent_with_reflection(task, tools, llm):
    # Initial attempt
    answer = run_agent(task, tools, llm)
    
    # Self-critique
    critique = llm.call(CRITIQUE_PROMPT.format(task=task, answer=answer))
    
    if critique.strip() == "LOOKS GOOD":
        return answer
    
    # Revise based on critique
    revised = run_agent(
        task=task,
        tools=tools,
        llm=llm,
        initial_context=f"Previous attempt had issues: {critique}\nTry again addressing these."
    )
    return revised
```

**When reflection helps**:

- Complex synthesis tasks where correctness is hard to verify mid-stream
- Tasks with explicit quality criteria to check against
- When false negatives (missing information) are costly

**When reflection doesn't help**:

- Simple factual queries (the agent is either right or wrong; critique doesn't help)
- When the agent is confidently wrong — it will confirm its wrong answer

## Verification Patterns

Stronger than reflection — actively verify claims using tools:

```python
def verify_claim(claim, tools, llm):
    """Try to find evidence that contradicts a claim."""
    VERIFY_PROMPT = f"""I made this claim: "{claim}"
    
Search for evidence that either confirms or contradicts this claim.
Use the web_search tool to find 2-3 relevant sources."""
    
    evidence = run_mini_agent(VERIFY_PROMPT, tools=["web_search"], llm=llm)
    
    ASSESS_PROMPT = f"""Claim: {claim}
Evidence found: {evidence}

Is the claim supported by the evidence? 
Output: SUPPORTED / CONTRADICTED / INSUFFICIENT_EVIDENCE
And brief explanation."""
    
    return llm.call(ASSESS_PROMPT)
```

Use verification for high-stakes claims (financial figures, medical information, legal statements).

## The Complexity Tax

Each capability adds complexity:

- Memory: requires external storage, sync, retrieval latency
- Planning: requires extra LLM calls before execution
- Reflection: doubles the number of LLM calls
- Verification: adds tool calls per claim

**Rule**: Add each capability only when you've measured that it improves task success in your evaluation set. Don't add all three by default — start minimal and add based on observed failure modes.
