# RAG Evaluation Frameworks

## Why RAG Evaluation is Different

RAG systems have two distinct failure modes that require separate measurement:

1. **Retrieval failure**: The right document wasn't retrieved
2. **Generation failure**: The right documents were retrieved but the answer is still wrong

Standard LLM evaluation (does the output match a reference?) conflates these. RAG evaluation must measure each component independently.

---

## The RAGAS Framework

RAGAS (Retrieval Augmented Generation Assessment) is the standard framework for RAG evaluation. It defines component-specific metrics computable without a labeled ground truth.

### Core RAGAS Metrics

**1. Faithfulness**

Is every claim in the generated answer supported by the retrieved context?

```python
# Algorithmic approach:
# 1. Break answer into atomic factual claims
# 2. For each claim, check if it can be inferred from the retrieved context
# 3. Faithfulness = supported_claims / total_claims

# Example:
answer = "Apple's revenue was $85.8B, up 12% YoY. The growth was driven by iPhone."
claims = [
    "Apple's revenue was $85.8B",          # ← Is this in context? Yes
    "Revenue was up 12% year-over-year",    # ← Is this in context? Yes
    "Growth was driven by iPhone",          # ← Is this in context? Yes
]
# Faithfulness = 3/3 = 1.0
```

Computed by an LLM judge that checks each claim against retrieved context.

**2. Answer Relevance**

Does the answer actually address the question asked?

```python
# Algorithmic approach:
# 1. Generate N questions that the answer would address (reverse engineering)
# 2. Compute cosine similarity between generated questions and original question
# 3. Answer relevance = mean similarity

# If answer is off-topic or irrelevant, generated questions won't match original
```

**3. Context Recall**

Was the information needed to answer the question present in the retrieved context? (Requires ground truth answer)

```python
# Algorithmic approach:
# 1. Break ground truth answer into statements
# 2. Check if each statement can be attributed to the retrieved context
# 3. Context recall = attributed_statements / total_statements
```

**4. Context Precision**

Were the retrieved chunks actually useful? Filters out noise in the context.

```python
# Context precision = useful_chunks / total_retrieved_chunks
# Penalizes over-retrieval of irrelevant content
```

### RAGAS in Practice

```python
from ragas import evaluate
from ragas.metrics import faithfulness, answer_relevance, context_recall

# Dataset format
dataset = {
    "question": ["What was Apple's Q3 revenue?", ...],
    "answer": ["Apple's Q3 2024 revenue was $85.8B...", ...],       # model output
    "contexts": [["[Retrieved chunk 1]", "[Retrieved chunk 2]"], ...],  # retrieved
    "ground_truth": ["Revenue was $85.8B", ...],                    # reference
}

results = evaluate(dataset, metrics=[faithfulness, answer_relevance, context_recall])
print(results)
# {'faithfulness': 0.92, 'answer_relevance': 0.87, 'context_recall': 0.78}
```

## Retrieval-Only Evaluation

Measure retrieval quality independent of generation:

### Recall@K

Is the relevant document in the top-K results?

```python
def recall_at_k(queries, relevant_docs_map, retriever, k=10):
    hits = 0
    for query, relevant_ids in queries.items():
        results = retriever.search(query, top_k=k)
        result_ids = {r.id for r in results}
        if any(rid in result_ids for rid in relevant_ids):
            hits += 1
    return hits / len(queries)
```

### MRR (Mean Reciprocal Rank)

How highly ranked is the first relevant result?

```python
def mrr(queries, relevant_docs_map, retriever, k=10):
    reciprocal_ranks = []
    for query, relevant_ids in queries.items():
        results = retriever.search(query, top_k=k)
        for rank, result in enumerate(results, 1):
            if result.id in relevant_ids:
                reciprocal_ranks.append(1.0 / rank)
                break
        else:
            reciprocal_ranks.append(0.0)
    return sum(reciprocal_ranks) / len(queries)
```

### nDCG@K (Normalized Discounted Cumulative Gain)

Measures ranking quality when relevance is graded (not binary):

```python
# Higher-ranked relevant results score higher than lower-ranked ones
# Normalized against ideal ranking
```

## Building an Evaluation Dataset

### Golden Set Construction

A golden set is a curated collection of (question, correct_answer, relevant_document_ids) triples:

```python
golden_set = [
    {
        "question": "What was Apple's Q3 2024 iPhone revenue?",
        "answer": "$39.3B",
        "relevant_doc_ids": ["earnings_q3_2024", "analyst_report_q3"],
        "metadata": {"category": "financial", "difficulty": "easy"}
    },
    ...
]
```

**How to build it**:

1. Collect 100–500 representative queries from real user traffic or domain experts
2. For each query, manually identify relevant documents and write the correct answer
3. Cover: easy/hard queries, different domains, edge cases, adversarial queries

**Maintenance**: Add to the golden set whenever you discover a retrieval or answer failure in production.

### Synthetic Dataset Generation

For rapid development, generate golden sets automatically:

```python
QUESTION_GEN_PROMPT = """
Based on this document chunk, generate 3 questions that can be answered 
using information in this chunk. Include the answer for each question.

Chunk: {chunk}

Output JSON: [{"question": "...", "answer": "..."}, ...]
"""

def generate_golden_set(chunks, llm):
    golden_set = []
    for chunk in chunks:
        qa_pairs = json.loads(llm.call(QUESTION_GEN_PROMPT.format(chunk=chunk.text)))
        for qa in qa_pairs:
            golden_set.append({
                "question": qa["question"],
                "answer": qa["answer"],
                "relevant_doc_ids": [chunk.document_id]
            })
    return golden_set
```

Synthetic sets are lower quality than manual but fast to generate for initial system development.

## Continuous Evaluation in Production

Run evaluation continuously against a fixed golden set on every model/prompt/index change:

```python
class RAGEvalPipeline:
    def run(self, rag_system, golden_set) -> EvalReport:
        results = []
        for example in golden_set:
            # Run full RAG pipeline
            retrieved_chunks, answer = rag_system.query(example["question"])
            
            # Score each metric
            result = {
                "question": example["question"],
                "recall_at_10": self.check_recall(retrieved_chunks, example["relevant_doc_ids"]),
                "faithfulness": self.score_faithfulness(answer, retrieved_chunks),
                "answer_correct": self.check_answer(answer, example["answer"]),
            }
            results.append(result)
        
        return EvalReport(results)
    
    def check_answer(self, generated, reference):
        # LLM-as-judge: does generated answer contain the correct information?
        return self.judge_llm.call(f"Is '{generated}' equivalent to '{reference}'? Answer yes/no.")
```

**Trigger eval on**:

- Embedding model change
- Chunking strategy change
- Retrieval parameter change (top-K, reranker threshold)
- Prompt template change
- New data connector added (did it affect existing queries?)

## Tracing Individual Failures

When a query returns a wrong answer, trace through the pipeline:

```
Wrong answer: "Revenue was $90B" (actual: $85.8B)
      │
      ├── Check retrieval: Was the earnings doc retrieved?
      │   ├── Yes → Generation failure (model misread context)
      │   └── No  → Retrieval failure
      │              ├── Check if doc is in index
      │              ├── Check embedding similarity for query
      │              └── Check if doc has correct permissions
      │
      └── If retrieval failure:
          ├── Keyword match? → Dense retrieval issue, check embedding quality
          ├── Exact term match? → BM25 issue, check index
          └── Metadata filter issue? → Check filter logic
```
