# Rapid Fire - JavaScript

Short answers for recall. Each links to the note with the full treatment — if an answer here does not feel solid, that link is where to go.

## Language fundamentals

**Difference between `var`, `let` and `const`?**
`var` is function-scoped, hoisted and initialized to `undefined`, redeclarable. `let` and `const` are block-scoped and sit in the temporal dead zone until their declaration executes. `const` cannot be reassigned but the value it points at can still be mutated. → [[05.1 - var let and const]]

**What is hoisting?**
Nothing moves. During the creation phase of an execution context, every declaration is registered before any code runs — `var` initialized to `undefined`, function declarations fully assigned, `let`/`const`/`class` left uninitialized. → [[05.2 - Hoisting and the Temporal Dead Zone]]

**What is the temporal dead zone and why does it exist?**
The span between entering a scope and a `let`/`const` declaration executing, during which access throws. It exists because `const` cannot sensibly start as `undefined`, and because use-before-declaration is almost always a bug worth failing loudly. Note `typeof` throws in the TDZ. → [[05.2 - Hoisting and the Temporal Dead Zone]]

**`==` vs `===`?**
`===` compares type and value with no conversion. `==` converts first: `null == undefined` is true and neither equals anything else; number vs string converts the string; booleans become numbers; objects convert to primitives. It is not transitive — `0 == ""` and `0 == "0"` are true but `"" == "0"` is false. → [[05.3 - Types Coercion and Equality]]

**`null` vs `undefined`?**
`undefined` is the engine's absence — unassigned variables, missing properties, omitted arguments. `null` is a deliberate absence someone assigned. Default parameters trigger on `undefined` only, never on `null`. → [[05.4 - null vs undefined]]

**Why is `typeof null === "object"`?**
A bug from the original implementation, where values were tagged by low bits and `null` was the null pointer sharing the object tag. Fixing it would break the web. → [[05.3 - Types Coercion and Equality]]

**What are the falsy values?**
`false`, `0`, `-0`, `0n`, `""`, `null`, `undefined`, `NaN`. Everything else is truthy — including `[]`, `{}` and `"0"`. → [[05.3 - Types Coercion and Equality]]

**Difference between `||` and `??`?**
`||` falls back on any falsy value; `??` only on `null` or `undefined`. Use `??` wherever `0`, `""` or `false` are valid. → [[05.7 - Optional Chaining and Nullish Coalescing]]

**Spread vs rest?**
Same syntax, opposite jobs. Spread expands where values are consumed; rest collects where they are declared. Both are shallow. → [[05.6 - Spread vs Rest]]

## Scope and functions

**What is a closure?**
A function together with the lexical environment it was defined in. It keeps that environment alive because the environment is still referenced. Closures capture **bindings**, not snapshots — later mutations are visible. → [[02.3 - Closures]]

**Explain lexical scope.**
Scope is determined by where code is written, not where it is called from. Each function stores a reference to its defining environment, and unresolved names walk that chain outward. → [[02.2 - Lexical Scope]]

**Why does `var` in a loop with `setTimeout` log the final value?**
One function-scoped binding shared by every callback. `let` creates a fresh binding per iteration and copies the current value into it. → [[02.3 - Closures]]

**What does `this` refer to?**
Determined by the call site, in priority order: `new` binding, explicit binding (`call`/`apply`/`bind`), implicit binding (the object left of the dot), then default (`undefined` in strict mode and modules). Arrow functions opt out and inherit lexically. → [[02.7 - this in JavaScript]]

**`call` vs `apply` vs `bind`?**
`call` invokes now with individual arguments; `apply` invokes now with an array; `bind` returns a new function with `this` permanently fixed. `bind` cannot be re-bound, though `new` overrides it. → [[02.8 - call apply and bind]]

**Difference between arrow and regular functions?**
Arrows have no own `this` (lexically inherited), no `arguments`, cannot be constructed, have no `prototype`, and cannot be generators. Never use one as an object or prototype method. → [[02.6 - Arrow Functions]]

**Currying vs partial application?**
Currying converts `f(a,b,c)` into a chain of unary functions `f(a)(b)(c)`. Partial application fixes some arguments and returns a function taking the rest. → [[02.9 - Currying and Partial Application]]

## Objects and prototypes

**Explain the prototype chain.**
Every object has an internal link to a prototype. Property reads walk that chain until found or until `null`. Writes never walk — assignment always creates an own property, which is why mutable state on a prototype is shared. → [[03.2 - The Prototype Chain]]

**`Fn.prototype` vs `__proto__`?**
`Fn.prototype` is a plain object on a function that becomes the prototype of instances created with `new`. `__proto__` (properly `Object.getPrototypeOf`) is the link an object itself uses for lookups. → [[03.2 - The Prototype Chain]]

**What does `new` do?**
Creates an object whose prototype is `Constructor.prototype`, calls the constructor with `this` bound to it, and returns the constructor's return value if it is an object, otherwise the new object. → [[03.2 - The Prototype Chain]]

**Are classes just syntactic sugar?**
Mostly, for method placement and prototype linking. But not for: TDZ behavior, forced strict mode, `new` enforcement, non-enumerable methods, `super` via `[[HomeObject]]`, private `#` fields, and correct built-in subclassing. → [[03.4 - Classes vs Prototypes]]

**Shallow vs deep copy?**
Shallow copies one level — spread, `Object.assign`, `slice`. Deep copies everything: `structuredClone` handles Dates, Maps, Sets and cycles; `JSON.parse(JSON.stringify())` silently loses Dates, `undefined`, functions, Maps, Sets and throws on cycles. → [[03.5 - Shallow vs Deep Copy]]

**What is a Symbol for?**
A unique primitive usable as a property key, so keys cannot collide. Well-known symbols like `Symbol.iterator` and `Symbol.toPrimitive` are language extension points. → [[03.6 - Symbols and Well Known Symbols]]

## Arrays and collections

**`map` vs `forEach`?**
`map` returns a new array of transformed values; `forEach` returns `undefined` and exists for side effects. `forEach` cannot break early or await. → [[06.1 - map filter reduce and forEach]]

**Why does `["1","2","3"].map(parseInt)` give `[1, NaN, NaN]`?**
`map` passes `(element, index, array)`, and `parseInt` reads the second argument as the radix. Radix 1 and 2 are invalid or wrong for those digits. → [[06.1 - map filter reduce and forEach]]

**Why pass an initial value to `reduce`?**
Without one, the first element becomes the accumulator, iteration starts at index 1, an empty array throws, and the accumulator type is unpredictable. → [[06.1 - map filter reduce and forEach]]

**`includes` vs `indexOf`?**
`includes` uses SameValueZero so it finds `NaN`; `indexOf` uses `===` and returns `-1` for `NaN`. Both are O(n) — use a `Set` for repeated lookups. → [[06.2 - find some every and includes]]

**When would you use a `Map` over an object?**
Non-string keys, guaranteed insertion order, O(1) `size`, direct iterability, no prototype collisions, and better performance under frequent insertion and deletion. → [[06.5 - Map and Set]]

**Why does the default `sort` order numbers wrongly?**
Without a comparator, elements are converted to strings and compared by UTF-16 code units, so `10` sorts before `9`. Also note `sort` mutates — use `toSorted` or spread first. → [[06.4 - Sorting and Comparators]]

**What is a generator?**
A function that can pause and resume, producing values lazily. Calling it runs no code; each `next()` runs to the following `yield`. `async/await` is implemented on the same machinery. → [[06.6 - Iterators and Generators]]

## Memory

**How does garbage collection work?**
By reachability from a set of roots, not reference counting — which is why cycles are collected. Modern engines use generational mark-and-sweep with cheap frequent minor collections and expensive infrequent major ones. → [[07.1 - How Garbage Collection Works]]

**What causes memory leaks in JavaScript?**
Uncleared timers and intervals, event listeners on long-lived targets, detached DOM nodes still referenced from JS, unbounded caches, and closures retaining more than they need. → [[07.2 - Memory Leaks from Closures and Timers]], [[07.3 - Memory Leaks from Listeners and Detached DOM]]

**What is a `WeakMap` for?**
Associating data with an object without preventing its collection. Keys must be objects, and it is not iterable — because enumerating it would make GC timing observable. → [[07.4 - WeakMap WeakSet and WeakRef]]

## Modules

**ESM vs CommonJS?**
ESM is static and analyzable (enabling tree shaking), gives live read-only bindings, loads asynchronously, is always strict, and supports top-level await. CJS is dynamic, copies values at require time, and loads synchronously. → [[08.1 - ES Modules vs CommonJS]]

**What is tree shaking and what does it require?**
Removal of unused exports. It requires static ES module syntax and accurate `sideEffects` metadata, because a module with import-time side effects cannot be safely dropped. → [[27.6 - Tree Shaking]]

**What is a Proxy used for?**
Intercepting fundamental object operations — get, set, has, delete. It is the mechanism behind Vue 3 reactivity and Immer's drafts. `Object.defineProperty` could not intercept property *addition*, which is why Vue rewrote it. → [[08.3 - Proxy and Reflect]]
