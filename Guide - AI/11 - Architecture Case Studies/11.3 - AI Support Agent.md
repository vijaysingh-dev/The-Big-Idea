# Architecture Case Study: AI Support Agent

## Product Definition

An AI support agent handles tier-1 customer support: answers questions from documentation, troubleshoots common issues, escalates to humans when needed. Reduces support ticket volume by 40–60%.

**Key difference from search/copilot**: Customer-facing, high reliability requirements, clear escalation path, must never make the company look bad.

---

## Requirements

```
Functional:
- Resolve 60%+ of tier-1 tickets without human involvement
- Graceful escalation to human agents with full context handoff
- Answer from: product docs, FAQ, known issue KB, past resolved tickets
- Collect structured information before escalating (account ID, steps to reproduce)
- Multi-channel: chat widget, email, Slack bot

Non-functional:
- Response latency: < 3s (customer-facing SLA)
- Availability: 99.9% (customer-facing)
- Safety: never provide incorrect billing/legal/security info
- Tone: consistent, professional, on-brand
- Escalation rate: < 40% (measure and optimize)
```

## Intent Classification

```python
INTENT_PROMPT = """Classify this support message into one category.

Categories:
- billing: payment, invoice, subscription, pricing questions
- technical_bug: something is broken, error message, unexpected behavior
- feature_request: asking for a capability that doesn't exist
- how_to: asking how to use an existing feature
- account: account access, password, permissions
- complaint: expressing dissatisfaction
- other: doesn't fit above

Message: {message}

Output JSON: {{"intent": "...", "confidence": 0.0-1.0, "keywords": ["..."]}}"""

def classify_intent(message: str) -> IntentResult:
    result = fast_llm.call(INTENT_PROMPT.format(message=message), temperature=0)
    return IntentResult(**json.loads(result))
```

**Route based on intent**:

- `billing` → RAG over billing docs only; flag for review if involves refunds
- `technical_bug` → RAG over KB + known issues; collect account ID + steps to reproduce
- `how_to` → RAG over docs; high confidence resolution expected
- `complaint` → empathy response + human escalation if severe

## Information Collection Before Escalation

When the agent can't resolve but before escalating to a human, collect structured context:

```python
INFO_COLLECTION_FLOWS = {
    "technical_bug": [
        "account_id",
        "error_message",
        "steps_to_reproduce",
        "browser_or_platform",
        "when_started",
    ],
    "billing": [
        "account_id",
        "invoice_number",
        "issue_description",
    ]
}

def collect_info(intent: str, already_collected: dict) -> str | None:
    required = INFO_COLLECTION_FLOWS.get(intent, [])
    missing = [field for field in required if field not in already_collected]
    
    if not missing:
        return None  # All info collected, can escalate
    
    # Ask for the next missing field naturally
    field = missing[0]
    return FIELD_QUESTIONS[field]

FIELD_QUESTIONS = {
    "account_id": "To help you faster, could you share your account ID or email address?",
    "error_message": "Could you copy and paste the exact error message you're seeing?",
    "steps_to_reproduce": "Could you walk me through the steps that lead to this issue?",
}
```

## Human Escalation with Context Handoff

```python
def escalate_to_human(session: SupportSession, reason: str):
    # Build a complete context summary for the human agent
    handoff_summary = {
        "customer": {
            "id": session.customer_id,
            "account_tier": session.customer_tier,
            "previous_tickets": session.ticket_history[:3],
        },
        "issue": {
            "intent": session.classified_intent,
            "description": session.issue_description,
            "collected_info": session.collected_info,
            "conversation_summary": summarize_conversation(session.messages),
        },
        "ai_attempts": {
            "responses_tried": len(session.ai_responses),
            "retrieved_docs": [r.title for r in session.last_retrieved],
            "why_escalating": reason,
        }
    }
    
    # Create ticket in support system (Zendesk, Freshdesk)
    ticket = support_system.create_ticket(
        customer_id=session.customer_id,
        subject=f"[AI Escalation] {session.issue_description[:100]}",
        description=format_handoff(handoff_summary),
        priority=calculate_priority(session),
        tags=["ai-escalated", session.classified_intent]
    )
    
    return f"I've connected you with our support team (ticket #{ticket.id}). They'll follow up within 4 hours."
```

## Safety Rules for Customer-Facing AI

These rules are non-negotiable and checked on every response:

```python
BLOCKED_PATTERNS = [
    r"guaranteed",               # "We guarantee..." — legal liability
    r"you (will|won't) be charged",  # billing commitments
    r"refund (your|the) money",  # financial commitments
    r"this is a (security|data) breach",  # security incidents need legal review
    r"your data (was|has been) (leaked|compromised)",
    r"\$\d+",                    # no specific dollar amounts
]

def validate_response(response: str) -> tuple[bool, str]:
    for pattern in BLOCKED_PATTERNS:
        if re.search(pattern, response, re.IGNORECASE):
            return False, f"Response contains disallowed pattern: {pattern}"
    return True, ""

def safe_respond(question, context, session):
    response = llm.call(build_support_prompt(question, context, session))
    safe, reason = validate_response(response)
    
    if not safe:
        # Escalate rather than give potentially harmful response
        return escalate_to_human(session, reason=f"Safety filter: {reason}")
    
    return response
```

## Deployment Architecture

```
Load Balancer
    │
    ├── Support API (3 replicas)
    │   FastAPI + Uvicorn
    │
    ├── Redis Cluster
    │   Session state + cache
    │
    ├── Vespa Cluster
    │   Knowledge base index
    │
    └── Celery Workers (2)
        Background: KB sync, ticket processing
```

Self-hosted LLM (Llama 3 70B via vLLM) considered vs API-based:

- API-based (gpt-4o-mini): chosen for reliability, managed scaling, no GPU ops
- Self-hosted: considered for cost at >5M tickets/month; not needed at current scale
