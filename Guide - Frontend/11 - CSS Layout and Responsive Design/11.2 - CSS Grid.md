# CSS Grid

Grid lays out content in **two dimensions** at once. The defining property is that you define the layout first and place content into it, rather than letting content sizes determine the arrangement.

## Defining a grid

```css
.grid {
  display: grid;
  grid-template-columns: 200px 1fr 200px;
  grid-template-rows: auto 1fr auto;
  gap: 1rem;
}
```

**`fr`** is the grid-specific unit: a fraction of the *leftover* space after fixed sizes and gaps are subtracted. `1fr 2fr` splits remaining space one-third and two-thirds.

An important subtlety: `1fr` is shorthand for `minmax(auto, 1fr)`, so a track will not shrink below its content's minimum size. Long words and wide tables cause overflow for the same reason as in flexbox. The fix:

```css
grid-template-columns: minmax(0, 1fr) minmax(0, 2fr);
```

This is the Grid equivalent of `min-width: 0` and is needed just as often.

## repeat, auto-fit and auto-fill

```css
grid-template-columns: repeat(3, 1fr);
grid-template-columns: repeat(auto-fit, minmax(250px, 1fr));
grid-template-columns: repeat(auto-fill, minmax(250px, 1fr));
```

The `auto-fit`/`auto-fill` line is the single most useful pattern in Grid — a responsive card layout with **no media queries**. Columns are at least 250px, as many as fit, sharing space equally.

The difference between the two:

- **`auto-fill`** creates as many tracks as fit, leaving empty ones if there is not enough content.
- **`auto-fit`** collapses empty tracks, so existing items stretch to fill the row.

With three cards in a container wide enough for five: `auto-fill` gives three cards at 250px with empty space; `auto-fit` gives three stretched cards. `auto-fit` is usually what you want.

## Placing items

```css
.item {
  grid-column: 1 / 3;        /* from line 1 to line 3 — spans 2 columns */
  grid-row: 2 / 4;
  grid-column: span 2;       /* span from wherever it is placed */
  grid-column: 1 / -1;       /* full width — -1 is the last line */
  grid-area: 2 / 1 / 4 / 3;  /* row-start / col-start / row-end / col-end */
}
```

Grid lines are numbered from 1, and negative numbers count from the end. `1 / -1` for full-width rows is worth memorizing.

## Named areas

The most readable form for page layout:

```css
.page {
  display: grid;
  grid-template-columns: 200px 1fr;
  grid-template-rows: auto 1fr auto;
  grid-template-areas:
    "header header"
    "sidebar main"
    "footer footer";
  min-height: 100dvh;
}

.header  { grid-area: header; }
.sidebar { grid-area: sidebar; }
.main    { grid-area: main; }
.footer  { grid-area: footer; }
```

Rearranging for mobile is a matter of rewriting the template, with no changes to any child:

```css
@media (width < 48rem) {
  .page {
    grid-template-columns: 1fr;
    grid-template-areas: "header" "main" "sidebar" "footer";
  }
}
```

A `.` in the template denotes an empty cell. Every named area must form a rectangle, or the whole declaration is invalid.

## Implicit tracks

Items placed beyond the explicit grid create implicit tracks, sized by `grid-auto-rows` / `grid-auto-columns`:

```css
.grid {
  grid-template-columns: repeat(3, 1fr);
  grid-auto-rows: minmax(150px, auto);   /* every implicit row: at least 150px */
  grid-auto-flow: row;                   /* or column, or "row dense" */
}
```

`grid-auto-flow: dense` backfills gaps left by items that could not fit, which produces a tighter masonry-like result — but it reorders items visually relative to the DOM, so the same accessibility caveat as flexbox `order` applies.

## Alignment

Grid has both axis-level and item-level alignment, in two families:

```css
.grid {
  justify-items: start | center | end | stretch;   /* items within their cell, inline axis */
  align-items: start | center | end | stretch;     /* items within their cell, block axis */
  place-items: center;                             /* shorthand for both */

  justify-content: start | center | space-between; /* the whole grid within the container */
  align-content: start | center | space-between;
  place-content: center;
}

.item {
  justify-self: end;
  align-self: center;
  place-self: center;
}
```

The `-items` versus `-content` distinction: `-items` positions each item inside its cell; `-content` positions the entire grid inside the container when the tracks do not fill it.

Perfect centering in two lines:

```css
.center { display: grid; place-items: center; }
```

## subgrid

```css
.card {
  display: grid;
  grid-row: span 3;
  grid-template-rows: subgrid;
}
```

A subgrid child adopts its parent's track sizing, so cards in a row can align their titles, bodies and footers to each other even with different content lengths. Before subgrid this required either fixed heights or JavaScript measurement.

Supported in all current browsers. It is the correct solution to the "make all card footers line up" problem.

## Overlapping and layering

Grid items can occupy the same cell, which makes overlays trivial without absolute positioning:

```css
.hero { display: grid; }
.hero > * { grid-area: 1 / 1; }   /* all children stack in the same cell */
```

Everything lands in cell 1/1, stacked in DOM order, and each can be aligned independently with `place-self`. This avoids the containing-block and stacking-context complications of absolute positioning ([[10.5 - Positioning and Stacking Contexts]]).

## The content-out grid

A widely used pattern for article layouts where most content is narrow but some elements break out full-width:

```css
.prose {
  display: grid;
  grid-template-columns:
    [full-start] minmax(1rem, 1fr)
    [content-start] min(65ch, 100% - 2rem) [content-end]
    minmax(1rem, 1fr) [full-start];
}

.prose > * { grid-column: content; }
.prose > .full-bleed { grid-column: full; }
```

Named lines make the intent readable, and adding a full-width image becomes one class rather than negative margins.

## Grid vs flexbox, again

Use Grid when you need alignment in both directions, when the layout is defined independently of content, or when items must line up across rows. Use flexbox for single-axis distribution where content sizes drive the result ([[11.1 - Flexbox]]).

In practice a page is a grid, and the components inside it are flex.

## Debugging

DevTools' grid overlay — the `grid` badge in the Elements panel — draws track lines, numbers, and named areas over the page. For grid, this is not optional tooling; line numbering is genuinely hard to reason about without it, especially with implicit tracks and negative indices.

## How senior engineers actually use this

**They use `repeat(auto-fit, minmax(Npx, 1fr))` for card grids** instead of writing breakpoints. One line replaces four media queries.

**They use named areas for page-level layout** because the CSS then documents the layout visually.

**They add `minmax(0, 1fr)` when tracks contain text or overflow containers**, for the same reason as `min-width: 0` in flexbox.

**They use the stacked-cell technique for overlays** rather than absolute positioning, avoiding stacking-context surprises.

**They pair Grid with container queries** so components adapt to their container rather than the viewport ([[11.3 - Responsive Design]]).

## Common pitfalls

- Track overflow from `1fr` not shrinking below content — needs `minmax(0, 1fr)`.
- Confusing `auto-fill` and `auto-fit` and getting stretched or unstretched cards.
- Non-rectangular named areas invalidating the entire `grid-template-areas`.
- Confusing `justify-items` with `justify-content`.
- `grid-auto-flow: dense` reordering content away from DOM order.
- Percentage `gap` resolving against the container size in ways that surprise.
- Reaching for Grid for a simple row of items where flexbox is simpler.

## Interview angle

Grid usually appears as "when would you use Grid over flexbox" and as a practical layout task — a holy-grail page layout or a responsive card grid. Have `grid-template-areas` and `repeat(auto-fit, minmax())` ready; both are short and demonstrate real familiarity. Mentioning `subgrid` for cross-card alignment and the stacked-cell overlay technique shows you use Grid beyond the basics.
