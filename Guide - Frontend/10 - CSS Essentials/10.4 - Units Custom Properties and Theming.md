# Units, Custom Properties and Theming

## Absolute vs relative units

```css
px      /* CSS pixel — not a device pixel; scales with zoom */
rem     /* relative to the ROOT font size */
em      /* relative to the ELEMENT's font size (or parent's, for font-size itself) */
ch      /* width of "0" in the current font */
ex      /* x-height */
%       /* relative to the parent's corresponding property */
vw vh   /* 1% of viewport width / height */
vmin vmax
svh lvh dvh  /* small / large / dynamic viewport height */
```

**`rem` is the default choice for font sizes and most spacing.** It respects the user's browser font-size setting, which `px` does not. A user who sets their default to 20px because of low vision gets a proportionally larger interface with `rem` and an unchanged one with `px`.

**`em` compounds**, which is occasionally the point and often a bug:

```css
.card { font-size: 1.2em; }
.card .card { font-size: 1.2em; }   /* 1.44em of the original */
```

`em` is genuinely useful for properties that should scale with their own element's text — padding on a button, `border-radius`, icon sizing:

```css
.button {
  padding: 0.5em 1em;   /* scales automatically with any font-size */
}
```

**`ch`** is the right unit for line length:

```css
.prose { max-width: 65ch; }   /* ~65 characters, the readable range */
```

**`dvh`** solves the mobile `100vh` problem — `vh` uses the largest viewport height, so `100vh` is taller than the visible area while the browser chrome is showing. `100dvh` tracks the actual visible height as chrome collapses.

Never set a `px` font-size on `html`, since that overrides the user's preference and defeats `rem` entirely.

## Modern colour

```css
color: rgb(11 85 51 / 0.5);      /* space-separated, slash for alpha */
color: hsl(150 77% 19%);
color: oklch(45% 0.12 155);       /* perceptually uniform */
color: color-mix(in oklch, var(--brand) 70%, white);
color: light-dark(#111, #eee);    /* picks by color-scheme */
```

`oklch` matters practically: unlike HSL, equal lightness values look equally light across hues. Generating a palette by varying lightness in HSL produces a yellow that looks much brighter than a blue at the same value; in OKLCH it does not. This is why design systems have largely moved to it.

`color-mix()` generates hover and disabled variants from one base colour without a preprocessor:

```css
.button:hover { background: color-mix(in oklch, var(--brand), black 10%); }
```

## Custom properties

```css
:root {
  --brand: #0b5;
  --space-1: 0.25rem;
  --space-4: 1rem;
  --radius: 0.5rem;
}

.card {
  padding: var(--space-4);
  border-radius: var(--radius);
  background: var(--surface, #fff);   /* fallback if undefined */
}
```

Two properties that distinguish them from preprocessor variables:

**They inherit and cascade.** Redefining a custom property on an element applies to that entire subtree ([[10.1 - The Cascade Specificity and Inheritance]]):

```css
.card { --brand: #b50; }        /* everything inside .card uses the new value */
```

**They are live at runtime.** JavaScript and media queries can change them, and everything using them updates:

```js
element.style.setProperty("--x", `${e.clientX}px`);
getComputedStyle(element).getPropertyValue("--brand");
```

This is what makes runtime theming possible without regenerating stylesheets.

Note the substitution is textual and happens at computed-value time, so you can build values from parts:

```css
:root { --shadow-color: 220 3% 15%; }
.card { box-shadow: 0 1px 3px hsl(var(--shadow-color) / 0.2); }
```

Invalid values behave surprisingly: `var()` that resolves to something invalid makes the property compute to its **inherited or initial value**, not to the previous declaration. This "invalid at computed-value time" behavior is a common source of confusion.

## @property

Registering a custom property gives it a type, a default and inheritance behavior:

```css
@property --angle {
  syntax: "<angle>";
  initial-value: 0deg;
  inherits: false;
}

.spinner {
  transition: --angle 1s;
}
```

Untyped custom properties cannot be animated or transitioned — the browser does not know how to interpolate a string. Registering the type makes gradient angles, colour stops and numeric values animatable, which was previously impossible.

## Theming

The standard pattern is semantic tokens layered over primitive ones:

```css
:root {
  /* primitives */
  --gray-50: oklch(98% 0 0);
  --gray-900: oklch(20% 0 0);
  --blue-500: oklch(60% 0.15 250);

  /* semantic tokens */
  --color-surface: var(--gray-50);
  --color-text: var(--gray-900);
  --color-accent: var(--blue-500);
}

[data-theme="dark"] {
  --color-surface: var(--gray-900);
  --color-text: var(--gray-50);
}
```

Components reference only semantic tokens. Switching themes reassigns a handful of variables; nothing else changes ([[28.10 - Design Systems and Component Libraries]]).

For system preference:

```css
:root { color-scheme: light dark; }

@media (prefers-color-scheme: dark) {
  :root:not([data-theme="light"]) {
    --color-surface: var(--gray-900);
  }
}
```

`color-scheme` is important and often missed — it tells the browser to render form controls, scrollbars and the default background in the matching scheme. Without it, a dark page has light scrollbars and white input backgrounds.

**The flash of wrong theme** is the classic bug: if the theme is read from `localStorage` in a `useEffect`, the page paints light before switching. The fix is a small blocking script in `<head>`, before any stylesheet:

```html
<script>
  document.documentElement.dataset.theme =
    localStorage.getItem("theme") ?? "system";
</script>
```

This is one of the very few places a render-blocking inline script is correct.

## Fluid sizing

```css
:root {
  --step-0: clamp(1rem, 0.95rem + 0.25vw, 1.125rem);
  --step-1: clamp(1.25rem, 1.1rem + 0.75vw, 1.5rem);
}

h1 { font-size: var(--step-1); }
```

`clamp()` replaces most typographic breakpoints. The caveat: a viewport-only value can prevent zoom from increasing text size, which fails an accessibility criterion — hence the `rem` component in the middle term, which keeps it responsive to the user's font size.

## Container queries and container units

```css
.card-wrapper { container-type: inline-size; container-name: card; }

@container card (width >= 30rem) {
  .card { grid-template-columns: 1fr 2fr; }
}

.card__title { font-size: clamp(1rem, 5cqi, 2rem); }
```

`cqi`, `cqw`, `cqh`, `cqb` are relative to the container, not the viewport. This makes a component genuinely reusable — the same card adapts whether it sits in a sidebar or a full-width grid, which viewport media queries cannot express ([[11.3 - Responsive Design]]).

## How senior engineers actually use this

**They define a spacing and type scale as custom properties on `:root`** and use nothing else. Arbitrary `13px` values scattered through a codebase are the main source of visual inconsistency.

**They separate primitive tokens from semantic tokens.** Components never reference `--blue-500` directly, only `--color-accent`, which makes rebranding and theming a single-file change.

**They use `rem` for anything text-related and `em` for element-relative spacing.**

**They set `color-scheme` and handle the theme flash with a blocking script.** Both are small and both are noticed immediately when missing.

## Common pitfalls

- `px` font sizes, ignoring user preferences.
- `html { font-size: 62.5% }` to make `rem` arithmetic easier — it breaks the user's setting.
- Compounding `em` in nested components.
- `100vh` on mobile.
- Missing `color-scheme`, giving light scrollbars on a dark page.
- Theme flash from reading storage in an effect.
- Assuming an invalid `var()` falls back to the previous declaration — it does not.
- Trying to animate an unregistered custom property.

## Interview angle

Units come up as "difference between `rem` and `em`" — answer with root versus element-relative, plus when compounding is desirable. Custom properties are usually asked as "how would you implement dark mode": semantic tokens redefined under a data attribute or media query, `color-scheme` for native controls, and a blocking script to avoid the flash. That last detail is the one that shows you have actually shipped a theme switcher.
