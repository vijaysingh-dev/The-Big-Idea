# The Box Model and Sizing

Every element is a rectangular box made of four nested areas: content, padding, border, margin.

```
+-------------------------------- margin ---+
|  +---------------------- border ------+   |
|  |  +--------------- padding ------+   |  |
|  |  |         content              |   |  |
|  |  +-----------------------------+   |  |
|  +-----------------------------------+   |
+-------------------------------------------+
```

## content-box vs border-box

The default, `content-box`, makes `width` mean the *content* width — padding and border are added on top:

```css
.box {
  width: 200px;
  padding: 20px;
  border: 2px solid;
  /* rendered width: 200 + 40 + 4 = 244px */
}
```

`border-box` makes `width` the total including padding and border:

```css
.box {
  box-sizing: border-box;
  width: 200px;
  padding: 20px;
  border: 2px solid;
  /* rendered width: 200px; content shrinks to 156px */
}
```

`border-box` is what almost everyone wants, because it makes `width: 50%` actually mean half the container regardless of padding. The universal reset:

```css
*, *::before, *::after { box-sizing: border-box; }
```

A slightly better version lets components opt out cleanly:

```css
html { box-sizing: border-box; }
*, *::before, *::after { box-sizing: inherit; }
```

Margin is **never** included in either. It is always outside the box.

## Margin collapsing

Adjacent vertical margins merge into one — the larger of the two, not their sum.

```html
<p style="margin-bottom: 20px">A</p>
<p style="margin-top: 30px">B</p>
<!-- gap is 30px, not 50px -->
```

Three cases where it happens:

**Adjacent siblings** — as above.

**Parent and first/last child** — a child's top margin escapes through the parent if there is nothing between them:

```css
.parent { }               /* no padding, no border */
.child { margin-top: 20px; }
/* the 20px appears ABOVE .parent, not inside it */
```

**Empty elements** — an element with no content, padding or border collapses its own top and bottom margins together.

Margin collapsing is blocked by: any padding or border on the parent, `overflow` other than `visible`, `display: flow-root`, any flex or grid container, absolute positioning, and floats.

```css
.parent { display: flow-root; }   /* creates a BFC, contains child margins */
```

Horizontal margins never collapse. Neither do margins inside flex or grid containers — which is one reason `gap` has largely replaced margin-based spacing.

## Block formatting contexts

A **BFC** is an independent layout region: floats inside it do not escape, margins do not collapse through it, and it does not overlap external floats.

Triggers: `overflow` not `visible`, `display: flow-root` (the purpose-built one), flex and grid containers, `position: absolute` or `fixed`, `contain: layout`, table cells, and `column-count`.

The historical `overflow: hidden` clearfix was really "create a BFC by side effect". `display: flow-root` does it without clipping anything.

## Sizing keywords

```css
width: auto;          /* fill available (block) or shrink to fit (inline-block) */
width: 100%;          /* percentage of the containing block's width */
width: min-content;   /* narrowest without overflow — longest word */
width: max-content;   /* widest — all content on one line, no wrapping */
width: fit-content;   /* max-content, clamped to available space */
width: stretch;       /* fill the container, accounting for margins */
```

`fit-content` is the useful one for buttons, tags and badges that should hug their content but never overflow.

Percentage heights need a definite parent height, which is why `height: 100%` so often does nothing. `100vh` or a grid/flex parent is usually the fix — and on mobile, `100dvh` accounts for the collapsing browser chrome that makes `100vh` too tall.

## min, max and clamp

```css
.card {
  width: clamp(300px, 50%, 600px);
}
```

`clamp(min, preferred, max)` is shorthand for `max(min, min(preferred, max))`. It replaces most breakpoint-based sizing.

Note `min-width` beats `width`, and `max-width` beats both — the constraint order is fixed regardless of source order.

`min-width: auto` on flex and grid items is the cause of the single most common layout bug in modern CSS: a flex item refuses to shrink below its content's intrinsic size, so long text or a wide table blows out the layout.

```css
.flex-item { min-width: 0; }      /* allow shrinking */
.grid-item { min-width: 0; }
```

Learning this one line saves hours.

## Overflow

```css
overflow: visible;   /* default — content spills out */
overflow: hidden;    /* clipped, no scrollbar, still scrollable by script */
overflow: scroll;    /* always shows scrollbars */
overflow: auto;      /* scrollbars only when needed */
overflow: clip;      /* clipped, not scrollable at all */
```

`overflow-x` and `overflow-y` can differ, but setting one to `hidden` and the other to `visible` forces the visible one to `auto` — a frequent surprise when trying to build a horizontally-scrolling row with overflowing dropdowns.

`overflow: clip` with `overflow-clip-margin` is the modern choice when you want clipping without creating a scroll container or a BFC.

## Text overflow

```css
.truncate {
  overflow: hidden;
  text-overflow: ellipsis;
  white-space: nowrap;
}

.clamp-lines {
  display: -webkit-box;
  -webkit-line-clamp: 3;
  -webkit-box-orient: vertical;
  overflow: hidden;
}
```

Single-line truncation needs all three properties. Multi-line clamping still requires the prefixed `-webkit-box` properties, which work in every browser despite the prefix; the standard `line-clamp` is arriving but is not yet universal.

## display and its effect on the box

```css
display: block;         /* full width, respects width/height */
display: inline;        /* flows with text, IGNORES width/height and vertical margins */
display: inline-block;  /* flows inline, respects width/height */
display: flex;          /* block-level flex container */
display: inline-flex;
display: grid;
display: none;          /* removed from layout and the accessibility tree */
display: contents;      /* box removed, children participate in the parent's layout */
```

`width` and `height` doing nothing on an inline element is a classic confusion — a `<span>` or `<a>` needs `inline-block` or a flex/grid context first.

`display: contents` is useful for unwrapping a component's wrapper div inside a grid, but it removes the element from the accessibility tree in some browser versions, so use it carefully on anything semantic.

## How senior engineers actually use this

**They set `border-box` globally, once, and never think about it again.**

**They use `gap` instead of margins for spacing inside flex and grid.** No collapsing, no last-child exceptions, no negative-margin tricks.

**They reach for `min-width: 0` the moment a flex layout overflows.** It is the answer roughly 80% of the time.

**They use `clamp()` for fluid sizing** rather than adding breakpoints for every size change.

**They inspect the box model in DevTools** rather than reasoning about it. The Computed pane's box diagram shows the actual content, padding, border and margin values, and hovering an element highlights each region in a different colour.

## Common pitfalls

- Forgetting `box-sizing: border-box`.
- Unexpected gaps from margin collapsing, especially a first child's margin escaping its parent.
- `height: 100%` doing nothing because the parent has no definite height.
- Flex items overflowing because of `min-width: auto`.
- `width` on an inline element having no effect.
- `100vh` being too tall on mobile browsers.
- Mixing `overflow-x: hidden` with `overflow-y: visible` and getting a scroll container.

## Interview angle

"Explain the box model" plus "difference between content-box and border-box" is close to guaranteed in any CSS screen. Give the four areas, the two sizing modes with a concrete arithmetic example, and note that margin is always outside. Margin collapsing and its escape hatches is the natural follow-up, and mentioning `min-width: 0` on flex items as a real-world gotcha tends to land well.
