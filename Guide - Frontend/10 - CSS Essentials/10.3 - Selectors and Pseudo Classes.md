# Selectors and Pseudo Classes

## Combinators

```css
.a .b       /* descendant — any depth */
.a > .b     /* direct child */
.a + .b     /* immediately following sibling */
.a ~ .b     /* any following sibling */
```

There is no "previous sibling" combinator and no parent combinator — `:has()` fills both gaps.

The child combinator is worth preferring over descendant when the structure is known, because it prevents styles leaking into nested instances of the same component.

## Attribute selectors

```css
[disabled]                /* attribute present */
[type="checkbox"]         /* exact value */
[class~="card"]           /* one of a space-separated list */
[lang|="en"]              /* exactly "en" or starting "en-" */
[href^="https"]           /* starts with */
[href$=".pdf"]            /* ends with */
[href*="example"]         /* contains */
[data-state="open" i]     /* case-insensitive */
```

These are how you style based on state without adding classes:

```css
[aria-expanded="true"] .chevron { rotate: 180deg; }
[data-loading] { pointer-events: none; opacity: 0.6; }
```

Driving styles off ARIA attributes is a good habit — it keeps the visual state and the accessible state from drifting apart, since they cannot diverge if one derives from the other.

## Structural pseudo-classes

```css
:first-child          :last-child          :only-child
:first-of-type        :last-of-type        :only-of-type
:nth-child(2n)                            /* even */
:nth-child(2n+1)                          /* odd */
:nth-child(3)                             /* the third */
:nth-child(n+4)                           /* fourth onward */
:nth-child(-n+3)                          /* first three */
:nth-last-child(2)                        /* second from the end */
:empty                                    /* no children, not even text */
```

`:nth-child(An+B of S)` filters first, then counts — genuinely useful when some children are hidden:

```css
li:nth-child(odd of :not(.hidden)) { background: #f5f5f5; }
```

The `-child` versus `-of-type` distinction: `p:first-child` means "a `<p>` that is the first child", which matches nothing if a `<h2>` comes first. `p:first-of-type` means "the first `<p>` among its siblings".

## :is, :where and :not

```css
:is(h1, h2, h3) > a { }          /* takes the highest specificity of its arguments */
:where(h1, h2, h3) > a { }       /* always zero specificity */
:not(.excluded) { }              /* takes the argument's specificity */
:not(.a, .b) { }                 /* multiple arguments allowed */
```

`:is()` collapses what used to be repetitive selector lists:

```css
/* Before */
.card h1, .card h2, .card h3 { margin-block: 0; }

/* After */
.card :is(h1, h2, h3) { margin-block: 0; }
```

`:where()` is for defaults you want easily overridable ([[10.1 - The Cascade Specificity and Inheritance]]).

A subtlety: `:is()` and `:where()` are **forgiving** — an unknown selector inside them does not invalidate the whole rule. A plain selector list is not: one bad selector in `a, b, :unknown` discards the entire rule.

## :has — the parent selector

```css
.card:has(img) { padding-top: 0; }
label:has(input:checked) { font-weight: bold; }
.form:has(:invalid) .submit { opacity: 0.5; }
article:has(> h2) { margin-top: 2rem; }
```

`:has()` styles an element based on its descendants — or, combined with sibling combinators, based on what follows it:

```css
h2:has(+ p) { margin-bottom: 0.5rem; }     /* h2 followed by a paragraph */
```

This removes a large category of JavaScript that existed purely to add classes to parents. It is not forgiving, and it cannot be nested inside another `:has()`.

Performance was the historical objection to a parent selector; browsers now implement it with invalidation optimizations, and it is fine in normal use. Avoid extremely broad forms like `*:has(*)`.

## State pseudo-classes

```css
:hover  :focus  :active  :visited  :target
:focus-visible      /* keyboard focus only — the one to use for outlines */
:focus-within       /* this element or any descendant has focus */
:disabled  :enabled  :checked  :indeterminate
:required  :optional
:valid  :invalid
:user-valid  :user-invalid    /* only after user interaction */
:placeholder-shown
:read-only  :read-write
:default  :in-range  :out-of-range
:autofill
```

The ones that matter most in practice:

**`:focus-visible`** — shows focus rings for keyboard users without showing them on mouse click, which is why it replaced the `outline: none` habit ([[09.5 - Accessibility Fundamentals]]).

**`:focus-within`** — highlight a form group when any field inside it is focused, with no JavaScript.

**`:user-invalid`** — validation styling that does not fire on an untouched empty required field ([[09.2 - Forms and Native Input Behavior]]).

**`:placeholder-shown`** — enables the floating-label pattern in pure CSS:

```css
.field label {
  transform: translateY(0);
  transition: transform 150ms;
}
.field input:placeholder-shown:not(:focus) + label {
  transform: translateY(1.5rem);
}
```

`:visited` is deliberately crippled for privacy — only colour-related properties apply, and `getComputedStyle` lies about it.

## Pseudo-elements

```css
::before  ::after        /* require a `content` property to render */
::first-line  ::first-letter
::selection              /* highlighted text */
::placeholder
::marker                 /* list bullets and numbers */
::backdrop               /* behind <dialog> and fullscreen elements */
::file-selector-button
```

```css
.tag::before {
  content: "#";
  color: var(--muted);
}

.icon::after {
  content: "";
  display: block;
  width: 1em;
  aspect-ratio: 1;
  background: url(icon.svg);
}
```

Two rules: `content` is mandatory (an empty string counts), and pseudo-elements cannot be created on replaced elements — `<img>`, `<input>`, `<br>`, `<video>` have no `::before` or `::after`.

Content generated with `content` is not reliably exposed to assistive technology and is not selectable or translatable, so it must never carry meaning. Decorative only.

`::marker` finally allows styling list bullets directly:

```css
li::marker { color: var(--brand); font-weight: bold; }
```

## Nesting

Native CSS nesting is now widely supported:

```css
.card {
  padding: 1rem;

  & .title { font-weight: 600; }

  &:hover { background: #f9f9f9; }

  @media (width >= 48rem) {
    padding: 2rem;
  }
}
```

The `&` is required when the nested selector starts with an element name, and optional otherwise — but writing it explicitly is clearer.

The same warning that applied to Sass applies here: deep nesting produces long, high-specificity selectors that are hard to override. Two levels is a reasonable ceiling.

## Performance

Browsers match selectors **right to left**, so the rightmost part (the "key selector") determines how many elements are considered.

```css
.sidebar * { }        /* every element in the document, then filtered — expensive */
.sidebar .link { }    /* only elements with .link — cheap */
```

In practice, selector matching is rarely the bottleneck in modern browsers. Style *invalidation* — how much has to be recalculated when something changes — matters more, which is why very broad selectors combined with frequently-toggled classes on `<body>` can cause noticeable recalculation ([[13.2 - Reflow Repaint and Composite]]).

## How senior engineers actually use this

**They drive state styling from data and ARIA attributes** rather than adding classes from JavaScript. One source of truth, and it keeps accessibility correct by construction.

**They use `:has()` to delete JavaScript.** Parent styling, "form has an error", "card contains an image" — all previously required class toggling.

**They keep selectors to one or two levels** and rely on component scoping (CSS Modules, scoped styles) rather than long descendant chains.

**They prefer `:focus-visible` over `:focus`** for outlines, universally.

## Common pitfalls

- `:first-child` when `:first-of-type` was meant.
- Forgetting `content` on `::before`/`::after`.
- Trying to add pseudo-elements to `<img>` or `<input>`.
- Meaningful text in `content`, invisible to screen readers.
- `:invalid` styling firing before interaction — use `:user-invalid`.
- One invalid selector in a comma list killing the whole rule.
- `:is()` unexpectedly raising specificity.

## Interview angle

Selector questions are usually rapid-fire: the four combinators, `:nth-child` versus `:nth-of-type`, and specificity of `:is`/`:where`/`:not`. The modern additions worth volunteering are `:has()` as a parent selector and `:focus-visible` for accessible focus styling — both are recent enough that mentioning them signals you keep up. The right-to-left matching detail is a good answer to "how would you optimize CSS performance".
