# Event Delegation

Attach one listener to a common ancestor and use bubbling to handle events from any descendant. It exists because listeners are per-element, but the *behavior* usually is not.

```js
// One listener per row — 1,000 listeners for 1,000 rows
rows.forEach(row => {
  row.addEventListener("click", () => select(row.dataset.id));
});

// One listener total
list.addEventListener("click", (e) => {
  const row = e.target.closest("[data-id]");
  if (!row || !list.contains(row)) return;
  select(row.dataset.id);
});
```

## The three benefits

**Fewer listeners.** Memory and setup cost scale with element count otherwise. For a virtualized table or an infinite feed this is not a micro-optimization.

**Dynamic content works automatically.** Rows added later need no wiring. Without delegation, every code path that inserts elements must remember to attach handlers — and one that forgets produces a silently dead button.

**Cleanup is trivial.** One listener to remove, so no per-element teardown and no leak risk from forgotten removals ([[07.3 - Memory Leaks from Listeners and Detached DOM]]).

## The correct matching pattern

```js
container.addEventListener("click", (e) => {
  const button = e.target.closest("button[data-action]");
  if (!button || !container.contains(button)) return;

  const { action, id } = button.dataset;

  switch (action) {
    case "delete": remove(id); break;
    case "edit":   edit(id);   break;
  }
});
```

Three details matter here:

**Use `closest()`, not `e.target` directly.** The click may land on a `<span>` or `<svg>` inside the button, so `e.target.matches("button")` fails intermittently — usually only when the user clicks the icon rather than the text, which makes it a maddening bug report.

**Verify containment.** `closest()` walks all the way up the document, so without the `container.contains(button)` check a click in a *sibling* container with the same markup can match. This matters when the same delegated handler is used for multiple regions or when portals place content elsewhere in the DOM.

**Dispatch on `data-action`**, not on class names. Classes are for styling and get renamed; a `data-action` attribute is an explicit behavioral contract.

## Events that do not bubble

`focus`, `blur`, `mouseenter`, `mouseleave`, `load` and `error` do not bubble, so they cannot be delegated directly. Use the bubbling equivalents:

| Non-bubbling | Delegate with |
| --- | --- |
| `focus` | `focusin` |
| `blur` | `focusout` |
| `mouseenter` | `mouseover` |
| `mouseleave` | `mouseout` |

Note `mouseover`/`mouseout` fire on every descendant boundary crossing, unlike `mouseenter`/`mouseleave`, so they need `relatedTarget` checks to avoid firing when moving between children:

```js
container.addEventListener("mouseout", (e) => {
  if (container.contains(e.relatedTarget)) return;  // still inside
  onLeave();
});
```

For non-bubbling events on many elements, capture-phase delegation is an alternative — capture reaches every element on the way down regardless of bubbling:

```js
container.addEventListener("focus", handler, { capture: true });
```

## Where delegation is the only reasonable option

**Infinite scroll and virtualized lists** — elements are constantly created and destroyed, so per-element listeners are both expensive and error-prone.

**Content from `innerHTML`** — listeners on replaced children are destroyed. Delegation on the stable parent survives.

**Third-party or CMS-rendered markup** you do not control:

```js
document.addEventListener("click", (e) => {
  const link = e.target.closest("a[href^='http']");
  if (link && !link.href.startsWith(location.origin)) {
    trackOutboundLink(link.href);
  }
});
```

**Global keyboard shortcuts:**

```js
document.addEventListener("keydown", (e) => {
  if (e.key === "Escape") closeTopmostOverlay();
  if (e.key === "k" && (e.metaKey || e.ctrlKey)) {
    e.preventDefault();
    openCommandPalette();
  }
});
```

Note this needs a guard so shortcuts do not fire while the user is typing:

```js
const tag = e.target.tagName;
if (tag === "INPUT" || tag === "TEXTAREA" || e.target.isContentEditable) return;
```

## Costs and limits

**Every event of that type in the subtree runs your handler.** A `mousemove` listener on `document` fires constantly; delegation is appropriate for discrete events (click, keydown, submit) and questionable for continuous ones without throttling ([[29.1 - Debounce and Throttle]]).

**`stopPropagation()` anywhere below breaks it.** A child component calling `stopPropagation` makes the delegated handler silently stop working, and nothing in either piece of code hints at the connection. This is the strongest argument against `stopPropagation` ([[12.3 - The Event Model]]).

**Disabled elements do not fire click events** in most browsers, so a delegated handler will not see clicks on a disabled button — usually desirable, occasionally surprising if you wanted to show a tooltip explaining why it is disabled. Wrap the button in that case.

## React does this for you

React attaches one listener per event type at the root container and dispatches through the component tree. So `onClick` on a thousand list items creates one native listener, not a thousand — the performance benefit of delegation is already there.

Manual delegation in React is therefore rarely about performance. It is worth it when:

```jsx
// A single handler reading the id from the DOM avoids one closure per row
function List({ items, onSelect }) {
  const handleClick = (e) => {
    const id = e.target.closest("[data-id]")?.dataset.id;
    if (id) onSelect(id);
  };

  return (
    <ul onClick={handleClick}>
      {items.map(item => (
        <li key={item.id} data-id={item.id}>{item.name}</li>
      ))}
    </ul>
  );
}
```

Compared with `onClick={() => onSelect(item.id)}` per row, this creates one stable function instead of N new ones per render — which matters when the rows are memoized, since a new callback prop defeats `React.memo` ([[19.2 - React.memo and Memoization Strategy]]).

For ten rows, use the inline arrow; it is clearer. For a virtualized list of thousands of memoized rows, delegation is the better trade.

## How senior engineers actually use this

**They use `closest()` with a containment check**, always. The two-line guard prevents both the icon-click bug and the wrong-container bug.

**They key behavior off `data-*` attributes**, keeping class names free for styling.

**They avoid `stopPropagation`** precisely because it breaks delegation invisibly.

**They delegate global concerns** — outbound link tracking, keyboard shortcuts, analytics on `[data-track]` elements — at the document level, once, in one place.

## Common pitfalls

- Using `e.target` instead of `closest()`, so clicks on nested icons miss.
- No containment check, matching elements outside the intended container.
- Trying to delegate `focus`, `blur`, `mouseenter` or `mouseleave`.
- Delegating `mousemove` or `scroll` without throttling.
- A descendant's `stopPropagation()` silently disabling the delegated handler.
- Matching on class names that later get renamed for styling reasons.
- Keyboard shortcut handlers firing while the user types in an input.

## Interview angle

"What is event delegation and why use it" is a standard question. Give the mechanism (bubbling plus one ancestor listener), the three benefits (fewer listeners, dynamic content, easy cleanup), and the `closest()` pattern with its containment check — the containment check is the detail most candidates omit. Adding that React already delegates internally, so the remaining benefit there is stable callback identity rather than listener count, shows you understand both layers.
