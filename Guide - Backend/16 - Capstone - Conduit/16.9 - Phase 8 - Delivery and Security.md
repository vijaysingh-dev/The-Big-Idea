# Phase 8: Delivery and Security

#backend #project #capstone

> **In one line:** The system works and is observable, and it is deployed by hand, running as root, with secrets in environment variables — this phase makes shipping it routine and makes the attack surface small.

---

## The Problem Phase 7 Created

```
Deploys: manual kubectl commands
Images:  running as root, 1.2GB, unscanned
Secrets: environment variables, never rotated
Auth:    a hand-rolled session, no SSO
Security testing: none
```

⚠️ **You have a well-engineered system nobody can deploy safely and an attack surface nobody has looked at.**

---

## What You Build

### The pipeline

```
On PR:
  lint + types            parallel    30s
  unit                    parallel    45s
  integration (4 shards)  parallel   120s
  contract                            40s
  migration lint                      10s
  schema compatibility                15s
  security scan                       45s
  build + image scan                 150s
  preview environment + smoke        180s
                          wall clock  ~6 min

On merge:
  migration job → wait
  deploy staging → smoke → error rate check
  deploy production → rollout status → error rate check
  auto-rollback if error rate > 1% for 5 minutes
```

💡 **Under 10 minutes to a verdict, zero flakiness.** Those two properties matter more than anything else in the pipeline ([[13.5 - CI CD Pipelines]]).

⚠️ **Nothing in the per-commit path requires another service running.** That is what contract tests buy you.

**The auto-rollback on error rate is what makes frequent deploys safe.** Without it, a bad Friday deploy is discovered by users.

### The production image

```dockerfile
# syntax=docker/dockerfile:1.10
FROM python:3.13-slim@sha256:... AS builder
RUN apt-get update && apt-get install -y --no-install-recommends gcc python3-dev \
    && rm -rf /var/lib/apt/lists/*
COPY requirements.txt .
RUN --mount=type=cache,target=/root/.cache/pip \
    pip install --prefix=/install --require-hashes -r requirements.txt

FROM python:3.13-slim@sha256:...
RUN groupadd -r -g 10001 app && useradd -r -u 10001 -g app app
COPY --from=builder /install /usr/local
WORKDIR /app
COPY --chown=10001:10001 . .
USER 10001
ENV PYTHONUNBUFFERED=1
CMD ["python", "-m", "uvicorn", "app.main:app", "--host", "0.0.0.0", "--port", "8000"]
```

⚠️ **`PYTHONUNBUFFERED=1` is not optional.** Without it, logs vanish when the container is killed — **which is exactly when you need them** ([[13.2 - Production Dockerfiles]]).

**One image, three roles:**

```yaml
- {name: api,       command: ["uvicorn", "app.main:app"]}
- {name: worker,    command: ["celery", "-A", "app", "worker"]}
- {name: scheduler, command: ["celery", "-A", "app", "beat"]}
```

💡 **Independent scaling and placement without separate services** ([[10.1 - Monolith Modular Monolith Microservices]]).

### The workload spec

```yaml
securityContext:
  runAsNonRoot: true
  runAsUser: 10001
  readOnlyRootFilesystem: true
  allowPrivilegeEscalation: false
  capabilities: {drop: ["ALL"]}
automountServiceAccountToken: false
terminationGracePeriodSeconds: 120
```

⚠️ **The extraction worker is the highest-risk component** — it runs third-party parsers over untrusted files. **No credentials, no network egress beyond what it needs, read-only root, strict resource limits.**

**Assume the parser will eventually be exploited and bound what that reaches** ([[14.4 - Common Vulnerabilities]]).

### Secrets, mostly eliminated

| Secret | Approach |
|---|---|
| Database credentials | **Workload identity** — no secret |
| Object storage | **Workload identity** — no secret |
| Embedding API key | Secret manager, mounted file, quarterly rotation |
| **Connector OAuth tokens** | **Encrypted with a dedicated DEK**, `org_id` as AAD |
| Webhook signing secret | **Dual-value**, quarterly |
| JWT signing key | KMS with `kid`, JWKS |

💡 **Two secrets eliminated entirely.** That is the first thing to reach for, and it is why the remaining list is short enough to manage ([[14.5 - Secrets and Key Management]]).

⚠️ **Every remaining secret must support two live values from the start.** Retrofitting dual-value support during an incident is much harder.

### Authentication, properly

```
Browser:      httpOnly cookie → opaque session in Redis, 24h idle
Services:     JWT, RS256, audience-scoped, 5 minutes
API keys:     hashed, prefixed ck_live_, scoped, shown once
Enterprise:   SAML and OIDC SSO, plus SCIM provisioning
```

💡 **Sessions for the browser, not JWTs.** Conduit needs immediate revocation — an admin removing a user must take effect now, not in fifteen minutes ([[14.2 - Sessions Tokens and Rotation]]).

⚠️ **SCIM matters more than expected.** Without it, an employee removed from the corporate directory keeps access to your product indefinitely ([[14.3 - OAuth2 and OIDC]]).

### The security automation

```yaml
- run: semgrep --config=./semgrep-rules --error
- run: pip-audit --require-hashes -r requirements.txt
- run: gitleaks detect --source . --redact
- run: trivy image --severity CRITICAL --exit-code 1 $IMAGE
- run: cosign sign $IMAGE
```

💡 **Custom `semgrep` rules are the highest-leverage security automation available:**

```
- f-string adjacent to execute/fetch
- subprocess with shell=True
- Pydantic model without extra="forbid"
- pickle.loads
- HTTP client call with a non-constant URL
- cache helper called without org_id
```

⚠️ **Fail on CRITICAL with a known fix; report the rest.** A policy that fails on every finding gets bypassed within a month ([[14.4 - Common Vulnerabilities]]).

## The Decisions

| Decision | Alternative | Because |
|---|---|---|
| **Sessions for browser auth** | JWTs | Immediate revocation |
| **JWTs between services only** | Sessions everywhere | Stateless verification where it helps |
| **Workload identity** | Secret manager for everything | No secret to leak or rotate |
| **Distroless-adjacent slim image** | Full base | Fewer CVEs, smaller surface |
| **One image, three roles** | Three images | One pipeline, no version skew |
| **GitOps (Argo CD)** | Push from CI | **CI holds no cluster credentials** |
| **Auto-rollback on error rate** | Manual | Makes frequent deploys safe |
| Custom semgrep rules | Review discipline | Caught at authorship |

💡 **The GitOps argument is stronger than it looks.** CI runs untrusted code from pull requests; **not giving it production credentials meaningfully shrinks the blast radius** ([[13.5 - CI CD Pipelines]]).

## What Will Go Wrong

### The pipeline is slow and flaky

⚠️ **A 40-minute pipeline means batched changes, which makes each deploy riskier.**

**Measure: total time, time to a lint failure, and the flakiness rate over 100 runs.** Anything above zero flakiness is a liability.

### `pull_request_target`

⚠️ **It runs with repository secrets and checks out the PR's code by default.** A fork can exfiltrate every secret you have.

**Reproduce it once in a throwaway repository with a dummy secret, then audit your real workflows.**

### The read-only root breaks things

⚠️ **Something will write to disk that you did not expect** — a temp file, a library cache, a matplotlib directory.

**Run with a read-only root and record every path it tries.** It is usually two or three.

### Signals do not reach PID 1

```
docker stop → 10 seconds → SIGKILL
```

⚠️ **Shell-form `CMD` means the shell is PID 1 and does not forward signals. Exec form alone is not sufficient either** if the process does not handle `SIGTERM` ([[13.1 - Containers From First Principles]]).

**Test all four combinations and time each.**

### Migrations on startup

⚠️ **N pods racing to run the same migration.** Most block on an advisory lock, delaying the deploy and possibly tripping readiness probes.

**Run migrations as a separate job that blocks the deploy on failure.**

### The account linking takeover

⚠️ **Automatic OIDC account linking by email is a documented takeover vector** ([[14.3 - OAuth2 and OIDC]]).

**Execute the attack against your own implementation, then fix it.**

## Acceptance Criteria

```
□  Pipeline under 10 minutes; lint failure in under 60 seconds
□  Flakiness rate zero across 100 runs
□  Registry layer caching; measured CI time reduction
□  Migrations as a separate job; a failure blocks the deploy
□  Auto-rollback fires on a deliberately bad deploy, timed
□  Image: non-root, read-only root, capabilities dropped, pinned by digest
□  One image serving three roles
□  Signals reach PID 1; docker stop under one second
□  Two secrets eliminated by workload identity
□  Every remaining secret supports dual-value rotation, tested
□  Session revocation takes effect immediately, measured
□  SCIM deprovisioning revokes access, with the delay measured
□  Custom semgrep rules fire on your own vulnerable code and run in CI
□  Unsigned images refused at admission
□  GitOps: a manual cluster edit is reverted
□  DORA metrics tracked over 20 changes
```

## What You Should Be Able To Explain

```
"How long from merge to production?"
  → About 14 minutes, of which 6 is the verdict. Auto-rollback if the
     error rate exceeds 1% for 5 minutes. Here are the DORA numbers

"Why sessions rather than JWTs for the browser?"
  → Revocation. An admin removing a user must take effect now.
     JWTs would give us a 15-minute window, and every fix for that
     reintroduces server-side state anyway

"What happens if your extraction worker is compromised?"
  → It has no credentials, no egress beyond object storage, a read-only
     root and strict resource limits. I tested what an attacker with
     code execution there can reach — it is nothing useful

"How do you rotate secrets?"
  → Two are eliminated by workload identity. The rest are dual-value:
     add, swap, remove. Three deploys, zero downtime. I practised it

"What is wrong with this system now?"
  → Search is lexical. It cannot answer "what did we decide about
     pricing" unless the document contains those words. Phase 9
```

## Codebase

**Repo:** `argoproj/argo-cd`, `sigstore/cosign`, `ory/kratos`

**Question to answer:** How does Argo CD detect drift between git and the cluster? Then: how does keyless signing and admission-time verification work?

**Read, in order:**

1. `argo-cd/controller/appcontroller.go` — the reconciliation loop and diff computation
2. `argo-cd/util/argo/diff/` — **normalisation.** Why comparing Kubernetes objects is hard: defaults, webhooks, managed fields
3. `sigstore/cosign` — **keyless signing via OIDC.** Removes key management entirely
4. `sigstore/policy-controller` — admission-time verification
5. `ory/kratos/session/` and `selfservice/` — a full identity system, including session revocation flows

💡 The Argo CD diff normalisation is the unglamorous, genuinely hard part — **deciding which differences to ignore is where GitOps tools earn their keep.**

**Size:** 2 sessions.

## Exercise

**Drill 16.9 — Ship it safely, then attack it**

⚠️ Security testing runs against your own stack only.

```
conduit/phases/08/
├── pipeline/{workflow.yml, timing.md, flakiness.md}
├── image/{Dockerfile, iterations/, MEASURE.md}
├── security/{semgrep-rules/, scan.sh, exploits/, FINDINGS.md}
├── secrets/{workload_identity.py, rotation.py, drill.md}
├── auth/{sessions.py, sso.py, scim.py, attacks/}
├── gitops/{argocd/, drift_test.sh}
├── adr/{041-pipeline.md ... 046-auth.md}
└── PHASE8.md
```

**Part 1 — Optimise the pipeline.** Build the slow version, measure it, then apply one change at a time: parallelisation, session-scoped containers, dependency caching, registry layer caching, test sharding, fastest-first ordering.

**Measure after each. Target: under 10 minutes, under 60 seconds to a lint failure.**

**Part 2 — Eliminate flakiness.** Write three flaky tests (shared state, `sleep`-based, wall-clock).

**Run 100 times, count failures per test.** Enable random ordering and confirm it exposes the order dependence.

**Fix all three, re-run 100 times, report before and after.**

**Part 3 — Image iterations.** Six versions from the naive baseline to hardened.

**Measure at each: size, cold build, warm build after a code change, CVE count, runs-as-root.**

**Then chart CVE count against image size** — the correlation should be strong.

**Part 4 — Signals and read-only root.** All four signal combinations, timed with `docker stop`.

Then run with `readOnlyRootFilesystem: true` and **record every path your application tries to write.** Mount `tmpfs` for each.

**Report how many you did not expect.**

**Part 5 — Deploy verification.** Deliberately deploy a version with a 5% error rate.

**Confirm auto-rollback fires. Measure time from deploy to rollback complete.**

Then a failing migration and **confirm the deploy does not proceed.**

**Part 6 — The security exploits.** Against your own code, on a branch:

| Exploit | |
|---|---|
| SSRF via a connector URL, including **DNS rebinding** | |
| Mass assignment setting `role` | |
| Stored XSS via an uploaded SVG | |
| **`pull_request_target` secret exfiltration** | Throwaway repo, dummy secret |
| Account linking takeover via unverified email | |

**Demonstrate each, then fix each structurally.**

**Part 7 — Secrets.** Eliminate two with workload identity. **Confirm no credential exists in configuration.**

Then dual-value rotation on the webhook secret: **single-value first, measure the failure window; then dual-value, confirm zero failures.**

Then the leak drill: commit a fake key, confirm pre-commit blocks it, bypass and confirm CI catches it, then run the full rotate-revoke-verify procedure and **time it.**

**Part 8 — Auth.** Sessions with immediate revocation — **measure the revocation window** against a JWT-only design.

Then SSO with SCIM: **deactivate a user in the directory and measure how long until access is revoked in Conduit.**

**Part 9 — GitOps and DORA.** Deploy via Argo CD. **Manually edit a Deployment and confirm drift is reverted.**

Then track DORA metrics over 20 changes. **Then deliberately batch changes weekly for another 20 and compare change failure rate and time to restore.**

**Done when:**
- Pipeline under 10 minutes with zero flakiness across 100 runs
- Your CVE-versus-size chart covers six image versions
- All four signal combinations are timed, and read-only root revealed unexpected write paths
- Auto-rollback fires on a bad deploy, timed
- All five exploits succeed and are then structurally prevented
- Two secrets are eliminated; dual-value rotation achieves zero failures
- Session revocation is immediate; SCIM deprovisioning delay is measured
- Argo CD reverts a manual cluster edit
- Your DORA numbers show batched deploys performing worse
