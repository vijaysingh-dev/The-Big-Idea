# Dataclasses

#python #dataclasses #oop

> **In one line:** `@dataclass` reads your annotated fields and generates `__init__`, `__repr__` and `__eq__` (plus ordering, hashing, slots and immutability on request). Use dataclasses for internal data, and Pydantic where data crosses a trust boundary and must be validated.

---

## The Basics

```python
from dataclasses import dataclass, field
from datetime import datetime, UTC

@dataclass
class Order:
    id: int
    customer_id: int
    items: list[str] = field(default_factory=list)      # NOT = [] (that raises ValueError)
    created_at: datetime = field(default_factory=lambda: datetime.now(UTC))
    notes: str = ""

o = Order(1, 42)
o                                  # Order(id=1, customer_id=42, items=[], created_at=..., notes='')
o == Order(1, 42, created_at=o.created_at)   # True — field-by-field equality
```

That is roughly 25 lines of boilerplate you no longer write, and cannot get subtly wrong.

## The Options That Matter

```python
@dataclass(frozen=True, slots=True, kw_only=True, order=False)
class Money:
    amount: Decimal
    currency: str
```

| Option | Effect | When |
|---|---|---|
| `frozen=True` | Assignment raises `FrozenInstanceError`; makes `__hash__` safe to generate | **Value objects**, config, events, cache keys |
| `slots=True` (3.10+) | Generates `__slots__` | Many instances; typo protection ([[06.4 - Slots]]) |
| `kw_only=True` (3.10+) | All fields are keyword-only in `__init__` | Many fields; avoid positional mix-ups. Also fixes "non-default argument follows default argument" in inheritance. |
| `order=True` | Generates `<`, `<=`, `>`, `>=` comparing fields as a tuple, in order | Sortable records. Mind the field order. |
| `eq=False` | Keeps identity equality | Entities compared by identity |
| `unsafe_hash=True` | Forces `__hash__` on a mutable class | Rarely. It is called unsafe for a reason ([[05.2 - Sets and Hashing Your Own Classes]]). |

The hashing rule: with `eq=True` (the default) and `frozen=False`, `__hash__` is set to `None`, so the instance is unhashable. With `frozen=True` it is hashable. That is the hash/eq contract enforced for you.

## field()

```python
@dataclass
class User:
    id: int
    email: str
    password_hash: str = field(repr=False)                  # keep secrets out of logs
    roles: set[str] = field(default_factory=set)
    _cache: dict = field(default_factory=dict, init=False, repr=False, compare=False)
    version: int = field(default=1, metadata={"db_column": "row_version"})
```

`repr=False` on secrets is a security habit worth keeping. Tracebacks and logs print reprs constantly.

## `__post_init__` and Derived Fields

```python
@dataclass
class Rect:
    w: float
    h: float
    area: float = field(init=False)

    def __post_init__(self):
        if self.w <= 0 or self.h <= 0:
            raise ValueError("dimensions must be positive")
        self.area = self.w * self.h
```

For frozen dataclasses, `__post_init__` must use `object.__setattr__(self, "area", ...)` to set derived fields. Small validations belong here. If validation logic grows (types, formats, nested data, error reporting), that is the sign you want Pydantic.

## Useful Functions

```python
from dataclasses import asdict, astuple, replace, fields

asdict(order)                   # recursive dict (deep-copies values; slow for big nested objects)
replace(money, amount=Decimal("5"))   # a new instance with changes — the frozen-object "setter"
[f.name for f in fields(Order)]
```

## Inheritance Gotcha

```python
@dataclass
class Base:
    id: int
    created: datetime = field(default_factory=now)

@dataclass
class Child(Base):
    name: str            # TypeError: non-default argument 'name' follows default argument
```

Fields are ordered parent first, and a field without a default cannot follow one with a default. Fix with `kw_only=True` on either class, or `name: str = field(kw_only=True)`.

## Dataclass vs the Alternatives

| | `NamedTuple` | `@dataclass` | `attrs` | Pydantic `BaseModel` |
|---|---|---|---|---|
| Validation of types at runtime | No | No | Optional validators | **Yes, always** |
| Type coercion (`"5"` → `5`) | No | No | Optional converters | Yes (lax mode) |
| Parsing JSON / dicts with nesting | No | No (manual) | With `cattrs` | **Yes** |
| JSON Schema / OpenAPI | No | Partial (via Pydantic) | No | **Yes** |
| Construction cost | Lowest | Low | Low | Higher (validation runs) |
| In the standard library | Yes | Yes | No | No |
| Best for | Tuple-like records | **Internal domain objects, DTOs between your own layers** | Same as dataclass, with more features | **Anything from outside: requests, config, external APIs, messages** |

The rule many teams use: **validate at the edges with Pydantic, pass trusted dataclasses (or Pydantic models) around inside.** Pydantic can validate into a standard dataclass too (`pydantic.dataclasses.dataclass`, or `TypeAdapter(MyDataclass)`), so you can keep the domain layer free of the Pydantic dependency if you want to.

## Codebase

**Repo:** `python/cpython`

**Question to answer:** How does `@dataclass` generate `__init__`, and why must it build a **new** class to add `__slots__`?

**Read, in order:**

1. `Lib/dataclasses.py` — `_process_class()`: collecting fields from `__annotations__` across the MRO
2. `_init_fn()` and `_create_fn()` (`_FuncBuilder` in 3.13+): the generated source text, then `exec`. Print the source of a generated `__init__` yourself by inspecting the builder.
3. `_hash_action`: the table that decides `__hash__` from `eq`, `frozen` and `unsafe_hash`
4. `_add_slots()`: why a new class object is needed (slots must exist when the class is created)

**Size:** 1 session.
