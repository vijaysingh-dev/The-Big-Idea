# Serialization and Structured Clone

Serialization is converting in-memory objects into something that can be stored or transmitted. Where you send it determines which algorithm applies — and each one loses different information.

## The two algorithms

**JSON** — text-based, used for network payloads and `localStorage`. Handles objects, arrays, strings, numbers, booleans and `null`. Nothing else.

**Structured clone** — binary, used by `postMessage`, `structuredClone()`, IndexedDB and the History API state. Handles most built-in types and cycles, but not functions.

## JSON.stringify

```js
JSON.stringify(value, replacer, space);
```

What it silently changes:

```js
JSON.stringify({
  date: new Date(),        // -> ISO string
  undef: undefined,        // key removed
  fn: () => {},            // key removed
  sym: Symbol(),           // key removed
  nan: NaN,                // -> null
  inf: Infinity,           // -> null
  map: new Map([[1, 2]]),  // -> {}
  set: new Set([1]),       // -> {}
  regex: /x/g,             // -> {}
  big: 1n,                 // throws TypeError
});
```

In arrays, `undefined`, functions and symbols become `null` rather than being dropped, because array indices cannot be omitted.

Circular references throw `TypeError: Converting circular structure to JSON`.

The `Date` conversion is the most consequential in practice: a `Date` goes out as a string and comes back as a string, so `.getTime()` fails at some distant call site. Revive explicitly:

```js
const ISO = /^\d{4}-\d{2}-\d{2}T/;

JSON.parse(text, (key, value) =>
  typeof value === "string" && ISO.test(value) ? new Date(value) : value
);
```

## toJSON

Any object can define how it serializes:

```js
class Money {
  constructor(amount, currency) {
    this.amount = amount;
    this.currency = currency;
  }
  toJSON() {
    return `${this.amount} ${this.currency}`;
  }
}

JSON.stringify({ price: new Money(500, "INR") });  // {"price":"500 INR"}
```

`Date.prototype.toJSON` is why dates become ISO strings. Defining `toJSON` on domain classes is the clean way to control API payloads, and it works recursively.

## replacer and reviver

```js
// Omit sensitive fields
JSON.stringify(user, (key, value) =>
  ["password", "token"].includes(key) ? undefined : value
);

// Serialize Maps and Sets
JSON.stringify(data, (key, value) => {
  if (value instanceof Map) return { __type: "Map", entries: [...value] };
  if (value instanceof Set) return { __type: "Set", values: [...value] };
  return value;
});
```

An array replacer acts as an allowlist of keys — simpler than a function when you just want to pick fields.

Handling cycles with a `WeakSet` ([[07.4 - WeakMap WeakSet and WeakRef]]):

```js
function safeStringify(obj) {
  const seen = new WeakSet();
  return JSON.stringify(obj, (key, value) => {
    if (typeof value === "object" && value !== null) {
      if (seen.has(value)) return "[Circular]";
      seen.add(value);
    }
    return value;
  });
}
```

## structuredClone

```js
const copy = structuredClone(original);
```

Handles what JSON cannot: `Date`, `RegExp`, `Map`, `Set`, `ArrayBuffer`, typed arrays, `Blob`, `File`, `ImageData`, `Error` (recent browsers), `BigInt`, `undefined`, `-0`, and **circular references**.

Throws `DataCloneError` on: functions, symbols, DOM nodes, class instances' prototypes (they come back as plain objects), property descriptors and getters (invoked, then copied as data).

It is the same algorithm `postMessage` uses, which is why the two restriction lists are identical — anything that cannot cross a thread boundary cannot be cloned ([[08.4 - Web Workers]]).

```js
structuredClone(value, { transfer: [buffer] });   // move instead of copy
```

## Performance

Rough ordering for large payloads, fastest first: native `JSON.parse` on a string, `structuredClone`, `JSON.parse(JSON.stringify())`.

`JSON.parse` is notably faster than an equivalent object literal for large data, because the parser is a tight C++ loop while an object literal must be compiled. This is why some bundlers emit large static configuration as `JSON.parse('{"...":...}')` rather than as an object literal — a real, measurable startup win at multi-megabyte scale.

Both `JSON.stringify` and `structuredClone` are **synchronous and blocking**. Serializing a 20 MB object freezes the main thread for hundreds of milliseconds ([[01.4 - The Event Loop]]).

## Where each is used

| Target | Algorithm | Notes |
| --- | --- | --- |
| `fetch` body | JSON | text only |
| `localStorage` / `sessionStorage` | JSON | strings only, manual conversion |
| IndexedDB | structured clone | stores `Date`, `Blob`, `Map` natively |
| `postMessage` (worker, iframe, `BroadcastChannel`) | structured clone | transferables available |
| `history.pushState` state | structured clone | size-limited (a few MB) |
| `structuredClone()` | structured clone | deep copy |

The IndexedDB point is underappreciated: it stores real `Date` objects and `Blob`s without any conversion, which is a genuine advantage over `localStorage` for structured data ([[14.3 - IndexedDB]]).

## localStorage specifics

Only strings, so everything round-trips through JSON with all its losses:

```js
function setItem(key, value) {
  try {
    localStorage.setItem(key, JSON.stringify(value));
  } catch (err) {
    if (err.name === "QuotaExceededError") evictOldEntries();
    else throw err;
  }
}

function getItem(key, fallback = null) {
  try {
    const raw = localStorage.getItem(key);
    return raw === null ? fallback : JSON.parse(raw);
  } catch {
    return fallback;   // corrupted or non-JSON data
  }
}
```

Both directions need guarding: writes can exceed the ~5 MB quota, and reads can encounter data written by an older version of your app or corrupted by a partial write. Silently falling back is usually better than crashing on boot.

Versioning stored data is worth doing from day one:

```js
const STORAGE_VERSION = 2;
// key: `app:v${STORAGE_VERSION}:settings`
```

Changing the key on a schema change avoids writing migration code for every historical shape.

## Alternatives

For large or performance-critical payloads, JSON is not the only option. **MessagePack** and **CBOR** are binary formats that are smaller and faster to parse. **Protocol Buffers** add a schema and are common in gRPC-backed systems. All require a library on both ends, so the tradeoff is bundle size and tooling against payload size — usually worth it only for high-frequency real-time data ([[15.8 - WebSockets and Server Sent Events]]).

Note that HTTP compression (gzip, Brotli) already shrinks JSON substantially over the wire, so the win from a binary format is mostly in *parse* time rather than transfer size.

## How senior engineers actually use this

**They normalize dates at the parse boundary.** One reviver in the API layer, so no component ever receives a date-shaped string ([[24.1 - Building an API Layer]]).

**They never persist class instances.** Storage holds plain data; classes are reconstructed on read. Trying to serialize instances always ends in a custom revival scheme that nobody maintains.

**They guard every storage read.** Data written by a previous version of the app is a certainty, not an edge case.

**They keep `postMessage` payloads small.** Design the worker protocol so the *result* crosses the boundary, not the raw input ([[08.4 - Web Workers]]).

## Common pitfalls

- Dates becoming strings and failing at a distant call site.
- `Map`, `Set` and `RegExp` silently becoming `{}`.
- `undefined` disappearing from objects but becoming `null` in arrays.
- `BigInt` throwing on stringify with no obvious cause.
- Circular references throwing in logging code, taking down a feature.
- `localStorage.getItem` returning the string `"null"` for a key that stored `null`, then `JSON.parse` turning it back — mostly harmless, but a source of confusion with `"undefined"`, which throws.
- Blocking the main thread on a large synchronous serialization.

## Interview angle

This usually appears as "what are the problems with `JSON.parse(JSON.stringify(obj))` for deep cloning" — answer with the lost types, the circular-reference throw, and `structuredClone` as the correct built-in. A follow-up about `postMessage` cost is common: messages are structured-cloned, so large payloads are copied synchronously, and transferables avoid that for binary data.
