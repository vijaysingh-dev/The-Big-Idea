# Decorator Pattern

## At a Glance

|||
|---|---|
|**Type**|Structural|
|**Intent**|Attach additional behavior to objects dynamically by wrapping them in decorator objects that implement the same interface|
|**Also Known As**|Wrapper|
|**Frequency in Backend**|★★★★★ — middleware, retry, caching, logging|

---

## The Problem It Solves

You need to add behaviors (logging, retry, auth, rate limiting, caching) to existing objects without modifying them. Subclassing creates a class explosion — `LoggingRetryingCachingUserService` is not maintainable.

---

## Structure

```
┌─────────────────┐
│   <<interface>> │
│   Component     │◀─────────────────────────────┐
├─────────────────┤                               │
│ + operation()   │                               │
└─────────────────┘                               │
        △                               ┌─────────┴──────────┐
        │                               │    Decorator        │
┌───────┴───────┐                       ├────────────────────┤
│ ConcreteComp  │                       │ - wrapped: Comp     │
│               │                       │ + operation()      │
│ + operation() │                       │   → wrapped.op()   │
└───────────────┘                       │   + extra behavior │
                                        └────────────────────┘
```

## Full Backend Example: HTTP Client Middleware Chain

```python
# http_client.py
from abc import ABC, abstractmethod
from dataclasses import dataclass
from typing import Optional
import time, logging, hashlib, json

@dataclass
class HttpRequest:
    method: str
    url: str
    headers: dict
    body: Optional[bytes] = None

@dataclass
class HttpResponse:
    status_code: int
    headers: dict
    body: bytes
    
    def is_success(self): return 200 <= self.status_code < 300
    def is_transient_error(self): return self.status_code in {429, 500, 502, 503, 504}


class HttpClient(ABC):
    """Component interface."""
    @abstractmethod
    def send(self, request: HttpRequest) -> HttpResponse: pass


class BaseHttpClient(HttpClient):
    """Concrete base — does the actual network call."""
    
    def send(self, request: HttpRequest) -> HttpResponse:
        import urllib.request
        req = urllib.request.Request(
            request.url,
            data=request.body,
            headers=request.headers,
            method=request.method
        )
        with urllib.request.urlopen(req) as resp:
            return HttpResponse(
                status_code=resp.status,
                headers=dict(resp.headers),
                body=resp.read()
            )


class HttpClientDecorator(HttpClient, ABC):
    """Base decorator — implements interface, wraps another client."""
    
    def __init__(self, wrapped: HttpClient):
        self._wrapped = wrapped
    
    def send(self, request: HttpRequest) -> HttpResponse:
        return self._wrapped.send(request)


class LoggingDecorator(HttpClientDecorator):
    """Decorator: log every request and response."""
    
    def __init__(self, wrapped: HttpClient, logger=None):
        super().__init__(wrapped)
        self._log = logger or logging.getLogger(__name__)
    
    def send(self, request: HttpRequest) -> HttpResponse:
        self._log.info(f"→ {request.method} {request.url}")
        start = time.monotonic()
        response = self._wrapped.send(request)
        elapsed = (time.monotonic() - start) * 1000
        self._log.info(f"← {response.status_code} in {elapsed:.1f}ms")
        return response


class RetryDecorator(HttpClientDecorator):
    """Decorator: retry on transient failures with exponential backoff."""
    
    def __init__(self, wrapped: HttpClient, max_retries: int = 3,
                 backoff_base: float = 1.0):
        super().__init__(wrapped)
        self._max_retries = max_retries
        self._backoff_base = backoff_base
    
    def send(self, request: HttpRequest) -> HttpResponse:
        last_response = None
        for attempt in range(self._max_retries + 1):
            try:
                response = self._wrapped.send(request)
                if not response.is_transient_error():
                    return response
                last_response = response
            except ConnectionError as e:
                if attempt == self._max_retries:
                    raise
                last_response = None
            
            if attempt < self._max_retries:
                sleep_time = self._backoff_base * (2 ** attempt)
                time.sleep(sleep_time)
        
        return last_response


class CachingDecorator(HttpClientDecorator):
    """Decorator: cache GET responses by URL."""
    
    def __init__(self, wrapped: HttpClient, cache: Cache, ttl_seconds: int = 300):
        super().__init__(wrapped)
        self._cache = cache
        self._ttl = ttl_seconds
    
    def send(self, request: HttpRequest) -> HttpResponse:
        # Only cache GET requests
        if request.method.upper() != "GET":
            return self._wrapped.send(request)
        
        cache_key = self._build_key(request)
        cached = self._cache.get(cache_key)
        if cached:
            return cached
        
        response = self._wrapped.send(request)
        if response.is_success():
            self._cache.set(cache_key, response, ttl=self._ttl)
        return response
    
    def _build_key(self, request: HttpRequest) -> str:
        key_data = f"{request.method}:{request.url}:{sorted(request.headers.items())}"
        return hashlib.sha256(key_data.encode()).hexdigest()


class AuthDecorator(HttpClientDecorator):
    """Decorator: inject auth headers automatically."""
    
    def __init__(self, wrapped: HttpClient, token_provider: TokenProvider):
        super().__init__(wrapped)
        self._tokens = token_provider
    
    def send(self, request: HttpRequest) -> HttpResponse:
        token = self._tokens.get_current_token()
        enriched_headers = {**request.headers, "Authorization": f"Bearer {token}"}
        enriched_request = HttpRequest(
            method=request.method,
            url=request.url,
            headers=enriched_headers,
            body=request.body
        )
        return self._wrapped.send(enriched_request)


class RateLimitDecorator(HttpClientDecorator):
    """Decorator: enforce max requests/second."""
    
    def __init__(self, wrapped: HttpClient, rps: int):
        super().__init__(wrapped)
        self._min_interval = 1.0 / rps
        self._last_call = 0.0
    
    def send(self, request: HttpRequest) -> HttpResponse:
        now = time.monotonic()
        elapsed = now - self._last_call
        if elapsed < self._min_interval:
            time.sleep(self._min_interval - elapsed)
        self._last_call = time.monotonic()
        return self._wrapped.send(request)


# Compose the chain — order matters!
# Rate limit → Auth (add token) → Cache (check before network) → Retry → Log → Base
client = LoggingDecorator(
    RetryDecorator(
        CachingDecorator(
            AuthDecorator(
                RateLimitDecorator(
                    BaseHttpClient(),
                    rps=10
                ),
                token_provider=JwtTokenProvider()
            ),
            cache=RedisCache(),
            ttl_seconds=60
        ),
        max_retries=3
    )
)

# Usage — caller unaware of decorators
response = client.send(HttpRequest("GET", "https://api.example.com/data", {}))
```

## Real-World Backend Scenarios

|Decorator|Wraps|
|---|---|
|Logging|Any service/repository|
|Caching|Repository, external API client|
|Retry|External API client, message producer|
|Auth guard|Service method, route handler|
|Rate limiter|API client, message producer|
|Metrics/tracing|Any service call|
|Circuit breaker|External dependency|
|Validation|Service input|

## Decorator vs Subclassing

```
Subclassing for combinations → class explosion:
LoggingUserService
RetryingUserService
CachingUserService
LoggingRetryingUserService          ← 2 behaviors = new class
LoggingCachingUserService           ← 2 behaviors = new class
RetryingCachingUserService          ← 2 behaviors = new class
LoggingRetryingCachingUserService   ← 3 behaviors = new class
[N behaviors = 2^N classes]

Decorator → compose at runtime:
client = LoggingDecorator(RetryDecorator(CachingDecorator(BaseClient())))
# 3 behaviors, 3 classes, any combination
```

---

## When NOT to Use Decorator

- **Simple single behavior** — just subclass or add the method
- **Need to introspect the chain** — hard to inspect what decorators are active
- **Order is complex and error-prone** — if ordering wrong decorators causes bugs, consider explicit pipeline
- **Many small decorators** — debugging stack traces become deep and confusing

---

## Tradeoffs

|Pro|Con|
|---|---|
|Composable — mix any combination|Deep chains hard to debug|
|OCP — add behavior without modifying|Lots of small classes|
|Runtime composition|Order of decoration matters (subtle bugs)|
|Single responsibility per decorator|Identity checks (`isinstance`) fail through wrapper|

---

## Common Mistakes

1. **Wrong decoration order** — auth before cache means uncached requests with no auth; cache before auth means cached responses bypass auth checks
2. **Stateful decorator in multi-threaded env** — `RateLimitDecorator` above is not thread-safe; use locks or atomic counters
3. **Decorator not forwarding all interface methods** — if interface grows, all decorators need updating

## Interview Perspective

> "How would you add retry and logging to your payment service without modifying it?"

Decorator pattern. Show the interface + `PaymentServiceDecorator` base + `LoggingPaymentDecorator` + `RetryPaymentDecorator`, then compose. Demonstrates OCP and single responsibility clearly.
