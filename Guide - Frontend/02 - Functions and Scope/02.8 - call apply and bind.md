# call, apply and bind

Three methods on `Function.prototype` that let you control `this` explicitly. They correspond to explicit binding, rule 2 in [[02.7 - this in JavaScript]].

## The difference in one block

```js
function introduce(greeting, punctuation) {
  return `${greeting}, I am ${this.name}${punctuation}`;
}

const user = { name: "Vijay" };

introduce.call(user, "Hello", "!");     // invokes now, args spread
introduce.apply(user, ["Hello", "!"]);  // invokes now, args as array
const bound = introduce.bind(user, "Hello");
bound("!");                             // returns a new function, invoked later
```

- **call** — invoke immediately, arguments listed individually.
- **apply** — invoke immediately, arguments as an array.
- **bind** — do not invoke; return a new function with `this` (and optionally leading arguments) permanently fixed.

The mnemonic: **a**pply takes an **a**rray; **c**all takes a **c**omma-separated list; **b**ind gives you back a function for later.

## bind is permanent

```js
function show() { return this.name; }

const a = { name: "A" };
const b = { name: "B" };

const boundA = show.bind(a);
boundA.call(b);        // "A" — rebinding has no effect
boundA.bind(b)();      // "A"
new (show.bind(a))();  // `new` DOES override bind
```

`bind` sets an internal `[[BoundThis]]` that later explicit binding cannot change. `new` is the sole exception, since it sits above explicit binding in the priority order.

Bound functions also lose their original `name` (they become `"bound show"`) and their `length` is reduced by the number of pre-supplied arguments.

## Partial application

`bind`'s extra arguments give you partial application for free:

```js
function request(method, url, body) { /* ... */ }

const get = request.bind(null, "GET");
const post = request.bind(null, "POST");

get("/api/users");
post("/api/users", { name: "Vijay" });
```

`null` as the first argument means "I do not care about `this`". This is the same idea developed further in [[02.9 - Currying and Partial Application]], where closures usually read better than `bind`.

## Borrowing methods

The historical use of `call` and `apply` was borrowing array methods for array-like objects — things with a `length` and numeric keys but no array prototype, such as `arguments` and `NodeList`.

```js
Array.prototype.slice.call(arguments);
Array.prototype.forEach.call(document.querySelectorAll("li"), fn);
```

Modern equivalents are almost always better:

```js
Array.from(document.querySelectorAll("li")).forEach(fn);
[...document.querySelectorAll("li")].forEach(fn);
```

One place borrowing survives is precise type checking, because `Object.prototype.toString` is not overridden the way `typeof` is unhelpful:

```js
const typeOf = v => Object.prototype.toString.call(v).slice(8, -1);

typeOf([]);        // "Array"
typeOf(null);      // "Null"
typeOf(new Date);  // "Date"
typeOf(/x/);       // "RegExp"
```

`typeof null === "object"` and `typeof []  === "object"` make this genuinely useful, and most library `isPlainObject` helpers are built on it.

## apply for spreading (mostly historical)

```js
Math.max.apply(null, numbers);   // old
Math.max(...numbers);            // modern
```

Both blow the stack on very large arrays — engines cap argument counts around 65,000 to 125,000. For a million-element array, use a reduce or a chunked loop instead.

## Implementing them

A frequent machine-coding question. The trick for `call` is to temporarily attach the function as a property of the target object so implicit binding applies, then delete it.

```js
Function.prototype.myCall = function (context, ...args) {
  context = context ?? globalThis;
  const key = Symbol("fn");
  context[key] = this;
  const result = context[key](...args);
  delete context[key];
  return result;
};

Function.prototype.myBind = function (context, ...preset) {
  const fn = this;

  function bound(...later) {
    const isNew = this instanceof bound;
    return fn.apply(isNew ? this : context, [...preset, ...later]);
  }

  bound.prototype = Object.create(fn.prototype ?? null);
  return bound;
};
```

Using a `Symbol` key avoids clobbering an existing property. The `isNew` check in `myBind` reproduces the rule that `new` overrides the bound `this`, and copying the prototype keeps `instanceof` working on instances created from the bound function. Interviewers look for exactly those two details.

## How senior engineers actually use this

**They rarely write these anymore.** Arrow functions cover the callback case, spread covers `apply`, and `Array.from` covers borrowing. The remaining everyday use is `bind` for event handlers in class components and for pre-configuring a function once.

**They use `Object.prototype.toString.call` in type guards.** Utility libraries and runtime validators still rely on it because it distinguishes `Date`, `RegExp`, `Map`, arrays and plain objects where `typeof` cannot.

**They bind once, never in render.** `bind` allocates a new function each call, so binding inside a render method produces a fresh prop identity every time and defeats `React.memo` ([[19.2 - React.memo and Memoization Strategy]]).

**They read these in library source constantly.** Polyfills, older frameworks and any code supporting ES5 targets are full of `call`/`apply`. Fluency here is mostly about reading comprehension.

## Common pitfalls

- Trying to rebind an already-bound function.
- Using `bind` inside a render or a hot loop and creating garbage plus new identities.
- Calling `apply` with a very large array and hitting the argument-count limit.
- Forgetting that `call`/`apply` on an arrow function silently does nothing.
- Passing `null` as `this` in sloppy mode, where it is coerced to the global object rather than staying `null`.

## Interview angle

"Difference between call, apply and bind" is near-guaranteed, often followed by "implement bind". Give the one-line distinction, then note that `bind` is permanent except under `new`, and that it supports partial application. For the implementation, handle the `new` case and the prototype chain — that is what the question is actually testing.
