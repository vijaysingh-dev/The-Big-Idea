# Pydantic in Production

#python #pydantic #fastapi #settings #production

> **In one line:** In a real service, Pydantic does four jobs: typed settings from the environment, request and response models in FastAPI, discriminated unions for polymorphic payloads and events, and `TypeAdapter` for validating anything that is not a model. Each has a few performance and safety rules worth knowing.

---

## 1. Settings From the Environment

```python
from functools import lru_cache
from pydantic import Field, PostgresDsn, SecretStr, AnyHttpUrl
from pydantic_settings import BaseSettings, SettingsConfigDict

class Settings(BaseSettings):
    model_config = SettingsConfigDict(
        env_prefix="CONDUIT_",
        env_file=".env",
        env_nested_delimiter="__",
        secrets_dir="/run/secrets",     # Docker/K8s secret files: one file per field
        extra="ignore",
    )

    env: Literal["dev", "staging", "prod"] = "dev"
    database_url: PostgresDsn
    redis_url: str = "redis://localhost:6379/0"
    jwt_secret: SecretStr
    allowed_origins: list[AnyHttpUrl] = []          # from JSON: CONDUIT_ALLOWED_ORIGINS='["https://a.com"]'
    db_pool_size: int = Field(10, ge=1, le=100)

@lru_cache
def get_settings() -> Settings:
    return Settings()
```

Why this beats `os.environ["X"]` scattered across the code:

- **Fail fast at startup.** A missing or malformed variable stops the process with a clear error, instead of a `KeyError` at 3 a.m. on the first request that needs it.
- **Types.** `"10"` becomes `10`, and `"true"` becomes `True`. Lists and nested objects come from JSON strings or `__`-delimited names.
- **Secrets stay secret.** `SecretStr` prints as `'**********'` in reprs and logs; you call `.get_secret_value()` deliberately.
- **One documented list** of every setting the service reads.

The 12-factor reasoning and secret rotation are in [[11.8 - Configuration and Secrets]] and [[15.5 - Secrets and Key Management]].

## 2. FastAPI Request and Response Models

```python
class OrderIn(ApiModel):
    items: list[ItemIn] = Field(min_length=1)
    coupon: str | None = None

class OrderOut(ApiModel):
    id: UUID
    status: OrderStatus
    total: Decimal
    created_at: datetime

@app.post("/orders", response_model=OrderOut, status_code=201)
async def create_order(body: OrderIn, user: CurrentUser) -> OrderOut:
    order = await service.place(user.id, body)
    return OrderOut.model_validate(order, from_attributes=True)
```

Rules that prevent real incidents:

| Rule | Why |
|---|---|
| **Separate input and output models** (`OrderIn`, `OrderOut`, `OrderPatch`) | One shared model lets clients set fields they should not (`status`, `id`, `is_admin`): **mass assignment** ([[15.4 - Common Vulnerabilities]]) |
| **Always declare a response model** | It filters output. Without it, adding a `password_hash` attribute to the ORM object leaks it to every client. |
| `extra="forbid"` on inputs | Typos and unexpected fields fail loudly |
| Do not return ORM objects with lazy relationships | Serialising may trigger lazy loads after the session is gone. Build the response explicitly. |
| Partial updates with `exclude_unset=True` | `patch.model_dump(exclude_unset=True)` gives only the fields the client actually sent, so "not sent" differs from "sent as null" |

## 3. Discriminated Unions

For payloads that can be one of several shapes (event types, payment methods, webhook bodies), tell Pydantic which field decides the type:

```python
from typing import Annotated, Literal, Union
from pydantic import BaseModel, Field, TypeAdapter

class CardPayment(BaseModel):
    method: Literal["card"]
    token: str
    last4: str

class BankPayment(BaseModel):
    method: Literal["bank"]
    iban: str

class WalletPayment(BaseModel):
    method: Literal["wallet"]
    provider: Literal["apple", "google"]

Payment = Annotated[Union[CardPayment, BankPayment, WalletPayment], Field(discriminator="method")]

class Checkout(BaseModel):
    order_id: UUID
    payment: Payment
```

| Without a discriminator | With one |
|---|---|
| Tries each union member in turn, may pick the wrong one when shapes overlap | Reads `method` and validates against exactly one model: O(1) and unambiguous |
| Errors from every member, hard to read | Errors only from the chosen model |
| OpenAPI shows `anyOf` | OpenAPI shows `oneOf` plus `discriminator`, so client generators produce proper types |

This is the right shape for event envelopes in a stream ([[10.2 - Event Modeling]]): a `type` literal per event plus versioned payload models.

## 4. TypeAdapter: Validating Non-Models

```python
from pydantic import TypeAdapter

ItemList = TypeAdapter(list[Item])
items = ItemList.validate_json(raw_bytes)          # parse + validate JSON in one Rust pass
ItemList.dump_json(items)

EventAdapter = TypeAdapter(Payment)               # validate a union directly
UserDict = TypeAdapter(UserPayload)               # a TypedDict — validated, stays a dict
```

⚠️ **Create `TypeAdapter`s once, at module level.** Building one compiles a schema, which is expensive. Creating it inside a request handler makes every request pay that cost.

---

## Performance Rules

| Do | Avoid |
|---|---|
| `Model.model_validate_json(raw_bytes)` | `Model.model_validate(json.loads(raw))` — two passes, and Python dicts in between |
| `model_dump_json()` for responses | `json.dumps(model.model_dump())` |
| Module-level `TypeAdapter`s | `TypeAdapter(...)` per call |
| Discriminated unions | Big plain unions on hot paths |
| `model_construct(**trusted)` for **already validated** data you built yourself | `model_construct` on anything from outside: it skips validation entirely |
| Plain dataclasses or tuples for millions of internal records | Millions of `BaseModel` instances in memory ([[07.2 - Dataclasses]]) |
| `defer_build=True` with very many models | Slow imports, slow test start-up |

A rough sense of scale: validating a small model from JSON costs on the order of a few to tens of microseconds in v2. For typical APIs it is far from the bottleneck, but in a loop over 1 million records it is seconds. See [[Assets.3 - Numbers To Know]].

## Pydantic and ORMs

```python
class UserOut(BaseModel):
    model_config = ConfigDict(from_attributes=True)
    id: int
    email: str

UserOut.model_validate(orm_user)       # reads attributes instead of dict keys
```

Keep ORM models (persistence) and Pydantic models (API boundary) **separate** unless the project is small. SQLModel merges them into one class, which is convenient early on and couples your API shape to your table shape later. The Repository pattern keeps the separation clean ([[02.20 - Repository Pattern]]).

## Migrating v1 → v2 (What Bites)

| v1 | v2 |
|---|---|
| `.dict()`, `.json()`, `.parse_obj()`, `.parse_raw()` | `.model_dump()`, `.model_dump_json()`, `.model_validate()`, `.model_validate_json()` |
| `@validator`, `@root_validator` | `@field_validator`, `@model_validator` |
| `class Config:` | `model_config = ConfigDict(...)` |
| `Optional[X]` implied a default of `None` | `X \| None` without a default is **required** |
| `int` field accepted `"1.0"` and numbers coerced to `str` | Stricter coercions: numbers are **not** coerced to `str` |
| `orm_mode = True` | `from_attributes=True` |
| `BaseSettings` in pydantic | Moved to the `pydantic-settings` package |

`bump-pydantic` automates most renames. The behaviour changes (optional fields, coercion) are what need tests.

## Codebase

**Repos:** `pydantic/pydantic-settings`, `fastapi/fastapi`

**Question to answer:** In what order does `BaseSettings` read sources (init kwargs, env vars, `.env`, secrets), and how does FastAPI use your response model to filter what an endpoint returns?

**Read, in order:**

1. pydantic-settings `pydantic_settings/main.py` — `BaseSettings._settings_build_values` and `settings_customise_sources`: the source priority order
2. pydantic-settings `pydantic_settings/sources/` — `EnvSettingsSource` (prefix and nested-delimiter handling), `SecretsSettingsSource`
3. FastAPI `fastapi/routing.py` — `serialize_response()`: the response is validated through the response model's field, which drops undeclared attributes
4. FastAPI `fastapi/_compat.py` — how FastAPI wraps Pydantic v2 `TypeAdapter`s for each field

**Size:** 1–2 sessions.
