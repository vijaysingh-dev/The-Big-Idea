# The itertools Toolkit

#python #itertools #iteration

> **In one line:** `itertools` is a set of fast, lazy building blocks for iterators: slice, chain, group, batch, combine and accumulate without building lists. Learn the dozen below and many hand-written loops become one clear line.

---

## The Ones You Will Use Weekly

| Function | Does | Example |
|---|---|---|
| `islice(it, stop)` / `islice(it, start, stop, step)` | Slice any iterator lazily | First 10 lines of a file |
| `chain(a, b, ...)`, `chain.from_iterable(its)` | Concatenate iterables | Merge results from several shards |
| `batched(it, n)` (3.12+) | Tuples of n items; the last may be shorter | Bulk insert 500 rows at a time |
| `groupby(it, key)` | Group **consecutive** items with the same key | Rows already sorted by user |
| `pairwise(it)` (3.10+) | `(a, b), (b, c), ...` | Deltas between timestamps |
| `accumulate(it, func=add)` | Running totals (or running anything) | Cumulative revenue |
| `count(start, step)` | Infinite counter | IDs, retry attempt numbers |
| `cycle(it)` | Repeat forever | Round-robin over backends |
| `repeat(x, n)` | x, n times | Default values for `zip` |
| `zip_longest(a, b, fillvalue=)` | `zip` without truncation | Align columns of uneven length |
| `takewhile(pred, it)`, `dropwhile(pred, it)` | Prefix while true / after it stops being true | Skip a file header |
| `tee(it, n)` | Split one iterator into n | Two consumers of one stream (with caveats) |
| `product`, `permutations`, `combinations` | Combinatorics | Test matrices, brute-force search |
| `starmap(f, it)` | `f(*args)` for each tuple | Apply to pre-packed arguments |
| `compress(data, selectors)` | Keep items where the selector is truthy | Mask-based filtering |

## Patterns

### Batching for bulk work

```python
from itertools import batched

for chunk in batched(user_ids, 1000):
    await conn.executemany(UPSERT, [(uid,) for uid in chunk])
```

Before 3.12, the recipe was `iter(lambda: list(islice(it, n)), [])`.

### groupby: the sort-first rule

```python
from itertools import groupby
from operator import itemgetter

rows.sort(key=itemgetter("user_id"))              # REQUIRED: groupby only groups adjacent items
for user_id, items in groupby(rows, key=itemgetter("user_id")):
    total = sum(r["amount"] for r in items)       # `items` is consumed as the loop advances
```

⚠️ Two traps: forgetting to sort (you get the same key several times), and storing `items` for later (it is a view into the shared iterator and is empty once the loop moves on; use `list(items)`). For unsorted data, a `defaultdict(list)` is usually clearer ([[05.3 - The collections Module]]).

### Pairwise deltas

```python
from itertools import pairwise
gaps = [b.ts - a.ts for a, b in pairwise(events)]
slow = [(a, b) for a, b in pairwise(events) if b.ts - a.ts > timedelta(seconds=5)]
```

### Round-robin over backends

```python
from itertools import cycle
backends = cycle(["10.0.0.1", "10.0.0.2", "10.0.0.3"])
def pick(): return next(backends)
```

That is the core of round-robin load balancing ([[04.2 - Load Balancer]] in the HLD guide builds one).

### Peeking at the first item

```python
from itertools import chain
def peek(it):
    it = iter(it)
    try:
        first = next(it)
    except StopIteration:
        return None, iter(())
    return first, chain([first], it)
```

### Infinite with a limit

```python
from itertools import count, islice
for attempt in islice(count(1), max_retries):
    ...
```

## tee: Use With Care

`tee(it, 2)` gives two independent iterators over one source by buffering everything one has seen that the other has not. If one consumer runs far ahead, the buffer holds the whole gap in memory. If both consume roughly in lockstep, it is fine; otherwise `list()` the data once.

Also: after calling `tee`, never use the original iterator again.

## more-itertools

The `more-itertools` package fills the gaps: `chunked`, `windowed`, `peekable`, `first`, `one`, `unique_everseen`, `bucket`, `split_at`, `partition`, `spy` and more. Many itertools "recipes" from the docs live there, ready to install.

```python
from more_itertools import one, first, windowed, unique_everseen
user = one(results)                 # exactly one item, or raise — great for "should be unique" queries
for w in windowed(prices, 7): ...   # sliding window
```

## Codebase

**Repos:** `python/cpython`, `more-itertools/more-itertools`

**Question to answer:** How does `groupby` share a single underlying iterator between the outer loop and each group, and why does that make stored groups go empty?

**Read, in order:**

1. The itertools docs page — each function lists "roughly equivalent" pure-Python code. Read the equivalents for `groupby`, `tee`, `batched` and `accumulate`. They are the specification.
2. The "Itertools recipes" section at the bottom of the same page
3. more-itertools `more_itertools/more.py` — `peekable`, `windowed` and `one`. Clean, readable generator code.
4. CPython `Modules/itertoolsmodule.c` — `groupby_next` and `_grouper_next`: see the shared `tgtkey` / `currkey` state

**Size:** 1 session.
