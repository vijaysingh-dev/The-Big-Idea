# Navigation and NavigationMixin

## Never build URLs by hand

```javascript
// Wrong in several ways
window.location.href = '/lightning/r/Warranty_Claim__c/' + claimId + '/view';
```

That breaks in the mobile app, breaks in Experience Cloud, breaks in a console by navigating away instead of opening a tab, and breaks if the URL format changes.

`NavigationMixin` produces the right behaviour for whatever context the component is running in.

```javascript
import { LightningElement, api } from 'lwc';
import { NavigationMixin } from 'lightning/navigation';

export default class ClaimRow extends NavigationMixin(LightningElement) {
    @api claim;

    navigateToClaim() {
        this[NavigationMixin.Navigate]({
            type: 'standard__recordPage',
            attributes: {
                recordId: this.claim.Id,
                objectApiName: 'Warranty_Claim__c',
                actionName: 'view'
            }
        });
    }
}
```

**The class extends `NavigationMixin(LightningElement)`**, and the methods are accessed with bracket notation because they are symbols.

## The page reference types

```javascript
// A record
{ type: 'standard__recordPage',
  attributes: { recordId, objectApiName: 'Warranty_Claim__c', actionName: 'view' } }

// New record, with prefilled fields
{ type: 'standard__objectPage',
  attributes: { objectApiName: 'Warranty_Claim__c', actionName: 'new' },
  state: { defaultFieldValues: encodeDefaultFieldValues({ Asset__c: assetId }) } }

// An object's list view
{ type: 'standard__objectPage',
  attributes: { objectApiName: 'Warranty_Claim__c', actionName: 'list' },
  state: { filterName: 'Open_Claims' } }

// A related list
{ type: 'standard__recordRelationshipPage',
  attributes: { recordId, objectApiName: 'Asset', relationshipApiName: 'Warranty_Claims__r',
                actionName: 'view' } }

// A custom tab
{ type: 'standard__navItemPage', attributes: { apiName: 'Claim_Dashboard' } }

// A Lightning component as a page
{ type: 'standard__component',
  attributes: { componentName: 'c__claimWizard' },
  state: { c__assetId: assetId } }

// An external URL
{ type: 'standard__webPage', attributes: { url: 'https://erp.northwind.com/claims/4471' } }

// A Visualforce page
{ type: 'standard__webPage',
  attributes: { url: '/apex/ClaimPdf?id=' + claimId } }

// An Experience Cloud page
{ type: 'comm__namedPage', attributes: { name: 'Claim_Status__c' } }

// The home page
{ type: 'standard__namedPage', attributes: { pageName: 'home' } }
```

## Prefilling a new record

```javascript
import { encodeDefaultFieldValues } from 'lightning/pageReferenceUtils';

createClaimForAsset() {
    // encodeDefaultFieldValues handles the encoding the state parameter requires
    const defaults = encodeDefaultFieldValues({
        Asset__c: this.assetId,
        Account__c: this.accountId,
        Claim_Date__c: new Date().toISOString().slice(0, 10)
    });

    this[NavigationMixin.Navigate]({
        type: 'standard__objectPage',
        attributes: { objectApiName: 'Warranty_Claim__c', actionName: 'new' },
        state: { defaultFieldValues: defaults }
    });
}
```

This opens the standard create modal with fields prefilled — no custom form, no Apex, and the org's page layout and validation rules apply.

It is frequently the right answer where a team was about to build a custom creation component.

## Generating a URL

For an anchor tag, or for a datatable's URL column, you need the URL rather than navigation.

```javascript
import { NavigationMixin } from 'lightning/navigation';

connectedCallback() {
    this[NavigationMixin.GenerateUrl]({
        type: 'standard__recordPage',
        attributes: {
            recordId: this.claim.Id,
            objectApiName: 'Warranty_Claim__c',
            actionName: 'view'
        }
    }).then((url) => {
        this.claimUrl = url;
    });
}
```

```html
<a href={claimUrl} onclick={handleLinkClick}>{claim.Claim_Number__c}</a>
```

**Generating the URL and rendering a real anchor** is better than a click handler alone — it gives middle-click, open-in-new-tab, and copy-link, which users expect and a `<div onclick>` does not provide.

For a datatable URL column, generating a URL per row is expensive; constructing the relative path is the pragmatic compromise there, since datatable renders it as an anchor anyway. See [[14.13 - Base Components and lightning-datatable]].

## Reading the current page

```javascript
import { CurrentPageReference } from 'lightning/navigation';

@wire(CurrentPageReference)
pageRef;

get assetIdFromUrl() {
    // custom state parameters are namespaced with c__
    return this.pageRef?.state?.c__assetId;
}
```

State parameters passed to a component page must be prefixed `c__`. Omitting the prefix means the parameter is dropped silently.

## Console navigation

In a console app, `Navigate` opens a workspace tab. The **Workspace API** gives control over tabs, and is available only in a console.

```javascript
import { LightningElement, wire } from 'lwc';
import { IsConsoleNavigation, openTab, openSubtab, getFocusedTabInfo,
         setTabLabel, setTabIcon, closeTab } from 'lightning/platformWorkspaceApi';

export default class ClaimWorkspace extends LightningElement {

    @wire(IsConsoleNavigation) isConsole;

    async openClaimAsSubtab(claimId) {
        // the guard matters — these APIs do not exist outside a console app
        if (!this.isConsole) {
            this.navigateToRecord(claimId);
            return;
        }

        const { tabId } = await getFocusedTabInfo();
        await openSubtab(tabId, { recordId: claimId, focus: true });
    }

    async flagUrgent() {
        const { tabId } = await getFocusedTabInfo();
        await setTabIcon({ tabId, iconName: 'utility:warning' });
        await setTabLabel({ tabId, label: `URGENT — ${this.claimNumber}` });
    }

    async closeAfterResolution() {
        const { tabId } = await getFocusedTabInfo();
        await closeTab(tabId);
    }
}
```

**`IsConsoleNavigation` guards every call.** The same component placed on a standard record page would otherwise throw.

The practical uses: opening a related record as a **subtab** rather than navigating away, closing the tab after a case is resolved, and flagging a tab visually. See [[05.8 - Service Console and Agent Productivity]].

## Navigating from a quick action

A headless quick action can navigate:

```javascript
export default class CreateRenewalAction extends NavigationMixin(LightningElement) {
    @api recordId;

    @api
    async invoke() {
        const renewalId = await createRenewal({ contractId: this.recordId });

        this[NavigationMixin.Navigate]({
            type: 'standard__recordPage',
            attributes: { recordId: renewalId, objectApiName: 'Opportunity', actionName: 'view' }
        });
    }
}
```

Create the record in Apex, then navigate to it — the standard shape for an action that produces something.

## Downloading a file

```javascript
navigateToFile(contentDocumentId) {
    this[NavigationMixin.Navigate]({
        type: 'standard__webPage',
        attributes: {
            url: `/sfc/servlet.shepherd/document/download/${contentDocumentId}`
        }
    });
}
```

For a generated file — a PDF from a Visualforce page:

```javascript
downloadClaimPdf() {
    this[NavigationMixin.Navigate]({
        type: 'standard__webPage',
        attributes: { url: `/apex/ClaimPdf?id=${this.recordId}` }
    });
}
```

`standard__webPage` opens in a new tab by default in most contexts, which is what you want for a download.

## Experience Cloud

Navigation behaves differently on an Experience Cloud site — record pages may not exist, and URLs are site-relative.

```javascript
import { NavigationMixin } from 'lightning/navigation';

navigateInCommunity() {
    this[NavigationMixin.Navigate]({
        type: 'comm__namedPage',
        attributes: { name: 'Claim_Detail__c' },
        state: { recordId: this.claimId }
    });
}
```

`standard__recordPage` **does** work in Experience Cloud when the object has a detail page configured, and fails when it does not. A component intended for both internal and external use should branch, or use a named page that exists in both.

Testing in the actual site rather than in the builder preview is worth doing — several navigation behaviours differ.

## Where to keep navigation

A small consideration that pays off: navigation logic scattered across components is hard to change when the org's page structure changes.

```javascript
// c/navigationUtils/navigationUtils.js
export function recordPageRef(recordId, objectApiName) {
    return {
        type: 'standard__recordPage',
        attributes: { recordId, objectApiName, actionName: 'view' }
    };
}

export function newRecordPageRef(objectApiName, defaultValues) {
    return {
        type: 'standard__objectPage',
        attributes: { objectApiName, actionName: 'new' },
        state: { defaultFieldValues: encodeDefaultFieldValues(defaultValues) }
    };
}
```

```javascript
import { recordPageRef } from 'c/navigationUtils';

this[NavigationMixin.Navigate](recordPageRef(this.claimId, 'Warranty_Claim__c'));
```

A shared module keeps page reference construction in one place, which matters when a page type changes or Experience Cloud support is added later. See [[14.2 - Component Structure and Metadata]] on module components.

## Testing

```javascript
import { getNavigateCalledWith } from 'lightning/navigation';

jest.mock('lightning/navigation', () => require('lightning/navigation'), { virtual: true });

it('navigates to the claim record on click', () => {
    const element = createElement('c-claim-row', { is: ClaimRow });
    element.claim = { Id: 'a0X123', Claim_Number__c: 'WC-00042' };
    document.body.appendChild(element);

    element.shadowRoot.querySelector('a').click();

    const { pageReference } = getNavigateCalledWith();
    expect(pageReference.type).toBe('standard__recordPage');
    expect(pageReference.attributes.recordId).toBe('a0X123');
});
```

The `lightning/navigation` stub in the LWC Jest setup records calls, which makes asserting on navigation straightforward. See [[14.18 - Jest Testing for LWC]].

## Practical guidance

**Never construct Lightning URLs by hand.**

**Use `GenerateUrl` and a real anchor** so middle-click and copy-link work.

**Use `encodeDefaultFieldValues`** to prefill the standard create modal rather than building a form.

**Prefix custom state parameters with `c__`.**

**Guard console APIs with `IsConsoleNavigation`.**

**Open related records as subtabs** in a console rather than navigating away.

**Test Experience Cloud navigation in the site**, not the builder.

**Centralize page reference construction** in a shared module.
