# Scopes and Closures

#python #functions #closures #scope

> **In one line:** Python decides at compile time whether a name is local, enclosing, global or built-in (LEGB). Assigning to a name anywhere in a function makes it local everywhere in that function, and a closure captures variables, not values. That last fact causes the late-binding bug.

---

## LEGB

When Python looks up a name, it searches four scopes in order:

```
B  Built-in      len, print, ValueError          (module `builtins`)
 ▲
G  Global        names at the top of the module
 ▲
E  Enclosing     locals of any outer function(s)
 ▲
L  Local         names assigned in the current function
```

```python
x = "global"
def outer():
    x = "enclosing"
    def inner():
        return x          # finds the enclosing x
    return inner()
```

There is no block scope. Variables assigned inside `if`, `for`, `with` and `try` belong to the function. Comprehensions are the exception: they get their own scope (and since 3.12 they are inlined but still isolated, PEP 709).

---

## Assignment Makes a Name Local, Everywhere

The compiler scans the whole function body. **If a name is assigned anywhere in the function, it is local for the entire function.**

```python
count = 0
def increment():
    count += 1        # UnboundLocalError: count is local (it is assigned), but read before assignment
```

```python
total = 10
def show():
    print(total)      # UnboundLocalError too!
    total = 5         # this line makes `total` local to the whole function
```

`global` and `nonlocal` change the rule:

```python
count = 0
def increment():
    global count          # bind to the module-level name
    count += 1

def make_counter():
    n = 0
    def step():
        nonlocal n        # bind to the enclosing function's name
        n += 1
        return n
    return step
```

⚠️ **Avoid `global` in application code.** Module-level mutable state is shared across every request in a server process, and across threads. It is the source of "works locally, wrong under load" bugs. Pass state explicitly, or use `contextvars` for per-request context.

---

## Closures

A **closure** is a function that remembers variables from the scope where it was defined, even after that scope has returned.

```python
def make_multiplier(k):
    def mul(x):
        return x * k          # k is a free variable
    return mul

double = make_multiplier(2)
double(21)                     # 42
double.__closure__             # (<cell at 0x...: int object at ...>,)
double.__closure__[0].cell_contents   # 2
double.__code__.co_freevars    # ('k',)
```

How it works: a variable used by an inner function is stored in a **cell** object instead of the frame's local array. Both the outer function and the inner function reference the same cell. The cell survives as long as any closure references it.

```
make_multiplier frame (gone)        double (function object)
                                    __closure__ ──► cell ──► int 2
```

Closures give you private state without a class:

```python
def rate_limiter(max_calls, per_seconds):
    import time
    calls = []
    def allow():
        now = time.monotonic()
        while calls and now - calls[0] > per_seconds:
            calls.pop(0)
        if len(calls) < max_calls:
            calls.append(now)
            return True
        return False
    return allow
```

When the state grows or needs several methods, use a class. A closure is a one-method object.

## The Late-Binding Trap

A closure captures the **variable**, not its value at the time of creation. Every closure created in a loop shares the same loop variable:

```python
callbacks = [lambda: i for i in range(3)]
[cb() for cb in callbacks]          # [2, 2, 2] — not [0, 1, 2]

handlers = []
for name in ["a", "b", "c"]:
    def h():
        return name
    handlers.append(h)
[h() for h in handlers]             # ['c', 'c', 'c']
```

All of them read `i` or `name` **when called**, and by then the loop has finished.

**Fixes:**

```python
# 1. Default argument: evaluated at definition time, so it captures the current value
callbacks = [lambda i=i: i for i in range(3)]

# 2. functools.partial
from functools import partial
callbacks = [partial(lambda i: i, i) for i in range(3)]

# 3. A factory function: each call creates a new scope
def make(i): return lambda: i
callbacks = [make(i) for i in range(3)]
```

Real-world forms of this bug: registering signal handlers or routes in a loop, creating `asyncio` tasks in a loop with a lambda, building button callbacks in UI code.

## contextvars — Scope for Concurrent Code

Globals are shared by every coroutine on a thread. Thread-locals are shared by every coroutine on the **same** thread, which is all of them in asyncio. For per-request values (request ID, current user, tenant) use `contextvars`:

```python
from contextvars import ContextVar
request_id: ContextVar[str] = ContextVar("request_id", default="-")

async def middleware(request, call_next):
    token = request_id.set(request.headers.get("x-request-id", new_id()))
    try:
        return await call_next(request)
    finally:
        request_id.reset(token)

def log(msg):
    print(request_id.get(), msg)     # correct value in every concurrent task
```

Each asyncio Task runs in a copy of the context, so values set in one request do not leak into another. This is how OpenTelemetry tracks the current span and how structlog binds per-request fields ([[07.6 - Logging Done Right]]). Multi-tenant context propagation is covered in [[15.6 - Multi Tenant Isolation]].
