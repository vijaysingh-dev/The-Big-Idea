# Factory Method Pattern

## At a Glance

|||
|---|---|
|**Type**|Creational|
|**Intent**|Define an interface for creating an object, but let subclasses decide which class to instantiate|
|**Also Known As**|Virtual Constructor|
|**Frequency in Backend**|★★★★☆ — pluggable providers, SDK wrappers|

---

## The Problem It Solves

You need to create objects, but the exact type depends on runtime context (config, input, environment). Hardcoding `new ConcreteClass()` everywhere makes swapping implementations painful.

---

## Structure

```
┌─────────────────────────────┐
│  Creator (abstract)         │
├─────────────────────────────┤
│ + create_notifier()  ← Factory Method (abstract or with default)
│ + send_notification()       │  (uses the product)
└─────────────────────────────┘
              △
    ┌─────────┴──────────┐
    │                    │
┌───┴────────┐   ┌──────┴───────────┐
│EmailCreator│   │SMSCreator        │
│            │   │                  │
│+create_not.│   │+create_not.      │
│ →EmailSender   │ →SmsSender       │
└────────────┘   └──────────────────┘
```

## Full Backend Example: Notification Provider Factory

```python
# notification_channel.py
from abc import ABC, abstractmethod
from dataclasses import dataclass
from typing import Optional

@dataclass
class NotificationRequest:
    recipient: str
    subject: str
    body: str
    metadata: dict = None

@dataclass
class DeliveryResult:
    success: bool
    message_id: Optional[str]
    provider: str
    error: Optional[str] = None

class NotificationChannel(ABC):
    """Product interface."""
    
    @abstractmethod
    def send(self, request: NotificationRequest) -> DeliveryResult:
        pass
    
    @abstractmethod
    def channel_type(self) -> str:
        pass


# concrete_channels.py
class EmailChannel(NotificationChannel):
    def __init__(self, smtp_host: str, smtp_port: int, api_key: str):
        self._host = smtp_host
        self._port = smtp_port
        self._key = api_key
    
    def send(self, request: NotificationRequest) -> DeliveryResult:
        try:
            msg_id = sendgrid.send(
                to=request.recipient,
                subject=request.subject,
                html=request.body,
                api_key=self._key
            )
            return DeliveryResult(success=True, message_id=msg_id, provider="sendgrid")
        except Exception as e:
            return DeliveryResult(success=False, message_id=None, provider="sendgrid", error=str(e))
    
    def channel_type(self): return "email"


class SmsChannel(NotificationChannel):
    def __init__(self, account_sid: str, auth_token: str, from_number: str):
        self._client = twilio.Client(account_sid, auth_token)
        self._from = from_number
    
    def send(self, request: NotificationRequest) -> DeliveryResult:
        try:
            msg = self._client.messages.create(
                to=request.recipient,
                from_=self._from,
                body=request.body
            )
            return DeliveryResult(success=True, message_id=msg.sid, provider="twilio")
        except Exception as e:
            return DeliveryResult(success=False, message_id=None, provider="twilio", error=str(e))
    
    def channel_type(self): return "sms"


class PushChannel(NotificationChannel):
    def __init__(self, fcm_key: str):
        self._fcm_key = fcm_key
    
    def send(self, request: NotificationRequest) -> DeliveryResult:
        try:
            result = fcm.send(
                token=request.recipient,
                title=request.subject,
                body=request.body,
                api_key=self._fcm_key
            )
            return DeliveryResult(success=True, message_id=result.message_id, provider="fcm")
        except Exception as e:
            return DeliveryResult(success=False, message_id=None, provider="fcm", error=str(e))
    
    def channel_type(self): return "push"


# channel_factory.py — The Factory
class NotificationChannelFactory:
    """
    Creates NotificationChannel instances based on channel type string.
    Centralizes construction logic and config binding.
    """
    
    def __init__(self, config: AppConfig):
        self._config = config
        # Registry: channel type → creator function
        self._creators = {
            "email": self._create_email,
            "sms":   self._create_sms,
            "push":  self._create_push,
        }
    
    def create(self, channel_type: str) -> NotificationChannel:
        creator = self._creators.get(channel_type.lower())
        if not creator:
            raise ValueError(f"Unknown channel type: {channel_type}. "
                           f"Supported: {list(self._creators.keys())}")
        return creator()
    
    def register(self, channel_type: str, creator):
        """Extension point: register new channel types at runtime."""
        self._creators[channel_type] = creator
    
    def _create_email(self) -> EmailChannel:
        return EmailChannel(
            smtp_host=self._config.smtp_host,
            smtp_port=self._config.smtp_port,
            api_key=self._config.sendgrid_key
        )
    
    def _create_sms(self) -> SmsChannel:
        return SmsChannel(
            account_sid=self._config.twilio_sid,
            auth_token=self._config.twilio_token,
            from_number=self._config.twilio_from
        )
    
    def _create_push(self) -> PushChannel:
        return PushChannel(fcm_key=self._config.fcm_key)


# notification_service.py — uses factory, unaware of concrete types
class NotificationService:
    def __init__(self, factory: NotificationChannelFactory):
        self._factory = factory
        self._channel_cache: dict[str, NotificationChannel] = {}
    
    def send(self, channel_type: str, request: NotificationRequest) -> DeliveryResult:
        channel = self._get_or_create_channel(channel_type)
        return channel.send(request)
    
    def send_to_all(self, channel_types: list[str],
                    request: NotificationRequest) -> list[DeliveryResult]:
        return [self.send(ct, request) for ct in channel_types]
    
    def _get_or_create_channel(self, channel_type: str) -> NotificationChannel:
        if channel_type not in self._channel_cache:
            self._channel_cache[channel_type] = self._factory.create(channel_type)
        return self._channel_cache[channel_type]


# Adding WhatsApp — zero changes to NotificationService
class WhatsAppChannel(NotificationChannel):
    def send(self, request): ...
    def channel_type(self): return "whatsapp"

factory.register("whatsapp", lambda: WhatsAppChannel(config.whatsapp_token))
```

## Factory Method vs Abstract Factory vs Simple Factory

||Factory Method|Abstract Factory|Simple Factory|
|---|---|---|---|
|Pattern type|True GoF pattern|True GoF pattern|Not GoF (idiom)|
|Creates|One product type|Families of related products|One product type|
|Extension|Subclass creator|New factory class|Add to if/elif|
|Use when|One product with variants|Multiple related products|Simple creation logic|

---

## Real-World Backend Uses

|Factory Creates|Variants|
|---|---|
|Storage backends|Local, S3, GCS, Azure Blob|
|Cache clients|Redis, Memcached, In-memory|
|Payment gateways|Stripe, Razorpay, PayPal|
|Search providers|Elasticsearch, Postgres FTS, Algolia|
|Auth providers|JWT, Session, OAuth2|
|Queue clients|SQS, RabbitMQ, Kafka, In-memory|

---

## When NOT to Use

- **Only one implementation** — just instantiate directly
- **Creation is trivial** — `SomeClass()` doesn't need a factory
- **Over-applying OCP** — if new types are rare, a simple `if/elif` is fine

---

## Tradeoffs

|Pro|Con|
|---|---|
|Decouples instantiation from usage|More classes/files|
|Easy to add new products (OCP)|Subclass explosion in classic version|
|Centralized construction logic|Factory itself needs testing|
|Enables configuration-driven behavior|Registry approach needs care (thread-safety)|

---

## Interview Perspective

> "How would you design a system that supports multiple cloud storage providers?"

Factory Method: `StorageProviderFactory.create(provider_name)` returns `S3Storage`, `GCSStorage`, or `AzureStorage` — all implementing `StorageProvider`. Service layer uses `StorageProvider` interface.
