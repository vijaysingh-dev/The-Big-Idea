# RLHF and DPO

## The Alignment Problem

After SFT, a model follows instructions but may not align with human preferences:

- Gives technically correct but unhelpful answers
- Verbose when brevity is wanted
- Hedges excessively
- Produces potentially harmful content
- Doesn't match the "helpful, harmless, honest" target

RLHF and DPO are methods to align model behavior to human preferences using feedback signals.

---

## RLHF (Reinforcement Learning from Human Feedback)

### Overview

Three-stage pipeline:

```
Stage 1: SFT
  Base model → fine-tune on demonstrations → SFT model

Stage 2: Reward Model Training
  SFT model → generate multiple responses per prompt
  Humans rank responses → preference pairs (chosen, rejected)
  Train reward model to predict human preference score

Stage 3: RL Optimization (PPO)
  SFT model → RL policy
  Use reward model to score generated responses
  Use PPO to push policy toward higher-reward outputs
  KL-divergence penalty keeps policy close to SFT model
```

### Stage 2: Reward Model

The reward model takes (prompt, response) as input and outputs a scalar score predicting human preference.

Training data format:

```json
{
  "prompt": "Explain quantum entanglement",
  "chosen": "Quantum entanglement is a phenomenon where two particles...",  ← preferred
  "rejected": "Quantum entanglement is complicated physics stuff..."  ← less preferred
}
```

Loss function: Bradley-Terry model (chosen should score higher than rejected):

```
loss = -log(sigmoid(reward(chosen) - reward(rejected)))
```

### Stage 3: PPO (Proximal Policy Optimization)

The RL algorithm used to update the LLM (acting as policy):

```
For each training step:
  1. Sample prompts from dataset
  2. Generate responses with current policy (LLM)
  3. Score each response with reward model
  4. Compute advantage (how much better than baseline?)
  5. Update policy to increase probability of high-advantage actions
  6. KL penalty: don't drift too far from SFT model
```

The KL-divergence penalty is critical — without it, the model finds reward hacking exploits (e.g., outputting blank responses that get neutral scores but never negative ones).

### RLHF Problems

1. **Expensive**: Requires human annotators, reward model training, complex RL setup
2. **Reward hacking**: Model exploits reward model weaknesses instead of being genuinely better
3. **Reward model errors**: Human preferences captured imperfectly → policy learns wrong signal
4. **Instability**: PPO training for language models is notoriously finicky
5. **Two models in memory**: Policy + reward model simultaneously during training

## DPO (Direct Preference Optimization)

DPO eliminates the reward model and RL entirely. It directly optimizes the LLM on preference pairs using a clever mathematical reformulation.

### Key Insight

RLHF implicitly defines an optimal policy in terms of reward. DPO shows you can express the same objective directly in terms of the policy's own log-probabilities — no reward model needed.

### DPO Loss

```python
# For each (prompt, chosen, rejected) triple:
log_ratio_chosen = log_prob(policy, chosen) - log_prob(reference_policy, chosen)
log_ratio_rejected = log_prob(policy, rejected) - log_prob(reference_policy, rejected)

loss = -log(sigmoid(β × (log_ratio_chosen - log_ratio_rejected)))
```

Where:

- `policy` = model being trained
- `reference_policy` = frozen SFT model (the "before" model)
- `β` = temperature controlling how much to diverge from reference

**What this does**:

- Increases probability of generating the chosen response relative to the reference model
- Decreases probability of generating the rejected response relative to the reference model
- β controls the strength of this push

### DPO Advantages Over RLHF

|Dimension|RLHF|DPO|
|---|---|---|
|Reward model needed|Yes|No|
|RL training needed|Yes (PPO)|No|
|Stability|Finicky|Much more stable|
|Implementation complexity|High|Low|
|Compute cost|High|Moderate|
|Quality|Strong|Competitive|

DPO has largely replaced RLHF for most teams. It's simpler, cheaper, and nearly as effective.

### DPO Data Requirements

Same format as reward model training — preference pairs:

```json
{"prompt": "...", "chosen": "better response", "rejected": "worse response"}
```

Typical dataset sizes: 20K–100K preference pairs. Quality of the preference labels matters enormously.

## RLAIF (RL from AI Feedback)

Human annotation is expensive. RLAIF replaces human annotators with an LLM:

```
Use GPT-4 or Claude to generate preference labels:
  Given (prompt, response_A, response_B), which is better?
  → LLM outputs preference
```

Quality is surprisingly competitive with human labels for many tasks. Used by Google (Constitutional AI) and is now common in open-source fine-tuning.

**Constitutional AI (Anthropic)**: A specific RLAIF variant where the AI rates responses against a list of principles (the "constitution") rather than open-ended preference. More systematic and auditable.

## Practical Fine-Tuning Path with DPO

```
1. Start with a good base instruction-tuned model
   (Llama 3 Instruct, Mistral Instruct, etc.)

2. (Optional) SFT on domain-specific demonstrations
   → Use if the model needs specialized knowledge or format

3. Generate preference pairs
   → Sample 2 responses per prompt
   → Use GPT-4 / Claude to label which is better (RLAIF)
   → Or use human annotators for high-stakes domains

4. DPO training
   → Use TRL library's DPOTrainer
   → Training on 20–50K pairs, 1–3 epochs
   → Monitor: reward margin (chosen - rejected reward should increase)

5. Evaluate
   → Run eval harness (MT-Bench, your custom eval)
   → Compare to pre-DPO model
   → A/B test with real users
```

## When to Use RLHF/DPO in Production

Most teams don't run RLHF/DPO themselves — they use:

- OpenAI/Anthropic's already-aligned models (RLHF is baked in)
- Open-source RLHF-trained models (Llama-Instruct, Mistral-Instruct)

Run DPO yourself when:

- You need alignment to **your specific preferences** (style, tone, domain behavior)
- You're using an open-source base model
- You've collected real user feedback (thumbs up/down) you want to act on
