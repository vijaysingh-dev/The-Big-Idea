# The collections Module

#python #collections #data-structures

> **In one line:** `defaultdict` removes "check if key exists" boilerplate, `Counter` counts, `deque` is the right queue, `ChainMap` layers configs, and `namedtuple` gives tuples field names. Each replaces a pattern you would otherwise hand-write, and usually gets it wrong.

---

## defaultdict

```python
from collections import defaultdict

by_user = defaultdict(list)
for order in orders:
    by_user[order.user_id].append(order)       # no "if key not in" needed

counts = defaultdict(int)
for word in words:
    counts[word] += 1

tree = lambda: defaultdict(tree)               # auto-vivifying nested dict
config = tree(); config["db"]["primary"]["host"] = "x"
```

The argument is a **factory** (called with no arguments), not a value. `defaultdict([])` is wrong; `defaultdict(list)` is right.

⚠️ **Reading a missing key inserts it.** `if by_user[42]:` creates an empty list for user 42. Use `42 in by_user` or `by_user.get(42)` to check without side effects. And convert to a plain `dict` before returning it from an API or serialising it, so callers do not get the auto-insert behaviour by surprise.

## Counter

```python
from collections import Counter

c = Counter(["a", "b", "a", "c", "a"])
c.most_common(2)              # [('a', 3), ('b', 1)]
c["missing"]                  # 0 — no KeyError, and no insertion
c.update(["b", "b"])
c + Counter(a=1)              # add counts
c - Counter(a=5)              # subtract, dropping zero and negative counts
c.total()                     # 3.10+
Counter(status for _, status in responses).most_common()
```

Good for quick stats, histograms, top-N and "are these two multisets equal?" (`Counter(a) == Counter(b)` is an order-insensitive comparison that counts duplicates).

## deque

A double-ended queue: O(1) append and pop at **both** ends (a list is O(n) at the front).

```python
from collections import deque

q = deque()
q.append(job); q.popleft()               # FIFO queue
q.appendleft(x); q.pop()

recent = deque(maxlen=100)               # bounded: oldest falls off automatically
recent.append(latency_ms)
p99 = sorted(recent)[98]

q.rotate(1)                              # round-robin
```

| Use | Choose |
|---|---|
| FIFO within one thread or coroutine | `deque` |
| Producer/consumer across **threads** | `queue.Queue` (has locking and blocking `get`) |
| Producer/consumer across **coroutines** | `asyncio.Queue(maxsize=...)` ([[01.11 - Backpressure Inside One Process]]) |
| Priority order | `heapq` on a list, or `queue.PriorityQueue` |
| Sliding window of the last N | `deque(maxlen=N)` |

`deque.append` and `popleft` are atomic in CPython, which is why `queue.Queue` is built on a deque. That is still not a reason to share a bare deque between threads without a lock if you need "check then act" logic.

## ChainMap

Look up a key through several dicts in order, without copying them:

```python
from collections import ChainMap
import os

defaults = {"debug": False, "port": 8000}
file_cfg = {"port": 9000}
env_cfg = {k.lower(): v for k, v in os.environ.items() if k in ("DEBUG", "PORT")}

cfg = ChainMap(env_cfg, file_cfg, defaults)
cfg["port"]        # env wins, then file, then defaults
cfg.maps           # the layers
child = cfg.new_child({"port": 1})   # a temporary override layer
```

Writes go to the first map only. It is useful for layered configuration and for scopes in an interpreter. In application code, `pydantic-settings` usually does this job better, with validation ([[07.4 - Pydantic in Production]]).

## namedtuple

A tuple subclass with named fields: immutable, lightweight, unpackable, and hashable when its items are.

```python
from collections import namedtuple
from typing import NamedTuple

Point = namedtuple("Point", ["x", "y"])

class Row(NamedTuple):            # the typed, class-based form — prefer this
    id: int
    email: str
    active: bool = True

r = Row(1, "a@x.com")
r.email, r[1]                     # by name or position
id_, email, active = r            # unpacking
r._replace(active=False)          # a new tuple
r._asdict()                       # {'id': 1, 'email': ..., 'active': True}
```

When to use what (more in [[07.2 - Dataclasses]]):

| | `NamedTuple` | `@dataclass` | Pydantic `BaseModel` |
|---|---|---|---|
| Mutable | No | Yes (or `frozen=True`) | Yes (or `frozen=True`) |
| Is a tuple (indexable, unpackable) | Yes | No | No |
| Validation | No | No | **Yes** |
| Memory | Smallest | Small with `slots=True` | Largest |
| Good for | Rows from a DB driver, returning several values | Internal domain objects | Data crossing a trust boundary: requests, config, external APIs |

⚠️ Because a namedtuple **is** a tuple, `Point(1, 2) == (1, 2)` is `True`, and two different namedtuple types with the same values compare equal. That is sometimes surprising in equality-based code.

## OrderedDict and UserDict

- **`OrderedDict`**: plain dicts are ordered now, so it is mostly legacy. It still has `move_to_end()` and order-sensitive equality, which makes it a neat LRU cache:

```python
from collections import OrderedDict

class LRU:
    def __init__(self, capacity):
        self.data = OrderedDict(); self.capacity = capacity
    def get(self, k):
        if k not in self.data: return None
        self.data.move_to_end(k)
        return self.data[k]
    def put(self, k, v):
        self.data[k] = v
        self.data.move_to_end(k)
        if len(self.data) > self.capacity:
            self.data.popitem(last=False)
```

- **`UserDict` / `UserList`**: subclass these, not `dict`/`list`, when customising behaviour. Built-in `dict` methods implemented in C (`update`, `get`, `__init__`) **do not call your overridden `__setitem__`**, so a `dict` subclass that normalises keys in `__setitem__` silently misses `d.update(...)`. `UserDict` routes everything through your methods.

## Codebase

**Repo:** `python/cpython`

**Question to answer:** How does `namedtuple` create a class at runtime, and how does `OrderedDict` keep `move_to_end` O(1)?

**Read, in order:**

1. `Lib/collections/__init__.py` — `namedtuple()`: it builds the class with `type(...)` and generated methods (a nice preview of [[06.8 - Metaprogramming]]). Then `OrderedDict` (pure-Python version: a doubly linked list plus a dict), `Counter`, `ChainMap`, `UserDict`.
2. `Modules/_collectionsmodule.c` — `deque`: a doubly linked list of fixed-size blocks. Read the comment at the top describing the block layout.
3. `Lib/queue.py` — how `Queue` wraps a deque with locks and conditions ([[02.4 - Locks and Synchronization]])

**Size:** 1–2 sessions.
