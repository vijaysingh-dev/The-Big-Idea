# Shallow vs Deep Copy

Objects are held by reference. Copying one means deciding how far down the tree you want new references — and getting that wrong is the source of a large fraction of React state bugs.

```js
const original = { name: "config", nested: { retries: 3 } };

const alias = original;              // no copy at all
const shallow = { ...original };     // top level copied, nested shared
const deep = structuredClone(original); // everything new
```

```
alias   ────────────────► { name, nested ──► { retries } }
                             ▲                    ▲
shallow ──► { name, nested ──┘ }  (same nested)   │
deep    ──► { name, nested ──► { retries } }  (new)
```

## Shallow copy techniques

```js
const a = { ...obj };
const b = Object.assign({}, obj);
const c = Array.from(arr);
const d = [...arr];
const e = arr.slice();
```

All copy one level. Differences worth knowing:

- **Spread and `Object.assign` copy own enumerable properties only** — inherited properties and non-enumerable ones are dropped.
- **Both invoke getters** and copy the returned value as a plain data property. An accessor becomes a frozen snapshot.
- **`Object.assign` triggers setters on the target**; spread does not, it defines properties directly. This matters when the target is a proxy or a class instance with accessors.
- **Neither preserves the prototype.** `{...classInstance}` gives a plain object with no methods.

```js
class User { constructor(n) { this.n = n; } greet() {} }
const u = new User("a");
const copy = { ...u };
copy.greet; // undefined
```

To preserve prototype and descriptors:

```js
const clone = Object.create(
  Object.getPrototypeOf(obj),
  Object.getOwnPropertyDescriptors(obj)
);
```

## Deep copy: structuredClone

The platform-provided answer, available in all modern browsers and Node 17+.

```js
const deep = structuredClone(original);
```

What it handles that `JSON` cannot:

- `Date`, `RegExp`, `Map`, `Set`, `ArrayBuffer`, typed arrays, `Blob`, `File`
- **Circular references** — preserved correctly
- `undefined` values, `-0`, `BigInt`

What it cannot handle:

- **Functions** — throws `DataCloneError`
- **Symbols** — throws
- **DOM nodes** — throws (except a few specific types)
- **Prototypes** — class instances come back as plain objects
- **Property descriptors** — getters are invoked, non-enumerables dropped

It is the same algorithm used by `postMessage` to send data to a Worker ([[08.5 - Serialization and Structured Clone]]), which is why the restrictions look the way they do: anything that cannot cross a thread boundary cannot be cloned.

## The JSON round-trip, and why it is not fine

```js
const bad = JSON.parse(JSON.stringify(original));
```

It is fast and it is everywhere in existing code, but it silently corrupts data:

```js
JSON.parse(JSON.stringify({
  date: new Date(),        // becomes an ISO string
  undef: undefined,        // key disappears
  fn: () => {},            // key disappears
  nan: NaN,                // becomes null
  inf: Infinity,           // becomes null
  map: new Map([[1, 2]]),  // becomes {}
  set: new Set([1]),       // becomes {}
  regex: /x/g,             // becomes {}
}));
```

Circular references throw outright. The `Date`-to-string conversion is the one that bites hardest in practice, because the code keeps working until something calls `.getTime()` three layers away.

Use it only when you know the payload is plain JSON — which, for data that came from an API, it usually is.

## Manual deep clone

Worth being able to write, since it is a standard interview question and the circular-reference handling is the interesting part.

```js
function deepClone(value, seen = new WeakMap()) {
  if (value === null || typeof value !== "object") return value;
  if (seen.has(value)) return seen.get(value);

  if (value instanceof Date) return new Date(value);
  if (value instanceof RegExp) return new RegExp(value.source, value.flags);

  const result = Array.isArray(value) ? [] : Object.create(Object.getPrototypeOf(value));
  seen.set(value, result);

  if (value instanceof Map) {
    value.forEach((v, k) => result.set(deepClone(k, seen), deepClone(v, seen)));
    return result;
  }
  if (value instanceof Set) {
    value.forEach(v => result.add(deepClone(v, seen)));
    return result;
  }

  for (const key of Reflect.ownKeys(value)) {
    result[key] = deepClone(value[key], seen);
  }
  return result;
}
```

The `WeakMap` tracks already-cloned objects so cycles resolve to the same clone rather than recursing forever, and it must be populated *before* recursing into children. Using a `WeakMap` rather than a `Map` means the bookkeeping does not retain anything after the clone finishes ([[07.4 - WeakMap WeakSet and WeakRef]]).

Note this is recursive, so deeply nested structures can overflow the stack ([[01.3 - The Call Stack]]).

## Why React cares

React compares state by reference. Mutating an object in place produces the same reference, so no re-render happens:

```js
// Broken — same reference
setUser(u => { u.name = "new"; return u; });

// Correct — new reference at every level you changed
setUser(u => ({ ...u, name: "new" }));

// Nested — every level on the path needs a new reference
setState(s => ({
  ...s,
  profile: { ...s.profile, address: { ...s.profile.address, city: "Delhi" } },
}));
```

The nesting depth is exactly why Immer exists: it lets you write mutations and produces the correct structurally-shared copy ([[20.6 - Immer and Immutable Updates]]).

**Structural sharing** — the term for reusing unchanged subtrees rather than deep-copying — is the goal. A full deep clone on every state update is both slower and worse for memoization, because unchanged children get new references and re-render anyway.

## How senior engineers actually use this

**They default to shallow copies with explicit paths.** Deep cloning entire state trees is almost always a sign the state shape is wrong — usually too nested, fixable by normalizing ([[20.7 - State Normalization]]).

**They use `structuredClone` when they genuinely need a deep copy**, and reach for Lodash's `cloneDeep` only when class instances or functions must survive.

**They ban `JSON.parse(JSON.stringify())` in review** for anything but known-plain API payloads.

**They freeze state in development.** `Object.freeze` on state in dev builds turns accidental mutation into a thrown error rather than a mysterious missing re-render.

## Common pitfalls

- Spreading a class instance and losing its methods.
- Assuming spread is deep, then mutating a nested object and seeing the original change.
- `JSON` round-tripping data containing `Date`s.
- Deep cloning to "be safe" and destroying referential equality that memoization depended on.
- Cloning objects containing DOM nodes or functions with `structuredClone` and getting a `DataCloneError` at runtime.

## Interview angle

"Difference between shallow and deep copy" almost always leads to "implement deep clone". Write the recursive version, handle `Date`/`RegExp`/`Map`/`Set`, and — most importantly — handle circular references with a `WeakMap`, explaining why the map is populated before recursion. Mentioning `structuredClone` as the built-in answer and listing what it refuses to clone is a strong close.
