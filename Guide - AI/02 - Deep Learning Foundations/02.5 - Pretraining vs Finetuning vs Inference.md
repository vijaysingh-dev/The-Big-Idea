# Pretraining vs Fine-tuning vs Inference
## The Three Phases of a Model's Life

Every LLM you interact with has gone through these phases before reaching you:

```
[Pretraining]  →  [Fine-tuning / Alignment]  →  [Inference / Deployment]
   Weeks–months        Days–weeks                   Milliseconds per call
   Huge compute        Moderate compute              Low compute
   Billions of tokens  Thousands–millions of examples  Single prompts
```

Understanding what happens in each phase is critical for deciding _what to change_ when your AI system behaves incorrectly.

---

## Phase 1: Pretraining

### What Happens

The base model is trained from random weights on a massive, diverse corpus of text (Common Crawl, books, GitHub, Wikipedia, etc.) — trillions of tokens.

**Objective**: Predict the next token. That's it.

```
For every token t in the corpus:
    given [t-n, ..., t-2, t-1], predict t
    compute loss = cross_entropy(prediction, t)
    update weights via backpropagation
```

### What the Model Learns

By being forced to predict every next token across all human-written text, the model implicitly learns:

- Grammar and syntax
- World knowledge (facts, concepts)
- Reasoning patterns
- Code structure
- Mathematical relationships
- Common sense

This is called **emergent knowledge** — it wasn't explicitly programmed.

### Cost

Pretraining GPT-3 (175B parameters) cost ~$5M in compute. Llama 3 (405B) cost hundreds of millions. Only labs and large companies pretrain models.

**As an AI engineer, you will never pretrain a model.** You will always start from a pretrained base.

### Output: Base Model

A base model (e.g., Llama-3-base) knows a lot about the world but is **not instruction-following**. Ask "What is the capital of France?" and it might complete the sentence in weird ways rather than answering.

---

## Phase 2: Fine-tuning

Fine-tuning adapts a pretrained model for a specific behavior or task. There are several types:

### Supervised Fine-tuning (SFT)

Train on curated examples of `(instruction, ideal_response)` pairs:

```
Instruction: "Summarize this article: ..."
Response:    "The article discusses..."
```

This teaches the model to _follow instructions_ rather than just complete text. GPT-3 → InstructGPT was SFT. Llama-base → Llama-Instruct is SFT.

### RLHF (Reinforcement Learning from Human Feedback)

After SFT, further align the model using human preference data:

1. Generate multiple responses to the same prompt
2. Human rankers compare and rank them
3. Train a **reward model** to predict human preferences
4. Use RL (PPO) to push the LLM toward higher-reward outputs

This is how OpenAI made GPT-4 safer and more helpful. Covered in depth in [[../04 - Fine-Tuning and Model Adaptation/04.2 - RLHF and DPO]].

### Task-Specific Fine-tuning

Fine-tune for a specific narrow task: code generation, SQL, medical QA. Typically much smaller datasets (thousands of examples), much lower cost.

### PEFT (Parameter-Efficient Fine-tuning)

Instead of updating all weights, update only a small subset. LoRA, QLoRA, adapters. Enables fine-tuning on consumer GPUs. See [[../04 - Fine-Tuning and Model Adaptation/04.3 - PEFT - LoRA QLoRA Adapters]].

### Cost

SFT on an 8B model with LoRA: can be done on a single A100 GPU in hours. Full fine-tuning of a 70B model: requires a cluster of A100s, costs thousands of dollars.

---

## Phase 3: Inference

Running the trained model to generate outputs. No weight updates — purely forward passes.

### The Autoregressive Loop

Text generation is an **iterative process**:

```
Input tokens: ["Tell", "me", "a", "joke"]

Step 1: Model sees ["Tell", "me", "a", "joke"] → predicts "Why"
Step 2: Model sees ["Tell", "me", "a", "joke", "Why"] → predicts "did"
Step 3: ...continues until <EOS> token
```

Each step is one forward pass through the entire model. This is why:

- Longer outputs take longer to generate
- Time-to-first-token (TTFT) and tokens-per-second are separate metrics
- You can stream tokens as they're generated (each step produces one token immediately)

### KV Cache

During inference, the attention keys and values for previous tokens don't change. They're cached to avoid recomputation:

```
Without KV cache: Every step recomputes attention over the entire context from scratch
With KV cache:    Only compute new token's K, V; reuse all previous K, V pairs
```

KV cache makes inference fast but is memory-intensive — this is why context length directly impacts GPU memory requirements.

### Quantization

Production inference often uses quantized models (e.g., INT8 or INT4 instead of FP16/BF16 weights). This:

- Reduces GPU memory by 2–4×
- Slightly reduces precision (usually acceptable)
- Enables serving larger models on fewer GPUs

## Decision Framework: Pretrain vs Fine-tune vs Prompt

```
Problem: My AI system isn't behaving correctly

├── Does it lack knowledge (doesn't know recent facts, private data)?
│   └── Use RAG (don't fine-tune for knowledge) ← most common answer
│
├── Does it behave wrong (wrong tone, wrong format, wrong reasoning style)?
│   ├── Can prompting fix it?
│   │   └── Yes → Fix the prompt first (cheapest)
│   │
│   └── Does it need consistent behavior at scale across many calls?
│       └── Yes → Fine-tune (SFT with LoRA)
│
└── Is it a fundamentally different domain (medical, legal, code)?
    ├── Small dataset available → Fine-tune base model
    └── Large domain corpus available → Consider domain-adaptive pretraining
        (rare; only if domain language differs significantly from general web)
```

**The most common mistake**: fine-tuning to inject knowledge (use RAG instead). **The second most common mistake**: not trying prompting before fine-tuning.

## Summary Table

|Phase|Who does it|Cost|Changes weights?|Output|
|---|---|---|---|---|
|Pretraining|Labs only|$M–$100M|Yes (from scratch)|Base model|
|SFT|Teams, fine-tuning services|$10–$10K|Yes (partial or full)|Instruction-tuned model|
|RLHF/DPO|Teams with data|$100–$100K|Yes|Aligned model|
|PEFT/LoRA|Individual engineers|$1–$100|Yes (tiny subset)|Adapted model|
