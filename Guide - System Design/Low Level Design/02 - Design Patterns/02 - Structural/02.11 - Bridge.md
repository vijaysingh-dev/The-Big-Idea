# Bridge Pattern

## At a Glance

|||
|---|---|
|**Type**|Structural|
|**Intent**|Decouple an abstraction from its implementation so that the two can vary independently|
|**Frequency in Backend**|★★☆☆☆ — multi-dimensional variation (provider × format, transport × serialization)|

---

## The Problem It Solves

Two orthogonal dimensions of variation. Without Bridge, every combination needs a class:

```
Without Bridge (class explosion):
  SalesReportPDF      SalesReportCSV      SalesReportExcel
  InventoryReportPDF  InventoryReportCSV  InventoryReportExcel
  AuditReportPDF      AuditReportCSV      AuditReportExcel
  [N report types × M formats = N×M classes]

With Bridge:
  SalesReport   + PDFRenderer    → compose at runtime
  InventoryReport + CsvRenderer
  [N + M classes, any combination]
```

---

## Structure

```
Abstraction (Report)          Implementation (Renderer)
       │                              △
       │ has-a                 ┌──────┴──────┐
       ▼                       │             │
┌──────────────┐          PDFRenderer   CsvRenderer
│ Report       │◄──────── (impl)
│ - renderer   │
│ + generate() │─────calls────► renderer.render(data)
└──────────────┘
       △
┌──────┴──────┐
│             │
SalesReport  InventoryReport
```

## Full Backend Example: Notification Transport × Serialization

```python
# serializer.py — Implementation hierarchy
from abc import ABC, abstractmethod

class MessageSerializer(ABC):
    """Implementation: how to serialize the message payload."""
    
    @abstractmethod
    def serialize(self, data: dict) -> bytes: pass
    
    @abstractmethod
    def content_type(self) -> str: pass


class JsonSerializer(MessageSerializer):
    def serialize(self, data: dict) -> bytes:
        import json
        return json.dumps(data).encode("utf-8")
    
    def content_type(self): return "application/json"


class ProtobufSerializer(MessageSerializer):
    def __init__(self, message_class):
        self._cls = message_class
    
    def serialize(self, data: dict) -> bytes:
        msg = self._cls(**data)
        return msg.SerializeToString()
    
    def content_type(self): return "application/protobuf"


class MsgpackSerializer(MessageSerializer):
    def serialize(self, data: dict) -> bytes:
        import msgpack
        return msgpack.packb(data)
    
    def content_type(self): return "application/msgpack"


# transport.py — Abstraction hierarchy
class MessageTransport(ABC):
    """
    Abstraction: knows HOW to send, delegates serialization to impl.
    Bridge: holds reference to serializer.
    """
    
    def __init__(self, serializer: MessageSerializer):
        self._serializer = serializer  # Bridge
    
    def send(self, topic: str, data: dict):
        payload = self._serializer.serialize(data)
        content_type = self._serializer.content_type()
        self._deliver(topic, payload, content_type)
    
    @abstractmethod
    def _deliver(self, topic: str, payload: bytes, content_type: str): pass


class KafkaTransport(MessageTransport):
    def __init__(self, serializer: MessageSerializer, bootstrap_servers: str):
        super().__init__(serializer)
        from kafka import KafkaProducer
        self._producer = KafkaProducer(bootstrap_servers=bootstrap_servers)
    
    def _deliver(self, topic: str, payload: bytes, content_type: str):
        self._producer.send(
            topic, value=payload,
            headers=[("content-type", content_type.encode())]
        )


class HttpTransport(MessageTransport):
    def __init__(self, serializer: MessageSerializer, base_url: str):
        super().__init__(serializer)
        self._base_url = base_url
    
    def _deliver(self, topic: str, payload: bytes, content_type: str):
        import requests
        requests.post(
            f"{self._base_url}/{topic}",
            data=payload,
            headers={"Content-Type": content_type},
            timeout=5
        )


class SqsTransport(MessageTransport):
    def __init__(self, serializer: MessageSerializer, queue_url: str):
        super().__init__(serializer)
        import boto3
        self._sqs = boto3.client("sqs")
        self._queue_url = queue_url
    
    def _deliver(self, topic: str, payload: bytes, content_type: str):
        self._sqs.send_message(
            QueueUrl=self._queue_url,
            MessageBody=payload.decode(),
            MessageAttributes={
                "ContentType": {"StringValue": content_type, "DataType": "String"},
                "Topic": {"StringValue": topic, "DataType": "String"}
            }
        )


# Compose any transport × any serializer at runtime
kafka_json   = KafkaTransport(JsonSerializer(),   bootstrap_servers="kafka:9092")
kafka_proto  = KafkaTransport(ProtobufSerializer(OrderEvent), bootstrap_servers="kafka:9092")
http_json    = HttpTransport(JsonSerializer(),    base_url="https://events.internal")
sqs_msgpack  = SqsTransport(MsgpackSerializer(),  queue_url="https://sqs.amazonaws.com/...")

# Usage is identical regardless of combination
kafka_json.send("order-events", {"order_id": "123", "status": "PAID"})
sqs_msgpack.send("inventory-events", {"product_id": "456", "qty": 10})
```

## Report Generation Example (Classic Bridge)

```python
# Renderer (implementation)
class ReportRenderer(ABC):
    @abstractmethod
    def render(self, title: str, data: list[dict]) -> bytes: pass
    
    @abstractmethod
    def file_extension(self) -> str: pass

class PdfRenderer(ReportRenderer):
    def render(self, title, data):
        return pdf_lib.generate(title=title, rows=data)
    
    def file_extension(self): return "pdf"

class CsvRenderer(ReportRenderer):
    def render(self, title, data):
        import csv, io
        buf = io.StringIO()
        if data:
            writer = csv.DictWriter(buf, fieldnames=data[0].keys())
            writer.writeheader()
            writer.writerows(data)
        return buf.getvalue().encode()
    
    def file_extension(self): return "csv"


# Report (abstraction)
class Report(ABC):
    def __init__(self, renderer: ReportRenderer):
        self._renderer = renderer   # Bridge
    
    def generate(self) -> tuple[bytes, str]:
        title, data = self._fetch_data()
        content = self._renderer.render(title, data)
        filename = f"{self._filename()}.{self._renderer.file_extension()}"
        return content, filename
    
    @abstractmethod
    def _fetch_data(self) -> tuple[str, list[dict]]: pass
    
    @abstractmethod
    def _filename(self) -> str: pass

class SalesReport(Report):
    def __init__(self, renderer, start_date, end_date):
        super().__init__(renderer)
        self._start = start_date
        self._end = end_date
    
    def _fetch_data(self):
        data = db.query("SELECT * FROM orders WHERE created_at BETWEEN %s AND %s",
                       (self._start, self._end))
        return "Sales Report", data
    
    def _filename(self): return f"sales_{self._start}_{self._end}"


# Any report × any renderer
sales_pdf = SalesReport(PdfRenderer(), start_date="2024-01", end_date="2024-03")
sales_csv = SalesReport(CsvRenderer(), start_date="2024-01", end_date="2024-03")
content, filename = sales_pdf.generate()
```

## When to Use Bridge

- Two independent dimensions of variation exist
- You want to switch implementations at runtime
- Extending one dimension shouldn't force changes to the other

## When NOT to Use Bridge

- Only one dimension varies — Strategy or Template Method is simpler
- Dimensions are not truly independent — the abstraction is artificial

---

## Tradeoffs

|Pro|Con|
|---|---|
|N + M classes instead of N × M|Indirection makes code less obvious|
|Vary abstraction and implementation independently|Requires upfront identification of both hierarchies|
|Runtime combination|Over-engineering when one implementation exists|
