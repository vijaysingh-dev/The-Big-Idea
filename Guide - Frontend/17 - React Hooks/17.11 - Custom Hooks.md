# Custom Hooks

A custom hook is a function whose name starts with `use` and which calls other hooks. That is the entire definition — there is no special API.

```jsx
function useToggle(initial = false) {
  const [on, setOn] = useState(initial);
  const toggle = useCallback(() => setOn(v => !v), []);
  return [on, toggle];
}
```

## They share logic, not state

```jsx
function A() { const [on, toggle] = useToggle(); }
function B() { const [on, toggle] = useToggle(); }
```

Each call allocates its own hook slots in its own component's list ([[17.1 - Rules of Hooks and How They Work]]). `A` and `B` have completely independent state.

This surprises people expecting a hook to behave like a shared store. Sharing state requires context or a store library ([[17.9 - useContext]]).

## The naming convention is load-bearing

The `use` prefix is not style. The ESLint plugin uses it to decide which functions to check for rule violations, and the React Compiler uses it to identify hook boundaries.

```jsx
function getFormState() { useState(); }   // linter cannot check this
function useFormState() { useState(); }   // checked
```

A function that calls no hooks should **not** be prefixed with `use` — that misleads readers into thinking it must follow the rules of hooks. A plain utility is a plain function.

## Extract behavior, not lines

The purpose is reusing **stateful logic**, not shortening components.

```jsx
// Not a useful hook — no shared behavior, just moved code
function useUserName(user) {
  return `${user.first} ${user.last}`;
}
```

That is a plain function with a misleading name. Good candidates involve state, effects, subscriptions or refs:

```jsx
function useOnlineStatus() {
  return useSyncExternalStore(
    (callback) => {
      window.addEventListener("online", callback);
      window.addEventListener("offline", callback);
      return () => {
        window.removeEventListener("online", callback);
        window.removeEventListener("offline", callback);
      };
    },
    () => navigator.onLine,
    () => true          // server snapshot
  );
}
```

## Designing the return value

**Return a tuple** when the consumer will rename the values — that is why `useState` returns an array:

```jsx
const [isOpen, setIsOpen] = useToggle();
const [isDark, setIsDark] = useToggle();
```

**Return an object** when there are more than two or three values, or when consumers may want only some:

```jsx
const { data, error, isLoading, refetch } = useFetch(url);
```

**Return stable references.** A hook cannot know whether its consumer will put the returned function in a dependency array or pass it to a memoized child, so functions should be wrapped in `useCallback` and objects in `useMemo` ([[17.7 - useCallback]]):

```jsx
function usePagination(total, perPage) {
  const [page, setPage] = useState(1);

  const next = useCallback(() => setPage(p => Math.min(p + 1, pages)), [pages]);
  const prev = useCallback(() => setPage(p => Math.max(p - 1, 1)), []);

  return useMemo(() => ({ page, next, prev }), [page, next, prev]);
}
```

Returning a fresh object every render silently defeats every consumer's memoization.

## Composing hooks

```jsx
function useDebouncedSearch(query, delay = 300) {
  const debounced = useDebounce(query, delay);
  const { data, isLoading } = useSearch(debounced);
  return { results: data, isLoading };
}

function useDebounce(value, delay) {
  const [debounced, setDebounced] = useState(value);

  useEffect(() => {
    const id = setTimeout(() => setDebounced(value), delay);
    return () => clearTimeout(id);
  }, [value, delay]);

  return debounced;
}
```

Hooks compose like functions. Each layer handles one concern and the composition reads top-to-bottom.

Note the cleanup in `useDebounce` — clearing the previous timeout on every change is what makes it debounce rather than fire repeatedly ([[29.1 - Debounce and Throttle]]).

## Custom hooks make effects disappear from components

One of the strongest arguments for extraction: a component with three effects becomes a component with three hook calls and no effects at all.

```jsx
// Before
function Chat({ roomId }) {
  useEffect(() => { /* connect */ }, [roomId]);
  useEffect(() => { /* presence */ }, [roomId]);
  useEffect(() => { /* typing indicator */ }, [roomId]);
}

// After
function Chat({ roomId }) {
  const connection = useChatConnection(roomId);
  const presence = usePresence(roomId);
  const typing = useTypingIndicator(roomId);
}
```

The effects still exist, but the component now reads as a declaration of what it needs rather than a list of imperative setups. The official documentation frames this as the primary benefit of custom hooks.

## Common patterns

```jsx
// Persisted state
function useLocalStorage(key, initial) {
  const [value, setValue] = useState(() => {
    try {
      const raw = localStorage.getItem(key);
      return raw ? JSON.parse(raw) : initial;
    } catch { return initial; }
  });

  useEffect(() => {
    try { localStorage.setItem(key, JSON.stringify(value)); } catch {}
  }, [key, value]);

  return [value, setValue];
}

// Media query
function useMediaQuery(query) {
  return useSyncExternalStore(
    (cb) => {
      const mql = window.matchMedia(query);
      mql.addEventListener("change", cb);
      return () => mql.removeEventListener("change", cb);
    },
    () => window.matchMedia(query).matches,
    () => false
  );
}

// Previous value
function usePrevious(value) {
  const ref = useRef(undefined);
  useEffect(() => { ref.current = value; });
  return ref.current;
}
```

`useSyncExternalStore` is the correct primitive for subscribing to anything outside React, because it prevents tearing during concurrent rendering ([[17.12 - Lesser Known Hooks]]). A `useState` + `useEffect` version of `useMediaQuery` works but can show a stale value on the first paint and during interrupted renders.

Note the try/catch in `useLocalStorage` — storage throws in private browsing on some browsers and when the quota is exceeded ([[14.2 - LocalStorage and SessionStorage]]).

## When not to extract

**A single use with no reuse in sight.** Extraction adds a file, an import and indirection. Inline it until there is a second consumer.

**Wrapping a single hook with no added logic.** `useMyState = useState` is noise.

**Over-abstracting into a "do everything" hook.** A `useUser` that fetches, caches, subscribes, syncs to storage and handles auth is untestable and impossible to reuse partially. Small hooks compose; large ones do not.

**Hiding an effect that should not exist.** Extracting a derived-state effect into a custom hook makes it reusable but does not make it correct ([[17.4 - useEffect Pitfalls]]).

## Testing

```jsx
import { renderHook, act } from "@testing-library/react";

test("toggles", () => {
  const { result } = renderHook(() => useToggle(false));
  expect(result.current[0]).toBe(false);
  act(() => result.current[1]());
  expect(result.current[0]).toBe(true);
});
```

`renderHook` mounts the hook in a throwaway component. Providers are supplied through the `wrapper` option ([[26.3 - React Testing Library]]).

## How senior engineers actually use this

**They extract when there is a second consumer**, not in anticipation of one.

**They return stable references** from every hook they intend others to use.

**They keep hooks small and composable**, layering them rather than growing one.

**They use custom hooks to remove effects from components**, which is where most of the readability gain comes from.

**They use `useSyncExternalStore` for anything external** rather than `useState` plus a subscription effect.

## Common pitfalls

- Expecting two components using the same hook to share state.
- Returning new objects or functions every render, breaking consumer memoization.
- Naming a non-hook function with a `use` prefix, or a hook without one.
- A single hook accumulating unrelated responsibilities.
- Extracting for its own sake, producing indirection with no reuse.
- Subscribing to external state with `useState` + `useEffect` instead of `useSyncExternalStore`.

## Interview angle

"What are custom hooks and why use them" should get: a convention, not an API — a function starting with `use` that calls hooks — for reusing stateful logic, with each consumer getting independent state. The distinguishing points are that they do **not** share state (which is a common misconception), that returned functions and objects need stable references, and that their main practical benefit is removing effects from components so a component reads as a declaration of what it needs.
