# Optional Chaining and Nullish Coalescing

Two operators from ES2020 that between them removed most defensive-access boilerplate from JavaScript.

## Optional chaining

`?.` short-circuits to `undefined` if the value before it is `null` or `undefined`, instead of throwing.

```js
user?.profile?.city;

// equivalent to
user === null || user === undefined
  ? undefined
  : user.profile === null || user.profile === undefined
  ? undefined
  : user.profile.city;
```

Three forms:

```js
obj?.prop        // property access
obj?.[key]       // computed access
fn?.(args)       // function call
arr?.[0]         // array index
```

The `fn?.()` form is particularly useful for optional callbacks:

```js
function Modal({ onClose }) {
  const handle = () => {
    onClose?.();   // no need to check first
  };
}
```

Note the syntax: `?.()` and `?.[]` keep the dot. `obj?[key]` is a syntax error.

**Short-circuiting stops the whole chain**, not just one link:

```js
const result = a?.b.c.d;   // undefined if a is nullish — b.c.d never evaluated
```

This means one `?.` protects everything after it *on that chain*, so `a?.b?.c?.d` is redundant if only `a` can be nullish. Writing `?.` at every level is a common habit that hides which value is actually optional. Put it only where absence is genuinely possible.

**It only guards `null` and `undefined`.** If `a.b` is `0` or `""`, the chain continues normally, which is correct.

**Optional chaining does not work on assignment:**

```js
obj?.prop = 1;   // SyntaxError
```

**Deleting is allowed:**

```js
delete obj?.prop;  // no-op if obj is nullish
```

## Nullish coalescing

`??` returns the right side only when the left is `null` or `undefined`.

```js
const port = config.port ?? 3000;
```

Compare with `||`, which falls back on any falsy value:

```js
const count = 0;
count || 10;   // 10  — wrong
count ?? 10;   // 0   — correct

const name = "";
name || "anon"; // "anon"
name ?? "anon"; // ""

const show = false;
show || true;  // true — wrong
show ?? true;  // false
```

Any setting where `0`, `""` or `false` is a legitimate value needs `??`. That covers most numeric configuration, most text inputs, and every boolean flag — which is to say, most defaults you will ever write.

`||` remains correct when you genuinely want "any falsy value means missing", such as `const display = trimmedInput || "(empty)"`.

## Combining them

```js
const city = response?.data?.user?.address?.city ?? "Unknown";

const timeout = options?.timeout ?? DEFAULT_TIMEOUT;

const items = data?.results ?? [];
items.map(render);   // safe — always an array
```

The `?? []` pattern is worth internalizing: normalizing to an empty array at the boundary removes every downstream null check.

## The mixing restriction

`??` cannot be combined with `||` or `&&` without parentheses:

```js
a ?? b || c;       // SyntaxError
(a ?? b) || c;     // fine
a ?? (b || c);     // fine
```

This is deliberate. The precedence would be ambiguous to readers, so the spec requires you to be explicit.

## Nullish assignment operators

```js
options.retries ??= 3;    // assign only if null/undefined
cache.value ||= compute(); // assign if falsy
flags.enabled &&= isValid; // assign if truthy
```

All three short-circuit — `??=` does not evaluate the right side at all if the left is already non-nullish, which matters when the right side is expensive or has side effects.

## Where these actually change code

**API responses** — server shapes are optional in ways types cannot always guarantee at runtime:

```js
const avatar = user?.profile?.avatar?.url ?? DEFAULT_AVATAR;
```

**DOM access** — `querySelector` returns `null`:

```js
document.querySelector(".banner")?.classList.add("hidden");
```

**Optional props and callbacks in React:**

```jsx
function List({ items, renderEmpty }) {
  if (!items?.length) return renderEmpty?.() ?? null;
  return items.map(/* ... */);
}
```

**Environment configuration:**

```js
const apiUrl = import.meta.env.VITE_API_URL ?? "http://localhost:3000";
```

## Performance and bundle size

Both compile to conditional expressions when transpiled for older targets, which adds a small amount of code — the transpiled output for a long chain introduces temporary variables. Irrelevant in almost all cases, but worth knowing if you are targeting ES5 and see bundle growth after adopting them heavily ([[27.5 - Babel and Transpilation]]).

Both are supported in all browsers released since 2020, so most projects can now ship them untranspiled.

## How senior engineers actually use this

**They use `?.` at the boundary, not throughout.** A chain full of `?.` is often a signal the data should have been normalized once on arrival. Validating and defaulting an API response at the parse layer ([[25.7 - Typing API Responses and Zod]]) beats sprinkling optional chaining through fifty components.

**They default to `??` over `||` for defaults.** The habit prevents a whole class of bugs where `0` or `false` is silently replaced.

**They avoid `?.` masking real bugs.** If `user` should never be nullish, `user?.name` turns a loud crash into a silently blank UI. Optional chaining is for genuinely optional values; a missing required value should fail visibly.

**They watch out for `?.` in conditions.** `if (obj?.enabled)` is `false` both when `obj` is missing and when `enabled` is `false`. If those cases need different handling, check them separately.

## Common pitfalls

- Using `||` for numeric or boolean defaults.
- Overusing `?.` and hiding genuine data problems.
- Assuming `?.` guards against `TypeError` from calling a non-function — it only guards nullish values; `obj.notAFunction?.()` still throws if the property is a string.
- Forgetting the parenthesization requirement when mixing `??` with `||`.
- Writing `obj?.prop = value` and hitting a syntax error.

## Interview angle

"Difference between `||` and `??`" is asked often, and the expected answer is the falsy-versus-nullish distinction with a `0` example. Follow with optional chaining's short-circuit behavior — that one `?.` protects the rest of the chain — and the point that overusing it can mask bugs. That last observation is the kind of judgment call interviewers listen for.
