# Case Study: Rate Limiter

**Difficulty:** Medium | **Patterns:** Strategy, Decorator, Proxy, Template Method

---

## Step 1: Requirements

### Functional

- Limit requests per user / per IP / per API key
- Multiple algorithms: fixed window, sliding window, token bucket, leaky bucket
- Per-endpoint configuration (login: 5/min, API: 1000/hour)
- Return remaining quota in response headers
- Configurable actions on limit exceeded: reject or queue
- Distributed (works across multiple server instances)

### Non-Functional

- Decision in <5ms (must not add latency to hot path)
- Redis for distributed state
- Atomic operations (no race conditions)
- Configurable per tenant in SaaS

---

## Step 2: Algorithm Comparison

```
Fixed Window:
  Count reqs in [0:00 - 0:59], reset at 1:00
  ✅ Simple, O(1) memory
  ❌ Burst at window boundary (100 at 0:59 + 100 at 1:00 = 200 in 2 seconds)

Sliding Window (log-based):
  Count reqs in rolling last 60 seconds
  ✅ Smooth, no boundary burst
  ❌ O(n) memory (stores each request timestamp)

Sliding Window (counter-based):
  Hybrid: current window count + weighted previous window count
  ✅ Approximate but smooth, O(1) memory
  ❌ Approximate (not exact)

Token Bucket:
  Bucket holds N tokens, refills at rate R/sec
  Consume 1 token per request; block if empty
  ✅ Allows bursts up to bucket size
  ✅ Smooth average rate
  ❌ Slightly complex

Leaky Bucket:
  Requests added to queue, processed at fixed rate
  ✅ Consistent output rate
  ❌ Queuing adds latency; bursty input dropped
```

```python
# rate_limit_result.py
from dataclasses import dataclass
from typing import Optional

@dataclass
class RateLimitResult:
    allowed: bool
    limit: int
    remaining: int
    reset_at_unix: int          # when window resets (for fixed/sliding window)
    retry_after_seconds: Optional[int] = None  # set when not allowed


# algorithms.py — Strategy pattern

from abc import ABC, abstractmethod
import time

class RateLimitAlgorithm(ABC):
    @abstractmethod
    def check_and_increment(self, key: str, limit: int,
                            window_seconds: int) -> RateLimitResult: pass
    
    @abstractmethod
    def algorithm_name(self) -> str: pass


class FixedWindowAlgorithm(RateLimitAlgorithm):
    """Simple fixed window counter using Redis."""
    
    def __init__(self, redis_client):
        self._redis = redis_client
    
    def check_and_increment(self, key: str, limit: int,
                            window_seconds: int) -> RateLimitResult:
        pipe = self._redis.pipeline()
        
        # Atomic: increment + set expiry if new key
        pipe.incr(key)
        pipe.expire(key, window_seconds, nx=True)  # only set if not already set
        results = pipe.execute()
        
        current_count = results[0]
        ttl = self._redis.ttl(key)
        reset_at = int(time.time()) + (ttl if ttl > 0 else window_seconds)
        
        if current_count > limit:
            return RateLimitResult(
                allowed=False, limit=limit, remaining=0,
                reset_at_unix=reset_at, retry_after_seconds=ttl
            )
        
        return RateLimitResult(
            allowed=True, limit=limit, remaining=max(0, limit - current_count),
            reset_at_unix=reset_at
        )
    
    def algorithm_name(self): return "fixed_window"


class SlidingWindowLogAlgorithm(RateLimitAlgorithm):
    """
    Exact sliding window using Redis sorted set (timestamps as scores).
    Each request stored as a timestamped entry. Prune old entries on each check.
    """
    
    def __init__(self, redis_client):
        self._redis = redis_client
    
    def check_and_increment(self, key: str, limit: int,
                            window_seconds: int) -> RateLimitResult:
        now = time.time()
        window_start = now - window_seconds
        
        pipe = self._redis.pipeline()
        # 1. Remove entries outside window
        pipe.zremrangebyscore(key, 0, window_start)
        # 2. Count remaining (in-window) entries
        pipe.zcard(key)
        # 3. Add current request
        pipe.zadd(key, {f"{now}:{id(object())}": now})
        # 4. Set key expiry
        pipe.expire(key, window_seconds + 1)
        results = pipe.execute()
        
        current_count = results[1] + 1  # +1 for the one we just added
        reset_at = int(now + window_seconds)
        
        if current_count > limit:
            # Undo the add
            self._redis.zremrangebyscore(key, now, now + 0.001)
            return RateLimitResult(
                allowed=False, limit=limit, remaining=0,
                reset_at_unix=reset_at, retry_after_seconds=1
            )
        
        return RateLimitResult(
            allowed=True, limit=limit, remaining=max(0, limit - current_count),
            reset_at_unix=reset_at
        )
    
    def algorithm_name(self): return "sliding_window_log"


class TokenBucketAlgorithm(RateLimitAlgorithm):
    """
    Token bucket using Redis with atomic Lua script.
    Bucket refills at rate (limit / window_seconds) tokens per second.
    """
    
    REFILL_SCRIPT = """
        local key = KEYS[1]
        local capacity = tonumber(ARGV[1])
        local refill_rate = tonumber(ARGV[2])  -- tokens per second
        local now = tonumber(ARGV[3])
        
        local bucket = redis.call('HMGET', key, 'tokens', 'last_refill')
        local tokens = tonumber(bucket[1]) or capacity
        local last_refill = tonumber(bucket[2]) or now
        
        -- Refill tokens based on time elapsed
        local elapsed = now - last_refill
        local new_tokens = math.min(capacity, tokens + elapsed * refill_rate)
        
        if new_tokens >= 1 then
            new_tokens = new_tokens - 1
            redis.call('HMSET', key, 'tokens', new_tokens, 'last_refill', now)
            redis.call('EXPIRE', key, math.ceil(capacity / refill_rate) + 1)
            return {1, math.floor(new_tokens)}  -- allowed, remaining
        else
            redis.call('HMSET', key, 'tokens', new_tokens, 'last_refill', now)
            return {0, 0}  -- denied
        end
    """
    
    def __init__(self, redis_client):
        self._redis = redis_client
        self._script = self._redis.register_script(self.REFILL_SCRIPT)
    
    def check_and_increment(self, key: str, limit: int,
                            window_seconds: int) -> RateLimitResult:
        refill_rate = limit / window_seconds  # tokens per second
        now = time.time()
        
        result = self._script(keys=[key], args=[limit, refill_rate, now])
        allowed, remaining = bool(result[0]), int(result[1])
        
        return RateLimitResult(
            allowed=allowed,
            limit=limit,
            remaining=remaining,
            reset_at_unix=int(now + 1 / refill_rate),
            retry_after_seconds=None if allowed else int(1 / refill_rate)
        )
    
    def algorithm_name(self): return "token_bucket"


# rate_limiter.py — Context using Strategy
from dataclasses import dataclass

@dataclass
class RateLimitRule:
    limit: int
    window_seconds: int
    algorithm: str = "sliding_window_log"   # default


class RateLimiter:
    """
    Main rate limiter. Uses configurable algorithm (Strategy).
    Resolves which rule applies based on key type.
    """
    
    def __init__(self, algorithms: dict[str, RateLimitAlgorithm],
                 rules: dict[str, RateLimitRule]):
        self._algorithms = algorithms
        self._rules = rules   # endpoint → rule
    
    def check(self, identifier: str, rule_name: str) -> RateLimitResult:
        rule = self._rules.get(rule_name, self._rules["default"])
        algorithm = self._algorithms[rule.algorithm]
        
        key = f"rl:{rule_name}:{identifier}"
        return algorithm.check_and_increment(key, rule.limit, rule.window_seconds)
    
    def check_multiple(self, identifier: str,
                       rule_names: list[str]) -> RateLimitResult:
        """Check multiple rules — most restrictive wins (e.g., per-user AND per-IP)."""
        results = [self.check(identifier, r) for r in rule_names]
        # Return most restrictive: if any denied, return that one
        denied = [r for r in results if not r.allowed]
        if denied:
            return min(denied, key=lambda r: r.remaining)
        return min(results, key=lambda r: r.remaining)


# middleware.py — Proxy/Decorator wrapping any handler
class RateLimitMiddleware:
    """
    Middleware (Proxy pattern): intercepts requests and checks rate limits.
    Completely transparent to the underlying handler.
    """
    
    def __init__(self, handler, rate_limiter: RateLimiter,
                 key_extractor, rule_selector):
        self._handler = handler
        self._limiter = rate_limiter
        self._get_key = key_extractor      # e.g., extract IP or user_id
        self._get_rule = rule_selector     # e.g., match endpoint to rule
    
    def handle(self, request) -> "HttpResponse":
        identifier = self._get_key(request)
        rule_name = self._get_rule(request)
        
        result = self._limiter.check(identifier, rule_name)
        
        if not result.allowed:
            response = HttpResponse.error(429, "Too Many Requests")
        else:
            response = self._handler.handle(request)
        
        # Always add rate limit headers
        response.headers.update({
            "X-RateLimit-Limit": str(result.limit),
            "X-RateLimit-Remaining": str(result.remaining),
            "X-RateLimit-Reset": str(result.reset_at_unix),
        })
        if not result.allowed and result.retry_after_seconds:
            response.headers["Retry-After"] = str(result.retry_after_seconds)
        
        return response


# Configuration and wiring
algorithms = {
    "fixed_window": FixedWindowAlgorithm(redis_client),
    "sliding_window_log": SlidingWindowLogAlgorithm(redis_client),
    "token_bucket": TokenBucketAlgorithm(redis_client),
}

rules = {
    "default":       RateLimitRule(limit=1000, window_seconds=3600),
    "login":         RateLimitRule(limit=5,    window_seconds=60,   algorithm="fixed_window"),
    "api_general":   RateLimitRule(limit=100,  window_seconds=60,   algorithm="token_bucket"),
    "send_otp":      RateLimitRule(limit=3,    window_seconds=300,  algorithm="fixed_window"),
    "search":        RateLimitRule(limit=30,   window_seconds=60,   algorithm="sliding_window_log"),
    "payment":       RateLimitRule(limit=10,   window_seconds=3600, algorithm="token_bucket"),
}

rate_limiter = RateLimiter(algorithms, rules)

# Apply as middleware
rate_limited_api = RateLimitMiddleware(
    handler=api_handler,
    rate_limiter=rate_limiter,
    key_extractor=lambda req: req.user_id or req.ip_address,
    rule_selector=lambda req: req.path.lstrip("/").split("/")[0]  # first path segment
)
```

## Step 4: Patterns Used

|Pattern|Where|Why|
|---|---|---|
|**Strategy**|`RateLimitAlgorithm`|Swap fixed/sliding/token-bucket without touching `RateLimiter`|
|**Proxy**|`RateLimitMiddleware`|Transparent interception — handler doesn't know it's rate-limited|
|**Decorator**|`RateLimitMiddleware` (alt view)|Wraps handler, same interface, adds behavior|
|**Template Method**|Base algorithm (check + increment)|All algorithms follow check → apply → return structure|

## Step 5: Distributed Concerns

```
Multi-instance race condition:
  Two instances check quota simultaneously — both see "99/100"
  Both allow — actual count becomes 101

Solution: Atomic operations in Redis
  - Use INCR (atomic) not GET + SET
  - Use Lua scripts for multi-step logic (executes atomically)
  - Redis single-threaded — all operations serialized

Redis failure handling:
  - Circuit breaker around Redis calls
  - Fallback: allow requests (fail open) or deny all (fail closed)
  - Fail open preferred for most APIs
  - Fail closed for sensitive operations (login, payment)
```
