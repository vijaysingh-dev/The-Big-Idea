# Dataset Preparation and Quality

## Why Data Quality Dominates

The single most important factor in fine-tuning quality is dataset quality — not the model, not the hyperparameters, not the PEFT method.

A model trained on 500 excellent examples will outperform one trained on 50K mediocre examples on a specific task. This is one of the most consistent empirical findings in fine-tuning research (e.g., LIMA: 1000 examples matched much larger fine-tuned models).

---

## Dataset Formats

### Instruction-Response (Most Common)

```json
[
  {
    "messages": [
      {"role": "system",    "content": "You are a financial analyst..."},
      {"role": "user",      "content": "Summarize this earnings report: ..."},
      {"role": "assistant", "content": "Q3 2024 results: Revenue grew 12%..."}
    ]
  }
]
```

Use this format for conversational, instruction-following tasks.

### Completion Format (Older)

```json
{"prompt": "Summarize this: ...", "completion": "The article describes..."}
```

Older format; the messages format is preferred for modern chat-style models.

### Preference Data (for DPO)

```json
{
  "prompt": "Explain compound interest",
  "chosen": "Compound interest means earning interest on your interest...",
  "rejected": "Compound interest is when banks calculate stuff."
}
```

## Data Collection Strategies

### Option 1: Human Demonstrations

Hire domain experts to write (instruction, response) pairs from scratch.

- Highest quality ceiling
- Expensive ($5–$50 per example)
- Doesn't scale well
- Best for: specialized domains where no existing data exists

### Option 2: Distillation from a Stronger Model

Use GPT-4/Claude to generate responses for your instructions.

```python
# Generate training data via distillation
for instruction in your_instruction_set:
    response = gpt4.call(
        system="You are a helpful financial analyst...",
        user=instruction
    )
    dataset.append({"instruction": instruction, "response": response})
```

**Caution**: OpenAI's ToS restricts training competitor models on outputs. Check terms for your specific use case.

- Lower cost (~$0.01 per example for GPT-4o)
- Quality limited by teacher model
- Best for: format normalization, style matching, general instruction tuning

### Option 3: Existing Datasets

|Dataset|Size|Type|Use case|
|---|---|---|---|
|Alpaca (52K)|52K|Instruction following|General|
|OpenHermes|1M|Diverse instructions|General|
|Dolly 15K|15K|Human-written|High quality general|
|CodeAlpaca|20K|Code|Coding tasks|
|Medical Meadow|160K|Medical|Healthcare domain|
|FinGPT datasets|Various|Finance|Financial domain|

### Option 4: Mine Existing Data

Extract (instruction, response) pairs from your own:

- Customer support ticket history
- Internal Q&A systems
- Expert-written documentation with Q&A sections
- Existing chat logs (with privacy considerations)

## Data Quality Criteria

### Must-Have

**Accuracy**: Every response must be factually correct. Errors bake in during training.

```python
# Quality gate: validate all factual claims in responses
for example in dataset:
    # At minimum: spot-check 10% with domain expert
    # Ideally: automated fact-checking for verifiable claims
```

**Consistency**: Same instruction should get similar responses. Contradictory examples confuse the model.

**Format compliance**: If target output format is JSON, every example must have valid JSON. Format errors become model errors.

**Completeness**: Responses must actually answer the instruction fully. Partial answers create partially-answering models.

### Quality Filters

```python
def quality_filter(example):
    response = example["response"]
    
    # Length check: too short = incomplete
    if len(response.split()) < 20:
        return False
    
    # Repetition check: repetitive responses indicate quality issues
    sentences = response.split(".")
    if len(set(sentences)) / len(sentences) < 0.7:
        return False
    
    # Format check if applicable
    if expected_json and not is_valid_json(response):
        return False
    
    return True

dataset = [ex for ex in raw_dataset if quality_filter(ex)]
```

## Data Diversity and Coverage

**The coverage problem**: If your dataset only has 10 types of questions but real users ask 100 types, the model will fail on the uncovered 90 types.

Audit your dataset by clustering examples and checking:

```python
# Cluster examples to find distribution
embeddings = embedding_model.encode([ex["instruction"] for ex in dataset])
clusters = kmeans(embeddings, k=50)

# Check: are all important use cases represented?
# Check: are any clusters over-represented (data imbalance)?
```

**Intentional imbalance is sometimes right**: If 80% of real traffic is one task type, bias toward it. But don't accidentally have 80% from one template that produces unnatural variation.

## Dataset Deduplication

Near-duplicate examples waste capacity and can cause overfitting:

```python
from datasketch import MinHash, MinHashLSH

# Near-duplicate detection
lsh = MinHashLSH(threshold=0.8, num_perm=128)
unique_examples = []

for ex in dataset:
    minhash = compute_minhash(ex["instruction"])
    if not lsh.query(minhash):
        lsh.insert(ex["id"], minhash)
        unique_examples.append(ex)
```

## Labeling Strategy for Preference Data

For DPO, the quality of preference labels determines alignment quality.

### Using LLM as Labeler (RLAIF)

```python
LABELING_PROMPT = """
Compare these two responses to the given instruction.
Which response is better according to these criteria:
1. Accuracy and factual correctness
2. Helpfulness and completeness  
3. Clarity and conciseness
4. Following instructions precisely

Output ONLY "A" or "B" followed by a brief reason.
"""

def get_preference(instruction, response_a, response_b):
    result = gpt4.call(LABELING_PROMPT + format(instruction, response_a, response_b))
    return parse_preference(result)
```

**Reliability tips**:

- Use a stronger model than you're training (GPT-4 to train Llama)
- Randomize A/B order (LLMs have position bias — prefer the first response)
- Use majority vote across 3 labeling calls for close comparisons

## Data Pipeline

```
Raw Sources
    │
    ├── Collection (scrape, generate, extract)
    │
    ▼
Cleaning
    ├── Remove HTML/formatting artifacts
    ├── Normalize whitespace
    └── Remove PII (email, phone, names if applicable)
    │
    ▼
Quality Filtering
    ├── Length filter
    ├── Language filter (if monolingual)
    ├── Content safety filter
    └── Domain relevance filter
    │
    ▼
Deduplication
    │
    ▼
Human Spot-Check (10% sample)
    │
    ▼
Train/Val/Test Split (e.g., 90/5/5)
    │
    ▼
Tokenize + Format per model chat template
```
