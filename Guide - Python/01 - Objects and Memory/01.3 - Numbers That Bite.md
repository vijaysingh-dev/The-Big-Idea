# Numbers That Bite

#python #numbers #decimal #fundamentals

> **In one line:** Python ints never overflow, floats are binary approximations that cannot store 0.1 exactly, money belongs in `Decimal` or integer cents, and `round()` rounds half to even. Each of these has shipped a bug to production somewhere.

---

## int: Arbitrary Precision

```python
2 ** 200            # exact, no overflow
(10 ** 100) + 1     # exact
```

Python ints grow as needed, stored as an array of 30-bit "digits". The cost is that big-int arithmetic is slower than machine ints, and very large conversions are capped:

```python
int("9" * 5000)     # ValueError since 3.11: exceeds the 4300-digit limit
```

That limit (`sys.set_int_max_str_digits`) was added because parsing huge numeric strings is quadratic, and a JSON body with a 100,000-digit number could pin a CPU. A small denial-of-service fix worth knowing.

| Operation | Behaviour |
|---|---|
| `7 / 2` | `3.5` — true division always returns float |
| `7 // 2`, `-7 // 2` | `3`, **`-4`** — floor division rounds toward negative infinity |
| `-7 % 2` | **`1`** — the sign follows the divisor, so `a == (a // b) * b + a % b` |
| `int(-3.7)` | `-3` — truncates toward zero |
| `math.floor(-3.7)` | `-4` |

⚠️ Python's `%` and `//` differ from C, Java and Go for negative numbers. Porting logic such as shard selection (`user_id % n`) between languages can silently change results for negative IDs.

### bool is an int

```python
True + True        # 2
isinstance(True, int)   # True
sum(x > 0 for x in nums)   # count of positives — idiomatic
```

This bites in validation: a check like `isinstance(value, int)` accepts `True`. Pydantic's strict mode and JSON schema treat them separately for this reason.

## float: IEEE 754 Doubles

```python
0.1 + 0.2              # 0.30000000000000004
0.1 + 0.2 == 0.3       # False
```

A float stores a binary fraction. 0.1 has no finite binary representation, just as 1/3 has no finite decimal one. You get about 15–17 significant decimal digits.

```python
import math
math.isclose(0.1 + 0.2, 0.3)                     # True — use this, not ==
math.isclose(a, b, rel_tol=1e-9, abs_tol=1e-12)  # abs_tol matters near zero
float("nan") == float("nan")                     # False — NaN is not equal to itself
math.isnan(x)
float("inf") > 10**308                           # True
```

| Gotcha | Example |
|---|---|
| Accumulated error | `sum([0.1] * 10)` is `0.9999999999999999`. Use `math.fsum`. |
| Large ints lose precision | `float(2**53 + 1) == float(2**53)` is `True` |
| JSON numbers become floats | A 64-bit ID such as `9007199254740993` is not safe as a JavaScript number. Send big IDs as strings. |
| NaN breaks sorting | A list containing NaN does not sort consistently |

## Decimal: For Money

```python
from decimal import Decimal, ROUND_HALF_UP, getcontext

Decimal("0.1") + Decimal("0.2") == Decimal("0.3")   # True
Decimal(0.1)        # Decimal('0.1000000000000000055511151231257827...') — built FROM a float: wrong
Decimal("0.1")      # always build from strings or ints

price = Decimal("19.99")
tax = (price * Decimal("0.0825")).quantize(Decimal("0.01"), rounding=ROUND_HALF_UP)
```

| Option for money | Pros | Cons |
|---|---|---|
| `Decimal` | Exact decimal arithmetic, explicit rounding | Slower than float, must be built from strings |
| **Integer minor units** (cents) | Fast, exact, trivial to store and serialise | You must handle currency exponents (JPY has 0 decimals, KWD has 3) |
| `float` | Fast | **Never for money** |

Postgres `NUMERIC` maps to `Decimal` in asyncpg and psycopg. Pydantic validates `Decimal` fields with `max_digits` and `decimal_places` constraints. Payment APIs (Stripe, for example) use integer minor units. See [[06.6 - Payment Gateway]] for the system view.

## Rounding

```python
round(2.5)      # 2  — banker's rounding: half to even
round(3.5)      # 4
round(2.675, 2) # 2.67 — 2.675 is really 2.67499999... as a float
```

Python's `round` uses **round half to even**, which avoids statistical bias across many roundings. Business rules usually want **half up**. Use `Decimal.quantize(..., rounding=ROUND_HALF_UP)` and state the rule explicitly.

## Fraction: Exact Rationals

```python
from fractions import Fraction
Fraction(1, 3) + Fraction(1, 6)   # Fraction(1, 2)
```

Rarely needed in backend code, but it is exact for ratios such as split payments, before you convert to currency at the very end.

## Integer Tricks Worth Knowing

```python
1_000_000                   # underscores for readability
int("ff", 16), hex(255)     # base conversion
(255).to_bytes(2, "big")    # b'\x00\xff' — binary protocols
int.from_bytes(b"\x00\xff", "big")
n.bit_length(), n.bit_count()   # bit_count is 3.10+
divmod(17, 5)               # (3, 2)
pow(3, 200, 1_000_007)      # fast modular exponentiation
```
