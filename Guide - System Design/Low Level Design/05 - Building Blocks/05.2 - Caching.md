# Caching

## When to Cache

```
Cache when:
  ✅ Data is read far more often than written
  ✅ Computation or DB lookup is expensive
  ✅ Slightly stale data is acceptable
  ✅ Data fits in memory

Don't cache when:
  ❌ Data changes every request (user cart in checkout)
  ❌ Must always be fresh (bank balance)
  ❌ Every key is unique (random queries)
  ❌ Data is too large relative to memory
```

## Caching Strategies

### Cache-Aside (Lazy Loading)

```
Read flow:
  App → Cache miss → DB fetch → populate cache → return

Write flow:
  App → DB write → invalidate (or update) cache

✅ Cache only has accessed data (memory efficient)
✅ DB failure doesn't affect writes
❌ Cache miss penalty on cold start
❌ Stale window between DB update and cache update

Use: General-purpose reads
```

### Write-Through

```
Write flow:
  App → Write to cache AND DB simultaneously → return

Read flow:
  App → Cache hit (always populated after writes) → return

✅ Cache always current after writes
❌ Write latency (two writes)
❌ Cache populated with rarely-read data

Use: When you can't tolerate stale data after writes
```

### Write-Behind (Write-Back)

```
Write flow:
  App → Write to cache → async → flush to DB

✅ Very fast writes
❌ Risk of data loss if cache crashes before DB flush
❌ Complex — need durability guarantees

Use: High write throughput, can tolerate some loss (metrics, counters)
```

### Read-Through

```
App doesn't know about cache — cache layer handles DB reads transparently.
Same as Cache-Aside but responsibility is in the cache layer, not app.

Use: When you want transparent caching abstraction
```

## Cache Invalidation Strategies

```python
# 1. TTL-based (simplest)
cache.set("product:123", product_data, ttl=300)   # expires in 5 min
# Problem: stale for up to TTL, even if data changes immediately

# 2. Event-based invalidation (precise)
class ProductService:
    def update_product(self, product_id, data):
        self._repo.save(product_id, data)
        self._cache.delete(f"product:{product_id}")   # invalidate on write
# Problem: write and cache invalidation aren't atomic → brief stale window

# 3. Versioned keys (cache busting)
def get_cache_key(product_id, version):
    return f"product:{product_id}:v{version}"
# Increment version on update — old key naturally expires
# Problem: need to track version alongside data

# 4. Two-level TTL (stale-while-revalidate)
class StaleWhileRevalidateCache:
    def get(self, key):
        entry = self._redis.get(key)
        if entry is None:
            return None, "miss"
        
        data = json.loads(entry)
        age = time.time() - data["cached_at"]
        
        if age < data["fresh_ttl"]:
            return data["value"], "fresh"
        elif age < data["stale_ttl"]:
            # Return stale, trigger background refresh
            self._refresh_async(key, data["fetch_fn_key"])
            return data["value"], "stale"
        
        return None, "expired"
```

## Cache Stampede (Thundering Herd)

```
Problem: Popular cache key expires.
1000 concurrent requests see cache miss simultaneously.
All 1000 hit the DB at once → DB overwhelmed.

Solutions:
```

```python
# 1. Mutex / Lock (single refresh)
import threading

class StampedeProtectedCache:
    def __init__(self):
        self._locks: dict[str, threading.Lock] = {}
    
    def get_or_compute(self, key: str, compute_fn, ttl: int):
        value = self._cache.get(key)
        if value is not None:
            return value
        
        # Only one thread computes — others wait
        lock = self._locks.setdefault(key, threading.Lock())
        with lock:
            # Double-check after acquiring lock
            value = self._cache.get(key)
            if value is not None:
                return value
            
            value = compute_fn()
            self._cache.set(key, value, ttl)
            return value

# 2. Probabilistic early expiration (XFetch)
import math, random

def should_early_refresh(remaining_ttl: float, delta: float, beta: float = 1.0) -> bool:
    """
    Probabilistically refreshes before expiry.
    Higher beta = more aggressive early refresh.
    """
    return -delta * beta * math.log(random.random()) > remaining_ttl

# 3. Jitter on TTL
import random

def set_with_jitter(cache, key, value, base_ttl: int, jitter_fraction: float = 0.1):
    """Add random jitter to prevent synchronized expiry."""
    jitter = int(base_ttl * jitter_fraction * random.random())
    cache.set(key, value, ttl=base_ttl + jitter)
```

## Redis Patterns

### Distributed Lock (Redlock)

```python
import redis
import uuid

class RedisDistributedLock:
    def __init__(self, redis_client, key: str, ttl_ms: int = 5000):
        self._redis = redis_client
        self._key = f"lock:{key}"
        self._ttl = ttl_ms
        self._token = str(uuid.uuid4())
    
    def acquire(self, timeout_ms: int = 3000) -> bool:
        """SET NX PX — atomic acquire."""
        result = self._redis.set(
            self._key, self._token,
            nx=True,              # only set if not exists
            px=self._ttl          # auto-expire (prevent deadlock)
        )
        return result is True
    
    def release(self):
        """Only release if we own the lock (Lua script for atomicity)."""
        script = """
            if redis.call('get', KEYS[1]) == ARGV[1] then
                return redis.call('del', KEYS[1])
            else
                return 0
            end
        """
        self._redis.eval(script, 1, self._key, self._token)
    
    def __enter__(self):
        if not self.acquire():
            raise LockNotAcquiredError(f"Could not acquire lock: {self._key}")
        return self
    
    def __exit__(self, *args):
        self.release()

# Usage
with RedisDistributedLock(redis_client, key="inventory:product-123"):
    inventory = inventory_repo.get("product-123")
    inventory.decrement(qty=1)
    inventory_repo.save(inventory)
```

### Rate Limiter with Redis

```python
class SlidingWindowRateLimiter:
    def __init__(self, redis_client):
        self._redis = redis_client
    
    def is_allowed(self, key: str, limit: int, window_seconds: int) -> bool:
        now = time.time()
        window_start = now - window_seconds
        
        pipe = self._redis.pipeline()
        pipe.zremrangebyscore(key, 0, window_start)  # remove old entries
        pipe.zadd(key, {str(uuid.uuid4()): now})      # add current request
        pipe.zcard(key)                               # count in window
        pipe.expire(key, window_seconds)              # auto cleanup
        results = pipe.execute()
        
        count = results[2]
        return count <= limit
```

## Cache Sizing and Eviction

### Eviction Policies (Redis)

|Policy|When to Use|
|---|---|
|`allkeys-lru`|General cache — evict least recently used|
|`volatile-lru`|Only evict keys with TTL set|
|`allkeys-lfu`|Evict least _frequently_ used (better for skewed access)|
|`noeviction`|Return error when full — for session stores|

### Memory Sizing Rule of Thumb

```
Cache hit rate target: >90% for meaningful benefit
Typical cache size: 10-20% of working dataset
Monitor: cache hit ratio, eviction rate, memory fragmentation

redis-cli INFO stats | grep keyspace_hits
redis-cli INFO stats | grep keyspace_misses
hit_rate = hits / (hits + misses)
```

## Multi-Level Caching

```
L1: In-process cache (dict, LRU cache)  ← fastest, per-instance
L2: Shared cache (Redis)                ← fast, shared across instances
L3: DB cache (connection pool cache)    ← slower
L4: Database                            ← source of truth

Read: L1 → L2 → L3 → L4
Write: L4 + invalidate L3, L2, L1
```

```python
from functools import lru_cache

class TieredProductRepository:
    def __init__(self, redis, db):
        self._redis = redis
        self._db = db
    
    @lru_cache(maxsize=1000)   # L1: in-process, per worker
    def get_product(self, product_id: str):
        # L2: Redis
        cached = self._redis.get(f"product:{product_id}")
        if cached:
            return json.loads(cached)
        
        # L3: DB
        product = self._db.query("SELECT * FROM products WHERE id = %s", (product_id,))
        if product:
            self._redis.setex(f"product:{product_id}", 300, json.dumps(product))
        return product
```
